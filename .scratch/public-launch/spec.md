# 对公众开放：OAuth 登录、自带密钥与数据删除

Status: done

术语以 `CONTEXT.md` 为准；相关决策见 ADR-0006（对公众开放，用 Google 或 GitHub 登录）、ADR-0003 的 2026-09-27 修订（不再只限小圈子，音色可以公开）、ADR-0005 的 2026-09-27 修订（公开部署不用 Gemini 免费层）。

## Problem Statement

系统原本只给自己和小圈子用：管理员在命令行里给每个人签发访问密钥，再把密钥发给朋友，朋友在设置页填进去。现在我想把它部署到公网，给更多人用。这样一来，手动签发密钥就不可行了。而且每位用户都有自己的记忆和制作人档案，必须可靠地区分每一个人。

所有服务的费用现在都由我承担。人多了以后，我希望愿意的用户可以用自己的 API key，替我分担一部分费用。另外，陌生人的记忆里会存着他们的私事，所以他们要能彻底删除自己的数据，也要能知道这些数据交给了哪些第三方处理。

## Solution

- 任何人都可以用 Google 或 GitHub 登录，第一次登录时自动成为一位新用户，不需要邀请或审核。GitHub 账号要注册满一年，Google 邮箱要已验证。
- 登录状态保存在后端的会话里，浏览器通过 httpOnly cookie 保持登录。访问密钥整个去掉，不做迁移。
- 用户登录后，可以在设置页绑定另一种登录方式。两个身份邮箱相同也不会自动合并；已经属于别人的身份不能再绑定。
- 没登录的访客只能看到登录页。首次登录时要同意隐私政策和使用条款，并声明年满 13 岁。
- 用户可以自带 LLM、语音合成（Fish Audio）、语音识别（Soniox）的密钥。自带密钥调用失败时，这个回合就算失败，不会改用部署者的 key。
  - 文字回合用了用户自己的 LLM key，就不计入限额。
  - 通话要 LLM、语音合成、语音识别三项都用了用户自己的 key，才不计入限额。
- 用户可以删除自己的全部数据，而且是真删。
- 管理员可以在命令行列出用户、封禁和解封用户、查看某位用户的用量。

## User Stories

1. 作为访客，我想打开网址就看到这个系统是做什么的、有哪些角色，这样我能决定要不要登录。
2. 作为访客，我想用 GitHub 账号一键登录，不用再等管理员发密钥。
3. 作为访客，我想用 Google 账号一键登录。
4. 作为访客，我想在登录前能看到隐私政策和使用条款，这样我知道自己的数据会被怎样处理。
5. 作为第一次登录的用户，我想看到明确的同意步骤，勾选同意条款并声明年满 13 岁，之后就能直接开始用。
6. 作为 GitHub 账号注册不满一年的访客，我想看到明确的拒绝原因，而不是一个莫名其妙的错误。
7. 作为 Google 邮箱没有验证的访客，我想看到明确的拒绝原因。
8. 作为用户，我想在一台设备上登录后，30 天内只要一直在用就不用重新登录。
9. 作为用户，我想在设置页退出当前设备的登录。
10. 作为用户，我想在设置页一键退出所有设备，以防某台设备丢了。
11. 作为用户，我想把 GitHub 和 Google 都绑定到自己名下，这样用哪个登录看到的都是同一份记忆。
12. 作为用户，如果我要绑定的身份已经属于另一位用户，我想看到清楚的提示，告诉我该怎么办。
13. 作为用户，我想解绑一种登录方式，但系统要防止我解绑最后一种，把自己锁在外面。
14. 作为用户，我想在设置页看到自己绑定了哪些登录方式。
15. 作为用户，我想删除自己的全部数据，包括记忆、对话、制作人档案、登录方式、自带密钥和会话。删除前要再确认一次，删除后在所有设备上都退出登录。
16. 作为删除了数据的用户，我想之后用同一个 GitHub 或 Google 身份登录时，得到的是一位全新的用户，看不到任何旧数据。
17. 作为用户，我想填写自己的 LLM 接口（base_url、key、模型名），用自己的额度和角色对话。
18. 作为用户，我想在保存 LLM 密钥前，系统先帮我试调一次，这样我能马上知道填对没有。
19. 作为用户，我想在界面上只看到自带密钥的末 4 位，以免密钥在屏幕上泄露。
20. 作为用户，我想随时修改或删除自带密钥，删除后自动改回用部署者的服务。
21. 作为用户，我想在界面上看到「小模型会降低扮演和记忆的质量」的提示。
22. 作为用户，我想在自带密钥调用失败时（比如余额不足、被吊销），看到明确的提示，指出是哪一项密钥出了问题。
23. 作为用户，我想填写自己的 Fish Audio key，通话时的语音合成用我的额度。
24. 作为用户，我想填写自己的 Soniox key，通话时的语音识别用我的额度。
25. 作为用自己 LLM key 的用户，我想文字回合不受每小时限额的约束。
26. 作为 LLM、语音合成、语音识别都用自己 key 的用户，我想通话不受每小时通话次数的约束。单次通话的时长和回合数仍有上限，这我可以接受。
27. 作为部署者，我想让陌生人登录时只能拿到自己的会话，而且会话凭证不会被网页上的脚本读走。
28. 作为部署者，我想在本地开发和端到端测试时不用走真实的 OAuth 流程也能登录。
29. 作为部署者，我想在生产环境误开了开发登录开关时，后端拒绝启动。
30. 作为管理员，我想在命令行里列出所有用户，看到他们绑定了哪些登录方式、什么时候创建的、是否被封禁。
31. 作为管理员，我想封禁一位用户，让他立刻在所有设备上退出登录，并且无法再登录。
32. 作为管理员，我想解封一位用户。
33. 作为管理员，我想查看某位用户最近的用量，这样能判断是不是有人在刷。
34. 作为部署者，我想让日志里不会出现用户记忆的原文。
35. 作为部署者，我想在公开部署还在用 Gemini 免费层时收到启动警告。
36. 作为想自己部署一套的人，我想在 README 和部署文档里看到怎样创建 Google 和 GitHub 的 OAuth 应用、需要配置哪些环境变量。

## Implementation Decisions

- **身份提供方**：新增 `IdentityProvider` 接口，负责生成授权跳转地址，并用回调里的授权码换取身份。身份包括提供方、提供方内的唯一 ID、显示名、邮箱、邮箱是否已验证、账号创建时间。Google 和 GitHub 各实现一个，像其他外部服务一样由装配根注入，测试时换成假实现。
  - 回调由 FastAPI 处理，用 state 参数防 CSRF。GitHub 的账号创建时间来自用户资料里的 `created_at`，Google 看 `email_verified`。
  - 「注册满一年」的时长写在代码里，不做成配置项。
- **数据模型**：
  - 新增「登录方式」表：用户、提供方、提供方内 ID，后两者联合唯一。
  - 新增会话表：只存会话令牌的哈希，以及最后活跃时间和过期时间。
  - 新增自带密钥表：用户、服务类型，外加加密后的密钥、LLM 的 base_url 和模型名、末 4 位。
  - 用户表：`name` 去掉唯一约束，只用来在管理员命令行里辨认是谁；新增是否已同意条款、是否被封禁两个字段。
  - 删除访问密钥表。
  - 数据库打开 WAL 模式。
- **会话**：
  - cookie 设为 httpOnly、Secure（开发环境除外）、SameSite=Lax。
  - 有效期 30 天，只要在用就续期。
  - 所有会改动数据的请求都要校验 Origin，防 CSRF。
  - 替换现有的「解析当前用户」依赖，语音信令同样按会话鉴权。
  - Next 代理层转发 Cookie 请求头和 Set-Cookie 响应头；OAuth 跳转和回调也经过这层同源代理。
- **开发登录**：`EIDOLON_DEV_LOGIN=1` 打开一个接口，可以直接以指定名字的用户登录。生产环境（Caddy 部署，用是否配置了 `EIDOLON_DOMAIN` 判断）检测到这个开关就拒绝启动。
- **首次同意**：用户没有同意条款前，除「同意」「退出登录」「删除数据」外的所有接口都返回一个专门的状态码，前端据此跳转到同意页。
- **自带密钥**：
  - 用 `EIDOLON_SECRET_KEY` 派生的对称密钥加密保存；没配置这个变量时，不开放自带密钥功能。
  - 每个回合、每次通话开始时，按用户解析出本次要用的 LLM、语音合成、语音识别客户端。提炼记忆的后台 LLM 跟随对话 LLM。判断要不要回忆剧情、向量化、重排不受影响。
  - 自带密钥调用出错时，回合按现有规则失败，不计入限额，错误信息里带上是哪一项服务。
- **限额豁免**：文字回合只要用了用户自己的 LLM 就不计入；通话要 LLM、语音合成、语音识别都是用户自己的才不计入。单次通话的时长和回合数上限不变。
- **删除用户**：在一个事务里删除这位用户的记忆和记忆向量、对话和消息、制作人档案、登录方式、自带密钥、会话和用量记录。如果这位用户正在通话，通话会被挂断。
- **管理员命令行**：
  - 把 `user create`、`key issue`、`key list`、`key revoke` 这几条命令换成 `user list`、`user ban`、`user unban`、`user usage`。
  - 封禁时同时删除这位用户的所有会话；被封禁的用户登录会被拒绝。
- **加固**：记忆 JSON 解析失败时，日志只记长度和会话 ID，不记模型的原始输出。公开部署（配置了 `EIDOLON_DOMAIN`）在用 Gemini 向量化、又没有声明已开计费（新增 `GEMINI_BILLING_ENABLED`）时，启动时打一条警告。

## Testing Decisions

- 好的测试只看外部行为：从 HTTP API 发请求，断言响应、后续请求能否成功、数据是否消失，不检查内部的表结构。
- **测试切入点**：
  - 沿用现有的 httpx 客户端工厂（`make_client`）和管理员命令行夹具（`Admin`）。
  - 新增唯一一个切入点：`FakeIdentityProvider`，由测试指定它返回的身份。
  - 客户端工厂从「带访问密钥」改为「带会话」，默认以一位已同意条款的用户登录；另外提供「以某个身份登录」的辅助函数。
- **自带密钥的测试**：扩展 `FakeLLM` 和 `FakeSpeech`，让它们记录每次调用用的是哪个 key，这样测试就能断言「这个回合用的是用户的 key，失败时也没有改用部署者的 key」。
- **可参考的现有测试**：`test_access_keys.py`（鉴权，会被新测试取代）、`test_rate_limit.py`（限额）、`test_memory_management.py`（删除记忆）、`test_voice_call.py`（通话鉴权）。
- 前端没有组件测试，登录页、同意页和设置页靠手动验证；前端 `lib` 目录里的纯逻辑用 vitest 测试。

## Out of Scope

- 国内的登录方式（QQ、bilibili 等）和邮箱验证码登录。
- 数据导出。
- 游客模式。
- 全站总预算上限。
- 按 IP 限制注册频率。
- 付费与订阅。
- 从 SQLite 换到 Postgres。
- 自动合并邮箱相同的身份，以及合并两位用户的数据。

## Further Notes

- 仓库保持私有，剧情库仍然不提交（ADR-0003）。
- 公开部署选 Gemini 向量化时，需要开计费，或者改用硅基流动（ADR-0005 修订）。
