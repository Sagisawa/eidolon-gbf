# 07: 自带 LLM 密钥

**What to build:** 用户在设置页填入自己的 LLM 接口（base_url、key、模型名），保存时系统先试调一次，能用才保存。之后这位用户的文字回合、通话里角色的回复和后台提炼记忆，都改用这个 LLM。key 在界面上只显示末 4 位。调用失败时回合就失败，并提示「你的 LLM 密钥调用失败」，不会改用部署者的 key。用户可以随时删除自带的 LLM，删除后改回用部署者的。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 新增自带密钥表：用户、服务类型、加密后的密钥、base_url、模型名、末 4 位；同一位用户、同一种服务只能有一条
- [ ] 用 `EIDOLON_SECRET_KEY` 派生的对称密钥加密保存；没配置这个变量时，自带密钥的接口返回「未开放」，设置页也不显示这一栏
- [ ] 保存前先发一次最小的请求试调，失败就不保存，并返回服务商的错误信息
- [ ] 每个回合、每次通话开始时，按用户解析出要用的 LLM 客户端；后台提炼记忆时用同一位用户的 LLM。判断要不要回忆剧情、向量化、重排仍然用部署者的
- [ ] 自带 LLM 调用失败时，回合按现有规则失败，不计入限额，错误信息里写明是「你的 LLM 密钥」出了问题
- [ ] 设置页新增 LLM 一栏：填写、修改、删除，只显示末 4 位，附带「小模型会降低扮演和记忆的质量」的提示
- [ ] 删除用户时连带删除自带密钥（接到 06 的统一删除入口上；如果 06 还没做，就在这里预留）
- [ ] `FakeLLM` 记录每次调用用的是哪个 key；测试覆盖：保存时试调失败则不保存；回合用的是用户的 LLM；提炼记忆也用用户的 LLM；调用失败时回合失败，也没有改用部署者的 key；删除自带密钥后改回部署者的；API 响应里不出现 key 的明文
