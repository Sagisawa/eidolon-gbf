# 04: 每回合变的内容挪到历史后面，历史分段截断

**What to build:** 对话模型连续几个回合的请求，开头（共用固定部分、制作人资料、历史）保持一致，让历史也能命中缓存；角色的表现和现在一样。用户读改动前后的对照稿确认。背景见 `../spec.md`「动态内容后移」「历史分段截断」「Anthropic 缓存断点」。

**Blocked by:** 02（开头系统消息已拆成两条），03（排法和 DeepSeek 上怎么禁止调用由实验结果和用户决定）

**Status:** done

**难度：中到大。** 改提示词结构，会影响角色表现，必须用真模型验证。若 03 选了「只追加」，还要记下每回合带上的动态内容。

## 已定的设计（详见 spec）

- 固定在前：共用固定部分（人设、世界设定、格式说明），然后制作人资料（称呼、性别、生日日期），然后历史。
- 靠后：当前时间、生日当天的提醒、好感度那几行、找到的记忆、预先回忆的剧情和参考资料，合成一条系统消息，放在历史后面、这句话前面。对话事件的旁白照旧放在用户的话前面。
- Chat Completions 原地发 `role: system`；Responses 原地发 system 角色的输入项，不拼进 `instructions`；Anthropic 改成用户这一轮最前面一个独立的文本块。
- 保存时的检查也带一条靠后的系统消息。
- Anthropic 第二个断点打在历史最后一条消息上。
- 历史分段截断：N 为下限，步长 ⌊N ÷ 2⌋（至少 1），砍掉 步长 × ⌊(T − N) ÷ 步长⌋ 回合；只用在对话模型上，判断和提炼记忆照旧看最近 N 回合。
- DeepSeek 上怎么禁止调用、是否「只追加」：按 03 的决定（见 Comments）。

- [x] 引擎测试：分段截断在 T = N、N + 1、N + 步长 − 1、N + 步长、N + 2 × 步长 时带的回合；N 为不限时全带；判断和提炼记忆看到的历史不变（这一项在引擎接缝上测不出来，没有测试，见 Comments）。

- 2026-10-15 实现：`producer_prompt(profile)` 只剩固定的档案（称呼、性别、生日日期）；新的 `now_prompt` 是「# 此刻」一段：当前时间、生日当天的提醒、好感度那几行。引擎发的请求依次是：共用固定部分（人设、世界设定、格式说明，带 `cache_breakpoint`）、制作人档案、历史（最后一条带 `cache_breakpoint`）、靠后的系统消息（此刻、记忆、预先回忆的剧情或参考资料）、这句话。第一回合没有历史，靠后那条紧跟在开头系统消息后面，三种协议上都会并进开头（Anthropic 上成为 `system` 的最后一块），对缓存没影响。分段截断是 `engine.chat_history`，只给对话模型用；检索、判断、提炼记忆仍用 `latest_turns(messages, N)`。判断模型自己只看最近两回合、提炼记忆只看最近几条消息，在引擎接缝上看不出 N 和分段截断的区别，所以「判断和提炼记忆看到的历史不变」没写引擎测试，由代码保证（两处仍传 `latest_turns` 的结果）。
