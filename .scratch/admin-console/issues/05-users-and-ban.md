# 05: 用户列表与封禁

**What to build:** 管理者在后台的「用户」页看到用户列表，能按名字、邮箱或用户 ID 搜索，打开某位用户看详情；能封禁（附只有管理者看得到的备注）和解除封禁。被封禁的用户登录时看到已被封禁和部署者的联系方式。管理者在这里永远看不到任何对话、记忆和制作人档案的内容。见 `../spec.md` 的「用户管理」一节。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 用户列表接口：分页；按名字、邮箱、用户 ID 搜索；每位用户返回名字、登录方式（提供方、显示名、邮箱、标识）、注册时间、最后活跃时间（会话的最近活动时间）、是否封禁、是否是管理者、是否自带密钥（按服务只给「有 / 没有」）。
- [ ] 用户详情接口：同上，加上封禁时间和备注。响应里不含任何对话、记忆、制作人档案的内容（测试里明确断言）。
- [ ] 封禁 / 解除封禁接口：复用 `Store.set_banned`（退出所有会话，通话由现有轮询挂断）；封禁时可以写备注，存进新字段。目标是管理者时拒绝，包括自己。
- [ ] 命令行 `eidolon user ban / unban` 与后台走同一段代码；`ban` 增加可选的备注参数。
- [ ] `.env` 新增可选的联系方式变量。被封禁的用户登录失败时，提示沿用「已被封禁」的说法并附上联系方式；没设联系方式时不显示这一句。
- [ ] 前端「用户」页：Table 列表加搜索框；用户详情；封禁对话框（备注、确认）；解除封禁。管理者那一行不显示封禁按钮。手机上列表、详情和封禁能用。
- [ ] 测试（HTTP API）：列表、分页、三种搜索；封禁后此人的请求得到 403、会话失效、进行中的通话被挂断；解除封禁后能重新登录；封禁管理者被拒绝；被封禁的人登录时的提示带联系方式；响应里没有内容数据；`test_admin_commands.py` 覆盖命令行的备注参数。
