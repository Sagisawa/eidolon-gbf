# 13: 人工验证

**What to build:** 在本地和 VPS 上真实地走一遍后台，确认自动测试覆盖不到的部分：真实服务商的「保存前先试」、运行中替换客户端时正在进行的通话、看板数字和真实账单的量级、手机上的可用性。

**Blocked by:** 01, 02, 03, 04, 05, 06, 07, 08, 09, 10, 11, 12

**Status:** ready-for-human

- [ ] 本地用 Playwright 走一遍：非管理者访问 `/admin` 得到 404；管理者从设置页进入；看板、配置、用户三页在电脑和手机宽度下都可用。
- [ ] 配置：在后台换一个扮演角色的模型和一个错误的 key，确认错误的 key 保存不了、原因说得清楚；换成正确的以后，下一个回合用上新模型。
- [ ] 通话中，在另一台设备上改语音合成的模型，确认这通电话的声音不变，挂断再打后变了。
- [ ] 在服务器上改 `.env` 里一项已被后台覆盖的值并重建容器，确认没有生效，且启动日志列出了被覆盖的项；在后台恢复成 `.env` 的值后生效。
- [ ] 把某项覆盖的 key 在服务商那边吊销后重启，确认服务照常启动、后台标出「覆盖已失效」。
- [ ] 用一个测试账号：封禁后它的通话被挂断、登录看到带联系方式的提示；解除封禁；设单独限额 1 并撞上；删除被封禁的测试账号后同一身份登录被拒绝。
- [ ] 看板：打几通电话、发几条文字后，健康、用量、花费的数字合理；花费和服务商控制台的用量在量级上一致。
- [ ] 隐私政策和部署文档读一遍，和实际行为一致。
