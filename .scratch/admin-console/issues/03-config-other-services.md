# 03: 其余服务的配置

**What to build:** 在 02 打通的路上，把其余服务也接进后台的「配置」页：提炼记忆的 LLM、语音合成、语音识别、判断模型（含情绪阈值和回忆阈值）、重排阈值。同时列出只能查看的项，并说明为什么不能改。见 `../spec.md` 的「配置覆盖」一节。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 提炼记忆的 LLM：协议、base_url、key、模型、max_tokens 可改；没有覆盖时仍沿用「不填就跟随扮演角色的 LLM」的规则，界面上说明当前值从哪里来。保存前用与扮演角色相同的探测。
- [ ] 语音合成：key 和模型可改，保存前做零成本检查（复用自带密钥的检查）。新配置只影响之后接通的通话。
- [ ] 语音识别：选 Soniox 或阿里云百炼，以及对应的 key 可改；保存前做零成本检查；选百炼时沿用启动时的地域探测。新配置只影响之后接通的通话。自带语音识别密钥的用户不受影响。
- [ ] 判断模型：选 Jev 或 Cloudflare、key、模型（Cloudflare 的 clef / clef-flash）、情绪的最低概率和超时、回忆阈值可改。保存前：Cloudflare 复用启动检查，Jev 问一个最小的问题。回忆阈值和情绪阈值的覆盖只对当前选用的模型生效；换模型时清掉，界面上说明。
- [ ] 重排：剧情和记忆的最低相关度可改；同样只对当前模型生效。
- [ ] 只读项一节：管理者名单、`EIDOLON_SECRET_KEY`（只显示设没设）、OAuth（只显示配了哪几家）、域名、WebRTC/TURN、备份、各种路径、向量化的服务和模型，每一类附一句为什么不能在后台改。任何密钥都不显示原文。
- [ ] 接口拒绝修改只读项。
- [ ] 测试（HTTP API + 假工厂）：每项服务保存后新的回合或通话用上新配置、进行中的通话不变；各自的保存前检查试不通不保存；换判断模型后阈值覆盖被清掉；重排阈值改了以后影响下一个回合的检索结果；修改只读项被拒绝。
