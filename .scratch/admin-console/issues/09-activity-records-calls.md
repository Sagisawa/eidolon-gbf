# 09: 运行记录：通话

**What to build:** 每次通话留下一条运行记录：结果（成功、没能接通、因故障中断）、时长、结束原因，以及通话里语音识别、语音合成、判断情绪的每次调用和用量；通话中的回合照常各有一条回合的运行记录，并挂在这次通话下。看板加上通话数和趋势、按角色的通话数、时长和结束原因的分布，以及每分钟自动刷新的进行中通话数。见 `../spec.md` 的「运行记录」一节。

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] 通话的结果与 GLOSSARY「接通」和限额的计入、退还使用同一个判断（`CallOutcome`），不另写一套。
- [ ] 记下时长和结束原因（用户挂断、离开对话页、撞上时长或回合上限、被封禁、故障）。
- [ ] 通话中的回合：被打断的回合、补充合并后的回合都按 GLOSSARY 判定结果；放下的那次回复不单独记。
- [ ] 埋点：语音识别记音频秒数，语音合成记字符或字节，判断情绪记调用；自带密钥的调用标记出来。Pipecat 管线里的错误要能落到对应服务的出错上。

- [ ] 测试（HTTP API + fakes，沿用 `test_voice_call.py`、`test_call_outcome.py` 的方式）：接通后正常挂断、没能接通、通话中撞上时长上限、被封禁挂断，各自的结果和结束原因正确；通话中的回合挂在这次通话下；语音合成出错时健康数据里能看到；进行中的通话数在接通和挂断后变化。
