# 12: 文档

**What to build:** 让产品说明、隐私政策和部署文档与后台一致：部署者知道怎么开启后台、后台和 `.env` 是什么关系；用户从隐私政策里知道管理者能看到什么、运行记录怎么处理。

**Blocked by:** 06, 07, 09, 10, 11

**Status:** ready-for-agent

- [ ] `PRODUCT.md`：改写「次要角色」（部署者兼管理者通过后台和命令行运维，引用 ADR-0013）；「现有页面」加上 `/admin`；Operating Context 补一句后台。
- [ ] 隐私政策（`zh.ts` 的 `privacy`）：管理者能看到登录方式（含邮箱）、用量、是否自带密钥，看不到对话、记忆、制作人档案；运行记录记什么、不记什么、保留 90 天、删除用户后匿名化；被封禁的用户删除后会保留登录方式的哈希，不能再登录；联系方式（设了才显示）。使用条款里「部署者可以封禁这样的用户」按需要调整。
- [ ] `.env.example`：管理者名单和联系方式两个变量的说明。
- [ ] `docs/deploy.md`：如何开启后台（找到自己的登录方式标识、填名单、重建容器）；后台覆盖优先于 `.env`、启动日志会列出被覆盖的项、覆盖失效时的回退；哪些项只能在 `.env` 里改；后台不可用时用命令行。
- [ ] 三份 README（中、英、日）：功能列表和配置一节加上后台，与 `docs/deploy.md` 一致。
