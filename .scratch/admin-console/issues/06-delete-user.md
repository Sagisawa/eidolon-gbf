# 06: 删除用户与封禁名单

**What to build:** 管理者可以在用户详情里替某位用户删除他的全部数据，效果和用户自己删除完全一样。被封禁的用户删除后，他用过的登录方式仍然不能再登录或被绑定，删除不会变成解封。见 `../spec.md` 的「用户管理」一节和 GLOSSARY「用户」「封禁」。

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] 删除接口复用用户自删的整体删除路径（对话、记忆、制作人档案、登录方式、会话、自带密钥等），进行中的通话照常被挂断。目标是管理者时拒绝。
- [ ] 删除被封禁的用户之前，把他每个登录方式的「提供方 + 标识」做成带密钥的哈希存进封禁名单表：有 `EIDOLON_SECRET_KEY` 时用它派生的密钥（HMAC），没有时用普通 SHA-256。这张表登记为「不是用户数据」。
- [ ] 登录和绑定登录方式时先查封禁名单，命中就按「已被封禁」拒绝，提示与 05 相同。
- [ ] 删除没有被封禁的用户时不写封禁名单，他之后可以重新注册。
- [ ] 前端：用户详情里的删除按钮，二次确认，说明「彻底删除、备份里最多再留 30 天；如果他已被封禁，他的登录方式不能再登录」。
- [ ] 测试（HTTP API）：删除后此人的所有数据都不在了（复用 `test_delete_account.py` 的检查方式）；被封禁的人删除后，用同一个 GitHub / Google 身份登录被拒绝、绑定到别的用户也被拒绝；未被封禁的人删除后能用同一身份重新注册；删除管理者被拒绝。
