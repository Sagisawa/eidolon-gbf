# 后台：管理部署的配置和用户，并查看看板

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准（本次新增「部署者」「管理者」「后台」「封禁」「运行记录」「看板」，修改「用户」「限额」）。架构决定见 ADR-0013。

## Problem Statement

对公众开放以后，部署者的日常运维全靠登录服务器：换模型、换 key、调限额，都要改 `.env` 再重建容器，所有人的通话都会被挂断；封禁刷量的用户要 `docker compose exec` 跑命令行，还得先知道对方的用户 ID，而唯一能看用量的 `eidolon user usage` 只有最近 24 小时的数据。

部署者也不知道这套部署跑得怎么样：哪家服务在出错、延迟多少、有多少人在用、每位角色多受欢迎、自己的 key 烧了多少钱，统统没有记录。失败的回合不进对话，只在 stdout 的文本日志里留一行；用了哪家服务、多少 token、花了多久，什么地方都没记。

## Solution

在同一个网站的 `/admin` 下增加后台，只有管理者能进入。管理者是部署者在 `.env` 里列出的、用某些登录方式登录的普通用户；没有设名单时，后台整个不存在。

后台有三块：

1. **看板**：按服务显示调用次数、出错率和延迟（自带密钥的调用单独统计）；活跃用户、回合和通话的数量与趋势、每位角色的用量、进行中的通话数；按管理者设定的单价估算部署者的花费。可选最近 24 小时、7 天、30 天、90 天。数据来自新增的运行记录，每个回合和每次通话一条，细到其中每一次服务调用，保留 90 天。
2. **配置**：扮演角色和提炼记忆的 LLM、语音合成、语音识别、判断模型、重排阈值、限额、单次通话上限、带上的历史轮数、各模型的单价。改动存进数据库、优先于 `.env`，保存前先试一下，保存后新的回合和新的通话立即生效，不用重启。每一项都能看到 `.env` 的值和当前生效的值，也能恢复成 `.env` 的值。不能改的项（管理者名单、`EIDOLON_SECRET_KEY`、OAuth、域名、WebRTC/TURN、备份、路径、向量化）只显示。
3. **用户**：列出和搜索用户，查看每位用户的登录方式（含邮箱）和近期用量，封禁、解除封禁、删除用户，给某位用户单独设限额。管理者在后台里永远看不到任何人的对话、记忆和制作人档案的内容。

## User Stories

进入后台

1. As a 部署者, I want to 在 `.env` 里列出哪些登录方式属于管理者, so that 我和信任的几个人用平常的 GitHub / Google 登录就能进后台，不用另记一套口令。
2. As a 部署者, I want to 管理者名单只能在服务器上改, so that 即使有人拿到了某位管理者的会话，也没法在后台里把别人加成管理者。
3. As a 部署者, I want to 用命令行看到每位用户的登录方式标识, so that 我知道该把哪一个填进管理者名单。
4. As a 管理者, I want to 在设置页看到进入后台的入口, so that 我不用记住地址。
5. As a 普通用户, I want to 看不到任何后台入口, so that 界面保持安静、只和角色有关。
6. As a 部署者, I want to 非管理者访问 `/admin` 或后台接口时得到 404, so that 外人连有没有后台都不知道。
7. As a 只用 `.env` 部署的人, I want to 不设管理者名单时一切照旧, so that 我不需要为后台做任何事。
8. As a 管理者, I want to 后台的所有权限都相同, so that 我们几个人之间不用划分谁能做什么。
9. As a 管理者, I want to 后台在电脑上好用、在手机上至少能看看板和封禁用户, so that 外出时发现有人刷量也能处理。

看板：健康

10. As a 管理者, I want to 看到每项服务（扮演角色的 LLM、提炼记忆的 LLM、语音合成、语音识别、判断模型、向量化、重排）在所选时间段内的调用次数、出错率和延迟, so that 我一眼就知道哪家在出问题。
11. As a 管理者, I want to 判断模型和重排的出错也算进去，即使回合照常完成, so that 这类不影响回合结果的故障不会被掩盖。
12. As a 管理者, I want to 用户自带密钥的调用和部署者的调用分开统计, so that 用户的 key 出错不会让我以为自己的服务坏了。
13. As a 管理者, I want to 看到回合和通话的结果分布（成功、失败、被拒绝、用户离开、没能接通）, so that 我知道用户实际体验如何。
14. As a 管理者, I want to 看到回合从发出到角色开口要多久, so that 我能判断换模型后是变快还是变慢了。
15. As a 管理者, I want to 看到通话的时长和结束原因的分布, so that 我知道用户是自己挂断、撞上通话上限，还是因为故障断开的。

看板：用量

16. As a 管理者, I want to 看到所选时间段的活跃用户数、回合数和通话数，以及它们随时间的趋势, so that 我知道有多少人在用、在变多还是变少。
17. As a 管理者, I want to 看到每位角色的回合数和通话数, so that 我知道哪位角色最受欢迎。
18. As a 管理者, I want to 看到有多少回合和通话用的是自带密钥, so that 我知道自带密钥替我分担了多少。
19. As a 管理者, I want to 看到此刻进行中的通话数，每分钟自动刷新, so that 重启或改配置前我知道会影响多少人。
20. As a 管理者, I want to 在 24 小时、7 天、30 天、90 天之间切换, so that 我既能看眼前也能看趋势。

看板：花费

21. As a 管理者, I want to 看到所选时间段内部署者的 key 大约花了多少钱，按服务和币种分开, so that 我知道钱花在哪儿。
22. As a 管理者, I want to 花费明确标注是按单价估算、不扣免费额度, so that 我不会把它当成账单。
23. As a 管理者, I want to 自带密钥的用量只显示数量、不换算成钱, so that 花费只反映我自己要付的部分。
24. As a 管理者, I want to 目前支持的各个模型已经预设好单价，并注明价格整理于哪天, so that 不填任何东西也能看到大致的花费，也知道价格可能已经过时。
25. As a 管理者, I want to 在后台修改或补充某个模型的单价和币种, so that 价格变了或者我换了个没预设的模型时，估算依然准确。
62. As a 管理者, I want to 单价自动从在线目录（models.dev、OpenRouter）获取并每天更新，并能看出每个单价来自目录、预设还是我自己设的, so that 新模型和调价不用等人去改代码，估算也不会悄悄过时。

配置

26. As a 管理者, I want to 在后台修改扮演角色和提炼记忆用的 LLM（协议、base_url、key、模型、max_tokens）, so that 换模型不用登录服务器。
27. As a 管理者, I want to 修改语音合成的 key 和模型, so that 换 key 或升级模型不用重建容器。
28. As a 管理者, I want to 选择语音识别用哪家服务并修改它的 key, so that 一家出故障时我能马上切到另一家。
29. As a 管理者, I want to 选择判断模型用哪家、修改 key 和模型，以及情绪和回忆的阈值, so that 我能根据实际表现调整。
30. As a 管理者, I want to 修改重排的阈值, so that 回忆和想起记忆的松紧可以在线调。
31. As a 管理者, I want to 修改每小时的回合数、通话次数，以及单次通话的时长和回合上限, so that 被刷或者预算吃紧时我能立刻收紧。
32. As a 管理者, I want to 修改带上的历史轮数, so that 我能在质量和花费之间调整。
33. As a 管理者, I want to 保存后新的回合和新的通话马上用上新配置，不用重启, so that 改配置不会挂断任何人。
34. As a 正在通话的用户, I want to 管理者改了配置也不影响我这通电话, so that 角色的声音和反应不会说到一半突然变了。
35. As a 管理者, I want to 保存前先试一下新的 key 或模型，试不通就不保存并告诉我原因, so that 我不会一手把整站弄坏。
36. As a 管理者, I want to 每一项旁边同时看到 `.env` 的值和当前生效的值, so that 我知道哪些被后台覆盖了。
37. As a 管理者, I want to 把某一项恢复成 `.env` 的值, so that 试验完能一键回到原状。
38. As a 部署者, I want to 启动日志列出哪些项被后台覆盖了, so that 我改了 `.env` 却没生效时能找到原因。
39. As a 部署者, I want to 重启时某项覆盖试不通（比如 key 已被吊销）就改用 `.env` 的值继续运行，并在后台醒目地标出, so that 坏掉的覆盖不会让服务起不来、我也进不了后台去修。
40. As a 管理者, I want to key 只显示末 4 位, so that 后台页面被人看到或截图也不会泄露。
41. As a 部署者, I want to 不能改的项（管理者名单、`EIDOLON_SECRET_KEY`、OAuth、域名、WebRTC/TURN、备份、路径、向量化）只显示不能改，并说明为什么, so that 后台出问题时也锁不住我，向量也不会因为误改而失效。
42. As a 没有设 `EIDOLON_SECRET_KEY` 的部署者, I want to 后台里的 key 只能看不能改，其他配置照常可以改, so that 没有加密手段时 key 不会以明文存进数据库。

用户

43. As a 管理者, I want to 看到用户列表：名字、登录方式（提供方、显示名、邮箱）、注册时间、最后活跃时间、是否封禁、是否有单独限额、是否自带密钥, so that 我对谁在用有个大致了解。
44. As a 管理者, I want to 按名字、邮箱或用户 ID 搜索用户, so that 有人发邮件来时我能找到他。
45. As a 管理者, I want to 看到某位用户最近 24 小时、7 天、30 天的回合数和通话数，以及撞上限额的次数, so that 我能判断他是不是在刷。
46. As a 管理者, I want to 从看不到任何对话、记忆和制作人档案的内容, so that 用户的隐私受到尊重，我也不用对这些内容负责。
47. As a 管理者, I want to 封禁一位用户并写一句只有管理者看得到的备注, so that 以后我们几个都知道当初为什么封他。
48. As a 管理者, I want to 封禁后这位用户在所有设备上立刻退出、进行中的通话随即挂断, so that 封禁马上生效。
49. As a 管理者, I want to 解除封禁, so that 封错了能改回来。
50. As a 被封禁的用户, I want to 登录时看到我已被封禁和联系方式，但看不到原因, so that 我知道发生了什么、该找谁。
51. As a 管理者, I want to 替某位用户删除他的全部数据，效果和他自己删除完全一样, so that 他发邮件要求删除时我能办到。
52. As a 管理者, I want to 被封禁的用户删除后，他用过的登录方式仍然不能再注册, so that 删除不会变成解封。
53. As a 管理者, I want to 后台不能封禁或删除任何管理者，包括我自己, so that 不会把自己锁在门外。
54. As a 管理者, I want to 给某位用户单独设定每小时的回合数和通话次数（数字、不限，或 0 即只能用自带密钥），附一句备注, so that 我能照顾测试者、限制可疑的人，而不必改全站限额。
55. As a 管理者, I want to 随时取消某位用户的单独限额, so that 他回到全站默认。
56. As a 被单独设了限额的用户, I want to 撞上限额时看到的提示和平常一样准确（几次、什么时候可以再试）, so that 我不会被含糊的说法弄糊涂。

运行记录与隐私

57. As a 用户, I want to 删除自己时，运行记录不再关联到我, so that 我的数据真的被删掉。
58. As a 管理者, I want to 用户删除以后，看板上的历史数字不变, so that 趋势不会因为有人离开而跳动。
59. As a 用户, I want to 隐私政策写明管理者能看到我的登录邮箱和用量、运行记录保留多久、被封禁后删除会留下什么, so that 我知道自己的数据被怎样处理。
60. As a 部署者, I want to 运行记录满 90 天自动删除, so that 数据库不会无限增长，隐私政策里的承诺也能兑现。

命令行

61. As a 部署者, I want to 原有的 `eidolon user ban / unban / list / usage` 照常可用，并且和后台的效果完全一致, so that 后台挂了时我仍有退路。

## Implementation Decisions

管理者

- `.env` 新增管理者名单，值是若干个「提供方:身份标识」（例如 `github:12345`），用登录方式的提供方和 subject 认定，不用邮箱（两个身份即使邮箱相同也不是同一位用户，见 GLOSSARY「登录方式」）。`eidolon user list` 要打印出每个登录方式的这一标识。
- 后端新增一个「管理者」依赖：在已登录、已同意条款的基础上，要求这位用户的某个登录方式在名单里；不满足时一律 404。名单为空时，所有后台接口都返回 404。
- 用户自己的账户信息接口多返回一个「是不是管理者」，前端据此在设置页显示入口。`/admin` 页面拿到 404 时显示 Next 的 404 页面。
- 现有的「非 GET 请求必须同源」中间件和 cookie 会话照样保护后台接口，不另做 CSRF。

配置覆盖（ADR-0013）

- 新增一张配置覆盖表：每项一行，记值（key 类用 `EIDOLON_SECRET_KEY` 派生的 Fernet 加密，HKDF 的 `info` 与自带密钥的不同）、末 4 位和更新时间。不留改动历史。
- 新增一个「生效配置」模块：由启动时的 `Settings` 加上数据库里的覆盖合成。它是后台读写配置的唯一入口，负责校验、保存前试一下、恢复成 `.env` 的值，并把「`.env` 的值 / 当前生效的值 / 覆盖已失效、回退到 `.env`」三种状态报给后台。
- 新增「按配置创建服务客户端」的工厂，LLM（两种用途）、语音合成、语音识别、判断模型共用。生效配置一变，就用工厂建出新客户端，换下旧的；旧客户端等所有用到它的回合和通话结束后再关闭。这是本次新增的唯一测试接缝。
- 每个回合开始时、每次通话接通前，各取一份当时的生效配置快照，这个回合或这通电话从头到尾用它。限额、单次通话上限、历史轮数、各种阈值也按这个规则生效。
- 「保存前先试一下」：LLM 复用启动时对扮演角色模型的探测（流式和工具调用），语音合成和语音识别复用自带密钥的零成本检查，判断模型复用 Cloudflare 的启动检查，Jev 问一个最小的问题。试不通返回原因，不保存。
- 启动时对每一项覆盖都试一次；试不通就这一项改用 `.env` 的值，在日志里写一行警告，后台标为「覆盖已失效」，覆盖本身保留，直到管理者修好或删除它。同时在日志里列出所有生效中的覆盖项。
- 后台可以修改的项和只能查看的项按 Solution 里的划分。判断模型的回忆阈值和重排的阈值原本按模型写在代码里，现在可以在后台覆盖；覆盖只对当前选用的模型生效，换模型时清掉这一项的覆盖，并在界面上说明。
- 自带密钥的路由（`OwnKeys.for_turn` / `for_call`）不变，只是「部署者的客户端」从启动时固定的那一组改为来自生效配置。
- 没有设 `EIDOLON_SECRET_KEY` 时，key 类的项只读，其他项照常可写。

用户管理

- 用户列表和用户详情的后台接口：分页，按名字、邮箱、用户 ID 搜索；返回登录方式（提供方、显示名、邮箱、标识）、注册时间、最后活跃时间（取会话的最近活动时间）、封禁状态和备注、单独限额、自带密钥的有无（只有「有 / 没有」，按服务列出）、近期用量（来自运行记录）。不返回任何对话、记忆、制作人档案的内容。
- 封禁和解除封禁复用 `Store.set_banned`（退出所有会话；通话由现有的轮询在几秒内挂断）；新增只有管理者可见的备注。命令行和后台走同一段代码。
- 管理者删除用户复用用户自己删除的那条路径（`database.py` 的整体删除），外加：被封禁的用户删除前，把他每个登录方式的「提供方 + 标识」做成带密钥的哈希存进一张封禁名单表（有 `EIDOLON_SECRET_KEY` 时用它派生的密钥，没有时用普通 SHA-256）；以后登录或绑定时命中名单就当作被封禁拒绝。
- 后台拒绝封禁和删除任何管理者。
- 被封禁的用户登录失败时，提示沿用「已被封禁」的说法（不用「停用」「账号」，见 GLOSSARY），后面加上部署者的联系方式；联系方式是 `.env` 里一个新的可选项，隐私政策也显示它，没设时不显示。
- 单独限额：新增一张按用户的限额覆盖表（每小时回合数、每小时通话次数、备注），值是正整数、「不限」或 0。`UsageLimiter.take` 先查这位用户的覆盖，再用全站值；超限的 429 文案和 `retry_at` 用的是这位用户实际适用的数字。自带密钥免计入的规则不变，所以 0 就等于「只能用自带密钥」。单次通话上限不能单独设。

运行记录

- 新增两张表：每个回合和每次通话一条运行记录（种类、用户、角色、开始时间、结果、对通话再记时长和结束原因、对回合再记到开口的时间），以及其中的每一次服务调用（服务、提供方、模型、是不是自带密钥、成败和出错类别、延迟、计费用量）。不在对话里发生的服务调用（例如对话结束后提炼记忆）也记，只是不挂在某个回合下。
- 结果沿用 GLOSSARY 的语义：成功、失败、被拒绝、用户离开、没能接通。被拒绝也记，因为看板要能显示有多少请求撞了限额。
- 计费用量按各家实际收费的单位记：LLM 记输入和输出 token（OpenAI 兼容协议在流式请求里要求返回 usage），语音合成记字符或字节，语音识别记音频秒数，判断模型、向量化、重排按各自的单位记。拿不到用量的，记为未知，不猜。
- `database.py` 的用户数据登记要多一类「删除用户时匿名化」：运行记录的用户字段置空，其他不动。
- 运行记录满 90 天删除，和现在 `usage` 表的清理放在一起做；`usage` 表本身（限额的滑动窗口，保留 24 小时）不变。
- 进行中的通话数直接从内存里的通话表取，不走运行记录。

看板与单价

- 看板接口按时间范围（24 小时、7 天、30 天、90 天）返回已经聚合好的数字和时间序列，前端不做聚合。
- 单价是一份以「提供方 + 模型 + 计费单位」为键的表，每项有单价、币种和「整理于」日期。代码里带一份预设，覆盖目前支持的所有模型，实现时查官方价格页填写并注明日期；管理者在后台的修改和新增存进数据库，优先于预设。花费 = 部署者的调用用量 × 单价，按币种分开合计，不做汇率换算。没有单价的模型显示用量和「未设单价」。
- 在线目录（ticket 14）：后端定期从 models.dev 和 OpenRouter 拉取模型目录，按「主机名 + 模型名」自动匹配单价。生效顺序是后台设的价格 > 目录 > 预设 > 未设单价，预设只做离线兜底，以及目录里没有的单价（按字节、按秒计费的和目录没收录的模型）。目录里有的模型直接用目录的价格（例如 DeepSeek 用目录里的一套美元价，不分高峰和低谷）。主机名对不上（中转、代理）时，按模型名用原厂价格估算并标注。花费仍按查看时的单价计算。

界面

- 后台页面在同一个 Next 前端的 `/admin` 下：看板（默认页）、配置、用户（列表和详情）。沿用 Astryx 和现有主题，遵守 AGENTS.md 的规则（不写裸 `<div>`、只用 token），数据密集的地方用 Table / List，不用卡片包列表项。图表遵循 dataviz 技能。
- 文案放进 `frontend/src/i18n/zh.ts` 的新的 `admin` 分区。
- 以电脑为主；手机上看板和用户列表、封禁操作要能用。

文档

- 隐私政策：管理者能看到登录邮箱和用量；运行记录的内容、保留 90 天、删除用户后匿名化；被封禁的用户删除后会留下登录方式的哈希；联系方式。

## Testing Decisions

- 好的测试只看外部行为：通过后端的 HTTP API 驱动，从用户一侧和后台一侧的 API 观察结果，不去断言表结构或内部调用。
- 后端只用一个接缝：对外的 HTTP API，沿用 `make_client` + fakes + `FakeClock`（先例：`test_rate_limit.py`、`test_text_turn.py`、`test_own_keys.py`、`test_delete_account.py`）。新增的唯一接缝是「按配置创建服务客户端」的工厂：测试注入一个记下收到的配置并返回 fake 的假工厂。
- 要覆盖的行为：
  - 管理者认定：名单里的登录方式能进，其他人、未登录、名单为空时一律 404。
  - 配置：保存后新回合用新配置、进行中的通话不变；保存前试不通就不保存；恢复成 `.env` 的值；key 只返回末 4 位；只读项拒绝修改；没有 `EIDOLON_SECRET_KEY` 时 key 只读；重启时覆盖试不通就回退并标出。
  - 限额：后台改了全站限额后，下一个回合就按新数字拒绝；单独限额的数字、不限、0 三种情况；429 文案用实际适用的数字。
  - 用户：列表和搜索；封禁后 403、会话失效、通话挂断；解除封禁；不能封禁或删除管理者；删除被封禁的用户后，同一身份登录和绑定都被拒绝；响应里没有任何对话、记忆、档案内容。
  - 运行记录和看板：驱动成功、失败、被拒绝、离开的回合和接通、没接通的通话后，看板数字正确；判断模型出错但回合成功时，健康数据里能看到；自带密钥单独统计；删除用户后看板数字不变、用户关联消失；推进时钟 90 天后记录被清掉；花费按单价和币种算对，没有单价时显示「未设单价」。
  - 命令行：`test_admin_commands.py` 继续覆盖，确认和后台共用的封禁逻辑行为一致。
- 前端只测 `lib/` 里的纯逻辑（先例：`ownKeys.test.ts`、`conversationList.test.ts`）：配置项三种状态的展示规则、花费和用量的格式化、时间范围切换。页面用 Playwright 人工验证。

## Out of Scope

- 角色管理：新增、下线、修改角色，上传头像和背景图。角色仍由维护者在仓库里维护。
- 内容管理：人设、角色资料、世界设定、剧情库同步。
- 配置的改动历史。
- 告警推送（邮件、webhook）。
- 管理者分角色或分权限；在后台里增减管理者。
- 查看任何用户的对话、记忆、制作人档案的内容。
- 在后台修改向量化、OAuth、`EIDOLON_SECRET_KEY`、域名、WebRTC/TURN、备份和路径。
- 后台重启服务。
- 汇率换算、扣除免费额度、与真实账单对账。
- 单独设定某位用户的单次通话上限。
- 解除「被封禁后删除的用户」的封禁（哈希名单无法再对应到人）。
- 滥用分析（异常新用户、刷量识别）。
- 日语、英语界面。

## Further Notes

- 工程量最大、风险最高的是「运行中替换客户端」，建议最先做，而且先只做一项（例如扮演角色的 LLM）打通整条路，再推广到其他服务。
- 运行记录要在回合和通话的各条路径上埋点，其中通话的路径（Pipecat 管线、补充、打断）最容易漏。结果的判定必须和 GLOSSARY 里「回合」「接通」的定义一致，并与限额的计入、退还使用同一个判断。
- 预设单价会过时，界面上要显示「价格整理于某日」。ticket 14 改为优先用在线目录，预设只做兜底。
