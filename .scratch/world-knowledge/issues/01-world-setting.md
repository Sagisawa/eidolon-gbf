# 01: 世界设定：导入偶像和组合，并在每个回合带上

**What to build:** 部署者运行一条导入命令，就能从 im@sparql 和官方组合页抓到偶像、八个常设组合、社长和事务员，写成一份提交进仓库的资料文件；重启后端后，每位角色在每个回合都带着世界设定和一整套「怎么对待作品事实」的规则。背景见 `../spec.md`，术语见 `CONTEXT.md` 的「世界设定」「组合」「声优」，理由见 ADR-0008。这张 ticket 搭好导入命令和常驻部分的骨架，后面 03、04、06 往上面加来源、05 加检索。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 新增一条后台导入命令（和 `story sync` 同级），手动运行；从 im@sparql（查询品牌要写 `"ShinyColors"@en`）取偶像、声优、社长和事务员，用官方站点的组合页确定八个常设组合和成员；im@sparql 多出来的特别组合不进组合列表。
- [x] 生成的资料文件是结构化的（JSON），包含资料截止日（导入日期）、事务所的社长和事务员、偶像名单（日文全名、读音、所属组合、声优）、组合（名称、读音、成员），每一条都带来源 URL。
- [x] 导入命令在终端打印导入报告：各类条目数量、相对旧文件的增减、im@sparql 和官方组合页之间对不上的地方。
- [x] 任何一个来源抓取失败，命令报错退出，旧资料文件原样保留；只有全部成功才整体替换。
- [x] 后端启动时按显示名把角色配置里的每位角色对应到资料里的偶像；资料存在而有角色对不上时启动失败，报错写明是哪位角色；资料文件不存在时照常运行、不带这一层，日志说明原因。
- [x] 系统提示在人设之后多一节常驻的「世界设定」：资料截止日、社长和事务员、八个组合各有哪些偶像，以及规则——资料里查不到的歌曲、唱片、演出老实说想不起来，既不否认也不附和；不引用、不编造歌词；只知道演出的事实，不编造台上发生了什么；不谈论声优；不谈论具体的周边商品；资料截止日以后的事一概不知道。
- [x] 任何提示里都不出现声优的名字。
- [x] 测试：用假的 HTTP 站点跑完整条导入命令（先例：剧情同步测试的假镜像站点），覆盖正常导入、特别组合不进组合列表、来源失败时旧文件保留；从对话回合检查提示里有世界设定和规则、没有声优名字、没有资料文件时照常进行（先例：`test_turns`）；角色对不上资料时启动失败（先例：`test_characters`）。
- [x] 跑一次真实导入，把生成的资料文件提交进仓库。

## Comments
