# 05: 按需检索：歌曲、唱片、演出日的共享资料索引

**What to build:** 问到别的组合的歌、某张唱片的曲目、某场她没上的演出时，角色能通过检索找到资料来回答，而不是凭模型的记忆编；问「那次 live 怎么样」这类回顾经过的问题，也不会因为剧情库里没有这段经过就说自己没经历过。背景见 `../spec.md` 的「按需检索的部分」。

**Blocked by:** 03, 04

**Status:** resolved

- [x] 新增一个所有角色共享的资料索引：每首歌曲一条（曲名、演唱者、收录唱片），每张唱片一条（名称、发售日、曲目），每个演出日一条（演出名、日期、会场、出演偶像）；条目文字里没有声优名字。
- [x] 索引照搬角色资料索引的做法：向量在第一次检索时计算、存进 SQLite，按「文字 + 模型」为键，资料改了重启就生效且只重算改动的条目；切换 embedding 模型时旧模型的向量一并清掉。
- [x] 检索参考资料时，资料索引的候选和剧情、角色资料的候选一起交给 reranker 统一排序，共用同一个相关度阈值和条数上限；提示里这类参考资料放在单独的「资料」标题下，说明是关于歌曲、唱片和演出的事实。
- [x] Jev 判断是否需要检索的说明文字加上第三类资料：歌曲、唱片和演出。
- [x] Jev 判断为「回顾经过」时，除了回忆剧情也查一次资料索引，命中的演出或唱片条目和剧情一起带上；回忆剧情落空时的提示语不再说「你没有经历过这件事」。
- [x] 对话模型主动调用的 `recall_story` 工具仍然只查剧情。
- [x] 测试：从对话回合检查——参考资料检索能召回歌曲、唱片、演出日条目并放在「资料」标题下；回顾经过时带上资料索引的命中、落空时提示不说「没有经历过」；检索到的内容里没有声优名字（先例：`test_retrieval`、`test_recall_story`）；改动资料后只重算改动的条目、换模型后旧向量被清掉（先例：`test_reembed` 里角色资料的做法）。
