# 历史对话：开了新对话也能翻看

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准（新增「当前对话」「历史对话」「对话标题」，「礼物」随之改过）。对话标题的调研见 `research.md`（Cherry Studio、RikkaHub 的做法和本项目后台模型的现状）。界面的样子由原型定下：本地分支 `prototype/past-conversations` 里的方案 A（另有 B、C 两种没选，只留作参考）。

## Problem Statement

- 对话页「更多」菜单里有「新对话」，可开了新对话之后，原来那段对话在前端就再也打不开了：页面只打开她最新的那段，对话列表每位角色一行，也只看得到最新那段。数据都还在后端，只是没有入口。她结束了对话以后用户点「开个新对话」，被结束的那段同样再也看不到。
- 只靠日期和最后一句，很难认出哪一段聊的是什么：最后一句多半是道别或寒暄。
- 「更多」菜单和对话列表的长按菜单只有字没有图标，扫一眼不好认。

## Solution

1. **历史对话入口**：「更多」菜单在「新对话」下面加一项「历史对话」。点开以后，宽屏是居中的 Dialog，窄屏是底部的 Drawer，都用她的颜色。标题「历史对话」，说明「和{角色名}的所有对话，最新的在上面。」。
2. **面板里的行**：列出和她的所有对话，按开始时间排，最新的在上。当前对话排第一行，标「当前」；历史对话里一条记录都没有的不列。每行两行字：
   - 第一行是最后一次往来的日期（北京时间，「10月15日」，不是今年的带上年份）。当前对话标「当前」小胶囊；已结束的标「她结束了对话」那个图标加「她结束了」。
   - 第二行是最后一句，写法和对话列表的预览一样：她的日语、「你：…」或对话事件的图标加原文，跳过「她结束了对话」这条事件。超出截断。
   - 正在看的那一段铺中性的选中底色。
   - 只有当前对话这一行时，下面写一句「开了新对话以后，之前的对话会留在这里。」
3. **打开历史对话**：点一行就关掉面板，去看那段对话；点「当前」那一行回到当前对话。
   - 地址是 `/conversation/<角色>?c=<对话 id>`，能刷新也能分享。`c` 是当前对话、不属于她、或者是空对话时，当作没带。
   - 消息区和平时一样画（壁纸、气泡、对话事件、日期条），只读。
   - 页首在她的名字下面加一行 Meta 字号、muted 的「{日期}的对话」。
   - 电话键禁用，提示「回到当前对话才能打电话」。好感度标识、「新对话」「历史对话」「换衣装」照常能用。
   - 输入栏换成只读卡：左边 muted 的历史图标加「这是你们的历史对话」（已结束的写「这是你们的历史对话，她结束了它」），右边描边的大号按钮「回到当前对话」。一行放不下就折行，样子同结束卡。
   - 窄屏页首的返回键、只读卡的按钮、浏览器的返回键，都回到当前对话。
4. **通话和回复不受影响**：通话中、或者她正在回复时，也能打开历史对话。通话像换页一样缩成通话条，继续打；那条回复照常记进当前对话，回去就看得到。
5. **礼物只记进当前对话**：送礼时记进她的当前对话；当前对话已经结束，就记进一段新开的对话。不论从哪段对话跳去礼物页都一样。
6. **空的当前对话不能再开新对话**：当前对话一条记录都没有时，「新对话」禁用，免得堆出一串空对话。
7. **对话标题**：一段对话的第 3 个回合记下以后（打字和通话里的回合都算），在后台用这一回合的后台模型，根据这 3 个回合起一句中文短标题（12 字以内，忽略寒暄），只起一次，以后不改。有标题的行，第一行写标题、右边是日期和标记，第二行仍是最后一句；没有标题的（不满 3 个回合、没起成、上线前的旧对话）照旧。标题只在历史面板里出现，她不知道，管理者也看不到。
8. **菜单图标**：两个菜单每一项的文字前面加 16px 图标，跟着菜单文字的颜色，不用她的颜色：
   - 新对话 `SquarePen`、历史对话 `History`、换衣装 `Shirt`；
   - 置顶 `Pin`、取消置顶 `PinOff`、在列表中隐藏 `EyeOff`、在列表中显示 `Eye`。

## User Stories

1. 作为用户，我想在开了新对话以后，从「更多」菜单的「历史对话」里找到以前和她的对话，这样那些对话不会凭空消失。
2. 作为用户，我想在历史面板里一眼看出每段对话是哪天的、最后聊到哪句，这样我能找到想看的那段。
3. 作为用户，我想在面板里看出哪段是当前对话、点它就回去，这样我翻完历史不会迷路。
4. 作为用户，我想看出哪些对话是被她结束的，这样我记得那几次发生过什么。
5. 作为用户，我想像平时一样往上翻看一段历史对话，包括通话里说的话、她挂断电话和送礼的记录，这样我能完整地回顾那段经历。
6. 作为用户，我想在历史对话里清楚地看到这是历史对话、只能翻看，这样我不会以为她不理我了。
7. 作为用户，我想在历史对话里拨不出电话、也打不了字，这样我不会不小心把话说进历史对话。
8. 作为用户，我想用手机看历史对话时，按左上角的返回键或系统返回就回到当前对话，这样不会一下退到对话列表。
9. 作为用户，我想刷新页面或者把地址发给自己的另一台设备时，还停在同一段历史对话上，这样我能接着看。
10. 作为用户，我想在打电话时也能翻看历史对话，这样我能边聊边找以前说过的事，电话不会因此挂断。
11. 作为用户，我想在历史对话里点「送她一件礼物」时，礼物记进当前对话，这样她在当前对话里知道收到了。
12. 作为用户，我想在一句话都没说时点不了「新对话」，这样不会堆出一串空对话。
13. 作为用户，我想在历史面板里看不到空对话，这样列表里每一行都有内容可看。
14. 作为用户，我想在还没开过新对话时点「历史对话」也能看到一句说明，这样我知道这个功能是做什么的。
15. 作为用户，我想在「更多」菜单和对话列表的长按菜单里看到每一项的图标，这样扫一眼就认得出。
16. 作为用户，我想在历史对话里照样能换衣装、看好感度，这样跟着她的东西不因为翻看历史而用不了。
17. 作为用户，我想在历史面板里看到每段对话一句话的标题，这样不用靠最后一句去猜那段聊了什么。
18. 作为用自带后台模型的用户，我想照样得到对话标题，并且用的是我自己的模型，这样我的对话不会交给部署者的模型。
19. 作为用户，我想在只聊了一两句、或者标题没起成的对话上照样看到日期和最后一句，这样这些对话也认得出来。
20. 作为用户，我想让她不知道对话标题、管理者也看不到，这样标题只是给我自己认对话用的。
21. 作为管理者，我想在看板的花费里看到起标题的花费记在后台模型名下，这样我知道后台模型一共花了多少。
22. 作为部署者，我想起标题沿用已经配好的后台模型和思考强度，这样不用为它另配一个模型。

## Implementation Decisions

- **列出她的所有对话**：`GET /api/conversations?character_id=` 每条多带两项：
  - `last_message`：形状和 `/api/conversations/latest` 的同名字段一样，同样跳过「她结束了对话」这条事件；对话是空的就是 null。
  - `ended`：她是否结束了这段对话。

  空的历史对话由前端从列表里去掉。最新开的那段永远是第一条，它就是当前对话；后端不新增概念。
- **历史对话不经过 LiveConversation**：外壳里那一个对话实例管着当前对话的回合、通话和记录，不去切换它，否则正在进行的回复和通话会串到别的对话里。历史对话用一个只读的视图，自己按 id 读记录（`GET /api/conversations/{id}/messages`），用和打开对话时同一套记录转条目的规则转好，交给现有的消息区去画。对话页照旧向外壳要她的对话，所以通话层、通话条在历史对话里照常工作。
- **地址里的 `c`**：从面板打开历史对话时 `push` 一条浏览历史。「回到当前对话」这样处理：上一条浏览历史就是这一页的当前对话时，退回去；否则（比如直接打开的链接）换成不带 `c` 的地址。`c` 无效时当作没带，并把地址换掉。
- **面板的数据**：每次打开面板时重新读一次列表（不缓存），读的时候显示 Spinner。日期按北京时间写，和抽奖、好感度用同一个时区；最后一句的写法和对话列表复用同一段代码，不另写一份。
- **送礼的落点**：存储层记送礼时不再接收「从哪段对话来的」。规则是：她最新的对话没结束就记进去，否则新开一段。连带改动：
  - 礼物页地址 `/gifts?to=&conversation=` 去掉 `conversation`，只带角色；旧链接里带着也忽略。
  - 送礼请求体去掉 `conversation_id`。
  - DESIGN.md「从对话页跳来」那段跟着改。

  前后端一起部署。
- **「新对话」何时可用**：在现在的条件（对话已打开、没在回复、没在通话）之外，再加一条：当前对话里至少有一条记录。已结束的对话里一定有结束事件，不受影响。这个判断放在 LiveConversation 的快照里。
- **图标**：照 DESIGN.md「The Library Icon Rule」，新图标在图标表里按语义起别名导出，组件里不直接用 Lucide 原名；置顶和换衣装沿用已有的别名。菜单项里的图标默认就是 16px，不用另写尺寸。
- **前端规矩**：按前端的 shadcn 纪律写，文案进中文文案表。DESIGN.md 补上这些内容：更多菜单的三项和图标、历史面板、历史对话的页首和只读卡、对话列表长按菜单的图标。

- **对话标题**：
  - **存在哪**：`conversations` 表加一列 `title`（可空），旧库启动时补列。列表接口每条多带 `title`。
  - **什么时候起**：引擎在一个回合记下以后，如果这段对话正好有了第 3 个回合（用户的消息数为 3，打字和通话都算）而且还没有标题，就起一个后台任务，像提炼记忆那样脱离回合、不挡回复。这个任务不挂在提炼记忆里面，因为记忆关着时标题也要起。只在第 3 个回合试一次，失败就不再试（Cherry Studio、RikkaHub 都不重试）。她在第 3 个回合结束了对话，照样起。
  - **用哪个模型**：用这一回合交给提炼记忆的那个后台模型，自带后台模型的用户就用他自己的，部署者的那份同样在回合结束后继续持有。思考强度沿用后台模型那一档（ADR-0019）。服务调用和提炼记忆记在同一项服务下，不挂在回合的运行记录上；看板和设置里「提炼记忆的 LLM」的文案改成「后台模型」。
  - **自带密钥**：ADR-0017 里「持有到这一回合的后台记忆写完为止」改成「持有到这一回合的后台任务（记忆、标题）都做完为止」，通话同理。密钥照旧不落盘。
  - **喂什么**：这段对话到第 3 个回合为止的全部记录，按顺序：用户的话；她的话用中文字幕（没有字幕才用日语，去掉语气提示）；对话事件各写一行（「她挂断了电话」「你送给她一份{礼物名}」「她结束了对话」）。每条截到约 150 字。再加她的名字。不喂记忆和人设。
  - **提示词**：中文，要求概括这几轮聊了什么，忽略寒暄，12 字以内，不加引号和标点，只输出标题。
  - **后处理**：去掉首尾空白、引号、书名号和结尾的标点，截到 16 字；剩下空的就当没起成。失败只记 warn 日志，只写长度、不写内容；用户看不到任何提示。
  - **谁看得到**：标题不进她的提示词、记忆、判断模型，也不进看板、运行记录和日志。删除用户时随对话一起删掉。
  - **前端**：面板的行有标题时，第一行是标题（正文小一号、加粗一档，放不下截断），右边是日期和标记（Meta 字号、muted）；第二行是最后一句。没有标题时同现在。历史对话页首那行小字照旧写日期，不写标题。

## Testing Decisions

- 好的测试只测对外的行为：接口返回什么、记录里有什么、她的提示词里有什么，不测内部怎么实现。
- **后端**：通过对外接口测：
  - 列表接口带出 `last_message`（跳过结束事件、空对话为 null）和 `ended`；
  - 送礼一律记进最新且没结束的对话，最新的已结束时新开一段，请求里带不带对话 id 都一样；
  - 对话标题（伪造后台模型）：第 3 个回合后起一次，第 2、第 4 个回合不起；通话里的回合也算；记忆关着也起；后台模型失败或返回空的就没有标题、回复不受影响；后处理去掉引号和标点、截到 16 字；喂给它的有事件、没有记忆；她下一回合的提示词里没有标题；自带后台模型的回合用的是自带的那个。
  
  先例是 `test_conversation_events.py` 和送礼的那些测试。
- **前端**：
  - 对话状态模块（LiveConversation）的测试：当前对话是空的时不能开新对话，有了一条记录后可以。先例是它已有的测试。
  - 组件不写测试，面板和历史对话的样子由验收来看；不为面板另立新的测试切入点。
- **验收**：按 `docs/agents/local-acceptance.md` 在本地构建版上用 Playwright，宽屏和手机都看：
  - 菜单图标；
  - 打开面板、点开一段历史对话、页首日期和只读卡、电话键禁用；
  - 返回键和浏览器返回回到当前对话；
  - 刷新后还在同一段；
  - 拨出电话（呼叫中）后打开历史对话，通话条还在；
  - 空的当前对话里「新对话」禁用。

## Out of Scope

- 在历史对话里接着聊，或者把一段历史对话设回当前对话。
- 删除、重命名、搜索历史对话；重新生成或更新对话标题。（删除后来另外做了：分支 `feat/delete-past-conversations`，没有另写 spec。）
- 给上线前的旧对话补标题。
- 对话列表长按菜单里的「历史对话」入口。
- 清理库里已有的空对话。
- 她记得历史对话的原文（她只通过记忆接上历史对话，不变）。
- 历史面板分页：一位角色的对话一次全读出来，以后多了再说。
