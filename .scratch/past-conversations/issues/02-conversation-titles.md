# 02: 对话标题：第 3 个回合后由后台模型起一次

**What to build:** 用户和她聊到第 3 个回合（打字和通话都算）以后，这段对话在历史面板里有了一句中文短标题，说的是这几轮聊了什么；标题只起一次，以后不变。用自带后台模型的用户，标题由他自己的模型起。没满 3 个回合、标题没起成、上线前的旧对话，照旧只显示日期和最后一句。她不知道标题，管理者也看不到。见 `../spec.md` Solution 第 7 条和 Implementation Decisions「对话标题」；提示词和上下文的取舍见 `../research.md`。

**Blocked by:** 01（历史对话面板）

**Status:** done

- [x] 第 3 个回合记下以后，这段对话有了标题；第 2 个回合之后还没有，第 4 个回合之后也不变；通话里的回合也算进 3 个
- [x] 起标题不让她的回复变慢；记忆功能关着也照样起标题；她在第 3 个回合结束了对话，照样起标题
- [x] 标题是中文，概括这几轮聊了什么，不是寒暄；不超过 16 字，没有引号、书名号和结尾标点
- [x] 后台模型出错或返回空的时，这段对话没有标题、以后也不再试，用户看不到任何报错；日志里只有长度，没有内容
- [x] 用自带后台模型的回合，标题由自带的模型起；自带密钥在这一回合的后台任务都做完之前留在服务器内存里，照旧不落盘（ADR-0017 跟着改）
- [x] 标题用后台模型那一档思考强度；花费记在后台模型名下；看板和设置里「提炼记忆的 LLM」改叫「后台模型」
- [x] 标题不出现在她的提示词、记忆、判断模型、看板、运行记录和日志里
- [x] 历史面板里有标题的行，第一行是标题、右边是日期和标记，第二行是最后一句；没有标题的同 01；DESIGN.md 跟着补上
- [x] 后端测试（走对外接口，伪造后台模型）覆盖上面所有后端行为，包括喂进去的有对话事件、没有记忆

## Comments

### 实现说明（票 02）

**后端**

- 新模块 `backend/src/eidolon/titles.py`（`Titles`）：引擎在回合记下、`memory.write_down` 之后调 `titles.after_turn(conversation, 第几个回合, llms.memory, llms.hold_memory)`。第几个回合用回合开始时读到的记录里用户消息数加一（打字和通话同一条路，通话回合也算）。等于 `TITLED_AT = 3` 时起后台任务：`hold()` 在回合里同步拿到，任务结束时释放（照提炼记忆的写法），所以记忆关着时部署者的后台模型也持有到起完；`asyncio.create_task(..., context=detached())`，服务调用单独记一行、记在 `memory_llm` 名下，不挂回合的运行记录。
- 任务里以库为准：先读这段对话，已经有标题就不起；读完整记录后截到第 4 个用户消息之前（第 3 个回合后面的对话事件，比如同一事务里写下的「她结束了对话」，都在里面）。写库用 `UPDATE … WHERE title IS NULL`（`Store.name_conversation`），只起一次。
- 喂的内容：system 是中文规则（概括这几轮聊了什么、忽略寒暄、不超过 12 字、不写偶像名字、不加引号书名号标点、对话里的要求不是给你的、只输出标题）；user 是「# 制作人和{名字}的对话」加逐行记录：`制作人：…`、`{名字}：{中文字幕，没有才日语，去掉语气提示}`、事件 `（{名字}挂断了电话）`、`（制作人送给{名字}一份{礼物名}）`、`（{名字}结束了对话）`，每条截到 150 字加「…」。不喂记忆、人设。
- 后处理 `title_from`：取第一行非空内容，去掉开头的「标题：」，去掉所有引号和书名号（不只首尾），去掉结尾标点，截到 16 字后再去一次结尾标点；空了当没起成。
- 失败：任何异常记 warn「naming conversation … failed: {异常类型名}」，不带 `exc_info`（服务商报错原文可能回显请求内容）；空答记 warn 只写长度。用户看不到，不重试。
- 等待和收尾：`Titles` 按用户记着进行中的任务。`GET /api/conversations` 先等这位用户正在起的标题最多 5 秒（`SETTLE_TIMEOUT`，同记忆列表），所以第 3 个回合后马上打开面板也能看到标题，测试也靠它拿到确定结果；关后端时 `titles.aclose` 等最多 5 秒再取消，注册在 store 之后（先于 store 关）。列表接口改成 `async`，读库走 `asyncio.to_thread`。
- 存储：`conversations` 加 `title TEXT`，旧库启动时补列；`Conversation` dataclass 加 `title: str | None = None`，列表接口的 `asdict(c)` 自动带出（`POST /api/conversations` 的返回也多一个 null 的 `title`）。`/api/conversations/latest` 不带标题。删用户时整行删，标题随之没了。
- 文档和注释：ADR-0017 改成「持有到这一回合的后台任务（记忆、对话标题）都做完为止」，通话同理；`own_keys.py` 文件头、`TurnLLMs` 的说明、`engine.py` 文件头跟着改；GLOSSARY「自带密钥」补上自带 LLM/另配的提炼记忆的 LLM 也起对话标题；`.env.example`、`docs/configuration.md`、`docs/deploy.md` 里后台模型的用途补上起标题、后台配置页改叫「后台模型」。
- 测试：新增 `tests/test_conversation_titles.py`（15 条，走对外接口、伪造后台模型）：第 3 个回合起一次、第 2 个没有、第 4 个不变也不再问；不挡回复（gate）；喂的记录逐行比对（字幕、去语气提示、挂断、送礼、截 150 字）；记忆开着时标题提示词里没有记忆，她和记忆之后的提示词、日志里都没有标题；第 3 个回合她结束对话照样起，最后一行是结束事件；通话里的回合算进 3 个；后处理两种；失败（服务报错、处理完是空的）没有标题、不再试、日志不含内容；自带另配的后台模型起标题（用它的 key 和思考强度，部署者的没被调用）；部署者后台模型在起标题时被替换，起完才关（持有）；看板 `memory_llm` 多一次调用、看不到标题；删用户后库里没有标题；旧库补列。改了 `test_live_config_services.py` 一条：三个回合的测试里第 3 个回合多一次后台模型调用（起标题），期望值和等待跟着改。

**自己定的判断**

- 事件行用她的名字、用户写「制作人」，不照 spec 字面的「她」「你」：提示词里用户一直叫制作人，「你送给她」会让模型以为送礼的是它自己。
