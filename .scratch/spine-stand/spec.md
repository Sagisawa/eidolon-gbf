# 通话层的 Spine 立绘

Status: ready-for-agent

术语以 `CONTEXT.md` 为准，尤其是「立绘」「衣装」「情绪」三条（2026-09-30 定下），以及「通话层」「只看文字」「打断」「语气提示」。情绪和语气提示是两回事：语气提示只改变声音，情绪只改变立绘。相关 ADR：ADR-0003 的 2026-09-30 修订（立绘对公众提供，但不进仓库）、ADR-0009（暂不购买 Spine Editor 许可证）。

每一项决定的来龙去脉都在 `map.md` 和 `issues/01`–`13` 这十三张 wayfinder ticket 里；这份 spec 只汇总结论，要看依据和实测数据时，去对应的 ticket 里找。

## Problem Statement

打电话时，通话层上的角色只有一张静止的背景图和一个头像。她说话时画面不会动，开心也好、害羞也好，看起来都一样；用户开口说话时，她也没有任何反应。原作的剧情里，同一位角色是一个会呼吸、会眨眼、会动嘴、会随心情换表情和动作的 Spine 立绘。和她打电话，反而没有看剧情时那种「她就在眼前」的感觉。

## Solution

在通话层的背景图上叠一层和原作剧情一致的 stand 立绘：

- **会动**：待机时呼吸、眨眼。
- **说话有口型**：她的声音在播放时嘴就动，停下时闭嘴。
- **有情绪**：每段台词都判断一次情绪（平静、开心、害羞、惊讶、难过、生气、思考），在这段声音开始播放时换上对应的表情和动作；要表示同意或否定时，她会点头或摇头。
- **心情会延续**：平淡的话不会把她拉回平静，一次通话里心情会延续下去，挂断后清空。
- **会回应用户**：用户开口时她看向用户，用户说完时她点一下头。
- **衣装由用户选**：在对话页页首的「换衣装」里，从这位角色的几十套衣装中选一套，只保存在这台设备上。

手机上是「大立绘」：立绘从底部升起，字幕放在上方。电脑上是「半身 ADV」：立绘铺满通话层，字幕放在底部的对话框里。立绘只是锦上添花：素材加载不到、浏览器不支持时，退回现在的背景图，通话本身不受影响。

## User Stories

**立绘本身**

1. 作为用户，我想在打电话时看到角色的立绘在通话层上动起来，这样感觉她就在我面前，而不是只有一张图。
2. 作为用户，我想看到她在没说话时也会呼吸、眨眼，这样画面不像一张静止的图片。
3. 作为用户，我想看到的立绘和原作剧情里的一模一样（同样的动作、表情和过渡），这样她就是我认识的那个她。
4. 作为手机用户，我想看到她从底部升起、占满大半个屏幕，名字、计时和字幕在上方，这样竖屏上看得清她，也看得清字幕。
5. 作为手机用户，我想让底部的按钮压在一层深色渐变上，这样挂断、静音按钮不会和立绘混在一起。
6. 作为电脑用户，我想看到她铺满通话层、从头到腰的半身像，字幕放在底部一个半透明的对话框里，像原作剧情那样。
7. 作为用户，我想让立绘叠在这位角色原来的背景图上，这样整个画面还是属于她的颜色。

**说话与口型**

8. 作为用户，我想在她的声音播放时看到她的嘴在动，停下时闭上，这样声音和画面是对得上的。
9. 作为用户，我想让她段与段之间停顿得够久时自然合上嘴，而不是一直张着。
10. 作为用户，我想让她停下时嘴真的完全不动，而不是还在微微抖动。
11. 作为开了「只看文字」的用户，我想让她始终闭着嘴，因为她并没有出声。

**情绪**

12. 作为用户，我想让她每说一段话，表情和动作都跟着这段话的心情变化，这样开心的话配笑脸，难过的话配难过的样子。
13. 作为用户，我想让表情和动作在这段声音开始播放时才换，而不是字幕先出来就换，这样表情和她正在说的话对得上。
14. 作为用户，我想让情绪之间的切换有一个短短的过渡，而不是一下子跳过去。
15. 作为用户，我想在她表示同意时看到她点头，否定时看到她摇头。
16. 作为用户，我想让她的心情在一次通话里延续：平淡的一句话不会让刚才还开心的她突然恢复面无表情。
17. 作为用户，我想让她在新的一条回复以平静开头时回到平静，这样心情不会永远停留在很久以前的某一句。
18. 作为用户，我想让她在判断不准的时候保持原来的心情，而不是在两种表情之间来回乱跳。
19. 作为用户，我想在挂断后再打过去时，她从平静开始，而不是接着上一通电话的心情。
20. 作为开了「只看文字」的用户，我想让她的情绪和点头在每段字幕出现时切换，因为这时没有声音可以对齐。
21. 作为部署者，我想让情绪判断和语音合成同时进行，这样判断不会拖慢她开口。
22. 作为部署者，我想在没有配置 Jev 密钥时照样能打电话，立绘只做待机、口型和听用户说话时的反应。
23. 作为部署者，我想让情绪判断的费用始终由我承担、不能用自带密钥，因为每段只要约 $0.00003。
24. 作为用户，我想让情绪只影响立绘，不记进对话记录，这样文字记录保持原样。

**用户开口时**

25. 作为用户，我想在我开口说话时看到她看向我，这样感觉她在听。
26. 作为用户，我想在我说完时看到她点一下头，表示她听到了。
27. 作为用户，我想在我打断她时看到她立刻闭嘴并看向我，而不是继续张着嘴做动作。
28. 作为用户，我想在打断后让她的心情保持不变，这样她不会因为被打断就换了一副表情。

**衣装**

29. 作为用户，我想在对话页页首、打电话键旁边找到一个「换衣装」按钮，这样打电话前就能选好她穿什么。
30. 作为电脑用户，我想让「换衣装」打开一个弹窗；作为手机用户，我想让它打开一个底部面板。
31. 作为用户，我想按原作卡片的发布顺序浏览这位角色的所有衣装，每张卡显示缩略图和卡名。
32. 作为用户，我想在同一张卡的「私服」和「演出服」之间切换，因为这是两套不同的衣服。
33. 作为用户，我想让私服和演出服其实一模一样的卡只算一套，并清楚地显示「只有一套」。
34. 作为用户，我想点一张卡先看到一个会动的大预览，确认之后再点「穿这套」，这样不会误换。
35. 作为用户，我想在预览里看到卡名、私服还是演出服、稀有度，以及这套是不是正在穿的。
36. 作为用户，我想让选好的衣装保存在这台设备上，每位角色各记一套，下次打电话她还穿着这套。
37. 作为从没选过衣装的用户，我想看到她穿着部署者配好的默认衣装。
38. 作为用户，我想让衣装列表里的缩略图很快出现，而不是等几十张图在浏览器里现场渲染。
39. 作为手机用户，我想让预览随列表一起滚动，这样小屏幕上不会被一张固定的大图挡住列表。

**加载与失败**

40. 作为用户，我想在一打电话时立绘就已经在了，所以浏览器应该在我打开对话页后、空闲时先把立绘预取好。
41. 作为开了省流量的用户，我想让浏览器不要预取立绘，只在我按下打电话键时才下载。
42. 作为用户，我想在立绘还没下载完时只看到背景图，不要转圈，也不要占位剪影；立绘到了就淡入。
43. 作为用户，我想在立绘晚到时，她直接以当前的心情、口型和视线出现，而不是从头开始。
44. 作为用户，我想让字幕的位置在通话中途不要跳，不论立绘是晚到了还是加载失败了。
45. 作为用户，我想在我选的衣装加载不到时，看到她穿默认衣装；默认衣装也加载不到时，看到原来的背景图。
46. 作为用户，我想在立绘出问题时通话照常进行，不要弹出报错打断通话。
47. 作为用户，我想在一次加载失败后，下次打电话时再重新尝试，而不是永远不再显示立绘。
48. 作为用户，我想在网络偶尔出问题后，我选的衣装还记着，不会被清掉。
49. 作为用户，我想在手机切后台再回来、或者显卡上下文丢失后，立绘能恢复，而且颜色正常、边缘不发白。
50. 作为浏览器不支持 WebGL 的用户，我想照样能打电话，只是看到背景图。

**减少动态效果**

51. 作为开了「减少动态效果」的用户，我想让她不再做大幅度的身体动作，也不从底部升起，只是原地淡入。
52. 作为开了「减少动态效果」的用户，我想让她照样动嘴、换表情、看向我、点头，因为这些表达的是她在说话、是什么心情。
53. 作为开了「减少动态效果」的用户，我想让换衣装的预览遵守同样的规则。
54. 作为用户，我想在通话中途切换系统的「减少动态效果」时，立绘从下一个动作开始就照新设置走。

**性能**

55. 作为手机用户，我想让立绘流畅地以 60 帧播放，不卡顿，手机也不发热。
56. 作为 120Hz 屏幕的用户，我想让立绘最多画 60 帧，不白白多耗一倍的电。
57. 作为高分辨率屏幕的用户，我想让画面清晰，但不按超过 2 倍的像素比渲染，免得白白耗电。
58. 作为用户，我想在收起通话层时让立绘暂停渲染，展开时从当前状态接着画。
59. 作为用户，我想在反复换衣装后，内存不会越占越多。

**部署**

60. 作为部署者，我想用一个同步脚本，把已配置角色的全部 stand 衣装从本地镜像上传到我选的 S3 兼容对象存储，这样素材不用进仓库。
61. 作为部署者，我想在 `characters.toml` 里给每位角色配上原作的偶像编号和一套默认衣装，这样程序就知道她有哪些衣装。
62. 作为部署者，我想通过环境变量配置对象存储的地址、存储桶和密钥，而不是写死用哪一家。
63. 作为部署者，我想让没配偶像编号、没配默认衣装或者没配素材地址的角色，照现在一样只显示背景图。
64. 作为部署者，我想在收到权利方要求时，清空存储桶就能下架全部立绘，前端自动退回背景图。
65. 作为部署者，我想在部署文档里看到存储桶要配 CORS 和长期缓存，否则 WebGL 加载不了贴图。
66. 作为部署者，我想以后新增角色时，只要配好偶像编号再跑一次同步脚本。

**许可证**

67. 作为项目维护者，我想让 Spine runtime 原样放在一个单独的 vendor 目录里，附上它自己的许可证和来源说明，这样一眼能看出它不属于 AGPL 的部分。
68. 作为项目维护者，我想在项目许可证里加一条 AGPL 第 7 节的附加许可，允许本项目和 Spine Runtimes 组合在一起分发。

## Implementation Decisions

### 通话里的新消息（后端 → 前端）

现在的 `CallTurns` 通过 RTVI server message 发 `user`、`delta`、`done`、`error`、`ended`。新增两种，都带上**回复编号**（`CallTurns` 给每条回复编号，一次通话里递增）和**段号**：

- **`segment-playing {reply, segment}`**：第 N 段的声音开始播放。由 TTS 在第 N 段第一块音频之前，往音频队列里插一条 `OutputTransportMessageFrame` 发出。输出传输层按播放节奏发送，所以到达浏览器时大约比听到声音早 50–150ms，0.3 秒的过渡可以盖住。
- **`emotion {reply, segment, emotion, nod}`**：这一段的情绪判断结果。`emotion` 是七种情绪之一；`nod` 是 `yes`、`no` 或 `null`。
- **`user` 带上 `reply`**（ticket 17 实现时补充）：通话里的 `user` 消息多一个字段 `reply`，说明它开启的是哪一条回复。「只看文字」时没有 `segment-playing`，前端靠它把字幕和 `emotion` 对上同一条回复。

另外，前端要开始监听 pipecat 已经在发、但前端还没用上的标准 RTVI 事件：`bot-started-speaking` / `bot-stopped-speaking`（开嘴、闭嘴），以及 `user-started-speaking` / `user-stopped-speaking`（看向用户、点头）。

### 情绪判断（后端）

- 新增一个情绪判断的协议（和检索用的 `RetrievalJudge` 并列），生产实现是 `JevJudge` 加上 Choice 题型：一次请求问两题，一题是七选一的情绪，一题是「同意 / 否定 / 都不是」。
- **时机**：通话中每一段完整了（`SegmentComplete`），就单独起一个任务调用 Jev，和这段的语音合成同时进行，不阻塞回复。
- **给 Jev 的内容**：角色、用户这句话、这条回复前面几段、这一段的日语（带语气提示）和中文字幕。
- **兜底**：
  - 概率最高的一项低于阈值（初定 0.5）时，发出的情绪按「平静」处理。点头那一题同样：概率最高的一项低于阈值时 `nod` 为 `null`（ticket 17 实现时补充）。
  - 超时（初定 1.5 秒，不用检索那边的 5 秒）或失败时不重试，**不发** `emotion` 消息，前端沿用当前心情。
  - 阈值和超时做成可调的设置，实现时再调。
- **范围**：只在通话中判断，「只看文字」时照常判断；文字对话页不调用。没有配置 `JEV_API_KEY` 时不判断。费用始终由部署者承担，不走自带密钥。情绪不写进对话记录。

### Fish 分段合成（后端）

Fish 的流式合成不标出段落边界，所以**每段用一个 Fish 会话**：

- 当前这段在合成时，就把下一段要用的连接打开等着；当前段结束（发 `stop` 后等到 `finish`）后，立即在备用连接上开始下一段。实测这样段落之间不会多出停顿；每段现开会话则会多停顿，最长约 4 秒（见 ticket 11）。
- 第 N 段第一块音频之前插入 `segment-playing` 标记。
- 在段落边界主动 flush。这顺便修掉了现在的问题：每段最后一句日语要等下一段的中文字幕生成后才送去合成。
- 打断时的行为和现在的 `InterruptsFirst` 一致：立即放行打断，在后台重建连接；备用连接一起作废。
- 后备方案（只在上线后预开连接不够稳时才做）：各段会话并行合成，按顺序接起来。已经确认 Fish 允许同一个 key 同时开多个会话。

### 立绘指令（前端，`LiveConversation`）

`LiveConversation` 的快照里新增一份「立绘指令」，只描述她现在该是什么样子，不涉及具体动画：

```ts
// 来自原型，只保留决定性的部分
type StandDirection = {
  mood: Emotion;          // 七种之一，通话开始时是平静
  speaking: boolean;      // 嘴在动
  looking: boolean;       // 看向用户
  nod: { kind: "yes" | "no"; id: number } | null; // 每次点头/摇头给一个新 id，渲染层据此只播一次
};
```

规则：

- **嘴**：`bot-started-speaking` 时开嘴，`bot-stopped-speaking` 时闭嘴。「只看文字」时始终闭着。
- **情绪和点头的切换时机**：有声音时，在这段的 `segment-playing` 到达时切换；「只看文字」时，在这段第一句字幕出现时切换。`emotion` 结果晚于切换时机到达的：这段还在说就照样换过去，已经说完就丢掉。
- **心情延续**：判断结果是「平静」的段，沿用当前心情；但一条回复的**第一段**是「平静」时，回到平静。
- **用户开口**：`user-started-speaking` 时看向用户；`user-stopped-speaking` 时不再看向用户，并点一次头。
- **打断**：声音一停就闭嘴，同时看向用户；心情不变。补充发生在她开口之前，立绘上什么都不变。
- **挂断**：清空，下次通话从平静开始。
- **收起通话层**：指令照常更新，只是渲染暂停。

### 选动画（前端，新增的纯函数）

输入「立绘指令 + 这套衣装有哪些动画 + 是否减少动态效果」，输出每条轨道该播什么。这是唯一新增的测试接缝，所有逐级替代的规则都放在这里。

轨道照原作 ADV 的布局：0 身体、1 表情、2 点头、3 视线、4 脸红（暂不使用）、5 口型。同一条轨道上切换动画时，混合时间 0.3 秒。

逐级找替代的列表（来自原型，已经在两位角色的衣装上验证过）：

```ts
const BODY = {
  平静: ["wait"],
  开心: ["smile1", "smile2"],
  害羞: ["shy1", "shy2", "smile2"],
  惊讶: ["surp1", "surp2"],
  难过: ["sad1", "sad2"],
  生气: ["anger1", "anger2"],
  思考: ["think", "think1", "think2", "wait4", "wait"],
}; // 都找不到时用 wait
const FACE = {
  平静: ["face_wait"],
  开心: ["face_smile", "face_smile1", "face_smile2"],
  害羞: ["face_shy", "face_shy2"],
  惊讶: ["face_surp"],
  难过: ["face_sad"],
  生气: ["face_anger", "face_anger1", "face_anger2"],
  思考: ["face_serious"],
}; // 都找不到时用 blank，把脸交还给身体动作自带的表情
const LIP = { 平静: "wait", 开心: "smile", 害羞: "shy", 惊讶: "surp", 难过: "sad", 生气: "anger", 思考: "serious" };
// 口型：lip_<k>、lip_<k>1、lip_<k>2、lip_smile、lip_wait，再找不到就用任意一个时长不为 0 的 lip_*（排除 lip_*_s 和 lip_a）
// 点头：yes / yes2，摇头：no / no2；视线：eye_front
```

- **身体动作**：带 `loop_start` 事件的动作，开头播一次，之后从 `loop_start` 起循环尾段；没有这个事件的整段循环。离开带 `relay` 事件的动作时，先播它指定的 `arm_down*`，把抬起的手放下，再接下一个动作。
- **口型**：说话时循环播说话口型。闭嘴时把**同一个说话口型冻结在第 0 帧**：用 `animationEnd = 0`，不用 `timeScale = 0`，也不用 `lip_*_s`（原因见「原型：通话层里的立绘」）。开嘴、闭嘴的混合时间是 0.1 秒。
- **点头**：播一次，然后清空这条轨道，因为 `yes` 播完时不在中立姿势。
- **视线**：看向用户时播 `eye_front`；不看时清空这条轨道，混合时间 0.3 秒。
- **减少动态效果**：身体一律用 `wait`，其余照常。

### 渲染（前端）

- **runtime**：官方 spine-ts 3.6 的 `spine-webgl.js`，一个字都不改，放在单独的 vendor 目录里，附上它自己的 LICENSE 和一份记录来源、版本、校验和的 README。在 `.gitattributes` 里把这个目录标成 `-text`，免得换行符转换改变校验和。页面用 `<script>` 在客户端加载，通过 `window.spine` 调用。
- **立绘引擎**：一个不依赖 React 的类，负责载入衣装、每帧推进和绘制，再按「选动画」的结果设置各条轨道。它必须处理下面这些已知问题：
  1. **spine-ts 3.6 的剪裁 bug**：剪裁的结束插槽当下没有附件时，剪裁永远不会结束，后面画的东西会全被裁掉。2215 套里有 304 套在初始姿势下就会触发。绕法是每帧把剪裁的结束插槽改成「范围内最后一个真的会画出来的插槽」；范围内什么都不画时，这一帧摘掉剪裁附件。
  2. **预乘 alpha**：上传贴图前开启 `UNPACK_PREMULTIPLY_ALPHA_WEBGL`，绘制时用 `premultipliedAlpha = true`。
  3. **上下文丢失与恢复**：runtime 自己会重新上传贴图。但重设 `UNPACK_PREMULTIPLY_ALPHA_WEBGL` 的监听要在创建 `ManagedWebGLRenderingContext` **之前**注册，保证先于重新上传执行，否则恢复后会出白边。恢复不了的，这次通话退回背景图，不再重试。
  4. **换衣装时释放旧素材**：3.6 的 `AssetManager.remove` 只把条目设成 null，之后 `removeAll` 会对 null 调 dispose 报错，所以连条目一起删掉。旧贴图还要从 `ManagedWebGLRenderingContext.restorables` 里移除，否则上下文恢复时会把旧衣装再上传一遍。
  5. **React 开发模式下 effect 会执行两次**：销毁引擎时不能调用 `loseContext()`，因为在同一块画布上重建引擎，拿到的还是同一个 context。
- **取景**：手机「大立绘」贴着头顶、到膝；电脑「半身 ADV」贴着头顶、到腰，宽度不窄于身体的约 70%。
- **性能**：像素比取 `min(devicePixelRatio, 2)`；最多 60 帧，屏幕刷新率更高时跳过多余的帧；收起通话层时暂停渲染。

### 通话层（前端）

- `CallLayer` 新增一个立绘的位置。只要角色有立绘（见下面的配置），一打电话就用立绘版的布局，中途不切换，加载失败时也保持这个布局：
  - **手机「大立绘」**：立绘从底部升起，名字、计时和字幕在上方，底部压一层她颜色的深色渐变，保证按钮看得清。
  - **电脑「半身 ADV」**：立绘铺满通话层做底，名字、计时和字幕放在底部一个半透明的对话框里，底部同样压一层深色渐变。
- 立绘叠在背景图和纱上面。加载中只显示背景图和纱，立绘到了用 0.3 秒淡入，从当前的立绘指令开始画。
- 失败时依次退到选中的衣装、默认衣装、背景图。runtime 加载不到或浏览器不支持 WebGL 时，直接退到背景图。通话层里不提示用户，下次打电话再试。
- **减少动态效果**：手机上的升起入场改成原地淡入；监听系统设置的变化，从下一个动作开始生效。
- DESIGN.md 的「Call layer」一节要改写成立绘版的两种布局。

### 衣装与换衣装（前端）

- **入口**：对话页页首、打电话键旁边加一个「换衣装」图标按钮（Lucide `Shirt`）。只在角色有立绘时显示。宽屏（≥ 768px，和对话页用同一个断点）打开弹窗，窄屏打开底部面板。通话层里没有这个入口。
- **列表**：按卡片排列，顺序是原作发布顺序。每张卡显示缩略图和卡名（原文，去掉【】和角色名），下面一个铺满卡片宽度的「私服 / 演出」切换。只有一套的卡显示一个灰掉的「只有一套」。所有卡片一样高；标题固定占两行，超出截断，悬停时显示全名。
- **预览**：弹窗左侧、底部面板上方，是一张会动的全身大预览，配卡名、「私服/演出 · 稀有度 · 正在穿」和「穿这套」按钮。点卡片只是预览，点「穿这套」才保存。手机上预览随列表一起滚动。
- **保存**：按角色各存一套，存在本机，照现有通话偏好设置那样防御性地读写。选中的衣装加载失败时不清掉这个选择。衣装清单还没到或者读不到时，按存储桶的布局直接找选中的那套（ticket 19 实现时补充），清单到了再核对它还在不在。
- **预取**：进入对话页后，浏览器空闲时把 runtime 和当前衣装预取进缓存；开了省流量（`navigator.connection.saveData`）就不预取。

### 配置与 API（后端）

- `characters.toml` 每位角色新增两个可选字段：原作的**偶像编号**（`spine_manifest.json` 里的 `idolId`）和**默认衣装**。
- 新增环境变量：立绘素材的公开访问地址（存储桶的 URL）。前端没有构建期的环境变量，所以通过 `/api/characters` 下发：每位角色多一个 `stand` 字段，只有偶像编号、默认衣装、素材地址都配好了才有值，否则为 `null`，前端照现在一样只显示背景图。`stand` 里包含衣装清单的 URL 和默认衣装。

### 素材同步（部署）

- **存储桶里的结构**：按衣装存放立绘文件（`data.json`、`data.atlas`、`data.png`），另有每位角色一份**衣装清单**和每套衣装一张缩略图。立绘文件内容不会改，所以缓存设成长期、不可变（immutable）。衣装清单随新卡变化，缓存设成每次确认（`no-cache`）；缩略图可能重画，缓存一天（ticket 18 实现时补充；缓存头由同步脚本上传时设置）。存储桶公开可读、不签名，并且要配 CORS 允许站点域名访问。
- **衣装清单**：由同步流程生成，列出这位角色的每张卡，包括编号、卡名、稀有度，以及私服和演出服各自对应哪套衣装。私服和演出服贴图逐字节相同的只记一套。只收 stand，不收 cb。
- **同步流程**：照剧情库的同步脚本来写（日志、加锁、约定好的退出码），分三步：
  1. 整理衣装清单：Python，做成 `eidolon` 的一个命令，可以测试。
  2. 渲染缩略图：用和线上同一套播放代码，在无界面浏览器里渲染半身图。渲染前让动画先走约 1 秒，避开待机表情开头的眨眼。
  3. 上传：用 S3 兼容接口上传。endpoint、存储桶和密钥都从环境变量读，不写死用哪一家。
- **只同步已配置角色**：`characters.toml` 里配了偶像编号的角色才同步，每位约 60MB。
- PNG 不转 WebP。

## Testing Decisions

好的测试只看外部行为：给定输入事件，看发出的消息或者快照里的指令。不检查内部调用了什么、按什么顺序调用。沿用已有的接缝，只新增一个纯函数。

1. **后端通话的帧级测试**（沿用 `CallUnderTest` 和假 LLM、`FakeJudge`）：
   - 多段回复时，每段各发一条 `emotion`，带上正确的回复编号和段号。
   - 置信度低时发「平静」；超时、失败、没配 key 时不发。
   - 「只看文字」时照常判断。
   - 回复被打断后，不再为没有完整的段发 `emotion`。
2. **后端 Fish 分段合成**（照语音打断测试的做法，用一个假的 Fish WebSocket）：
   - 每段一个会话，下一个连接预先打开。
   - 段落边界会 flush。
   - `segment-playing` 正好排在这一段第一块音频之前，并带上正确的回复编号和段号。
   - 打断时立即停止，备用连接作废。
3. **前端立绘指令**（沿用 `liveConversation.test.ts` 的 `FakeCall` 和假 `Ports`），逐条覆盖「立绘指令」一节的规则：
   - 开嘴和闭嘴。
   - 按 `segment-playing` 切换；`emotion` 早到、晚到、这段已说完时丢掉。
   - 平静沿用当前心情，但回复第一段是平静时回到平静。
   - 「只看文字」按字幕切换，嘴始终闭着。
   - 用户开口看向、停下点头。
   - 打断时闭嘴并看向用户，心情不变。
   - 挂断后清空。
4. **选动画的纯函数**（新增）：用两位已配置角色的几套真实衣装的动画名单做测试数据，覆盖七种情绪各自的逐级替代、缺表情时用 `blank`、口型的替代链、减少动态效果时身体一律用 `wait`、点头和视线。
5. **配置与 API**（沿用 `test_characters.py` 和 API 测试）：新字段可选；三项都配好时 `stand` 才有值；编号格式不对时报错。
6. **衣装选择的本机保存**（照 `callPreferences.test.ts`）：按角色分开存；读到坏数据时退回默认衣装。
7. **衣装清单的生成**（照剧情库同步的测试）：用小份的假镜像数据，覆盖私服和演出服的配对、贴图相同时去重、按编号排序、卡名处理。

**人工验收**（前端没有组件测试和 WebGL 测试环境，这些在原型上已经人工验证过，实现后再按这个清单验一遍）：

- 两位角色各选几套衣装，构图正确。「花風Smiley」上剪裁没问题（眼睛、睫毛、眉毛完整）。
- 七种情绪的动作和过渡、带 `relay` 的放下手臂、停嘴后嘴部完全不动。
- 真实通话里，表情在这段声音开始时切换，被打断时闭嘴并看向用户。
- 加载慢时淡入；断网或清空存储桶时退回背景图；模拟上下文丢失后能恢复，颜色正常。
- 减少动态效果时的表现；换衣装面板的弹窗和底部面板。
- 安卓手机上 60 帧、不发热。**iPhone Safari 上验证内存（页面不会自己重新加载）和上下文丢失后的恢复**（wayfinder 阶段没有测过 iPhone）。

## Out of Scope

- cb（Q 版小人）立绘。
- 文字对话页的立绘。
- 按场合、季节自动换衣装。
- 心情跨通话保留。
- 给用户正在说的话另外调模型、根据内容即时反应（用户开口时的反应只靠前端：看向和点头）。
- 情绪分程度（例如「难过」加重成 `face_cry` 大哭）：先看七种情绪做出来的效果，上线后另开。
- 脸红、眼泪、道具这些叠加动画，以及 `hello` 等只有部分衣装才有的动作。
- 按音量驱动口型：原作也只有张合循环和闭嘴两种。
- 购买 Spine Editor 许可证（ADR-0009）。

## Further Notes

- **实测数据**：
  - Jev 的 p50 约 0.4 秒，早于 Fish 首个音频（约 0.6 秒）；上线后要在服务器上重测。
  - Redmi Note 12 Turbo 上各档像素比都稳在 60 帧，每帧约 1ms，内存不随换衣装增长。
  - 每段一个 Fish 会话并预开连接时，18 个段落边界全部不会多出停顿。
- **调研和原型**：详细调研在各 `research/*` 分支上，原型在 `prototype/spine-stand`，真机测量页在 `prototype/spine-stand-perf`。这些都是一次性代码，不合并。原型里的引擎、剪裁绕法和换衣装面板可以参考，但要按这份 spec 重写。
- **可以调的数值**：Jev 的置信度阈值（0.5）和超时（1.5 秒）、情绪过渡（0.3 秒）、口型混合（0.1 秒），实现时按实际效果调整。
- 素材镜像在部署机上的位置，由同步脚本的环境变量指定。
