# 06: 拍板：立绘素材怎么上线

Type: grilling
Status: resolved
Blocked by: none

## Question

立绘素材从镜像同步哪些文件（只同步已配置角色的 stand + stand_costume？PNG 要不要转 WebP）、放在服务器哪里、由后端还是静态服务提供、怎么缓存和版本化、部署脚本怎么做；角色和素材怎么对应（`characters.toml` 里的 idolId？默认衣装？）；ADR-0003 补一条修订：对公众提供官方 Spine 素材，素材不进仓库。

## Answer

2026-09-30 与用户 grilling 定下：

1. **同步范围**：只同步 `characters.toml` 里已配置角色的立绘，stand 和 stand_costume 全部都能选（真乃 90 套、恋钟 87 套，每套约 0.7MB，一位角色约 60MB）。以后新增角色时，素材跟着一起同步。
2. **存放与提供**：放在兼容 S3 的对象存储里（例如 Cloudflare R2、腾讯云 COS），**不写死用哪一家**，部署时再选（思路同 ADR-0005）。同步脚本通过环境变量配置 endpoint、存储桶和密钥；前端通过一个环境变量拿到素材的访问地址。存储桶**公开可读**，不签名，不要求登录。国内访问速度、ICP 备案这些属于部署层面的考虑，不影响代码。
3. **部署同步**：参照 `deploy/story-sync.sh` 写一个同步脚本，从镜像仓库按已配置的角色上传到存储桶。PNG 先不转 WebP，等手机性能问题摆出来再定。
4. **角色与素材的对应**：`characters.toml` 里每位角色加上原作的偶像编号（`spine_manifest.json` 的 `idolId`），程序据此找到她的全部衣装，并配一套默认衣装。用户没选过衣装时用默认衣装；默认衣装也没配、或者素材加载不到时，退回现在的背景图。
5. **版权立场**：接受对公众提供官方 Spine 立绘，记在 ADR-0003 的修订里。仓库只提交脚本和配置，不提交素材；收到权利方的要求就清空存储桶，前端退回背景图。
6. **部署要求**（写进 spec，不需要改应用代码）：存储桶配置 CORS，允许站点域名访问，否则 WebGL 加载不了贴图；缓存设为长期、内容不变（immutable），因为素材按衣装 ID 存放，内容不会改。

**遗留事实**：同一个 enzaId 常常同时有 stand 和 stand_costume，衣装名也一样（真乃有 28 个 enzaId 两类都有、20 个只有 stand、12 个只有 stand_costume）。两者的区别还没查清，这会影响选择界面把它们算作一套还是两套，归入迷雾「衣装在哪里选」。
