# 18: 立绘素材同步到对象存储

**What to build:** 部署者跑一次同步脚本，存储桶里就有了已配置角色的全部 stand 衣装、每位角色一份衣装清单、每套衣装一张缩略图；立绘改从存储桶加载。规则见 `../spec.md`「素材同步」「配置与 API」两节；依据见「拍板：立绘素材怎么上线」和「拍板：衣装在哪里选、怎么选」（`06-asset-delivery.md`、`09-outfit-picker.md`）。ADR-0003 的 2026-09-30 修订：素材对公众提供，但不进仓库。

**Blocked by:** 14

**Status:** ready-for-agent

- [ ] **衣装清单**（Python，做成 `eidolon` 的一个命令）：从镜像的 `spine_manifest.json` 和立绘文件，为 `characters.toml` 里配了偶像编号的每位角色生成一份清单：
  - 每张卡一项：编号、卡名（原文，去掉【】和角色名）、稀有度或类型，以及私服（`stand`）和演出服（`stand_costume`）各自对应哪套衣装。
  - 私服和演出服贴图逐字节相同的，只记一套。
  - 按编号排序，也就是原作的发布顺序。
  - 只收 stand 和 stand_costume，不收 cb。
  - 清单的具体格式由你定，写进部署文档。
- [ ] **缩略图**：用和线上同一套播放代码，在无界面浏览器里渲染每套衣装的半身图，渲染前让动画先走约 1 秒，避开待机表情开头的眨眼。
- [ ] **上传**：通过 S3 兼容接口上传立绘文件（`data.json`、`data.atlas`、`data.png`）、清单和缩略图。endpoint、存储桶、密钥和镜像位置都从环境变量读，不写死用哪一家。已经上传且内容相同的不重复上传。PNG 不转 WebP。
- [ ] **部署脚本**：照剧情库的同步脚本来写，包括日志、加锁、约定好的退出码，以及最后一行「结束：退出码 N（含义）」。
- [ ] **API**：`/api/characters` 的 `stand` 里加上衣装清单的 URL。
- [ ] **部署文档**：新增「立绘素材」一节：
  - 选择对象存储。
  - 存储桶要公开可读，配 CORS 允许站点域名访问，缓存设成长期、不可变。
  - 运行同步脚本；新增角色时怎么做。
  - 如何下架：清空存储桶后，前端自动退回背景图。
  - `.env.example` 补上所有新增的环境变量。
- [ ] **测试**：衣装清单的生成，照剧情库同步的测试做法，用一份小的假镜像数据：私服和演出服的配对、贴图相同时去重、按编号排序、卡名处理、没配偶像编号的角色跳过。
- [ ] **人工验证**：对一个真实的 S3 兼容存储（或者本地的 MinIO）跑一次，确认真乃和恋钟的清单数量合理（去重后真乃约 84 套、恋钟约 78 套），缩略图没有眨眼；把素材地址指向存储桶后，14 的立绘照常出现。在 Comments 里记下耗时和上传量。
- [ ] `uv run pytest`、`uv run pyright` 全部通过。
