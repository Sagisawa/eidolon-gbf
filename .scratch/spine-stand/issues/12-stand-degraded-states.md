# 12: 拍板：立绘在加载中、加载失败和减少动态效果时怎么表现

Type: grilling
Status: resolved
Blocked by: none

## Question

立绘素材（约 0.7MB 一套，来自对象存储）和 spine-ts runtime 都要现下载。三种情况下通话层显示什么：

1. **加载中**：打电话时立绘还没到，先显示背景图再淡入立绘？还是等到了再亮出通话层？立绘到的时候她已经在说话了怎么接（直接从当前心情和口型状态开始画）？
2. **加载失败**：「拍板：立绘素材怎么上线」定了退回背景图。要不要重试、要不要告诉用户、换衣装后加载失败时怎么办（退回默认衣装还是背景图）？
3. **减少动态效果**（`prefers-reduced-motion`）：DESIGN.md「Call layer」规定通话层本身无过渡。立绘还动不动：待机呼吸、情绪动作、口型、看向和点头，哪些保留、哪些冻结？手机「大立绘」从底部升起的入场怎么处理？

## Answer

2026-09-30 与用户 grilling 定下：

1. **预取**：进入对话页后，浏览器空闲时把 runtime（`spine-webgl.js`）和当前选中的衣装预取进缓存，打电话时直接从缓存读。只预取当前那一套。浏览器开了省流量（`navigator.connection.saveData`）时不预取，改成按下打电话键时才下载。
2. **布局不中途切换**：只要角色配了立绘（有偶像编号和默认衣装），一打电话就用立绘版布局（手机「大立绘」、电脑「半身 ADV」），立绘晚到或加载失败都不切回现在的布局；立绘的位置先露出背景图和纱。
3. **加载中**：只显示背景图和纱，不放转圈，也不放占位剪影。立绘到了用 0.3 秒淡入，从当前的心情、口型和视线状态开始画（轨道状态一直在更新，见「拍板：口型跟什么走」第 5 条）。
4. **加载失败**：
   - 依次退到选中的衣装、默认衣装、背景图；runtime 加载不到或浏览器不支持 WebGL 时，直接用背景图。
   - 通话中 WebGL 上下文丢失：等 `webglcontextrestored`，恢复后重新上传贴图接着画；恢复不了就保持背景图，这次通话里不再重试。
   - 通话层里不提示用户，下次打电话再重新尝试。
   - 本机保存的衣装选择不清掉（多半只是这一次网络出了问题；如果这套衣装已经不在存储桶里，换衣装面板里本来就看不到它）。
5. **减少动态效果**（`prefers-reduced-motion`）：
   - 保留：待机呼吸眨眼、口型、表情切换和 0.3 秒过渡、看向用户、点头和摇头（它们表达的是她正在说话、是什么心情，属于信息）。
   - 去掉：情绪的身体动作一律换成 `wait`，只换表情；手机「大立绘」从底部升起的入场改成原地淡入。
   - 换衣装面板里的大预览也用同样的规则。
   - 监听系统设置的变化，切换后从下一个动作开始生效，不打断正在播放的动作。

没有新术语，也没有难以回头的决定：不改 `CONTEXT.md`，不写 ADR。
