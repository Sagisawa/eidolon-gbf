# 09: 拍板：衣装在哪里选、怎么选

Type: prototype
Status: resolved
Blocked by: none

## Question

用户在哪里选衣装（通话层里、对话页、还是设置页），选择界面长什么样：每位角色近 90 套，要不要缩略图、缩略图从哪来（按衣装渲染一张？素材里没有现成的）、按什么分组（卡的稀有度 P_SR/P_SSR/Special、stand 和 stand_costume）；同一个 enzaId 的 stand 和 stand_costume 在画面上有什么区别，算一套还是两套（先在原型页面里对比几组再判断）。选择只存在这台设备上（「拍板：立绘素材怎么上线」）。

原型可以直接在分支 `prototype/spine-stand` 的 `/prototype/stand` 上加。

## Answer

2026-09-30 与用户 grilling 并在原型上试用后定下。原型在分支 `prototype/spine-stand` 的 `/prototype/stand?screen=picker`。

1. **在哪里选**：对话页页首，打电话键旁边加一个「换衣装」图标按钮（Lucide `Shirt`）。宽屏（≥ 768px，和对话页同一个断点）打开弹窗，窄屏打开底部面板。不放在通话层里。
2. **stand 和 stand_costume 的区别**（对照渲染确认）：P_SR/P_SSR 等卡，`stand` 是这张卡的**私服**，`stand_costume` 是**演出服**，是两套不同的衣服；Special 等两者贴图逐字节一致（全部数据里 182 对），只算一套。去重后真乃 62 张卡、84 套，恋钟 78 套左右。
3. **列表**：按卡片排列，按编号顺序（也就是原作发布顺序）；每张卡显示缩略图、卡名（原文，去掉【】和角色名），下面一个铺满卡片宽度的「私服 / 演出」切换；只有一套的卡显示一个灰掉的「只有一套」，所有卡片一样高。标题固定占两行高，超出的截断，悬停时显示全名。
4. **预览和保存**：弹窗左侧、底部面板上方是一张会动的大预览（全身）、卡名、「私服/演出 · 稀有度 · 正在穿」和「穿这套」按钮；点卡片只是预览，点「穿这套」才存进本机（按角色各存一套）。手机上预览不固定在顶部，随列表一起滚动，用户认为这样就行。
5. **缩略图**：同步素材时预先渲染（用和线上同一套播放代码在无界面浏览器里渲染半身图），和素材一起上传到存储桶。渲染前先让动画往前走约 1 秒，避开待机表情开头的眨眼。原型里是在浏览器里现场渲染的，62 张冷启动约 20 秒，正式版本不能这样做。
6. **原型里的实现细节**：换衣装后要释放旧衣装的素材，否则显存越撑越大；3.6 的 `AssetManager.remove` 只把条目设成 null，之后 `removeAll` 会对 null 调 dispose 报错，所以连条目一起删掉。
