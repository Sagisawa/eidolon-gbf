# 设置页分标签

Status: ready-for-agent

## Problem Statement

设置页是一栏从上到下排的八节：制作人档案、记忆入口、通话、自带密钥、登录方式（含退出登录）、后台入口、删除我的全部数据、关于。用户觉得它太长、太杂：

- 想改通话音质，要先滑过整个制作人档案。
- 自带密钥开头一段九句话的说明像一堵墙。真正要紧的「费用由你承担」「只存在这个浏览器里」淹在里面。
- 「退出所有设备」「删除我的全部数据」这类危险操作，夹在普通设置中间，没有隔开。
- 记忆只有一个链接，却单独占了一节。
- 通话因限额或自带密钥出错而结束时，「去设置自带密钥」只把人送到设置页顶部，还得自己往下找。

## Solution

设置页顶上加一排标签，分四组，一次只显示一组：

1. **档案**：制作人档案、记忆入口。
2. **通话**：默认麦克风、通话音质、电话质感。
3. **自带密钥**：整节。
4. **登录与数据**：登录方式（绑定、解绑）、后台入口（只有管理者看得到）、退出登录、删除我的全部数据（最底下）。

具体做法：

- 「关于 Eidolon-SC」不归哪一组，放在标签外面，哪个标签下都看得到。
- 当前标签记在地址里，刷新或分享地址都停在原来那一组。通话结束页可以直接把人送到自带密钥那一组。
- 文案做减法：
  - 自带密钥的长说明，外面只留两句，其余收进句末 ⓘ 弹出的说明里（电脑上鼠标移上去，手机上点一下）。
  - 删除全部数据的完整后果挪进确认框。
  - 只有一节的标签页，不再重复写和标签同名的节标题。

## User Stories

### 找到要改的设置

1. 作为用户，我希望设置页按类别分成几个标签，这样我一眼就能找到要改的那一类，不用整页往下滑。
2. 作为用户，我希望从对话列表的菜单进设置页时，默认看到档案，这样最常改的称呼、性别、时区一进来就在眼前。
3. 作为用户，我希望标签名短而明确（档案、通话、自带密钥、登录与数据），这样不用点进去就知道里面有什么。
4. 作为用户，我希望刷新页面后，还停在刚才那个标签上，这样不用重新找。
5. 作为用户，我希望把设置页某个标签的地址发给自己或别人，打开就是那一组，这样我能直接指给人看在哪里改。
6. 作为用户，我希望地址里的标签写错了或者过时了，页面照常打开在档案，这样坏链接不会让我看到空白页。
7. 作为用户，我希望切换标签不往浏览器历史里塞记录，这样按返回直接回到对话，不用一格一格退回之前的标签。
8. 作为用户，我希望切换标签时页面不跳回顶部、也不整页刷新，这样切换是即时的。
9. 作为在自带密钥那一组往下翻的用户，我希望标签栏吸在页首下面，这样不用滚回顶部才能切换。
10. 作为在手机上用的用户，我希望四个标签一行放得下、不用横着滑，这样一眼看全所有类别。
11. 作为在电脑上用的用户，我希望标签栏和内容一样限在一栏宽，这样版式和设置页其余部分对齐。

### 切换时不丢东西

12. 作为改了称呼还没保存、就切去看通话设置的用户，我希望切回来改动还在、「尚未保存」也还在，这样我不会不知不觉丢了改动。
13. 作为在自带密钥里填到一半的用户，我希望切走再切回来，填的内容还在，这样不用重填。
14. 作为来回切标签的用户，我希望每组不会每次切换都重新读取、闪一下「正在读取…」，这样切换显得干脆。

### 从别处直达

15. 作为通话因限额或自带密钥出错而结束的用户，我希望点「去设置自带密钥」后直接看到自带密钥那一组，这样马上就能填。
16. 作为从后台点「返回设置」或从记忆页返回的用户，我希望回到设置页默认的档案，这样落点可预期。

### 自带密钥的说明

17. 作为第一次看自带密钥的用户，我希望先看到最要紧的两句（费用由我承担、密钥只存在这个浏览器里，换设备要重填），这样不用读完一大段就明白要点。
18. 作为想细看的用户，我希望电脑上把鼠标移到 ⓘ 上就能看到其余说明，这样不用多点一下。
19. 作为在手机上用的用户，我希望点一下 ⓘ 就能看到其余说明、点旁边就关上，这样触屏上也看得到。
20. 作为用键盘的用户，我希望 ⓘ 能用 Tab 聚焦、回车打开、Esc 关上，这样不用鼠标也能看。
21. 作为用读屏的用户，我希望 ⓘ 读出来是「详细说明」，这样我知道点开会看到什么。
22. 作为介意隐私的用户，我希望收进 ⓘ 的说明一句不少：不存到服务器、只在处理请求期间使用、出错不改用部署者的密钥、只显示末 4 位，这样隐私承诺照旧完整。
23. 作为用户，我希望弹出的说明在深色模式下也清楚、跟页面分得开，这样晚上也读得舒服。
24. 作为用隐私模式的用户，我希望「这个浏览器无法保存自带密钥」的提示照旧显示在最上面，这样我不会以为填进去了。
25. 作为用户，我希望自带密钥那一组照旧告诉我这次计不计入限额，这样我知道填了有什么用。

### 登录与数据

26. 作为用户，我希望绑定、解绑登录方式在「登录与数据」的最上面，这样要加一种登录方式时一下就找到。
27. 作为只有一种登录方式的用户，我希望解绑键照旧是禁用的，并且告诉我为什么，这样我不会把自己锁在外面。
28. 作为管理者，我希望在「登录与数据」里找到后台入口，这样进后台的路跟以前一样短。
29. 作为不是管理者的用户，我希望根本看不到后台入口，这样不会被不相干的东西打扰。
30. 作为用户，我希望退出登录单独一节、放在绑定方式下面，这样它不会跟绑定按钮搅在一起。
31. 作为在共用电脑上用的用户，我希望退出登录时，照旧清掉这个浏览器里我的自带密钥，这样下一个人看不到。
32. 作为要退出所有设备的用户，我希望照旧先弹窗确认，并被告知其他设备上的自带密钥要自己去删，这样我知道后果。
33. 作为用户，我希望危险操作都在「登录与数据」的最底下，删除全部数据排在最后，这样改普通设置时不会误碰。
34. 作为要删除全部数据的用户，我希望节里只用一句话说明「彻底删除、无法恢复」，这样这一节不再是一大段字。
35. 作为要删除全部数据的用户，我希望在按下确认前，看到完整的后果：删掉什么、备份多久清掉、运行记录怎么处理、所有设备退出、浏览器里的自带密钥清掉，这样我是在知情的时候做决定。
36. 作为删除了全部数据的用户，我希望删除后的行为跟以前完全一样，这样改版不会改变数据怎么被处理。

### 页面整体

37. 作为用户，我希望在任何一个标签下都能找到「关于 Eidolon-SC」，这样随时能回去看落地页。
38. 作为用户，我希望只有一节的标签页（通话、自带密钥）不再重复一个和标签同名的标题，这样少一层噪音。
39. 作为用户，我希望有好几节的标签页（档案、登录与数据）照旧保留各节标题，这样分得清哪一块是哪一块。
40. 作为用读屏的用户，我希望每个标签面板都读得出它属于哪个标签，包括去掉了节标题的那几个，这样我知道自己在哪一组。
41. 作为用户，我希望标签的选中状态在浅色和深色模式下都看得清，而且是中性色，不带角色的印象色，这样跟应用其余部分一致。
42. 作为以后改设置页的人，我希望 DESIGN.md 里写明设置页的版式规则，这样我不用从代码里反推。

## Implementation Decisions

### 标签和地址

- 用已经装好的 shadcn `Tabs`（底层 Base UI），选下划线样式。
- 四个标签等宽，撑满设置页的一栏宽。
- 标签栏放在页面内容的滚动区里，吸在页首下面，铺实底，免得内容从下面透出来。
- 新增一个纯逻辑的**设置页标签模块**，管「当前标签」这条规则。页面只调用它，不自己解析地址。
  - 标签值固定四个：`profile`、`call`、`own-keys`、`sign-in`。
  - 从地址参数读出当前标签。参数名是 `tab`；缺省或者不认识的值，都当 `profile`。
  - 给定当前地址参数和要去的标签，生成新地址：只改 `tab`，保留其他参数。
- 切换标签时替换当前历史记录，不新增；切换时不滚动页面。
- 读地址参数要按这一版 Next 的要求包好 Suspense 边界，动手前先读 Next 自带的文档。
- 四个标签面板切走后都保持挂载，不卸载：
  - 没保存的档案、填到一半的表单都留着；
  - 切回来不用重新请求。
- 通话结束页「去设置自带密钥」的跳转，改成去 `own-keys` 标签。
- 标签名进 `copy.settings`：档案、通话、自带密钥、登录与数据。第四组不叫「账号」，因为 GLOSSARY 在「用户」和「登录方式」下都把「账号」列为避免的说法。

### 各组的内容和顺序

- **档案**：`ProducerProfileSettings`，下面是记忆入口那一节，两节都保留节标题。
- **通话**：`CallSettings`，不写节标题。
- **自带密钥**：`OwnKeysSettings`，不写节标题。包括它读取失败时显示的那一支。
- **登录与数据**，从上到下：
  1. **登录方式**：`SignInSettings` 只留绑定和解绑。
  2. **后台入口**：`AdminEntry`，只有管理者看得到，行为不变。
  3. **退出登录**：一个新组件，单独成一节，节标题「退出登录」。从 `SignInSettings` 拆过来的有：
     - 「退出登录」「退出所有设备」两个按钮；
     - 「退出所有设备」的确认框；
     - 退出时清掉这个浏览器里这位用户自带密钥的逻辑。

     行为不变：没取到用户之前，两个按钮都禁用。
  4. **删除我的全部数据**：`DeleteAccount`。
- `SettingsSection` 的标题改成可选。没有标题时，不渲染标题，也不自己声明标签关系，靠标签面板和它的标签之间的关联（Base UI 自动建立）。
- 「关于 Eidolon-SC」移到标签外面，作为页面内容的最后一块，跟着内容滚动。不用页面外壳那个固定在底部的页脚槽。

### 文案减法

- **自带密钥的说明**拆成两段文案：
  - **外面两句**：填了自己的 API key，这一项就改用你的额度，费用由你承担；密钥只保存在这台设备的这个浏览器里，换设备、换浏览器或清除浏览器数据后要重新填写。
  - **详细说明**是其余各句：
    - 不存到服务器；
    - 以前填过的要重新填一次；
    - 随请求发给服务器，只在处理期间使用；
    - 调用失败时这一轮失败，不改用部署者的密钥；
    - 只显示末 4 位。

  一句不删，措辞沿用 PR #62 对齐过的说法。
- **ⓘ 的做法**：
  - 外面两句末尾放一个图标按钮，读屏名称是「详细说明」。
  - 它打开 shadcn `Popover`，触发器设成悬停也能打开（Base UI 的 `openOnHover`）：电脑上悬停打开，手机上点开，键盘可以聚焦、回车打开、Esc 关上。
  - 不用 `Tooltip`，因为 Base UI 的 Tooltip 不响应触摸，也不该装长段文字。
  - 弹出层照 DESIGN.md 的浮层规则（阴影；深色模式高一层色调，带细边线）。
  - 这个用法目前只出现在这一处，按 shadcn 纪律直接写在 `OwnKeysSettings` 里，不抽成项目组件。
- **删除我的全部数据**：
  - 节里的说明只留一句，意思是「彻底删除你在这里的所有数据，无法恢复」。
  - 原来那段完整的后果拆成单独的文案键，原样放进确认框的说明里，措辞一个字不改。
- 「退出所有设备」的确认框文案不变。
- 改动只涉及 `copy.settings`，落地页的字体子集只收落地页和登录组件的文案，不受影响。

### DESIGN.md

在版式（Layout）一章加一条「设置页」，写明：

- 四个标签和地址参数；
- 下划线样式、等宽撑满、吸顶；
- 只有一节的标签页不写节标题；
- 危险操作放在「登录与数据」最底下，删除全部数据在最后；
- 「关于」在标签外面；
- 长说明收进 ⓘ Popover（悬停或点开），不用 Tooltip。

## Testing Decisions

- **接缝只有一个**：设置页标签模块，用 vitest 测，CI 会跑。这是和用户确认过的选择。界面行为大多是 Base UI 自带的（面板保持挂载、Popover 的开关），浏览器级的自动检查脚本不值得为它维护。
- **什么算好测试**：只测外部行为。给地址参数，断言得到的标签；给当前参数和目标标签，断言得到的地址。不测内部怎么实现，也不测组件的渲染细节。
- **要测的情形**：
  - 读：缺省、空字符串、不认识的值落到 `profile`，四个合法值各自原样返回。
  - 写：只改 `tab`，其他参数保留；从没有 `tab` 的地址也能生成正确的地址。
- **参照的已有测试**：`lib` 下那批纯逻辑测试，例如通话结束原因（`callEnd`）、通话偏好（`callPreferences`）、本地自带密钥（`localOwnKeys`），都是同样的输入输出断言，测试名写行为。
- 前端没有组件测试设施，这次不引入。
- 照常要通过的检查：前端单测，以及 shadcn 纪律检查脚本。
- **其余靠人工验证**，用构建版前端（`next build` + `next start`）：
  - 手机宽度 375px 和 320px，以及电脑宽度；
  - 浅色和深色模式；
  - 键盘操作；
  - 通话结束页的跳转；
  - 切走再切回来，没保存的档案还在；
  - 吸顶；
  - Popover 悬停和点开；
  - 管理者和普通用户看到的「登录与数据」不同。

## Out of Scope

- 三种保存方式（档案点保存、通话设置立即生效、自带密钥逐项试调保存）不统一，各有原因。
- 自带密钥三个子表单（LLM、语音合成、语音识别）的内部结构不动。
- 记忆页本身不动。
- 不加新的设置项。
- 不引入组件测试设施，也不写 Playwright 检查脚本。

## Further Notes

- 设计在 2026-10-10 的 grilling 中定下，没有新的 GLOSSARY 词条（标签名是界面用语，不是领域概念），也没有 ADR（改成标签不难撤回）。
- 自带密钥的说明和删除全部数据的说明，是 PR #62（ADR-0017，自带密钥只存在浏览器里）刚跟隐私说明逐句对齐过的。这次只搬位置、不改措辞；要改措辞另开一张票，并且要同步隐私说明。
- 分两波实现：
  - 第一波并行做 01（分标签，含去掉重复标题和整条 DESIGN.md 规则）和 02（ⓘ 说明）。02 只动自带密钥那一节内部，不用等 01。
  - 第二波做 03（登录与数据重新排序），它要往 01 建好的第四组里排各节。
