# 02: `eidolon reembed` 与缺向量警告

**What to build:** 管理员换了向量化服务、模型或维度后，运行 `eidolon reembed`，用库里已有的原文按当前模型重新向量化剧情库、角色资料和全部用户的记忆，完成后库里只剩当前模型的向量。不需要重新下载或导入剧情。服务可以照常运行：期间检索暂时不完整，但不会出错。后端启动时如果剧情库有段落缺当前模型的向量，日志里提示运行这条命令。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 新增顶层命令 `eidolon reembed`（不放在 `story` 下，因为它也处理资料和记忆），读取与服务相同的向量化配置；没配置向量化服务时报错退出
- [ ] 剧情库：对没有当前模型向量的段落，用 `episode_passages.text` 重新向量化并原地替换（该表主键是 `(episode_id, seq)`，一个段落只存一个模型的向量）；文档标题按 01 的规则取「出处 + 话标题」
- [ ] 角色资料：为 `characters.toml` 里每位角色补齐当前模型的向量（复用 `FactIndex` 现有的「只补缺的」逻辑）
- [ ] 记忆：为所有用户的记忆补齐当前模型的向量；已删除的记忆不补
- [ ] 全部成功后，删除三处中其他模型的向量；有任何一处失败则不删除，退出码非 0
- [ ] 分批提交：中断后重跑只补缺的，已完成的不重复向量化；打印进度和各处新向量化的条数
- [ ] 服务运行中执行不会出错：检索只查到已完成的部分；与正在进行的导入或记忆写入并发时不丢数据
- [ ] 启动检查：后端启动时若剧情库存在缺当前模型向量的段落，打一条警告（含缺失数量和 `eidolon reembed` 提示）；不阻止启动
- [ ] 测试：用 `FakeEmbedder`（两个不同的 `model`）覆盖三处的补齐、删除旧向量、中断续跑、失败时不删除、已删除记忆不补、启动警告
