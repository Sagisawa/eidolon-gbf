# 03: 重排校准，默认改用 Qwen3-Reranker-4B

**What to build:** 一份提交进仓库的小校准数据集和 `eidolon eval rerank` 命令，对着本地的私有剧情库和记忆，打印某个重排模型给「相关」与「不相关」候选的分数分布。用它比较 0.6B 与 4B，定出 4B 的检索阈值和记忆阈值；然后把默认重排模型改为 `Qwen/Qwen3-Reranker-4B`，阈值按模型分组。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 数据集 `backend/eval/rerank-calibration.toml`：二三十条有代表性的问题，每条注明角色、问的是剧情/资料/记忆，以及哪些候选相关、哪些不相关（用剧情编号、资料标题或记忆文本标识）。只含问题、编号、标题和标注，不含剧情原文（ADR-0003）。agent 起草，人工校对
- [x] 记忆类问题需要的记忆不来自真实用户：数据集里自带几条示例记忆，命令运行时临时向量化，不写入数据库
- [x] 命令 `eidolon eval rerank [--model 模型名]`：按与对话中相同的方式取候选（向量检索 `CANDIDATES_PER_SOURCE` / 记忆 `CANDIDATES`）并重排，按「相关 / 不相关」分组打印分数分布，以及给定阈值下的命中与误放数量；标注里的候选没进入向量检索结果时单独列出（这是召回问题，不是阈值问题）
- [x] 分别用 0.6B 和 4B 跑一遍，在 Comments 记录分数分布和选定的阈值及理由
- [x] 阈值按模型分组：0.6B 保持 `0.3` / `0.01`，4B 用校准出的值；未知模型用 4B 的阈值并在启动时打警告；`RERANK_MIN_RELEVANCE`（检索）与 `RERANK_MEMORY_MIN_RELEVANCE`（记忆）可手动覆盖
- [x] ~~`DEFAULT_RERANK_MODEL` 改为 `Qwen/Qwen3-Reranker-4B`~~ 校准后改回 0.6B，见 Comments（已确认国内站 `api.siliconflow.cn` 仍提供；国际站标为 Deprecated，在 Comments 里注明）
- [x] 测试：阈值选择（已知模型、未知模型、环境变量覆盖）；`eval rerank` 用假的 embedder/reranker 跑通并输出预期统计

2026-09-27 校准完成，默认模型改回 0.6B。

- **剧情库**：本地同步完成，汉化版 5342 段 + 镜像原文剧情 2617 段，向量化用硅基流动。
- **数据集校对**：用户逐条校对了 33 条原有问题，只把下雨那条的「あめのひ」改为 acceptable。第一次跑出 113 个得分 ≥ 0.3、但没有标注的候选，由 agent 读原文给出建议、用户确认后补进标注。主要漏洞是剧情题一条角色资料都没标，而「档案 / 名字的由来」「鸟 / 猫头鹰」「人物关系 / 父亲」这类资料正好回答了问题。另外，记忆题两边的分数挨得很近（4B 相关最低 0.0029、不相关最高 0.0031），所以补了 3 条示例记忆和 5 道间接说法、无关闲聊的记忆题，同样经用户确认。现在共 38 道题、11 条示例记忆，全部 `reviewed = true`。
- **分数分布**（最终标注）：

  | | 剧情与资料：相关 n=42 | 不相关 n=502～503 | 记忆：相关 n=11 | 不相关 n=108 |
  |---|---|---|---|---|
  | 0.6B | p10 0.60，中位 0.993 | 中位 0.0007，p90 0.26 | p10 0.0018，中位 0.20 | p90 0.0011，最高 0.052 |
  | 4B | p10 0.66，中位 0.997 | 中位 0.0017，p90 0.53 | p10 0.0065，中位 0.041 | p90 0.0010，最高 0.038 |

- **按对话里的实际口径统计**（检索取过阈值的前 `MAX_REFERENCES` = 5 条，记忆取前 `MAX_FOUND` = 3 条；「漏」包括花鸟园那题 6 段相关、超出 5 条上限的部分，以及 4 个召回问题）。`eval rerank` 只打印当前阈值下不设上限的命中与误放，这张表是用一次性脚本从它逐条打印的分数推算的：对每道题取分数不低于阈值的候选，按分数从高到低取前 5 条（记忆前 3 条），再按标注计数。

  | | 阈值 | 相关进入 | 可放可不放 | 误放 | 漏 |
  |---|---|---|---|---|---|
  | 0.6B 剧情与资料 | 0.3 | 38 | 27 | 17 | 4 |
  | 4B 剧情与资料 | 0.3 | 35 | 27 | 28（其中 1 条来自什么都不该放的问题） | 7 |
  | 4B 剧情与资料 | 0.7 | 34 | 23 | 14 | 8 |
  | 4B 剧情与资料 | 0.9 | 31 | 20 | 11 | 11 |
  | 0.6B 记忆 | 0.01 | 8 | 1 | 2 | 3 |
  | 4B 记忆 | 0.005 | 10 | 1 | 1 | 1 |

- **剩下的误放**：两个模型的误放大多是 0.9 分以上的「同话题、不是那件事」，比如别的便当剧情、别的粉丝来信、别家事务所的试镜、别的物产展，靠阈值挡不住。4B 还会把一批似是而非的候选打到 0.4～0.7（如其他年份的圣诞剧情），所以阈值要提到 0.7 才和 0.6B 接近。
- **召回问题**（两个模型相同，与阈值无关）：花鸟园线第 1 话、长椅 TE、离开佐世保、W.I.N.G. 优胜后那段没进入向量检索结果。
- **决定**（用户确认）：
  - 4B 的阈值定为检索 `0.7`、记忆 `0.005`。检索在 0.6～0.9 之间误放下降、相关基本不掉，过了 0.7 相关开始掉；记忆取 0.005，是命中最多、误放最少的点。
  - 0.6B 保持 `0.3` / `0.01`。
  - **默认模型改回 `Qwen/Qwen3-Reranker-0.6B`**：检索是每轮对话都走的主路径，0.6B 在这里更好；4B 在记忆上的优势只有 1～2 条，样本太小，抵不过检索上的退步；4B 的国际站也已经标了 Deprecated。
  - 未知模型仍用 4B 的阈值。
  - 默认改 4B 只在这个分支上、没进过 main，所以 deploy.md 里「升级后自动换成 4B」那段直接删掉了。
- **测试**：`tests/test_rerank_eval.py` 原来用剧情编号的前缀白名单排除剧情、再核对剩下的资料标题，新标注里的 `game_event_communications/`、`business_unit_communication/` 不在白名单里，所以改成按「标题路径里有 ` / `」认出资料标题（所有资料标题都是「上级 / 本级」，剧情编号里没有空格）。
