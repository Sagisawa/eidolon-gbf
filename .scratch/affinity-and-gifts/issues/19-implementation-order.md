# 19: 拍板：三份规格的实现顺序和分支衔接

Type: grilling
Status: resolved
Blocked by: 16, 17, 18

## Question

好感度、礼物、应用导航三份规格都写好以后，按什么顺序实现、分支怎么衔接：

- **谁依赖谁**：
  - 礼物页要放进导航外壳；
  - 送礼要用好感度和对话事件；
  - 冷却中的「送她一件礼物」要跳到礼物页；
  - 页首标识的 Popover 末尾也有送礼链接。

  哪块先做，先做的那块要不要先留出口（比如好感度先上线时，送礼入口先不显示）。
- **对话事件放在哪块**：对话事件（她挂断、送礼记录）的存储和样子（「原型：对话记录里的对话事件」）是跟好感度一起做，还是单独先做。
- **分支**：三块各一个 `feat/` 分支依次合进 main，还是有的叠在前一块的分支上。导航这一块内部怎么切由「拍板：应用导航规格里剩下的细节」定，这里只排三块之间的先后。
- **上线**：每块合进 main 后是否单独部署。好感度上线时没配判断模型的部署者看到什么（整块关闭已定）。要不要等三块都好了再一起开。「拍板：好感度和礼物在后台的部分」加了单独关掉好感度和礼物的开关、暂定默认开，上线时它要不要先默认关，在这里定。
- `DESIGN.md`、`GLOSSARY.md`、ADR 和对外文档（「拍板：隐私政策、使用条款、落地页、README 要跟着改哪些」）各跟哪个分支走。

## Answer

2026-10-12 grilling 定下，五项都按推荐。

- **先后**：导航 → 好感度 → 礼物。
  - 礼物页要放进导航外壳，送礼要用好感度，所以礼物最后做。
  - 好感度要改对话页的页首标识、变化胶囊、通话层里她挂断，导航第 1 张票要把通话搬进外壳，两边改同一批文件，不同时做；好感度直接在新外壳上做。
- **留口子**：
  - **导航**：先上线时导航栏和 dock 只有对话、设置两项，「礼物」那一项在礼物分支里加。「拍板：应用导航规格里剩下的细节」定的「『礼物』一直留着」从礼物上线起才成立。
  - **好感度**：先上线时，所有送礼入口都不显示：冷却时输入框里的「送她一件礼物」、标识 Popover 末尾的送礼链接；冷却版结束卡的主按钮先换成普通的关闭。冷却只靠自然恢复，最长 24 小时。礼物分支把这些入口打开。
- **共用部分归哪块**：
  - **对话事件**：存储和分隔线（「原型：对话记录里的对话事件」）跟好感度一起做，先用在「她挂断了电话」；礼物分支加上送礼记录这一种。
  - **重置卡**：整个归礼物，包括背包、使用、抽奖里出、后台发放。
  - **后台**：好感度分支建配置页的「好感度和礼物」卡，放开关；看板的「好感度」一节也在好感度分支。礼物分支往卡里加「给所有现有用户各发一张重置卡」。
- **分支和设计文档**：
  - 三块各一个分支：`feat/app-navigation`、`feat/affinity`、`feat/gifts`。都从 main 开，前一块合进 main 以后再开下一块，不叠在前一块的分支上。
  - `feat/affinity-and-gifts` 只放计划，自己不合进 main。每个实现分支开工时从它取出自己那份：
    - 导航：`.scratch/app-navigation/`
    - 好感度：`.scratch/affinity/`，加上这张地图 `.scratch/affinity-and-gifts/`
    - 礼物：`.scratch/gifts/`
  - `GLOSSARY.md` 这次的改动（「好感度与礼物」一节和相关词条）整份跟好感度分支走，礼物、抽奖、重置卡几条会比功能早上线一段时间，这能接受。
  - 导航第 1 张票改写「通话」词条时，main 上还没有「角色也会自己挂断」那半句；好感度分支带词汇表进来时手工合并。
  - 另外几样已经定过：
    - `DESIGN.md` 和「通话属于外壳」的 ADR 跟导航的各张票走（「拍板：应用导航规格里剩下的细节」）；
    - 对外文档按「拍板：隐私政策、使用条款、落地页、README 要跟着改哪些」分给好感度、礼物两个分支；
    - README 截图在礼物分支的最后一张票里重拍。
- **上线**：
  - 每块合进 main 后单独部署。
  - 好感度开关在好感度分支里**默认关**，礼物分支改成**默认开**。这样好感度先上线时，不管是这个部署，还是别人从 main 拉的部署，都不会出现能进冷却、却没法送礼的空档；想先试就在后台打开。
  - 礼物上线、开关打开以后，管理者发一条公告，介绍好感度和礼物，并说明隐私政策和使用条款更新了。
  - 没配判断模型的部署者看到的就是整块关闭的样子，不另做提示。
