# 18: 拍板：隐私政策、使用条款、落地页、README 要跟着改哪些

Type: grilling
Status: resolved
Blocked by: 17

## Question

好感度、礼物和导航改版上线后，对外的几份文字哪些地方要改，各改成什么意思（措辞实现时再写）：

- **隐私政策**（`/privacy`）：新存的数据都要说清：
  - 每位用户对每位角色的好感度和冷却；
  - 对话事件（送礼记录、她挂断）；
  - 背包里的礼物和重置卡，抽奖次数。

  还有这些边界：
  - 判断模型每个回合都会看到用户的话（现在写到什么程度）；
  - 好感度不能自己删、只随删除用户一起删（「好感度对用户有多透明」）；
  - 后台看不到个人的好感度；
  - 对话事件不进记忆。
- **使用条款**（`/terms`）：要不要写明好感度、冷却、角色会挂断电话是玩法的一部分，冷却不是封禁或限额；礼物和重置卡没有现金价值、不能转让。
- **落地页**：要不要介绍好感度和礼物，放在哪一段，用不用新截图。
- **README**：功能列表和截图（`npm run readme-media` 重拍）要不要加礼物页、新的导航。部署说明里加不加判断模型和好感度相关的开关（取决于「拍板：好感度和礼物在后台的部分」）。
- 哪些改动跟着各自的 `feat/` 分支走，哪些最后统一改。

## Answer

2026-10-12 grilling 定下。这里只定每处改成什么意思；措辞实现时再写，只有落地页那一句是用户定好的文案，实现时照抄。

- **隐私政策（`/privacy`）**：
  - 「我们保存哪些数据」：
    - 新加一条「好感度」：每位角色对你各一份好感度，以及有没有在冷却。你只看得到档位；不能单独删除，删除记忆也不影响它，删除全部数据时一起删。
    - 「对话」那条补上：对话里还有送礼记录和「她挂断了电话」这样的记录，这些不进记忆。
    - 新加一条「礼物」：背包里的礼物、重置卡，还有抽奖次数。
    - 「运行记录」那条补上：会记下判断模型对每个回合的判断结果（加分还是减分、有没有命中「不该说的话」等），不含对话内容。
  - 「交给哪些第三方」：原来「判断要不要回忆剧情时……」那一句，改成单独一条「判断模型」，和语音、向量化并列：
    - 每个回合你说的话都会发给部署者配置的判断模型（点名 Jev 或 Cloudflare），用来判断要不要回忆剧情或查资料、这句话让她的好感度怎样变化；
    - 通话中她的回复也会发过去，用来判断情绪（现在漏写了，这次一起补上）；
    - 这项服务始终由部署者提供，自带密钥不会改变这一点。
  - 「管理者能看到什么」：补上管理者看不到你的好感度、冷却、礼物和抽奖次数，只能看到所有用户合起来的统计。
- **最后更新和重新同意**：隐私政策和使用条款末尾都加「最后更新：{日期}」。不加同意版本号，已经同意过的用户不用重新勾选。上线时管理者发一条公告，说隐私政策和使用条款更新了。
- **使用条款（`/terms`）**：新加一条「玩法」：
  - 好感度、冷却、角色挂断电话都是玩法的一部分，由 AI 根据你说的话判断，可能误判；
  - 冷却会自动解除，不是封禁或限额，管理者也不会人工调整；
  - 礼物、重置卡、抽奖次数只是应用里的玩法物品，没有现金价值，不能转让或交易；服务调整或关闭时可能随之消失（和「不保证一直可用」那条一致）。
- **落地页**：不新加一幕（划到 Out of scope），只在第 6 幕「使用须知」里加一行，文案用户已定：「你的话语会影响她们对你的态度，切勿过于冒犯……」。用户最初写的是「情绪」，按词汇表改成了「态度」：「情绪」专指通话里决定立绘表情的那个心情，和好感度是两回事。改了 `copy.landing` 以后，要在 `frontend/` 下重跑 `node scripts/landing-fonts.mts`。
- **README（中、英、日三份同步）**：
  - 功能列表「和她说话」那组加一条「好感度和礼物」：她会因为你说的话亲近或疏远你，冒犯多了会冷却；每天抽奖得到礼物送给她。
  - 「部署和运营」的后台那条补上「好感度可以单独关掉」，并写明这一块需要判断模型。
  - 开关的环境变量写进 `docs/configuration*.md`（三种语言）和 `.env.example`；README 正文不列，和 `JUDGE_PROVIDER` 一样。`docs/deploy.md` 里引用隐私政策的地方跟着核对。
  - 截图用 `npm run readme-media` 全部重拍，导航栏、dock 和页首的好感度标识会自然出现。另外新加一张电脑上的礼物页截图 `gifts.webp`，放在「好感度和礼物」那条旁边。脚本要先准备好可重复的抽奖次数和背包。
- **哪些跟着哪个分支走**：
  - **好感度分支**：
    - 隐私政策：好感度、对话事件、运行记录、管理者、判断模型这几条；
    - 使用条款：「玩法」一条里好感度和冷却的部分；
    - 落地页「使用须知」那一行；
    - README 和 `docs/configuration*.md` 里好感度和开关的部分；
    - 两份文件的「最后更新」日期。
  - **礼物分支**：隐私政策「礼物」那条，使用条款里礼物和重置卡的部分，README 功能列表里礼物那半句。
  - **截图**：全部重拍、加 `gifts.webp`，放在三块里最后合进 main 的那个分支的最后一张票，只拍一次。
  - **公告**：「隐私政策和使用条款更新了」属于「拍板：三份规格的实现顺序和分支衔接」里的上线步骤。
