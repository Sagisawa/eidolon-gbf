# 02: 调研：判断模型能不能判断好感度变化

Type: research
Status: resolved
Blocked by: none

## Question

制作人说的一句话该让好感度升、降还是不变、变多少，这个判断交给谁做比较可靠？

- 现有判断模型（Jev、Cloudflare Clef / Clef-flash）的 `score` 和 `choice` 题型能不能表达「这句话对她是加分、减分还是不变，程度多大」，以及「这句话是不是不该说的话（冒犯、骚扰、恶意出戏）」。中文和日文输入的表现，有没有官方说明或公开评测；延迟和每回合费用量级。先读仓库里已有的 `.scratch/cloudflare-judge/research.md` 和 `.scratch/spine-stand/research/jev-emotion.md`，不重复已有结论。
- 另两种做法的已知利弊：让扮演角色的 LLM 在回复格式里顺带输出好感度变化（同步、懂角色，但可能偏袒、可能被「给我加好感度」之类的话操纵、自带 LLM 时由用户付费）；在回复之后的记忆提炼那次调用里顺带判断（异步、晚一个回合，记忆关闭时不跑）。
- 已有的 AI 陪伴 / 角色扮演项目（开源项目、SillyTavern 一类的扩展、恋爱模拟类 LLM 游戏、相关论文）怎么做好感度或关系值：谁打分、怎么防操纵、怎么避免一直升或一直降。记下许可证和一手来源。

## Research

## Answer

- **只有判断模型不能被用户伪造。** 自带 LLM 的地址和模型由用户填，用户可以指向自己的服务、回什么都行，所以「扮演角色的 LLM 顺带输出」和「记忆提炼时顺带判断」的结果都由用户控制；判断模型始终由部署者承担。
- **`score` 题型能表达方向和档位，不能给精确幅度**：2–10 级有序量表，从 0 级开始、没有负数，返回概率加权分、每级概率和 confidence。把中间一级定为「对她没有影响」就能表示升、不变、降；档位到增量的换算放在代码里。Clef 是否同样如此未确认。
- **「不该说的话」要单独出题**（每类一道是非题，或一道带「都不是」的 choice）；一道题只问一件事，choice 偏向排第一的选项。
- **判断模型也会被话里的指令带偏**（论文显示附加一句就能抬高评分），所以代码里要设每回合上限，「要求改好感度」单独作为一档或一道题。
- **中日文没有官方数据**（Jev 中文测试集 68.35%，不分题型；日文只有第三方小样本的 choice 测试），`score` 题在中日文上的效果要自建 eval。
- **费用和延迟很小（估算）**：并进现有检索判断请求时延迟基本不变，每回合多 300–500 输入 token，约 $0.00001–0.0001；但部署者关掉检索时现在不调判断模型，就要另开一次请求。
- 扮演角色的 LLM 顺带输出：同步、懂人设，但会迎合用户、分数挤在一处、易被注入，还和 `<ja><zh>` 流式格式冲突。记忆提炼时顺带判断：能看到她的回复、不挡回复，但晚一个回合生效、记忆关闭时不跑，还要改已经有 eval 的记忆提示词。
- 已有项目（Heartmorrow、BetterSimTracker 等）多用单独的判断调用，小的离散档位、拿不准给 0、代码限定每回合上限并卡住总值；没有项目专门防「给我加好感度」，也没有每日上限。
- 文件里有三种做法的取舍表和一份实测清单，选哪种留给「好感度变化由谁判断」那张票。
