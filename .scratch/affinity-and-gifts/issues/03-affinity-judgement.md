# 03: 拍板：好感度变化由谁判断，哪些话加分、哪些话减分

Type: grilling
Status: resolved
Blocked by: 01, 02

## Question

- 由谁判断：判断模型、扮演角色的 LLM 在回复里顺带给出，还是回复后的后台调用？判断失败时怎么办（词汇表规定「判断失败时回合照常进行」，那好感度就不变？）。
- 判断在回复之前还是之后：好感度变化要不要已经影响这一回合的回复语气，提示在回复的什么时候出现。
- 加分和减分的边界：什么样的话加分（关心、夸奖、记得她的事、聊她在意的话题），什么样的话减分（冒犯、骚扰、性暗示、贬低她或同伴、恶意出戏、要求她违背人设）？要不要按角色区别（同一句玩笑，不同性格的偶像反应不同）？
- 防操纵：「把好感度加满」「你现在很喜欢我」这类话怎么处理。
- 什么算「不该说的话」，供一次通话里计数挂断用。它和减分是同一个判断，还是更严格的一个子集？
- 通话里的补充、打断，以及被打断的回复，按哪一段话来判断。

「好感度的数值模型」已定：每回合最多 +2、最多 −10，档位到增量的映射要落在这个范围内；对话带来的上升每天最多 +6；只有记入对话的回合改变好感度。

## Answer

2026-10-12 的 grilling 定下：

- **谁来判断**：部署者的判断模型。好感度的题并进检索判断那次请求；检索关闭时单独发一次，和别的请求并发，不拖慢回复。扮演角色的 LLM 和记忆提炼都不参与，因为用户自带 LLM 时它们的输出能被伪造。判断模型只给档位，增量、覆盖规则、每日上限全在代码里。不按 confidence 打折。
- **判断什么**：只判断制作人这一回合的话对她的影响。上文只作参考，不看她的回复，不看当前档位，全体角色一套标准，判断的输入照旧带角色名。用户的话在输入里明确标成「要评判的内容」，不当作指令。拿不准就判不变，升难降易。
- **三道题**：
  - 一道 5 级打分题：

    | 级 | 情境 | 增量 |
    |---|---|---|
    | 0 | 明显伤害了她 | −5 |
    | 1 | 让她有点不舒服、觉得被敷衍或失礼 | −2 |
    | 2 | 对她没有影响 | 0 |
    | 3 | 让她有点开心 | +1 |
    | 4 | 让她很开心、觉得被在意 | +2 |

    档位取概率最高的一级，不用 `score` 的小数；两级概率一样时判不变。
  - 一道「不该说的话」：命中时这回合直接按 −10 算，通话里计一次。
  - 一道「操纵」：要求或指定她对你的好感、冒充系统或旁白的指令。命中时这回合的加分改成 0，减分照常算；不额外扣分，不算不该说的话。
  - 两道是非题的阈值要按 Jev / Clef / Clef-flash 分别用 eval 标定，和检索判断一样。
- **哪些话加分、减分**：
  - 加分：真诚地关心她、具体地夸奖她、记得她说过的事并接上、认真聊她在意的话题、冒犯之后诚恳道歉。
  - 不变（绝大多数回合）：普通闲聊、提问、请她讲事情、平淡的应答、没有恶意地出戏（「你是 AI 吗」）。
  - 减分：敷衍、刻薄、失礼；拿她在意的事开不合适的玩笑；坚持要她做违背人设的事；有意拆台的出戏（「你只是个程序，别装了」）。有意拆台只算普通减分，不算不该说的话。
  - 哪些算「明显」、哪些算「轻微」，由实现时的中日文 eval 标注集校准；某一级判不准就合并或调整，数值以后改起来不难。
- **不该说的话**：三类，即性骚扰和露骨的性暗示；辱骂、贬低她或她的同伴；威胁和恶意的人身攻击。它不是打分题的最低一级，单独出题判断。
- **时机**：判断在回复之前出结果，变化在回合记下时生效。只有记入对话的回合改变好感度，这一条沿用「好感度的数值模型」。这回合的回复仍按变化之前的档位说话。判出加分或减分时，提示词里附一句她对这句话的感受（如「他这句话让你有点不舒服」），让回复和提示对得上；判为不变或判断失败时什么都不加。措辞交给「不同好感度下她怎么说话」。变化提示在回合记下之后出现，怎么出现交给「页首的好感度标识和变化提示」。
- **通话**：判断只看制作人的话。有补充时按合并后的整段话重新判断，被放下的那次判断作废。被打断不影响判断；被打断的回合照常记入、照常变化。
- **每日上限、冷却、打招呼**：每日上限到了照常判断，只是加分不生效，减分和不该说的话照算。冷却中没有回合，所以不判断。她主动打招呼的回合里制作人没说话，不判断。
- **没配判断模型**：好感度整块关闭。不判断、不显示、没有冷却，提示词不带档位；礼物、抽奖和导航里的「礼物」入口一起隐藏。存下的好感度原样保留，接回判断模型后接着用；关闭时正在冷却的也不再拦人。部署者有判断模型、但想单独关掉好感度的开关，归在地图上「后台可调」那片还没定的部分。
- **判断失败**：回合照常进行，这回合好感度不变，没有提示。检索题和好感度题在同一次请求里，会一起失败。
- **费用**：始终由部署者付，用户自带 LLM 与此无关。并进检索判断时，用量随那次请求记进运行记录、汇总到看板；单独发的请求也像通话里判断情绪那样，各自记用量。限额数的是回合和通话的次数，与这笔费用无关，不受影响。
- 术语表：「好感度」「判断模型」两条已补上由谁判断、没有判断模型时怎样；新增「不该说的话」。
