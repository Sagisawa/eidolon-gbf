# 好感度、礼物与应用导航

Label: wayfinder:map

## Destination

三份可以直接拆票实现的规格，所需的决定全部定下、实现顺序也定好：

- **好感度**（`.scratch/affinity/spec.md`）：她对制作人的好感度随制作人说的话升降，不同好感度下说话不同，变化时有提示，对话页页首有标识；跌到底进入冷却，冷却中不能发起回合和通话，好感度随时间慢慢回到正常值；通话里好感度过低或说了太多不该说的话时，她说完最后一句自己挂断。
- **礼物与抽奖**（`.scratch/gifts/spec.md`）：每天发抽奖次数，抽到礼物，选一位角色送出，好感度提升比自然恢复快；极少数时候抽到重置卡，管理者也能给所有用户发。
- **应用导航**（`.scratch/app-navigation/spec.md`）：电脑最左边一条导航栏（对话、礼物、设置），手机底部 dock；设置改成像手机设置那样的一级、二级页面。

2026-10-12 已到达：19 张票全部关闭，三份规格都已写成、状态 `ready-for-agent`。实现按「拍板：三份规格的实现顺序和分支衔接」：导航 → 好感度 → 礼物。

实现进度：导航 PR #83 于 2026-10-12 合进 main；好感度 PR #85 于 2026-10-13 合进 main（10 张票，`.scratch/affinity/issues/`）；礼物 PR #86 于 2026-10-13 合进 main（10 张票，`.scratch/gifts/issues/`）。三份规格全部实现完，这张地图到此走完；计划分支 `feat/affinity-and-gifts` 已删（内容都在 main 上）。上线（部署、发公告）见礼物票 10 的 `## Answer`。`GLOSSARY.md` 以 main 为准，不再从计划分支取。

## Notes

- 术语以 `GLOSSARY.md` 为准，新加了「好感度与礼物」一节：好感度、冷却、礼物、抽奖。不说小偶像、聊天、账号、docker，分别说角色、对话或回合、用户、dock（导航栏）。好感度不是情绪，冷却不是封禁或限额。
- 每张拍板类（grilling）票都要调用 grilling 和 domain-modeling 两个 skill。原型票调用 prototype，原型放在 `prototype/<name>` 分支。前端相关的先读 `frontend/AGENTS.md` 的「shadcn 纪律」，视觉以 `DESIGN.md` 为准。
- 这张地图只做计划，交付物是规格，不是实现。某一块的票全部关闭后，把结论写成那一块的 `spec.md` 交接。地图和设计文档都放在 `feat/affinity-and-gifts` 分支，不进 main。
- 定图时已定（2026-10-12 的 grilling）：
  - 目的地是三份独立规格，每份对应一个 `feat/` 分支；导航改版放进这张地图。
  - 好感度按「用户 × 角色」各一份，跨这位角色的所有对话和通话延续，开新对话不清零。
  - 起点就是原作里那样的信任（正常值）：往上更亲近，往下疏远，跌到底进冷却；自然恢复回到这个正常值。
  - 冷却期间可以送礼物，让好感度更快回升，但一件礼物不能直接清掉冷却。
  - 送礼时不专门生成回复，对话里留一条送礼记录，她下一次回复时知道你送了什么。
  - 文字对话里没有「挂断」：跌破冷却线的那个回合她照常回复，之后不能再发起回合和通话。「说了太多不该说的话」只在一次通话内计数，用来让她挂断。
  - 礼物这次只有抽奖一种来源。
- 定图时查到的现状：
  - 判断模型（Jev 或 Cloudflare Clef，部署者付费）每个回合都在回复之前调用一次，回答是非题；同类模型还有 choice 和 score 题型（见 `.scratch/cloudflare-judge/research.md`、`.scratch/spine-stand/research/jev-emotion.md`）。
  - 记忆提炼是回复之后在后台单独调用一次 LLM，用户自带 LLM 时用用户的。
  - 服务器已经能主动结束通话：先让排队的话说完，再发 `ended` 和结束原因（`call_outcome.py`）。
  - 数据都存在一个 SQLite 文件里，每张新表都要登记是不是用户数据（`database.py`）。还没有按「用户 × 角色」存的数据。
  - 没有定时任务框架。
  - 制作人的「今天」按 `producer.effective_timezone` 算。
  - 设置页现在是四个标签（档案、通话、自带密钥、登录与数据）。`components/ui/sidebar.tsx` 已装好，但还没有地方用。

## Decisions so far

<!-- 每张关闭的票一行：名字链接加一句要点 -->

- [调研：判断模型能不能判断好感度变化](issues/02-judge-affinity-research.md)：自带 LLM 可以伪造结果，只有判断模型不能被用户控制；`score` 题能给方向和档位、不能给精确幅度，增量和每回合上限放代码里；「不该说的话」单独出题；判断模型也会被话里的指令带偏；中日文效果要自建 eval；并进现有判断请求时费用和延迟都很小。
- [调研：礼物的素材和角色的喜好从哪来](issues/08-gift-sources-research.md)：原作没有送给偶像的礼物，可借十几种物品名，但道具图标没有可靠来源；规范只允许 Lucide 图标（礼物常用物件都有），插画或 emoji 要先改 `DESIGN.md`；28 位角色的喜好在角色资料里都有，「讨厌」多半抽象，适合不喜欢不扣分；同类游戏按固定档位加好感、喜好和生日用倍率。
- [拍板：好感度的数值模型](issues/01-affinity-numeric-model.md)：内部 0–100、用户只看到五档（冷淡、疏远、信任、亲近、亲密），正常值 50；跌到 0 进冷却，自然恢复（低于 50 时每天 +10）回到 10 解除，最长 24 小时；高于 50 不回落；每回合 +2/−10，对话每天最多 +6；礼物 +3 到 +10、冷却中每件最多 +3。
- [拍板：好感度变化由谁判断，哪些话加分、哪些话减分](issues/03-affinity-judgement.md)：部署者的判断模型在回复前判断，并进检索那次请求；5 级打分题对应 −5/−2/0/+1/+2，另有「不该说的话」（直接 −10，通话里计数）和「操纵」（加分归零）两道是非题；不看档位、不分角色；回复按变化前的档位说，但知道这句话让她开心或不舒服；没配判断模型时好感度和礼物整块关闭；费用由部署者付，不影响限额。
- [拍板：不同好感度下她怎么说话](issues/04-reply-style-by-affinity.md)：除信任外每档一段通用态度描述，所有角色共用，按她自己的性格表现；信任档不加任何话，提示词和现在一样；硬性规则和共同经历不变，不出现数值和档名；感受句主语写「制作人刚才说的话」，操纵命中时不加开心那句；跌进冷却或通话挂断前那一回合加收尾指示；情绪判断和语气提示不跟档位挂钩。
- [拍板：冷却和她自己挂断电话](issues/05-cooldown-and-hang-up.md)：冷却中不能发起回合和通话，可以看记录、开新对话、送礼。输入框换成精确的解除时刻加「送她一件礼物」的入口。被拒的请求在取用限额前挡下，返回 409 带 `cooldown_until`，不计入限额、不写运行记录。她在两种情况下说完这句再挂断：这一通里跌进冷却，或一通里第 2 次说了不该说的话。在别的对话进了冷却，这边的通话直接挂断。挂断不额外扣分，可以马上回拨。这通电话照常计入限额，结束原因记为「角色挂断」。对话里留一条「{角色名}挂断了电话」的对话事件，她之后也知道。送礼记录同属对话事件。
- [原型：页首的好感度标识和变化提示](issues/06-affinity-badge-and-cues.md)：页首「…」旁边是心形键加档名，五档心形各不相同（亲近是半心），用她的颜色，点开看说明，冷却中换成沙漏加解除时刻；每回合有变化都在她的回复后面插一行居中胶囊（同档只说开心或不高兴，跨档写新档名），翻历史还在，要跟回复一起存；通话里名字下面的状态行暂时换成同一句话；冷却版结束卡的主按钮是「送她一件礼物」。
- [拍板：好感度对用户有多透明，能不能重置，删除时怎么处理](issues/07-affinity-transparency.md)：原则不改，好感度是她的感受、不是她知道的事；用户自己不能重置或删除，删除记忆不影响它；唯一的重置办法是「重置卡」（仿 Codex 的重置卡）：一张把所有低于信任的角色拉回 50、解除冷却，不是礼物、不留对话事件，抽奖极低概率出或管理者一次发给所有现有用户，能攒不过期；后台看不到也改不了某位用户的好感度。
- [拍板：礼物目录](issues/09-gift-catalog.md)：19 件通用礼物，分吃的、饮品、花草、小物件四类，三档稀有度普通 +3、少见 +5、稀有 +7，她喜欢的再 +3（最高 +10），没有扣分的礼物；每位角色 1–3 件有出处的喜欢的礼物，至少一件不是稀有；每件一张生成的插画（进 git，`DESIGN.md` 加例外），画风交给礼物页原型；目录和喜好在仓库里维护，后台不能改，上线后不删，下架只是不再抽到。
- [拍板：抽奖规则](issues/10-draw-rules.md)：每天 1 次，最多攒 7 次，按 `effective_timezone` 的当地 0 点，读取时补发；每次必出，重置卡 1%、普通 69%、少见 25%、稀有 5%，档内平均，重复叠加，不设保底；管理者不能单独给某位用户发次数或礼物，也不做全员发次数；多种登录方式算同一位用户，没判断模型时不发次数。
- [拍板：送礼的流程和对话里的送礼记录](issues/11-giving-a-gift.md)：只在礼物页送，对话页的入口跳过去并预选她；一次一件，不设每日上限，到顶后照常能送、不提示；记录放进她最新那段对话（没有就新建），用户看到「你送给{角色名}一份{礼物名}」，模型额外知道是不是她喜欢的；后面跟变化胶囊，冷却中没解除不出、解除时写「愿意和你说话了」；对话事件拼成旁白接在下一条用户消息开头，没回应过的那回合带一句「回应一次」的指示；不进记忆；通话中从别处送不拦，下一个通话回合回应。
- [原型：应用导航外壳（电脑左侧导航栏、手机底部 dock）](issues/12-app-navigation-shell.md)：取 B：电脑 72px 带字导航栏（对话、礼物、设置，GitHub 在底），手机 dock 三项，对话页里也在、键盘弹起时藏；公告铃铛留在列表页首；「…」菜单和列表底部的免责声明拿掉（声明搬进设置「关于」）；不用 shadcn Sidebar；三页放进同一个路由组共用外壳；通话提到外壳里，切到礼物、设置不挂断。
- [原型：像手机设置那样的一级、二级设置页面](issues/13-settings-hierarchy.md)：取 A 加 B 的摘要：一级六项分四组（档案、记忆／通话、自带密钥／登录与数据／关于），每行下面一行当前值摘要；二级就是现在各标签的内容，没有三级，自带密钥仍是一页；公告不进设置；网址按路径（`/settings/profile`），旧的 `?tab=` 和 `/memories` 跳过去；记忆成了设置的二级页、留在外壳里。
- [原型：礼物页](issues/14-gifts-page.md)：取 B：一栏，上面抽奖台（7 个小点、抽一次、全部抽完），有重置卡时一条重置卡条，下面按类别筛选的插画网格；点一件拉出头像网格选人，送出后底部提示加「去对话」，不自动跳转；抽奖弹窗开盒，稀有、重置卡样子不同；不透露她喜欢什么；画风取柔和平涂；重置卡改成只拉回低于信任这一档的角色。
- [原型：对话记录里的对话事件（她挂断电话、送礼记录）](issues/15-conversation-events-prototype.md)：取 B 分隔线：整行细线，中间是 `Gift` 或 `PhoneOff` 图标、一句话和时间，两种事件同一个样子，宽窄屏一样，不用她的颜色；变化胶囊放在线下面；事件把前后气泡分成两组；她挂断时通话层开着也立刻写进记录；列表「最后一句」是图标加原文，时间写事件的时间，也按它排序。
- [拍板：应用导航规格里剩下的细节](issues/16-app-navigation-spec-details.md)：通话条在非她对话页的外壳页面最顶上横跨整块（手机在页首之上）；「礼物」一直留在导航里；在外壳里换页不挂断，换一位角色先问再挂断；去后台、关于、隐私政策、使用条款走同一个确认框「离开这里，正在进行的通话就会挂断。」；档案草稿提到设置 layout、未保存时一级摘要写「有修改未保存」；一个 `feat/app-navigation` 分支分三张票（通话进外壳加 ADR 和术语改写 → 导航栏和 dock → 设置分级），`DESIGN.md` 跟着各自的票改。
- [拍板：好感度和礼物在后台的部分](issues/17-affinity-admin.md)：数值和抽奖概率只在代码里；加一个单独关掉好感度和礼物的开关（`.env` 和后台都能设，默认开），关掉时同没配判断模型，数据留着、再开接着用；配置页新卡「好感度和礼物」放开关和「给所有现有用户各发一张重置卡」（可再发、显示上次发放、不自动配公告）；看板加「好感度」一节：冷却次数和人数、两道是非题命中、5 级打分分布，再加按减分占比排的按角色表；后台仍看不到个人。
- [拍板：隐私政策、使用条款、落地页、README 要跟着改哪些](issues/18-public-docs.md)：隐私政策加好感度、对话事件、礼物、运行记录里的判断结果，判断模型单独一条（点名 Jev、Cloudflare，补上漏写的情绪判断）；两份文件加「最后更新」，不强制重新同意、上线发公告；条款加「玩法」一条（可能误判、冷却不是封禁、物品无现金价值）；落地页只在「使用须知」加「你的话语会影响她们对你的态度，切勿过于冒犯……」；README 三语加功能条、截图最后统一重拍并加礼物页；文字跟着好感度、礼物各自的分支走。
- [拍板：三份规格的实现顺序和分支衔接](issues/19-implementation-order.md)：导航 → 好感度 → 礼物，各自从 main 开 `feat/` 分支、合完再开下一个；导航先不带「礼物」项，好感度先藏起所有送礼入口；对话事件随好感度做，重置卡整个归礼物；规格目录在开工时从计划分支取出，词汇表跟好感度走；好感度开关在好感度分支默认关、礼物分支改成默认开，礼物上线后发公告。

## Out of scope

- 礼物的其他来源：签到、成就、充值等。这次只做抽奖（定图时决定）。
- 在对话列表里展示好感度：用户明确不要，对界面来说太复杂。
- 角色生日当天送礼的加成：要先定她的生日按哪个时区算、她知不知道是自己生日，更适合单独做成一个功能（[拍板：礼物目录](issues/09-gift-catalog.md)）。
- 落地页新加一幕介绍好感度和礼物：要另做视觉、动效和文案，和落地页那几幕的工作量一样大，这次只在「使用须知」加一行（[拍板：隐私政策、使用条款、落地页、README 要跟着改哪些](issues/18-public-docs.md)）。
