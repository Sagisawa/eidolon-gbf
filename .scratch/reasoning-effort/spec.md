# 思考强度：通话开口快一些，接 Gemini、Claude 这类会思考的模型时「回顾剧情」不再失败

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，本轮新增「思考强度」。遵守 ADR-0017（自带密钥只存在浏览器里）和本轮新增的 ADR-0019（思考强度只按协议原样传，不维护各家模型的兼容表）。

调研见同目录 `research.md`（各协议、各家服务、各网关怎么表达思考强度，思考内容要不要回传）和 `research-auto-effort.md`（magpie、CLIProxyAPI 的「自动填写推理强度」是怎么做的）。2026-10-14 实测：线上对话模型 DeepSeek（`deepseek-flash`）默认开着思考，工具调用那一轮不回传思考内容也能成功；`gemini-3.1-flash-lite` 走 chat-completions 时，工具调用的第二轮返回 400「Function call is missing a thought_signature」。

## Problem Statement

- **通话开口慢，而且没法调。** 现在的模型大多默认开着思考，档位还不低：线上的 DeepSeek 默认就在思考，GPT-5.5、Claude Opus 5.5 默认 medium，Kimi K3、GLM 默认 max。通话里她每句话都要先想一阵才开口，部署者和自带 LLM 的用户都没有办法把它调低或关掉。
- **接 Gemini 3 以上，「回顾剧情」必定失败。** 三个适配器都把模型的思考内容扔掉了。Gemini 3 以上走 chat-completions 时，工具调用之后的那次请求必须带回思考签名，否则返回 400。Claude 开着思考时也要求把 thinking 块原样带回。保存配置时的检查只发一轮请求，发现不了，要等有用户触发回顾剧情才失败。
- **最后一轮把工具清空，会让 Claude 5.5 的思考内容失效。** 工具调用之后那次请求把工具列表换成空的。Claude 5.5 系列只要工具列表一变，之前的 thinking 块就失效，新账号会直接返回 400。
- **各家私有的开关没处填。** Qwen 的 `enable_thinking`、GLM 和 Kimi 的 `thinking`、OpenRouter 的 `reasoning` 对象，这些参数现在没有任何地方能配。
- **不知道思考拖慢了多少。** 运行记录只记 LLM 整段输出的耗时，看不到首字花了多久，也看不到用的是哪一档，没法用数据决定通话该用哪一档。

## Solution

- **思考强度。** 每处能配模型的地方都加思考强度，共八档：不设置 / 关闭（none）/ 极低（minimal）/ 低（low）/ 中（medium）/ 高（high）/ 极高（xhigh）/ 最高（max）。「不设置」什么参数都不发，交给模型自己的默认；其他档位按协议原样发出（ADR-0019）。Anthropic 协议没有「极低」，界面上不提供。
- **在哪里设。**
  - 部署者的对话模型分「文字」和「通话」两项，后台模型（后台叫「记忆模型」）一项。
  - 自带 LLM 的用户也分「文字」和「通话」两项，提炼记忆跟「文字」那一项走。
- **额外请求参数（JSON）。** 部署者的两个模型和自带 LLM 都可以填一段 JSON，深合并进请求体，最后合并，所以能覆盖我们生成的思考参数。会弄坏请求的字段一律拒绝。界面提示：用 JSON 控制思考时，强度选「不设置」。
- **回合内回传思考内容。** 工具调用那一轮，把服务发来的思考内容原样带回下一次请求：chat-completions 的 `reasoning_content` 和 Gemini 的思考签名、Anthropic 的 thinking 块（含签名）、Responses 加密的推理内容。只带回服务发来的东西，不补也不改。回合结束后，对话历史里仍然只存文字。
- **最后一轮保留工具，但不许再调用。** 工具调用之后那次请求带着同样的工具列表，同时告诉模型这一轮不许调用工具。
- **保存时的检查把工具调用走完两轮。** 每一档用到的强度各检查一次，文字和通话设成同一档时只检查一次。模型第一轮没有调用工具，就只检查到这一步。被拒时报错先说是哪一项的哪一档，比如「通话的思考强度『关闭』被服务拒绝：」，后面接服务方的原文；截断时保证原文开头完整。
- **首字耗时。** 运行记录给每次 LLM 调用记下首字耗时和用的哪一档。看板的健康表显示 LLM 的首字耗时 p50 / p95，并按思考强度分行。
- **档位提示。** 在现有的 models.dev 目录里查得到这个模型时，后台和设置页在档位旁边标出它支持哪些档、能不能关闭。只标注、不隐藏，不拦保存，也不改变发出去的参数（ADR-0019）；查不到就照常列出全部档位。不显示默认档位。

## User Stories

1. 作为部署者，我想把通话的思考强度设成「关闭」或「低」，这样她在通话里开口快一些。
2. 作为部署者，我想让文字对话保留模型默认的思考，同时只调低通话那一项，这样文字回复的质量不受通话设置影响。
3. 作为部署者，我想给后台模型单独设一档强度，这样提炼记忆、起草人设可以多想一会儿。
4. 作为部署者，我什么都不设时，希望请求和现在一模一样，这样升级以后行为不变。
5. 作为部署者，我选了「极低」「极高」「最高」这些档时，希望它们原样发给服务，不被我们改成别的档。
6. 作为部署者，我选的档位服务不支持时，希望保存时就看到是哪一项、哪一档被拒，以及服务方的原话，这样我知道该换哪一档。
7. 作为部署者，我选 Anthropic 协议时，希望档位里没有它根本不支持的「极低」。
8. 作为部署者，我在 `.env` 里也能设这几项强度和额外请求参数，这样不进后台也能部署。
9. 作为部署者，后台改了强度，希望从下一个回合起生效，不用重启。
10. 作为部署者，我想给模型填 Qwen 的 `enable_thinking`、GLM 的 `thinking` 这类私有参数，这样我们没做成档位的开关也能用。
11. 作为部署者，我不小心在额外请求参数里写了 `model`、`messages` 这类字段时，希望保存时就被拒并告诉我原因，而不是把请求弄坏。
12. 作为部署者，我用额外请求参数控制思考时，希望界面提醒我把强度选成「不设置」，免得两套参数冲突。
13. 作为部署者，我把对话模型换成 Gemini 3 以上时，希望「回顾剧情」照常可用。
14. 作为部署者，我接的是默认开着思考的 Claude 5.5 时，希望「回顾剧情」照常可用。
15. 作为部署者，我接的是 OpenAI 推理模型、走 Responses 协议时，希望工具调用之后模型还记得自己刚才想了什么。
16. 作为部署者，我保存一个工具调用第二轮会失败的配置时，希望当场被拦下，而不是等用户的回合失败。
17. 作为部署者，我想在看板上看到对话模型的首字耗时，并按思考强度分开，这样能用数据决定通话用哪一档。
18. 作为部署者，我选模型时，希望看到这个模型在公共目录里写着支持哪些档、能不能关闭，作为参考。
19. 作为部署者，目录里查不到我用的模型（网关改了名、自建服务）时，希望档位照常全部可选，不被拦着。
20. 作为部署者，目录说某一档不支持、但其实能用时，希望我仍然能选它、保存它。
21. 作为自带 LLM 的用户，我想把自己的 LLM 在通话里的思考强度调低，这样通话开口快一些。
22. 作为自带 LLM 的用户，我想给文字和通话分别设一档。
23. 作为自带 LLM 的用户，我想填额外请求参数，用我那家服务的私有开关。
24. 作为自带 LLM 的用户，我填的强度和额外参数和密钥一样只存在我的浏览器里。
25. 作为自带 LLM 的用户，我检查自己的密钥时，希望强度和额外参数也一起被检查，不支持就当场告诉我是哪一项。
26. 作为自带 LLM 的用户，我在额外参数里写了不允许的字段时，希望检查时就被拒，并且就算绕过界面发上来，服务器也不会照发。
27. 作为自带 LLM 的用户，我从旧版本升级上来、浏览器里存的设置没有这几项时，希望一切照旧，等于「不设置」。
28. 作为自带 LLM 的用户，我在设置页选档位时，也能看到目录里的档位提示。
29. 作为用户，我在通话里和她聊天时，希望她开口不再因为默认思考而拖很久。
30. 作为用户，我问起过去的剧情时，不论部署者接的是哪家模型，希望她都能回想起来，而不是这个回合直接失败。
31. 作为管理者，我想在看板上看到每档强度的首字耗时 p50 / p95，这样调档以后能看到效果。

## Implementation Decisions

**模型设置**

- 一个模型的设置（协议、地址、密钥、模型名、输出上限）加两项：一项思考强度（八档之一，或不设置）、一项额外请求参数（一个 JSON 对象，或不设置）。适配器只认这一份设置，不知道「文字」「通话」。
- 部署者的对话模型存两项强度（文字、通话），由它派生出两份设置：文字回合用文字那份，通话里的回合用通话那份。两份共用一个 HTTP 客户端。后台模型（记忆模型）只有一项。
- `.env` 按槽位各加：`{SLOT}_LLM_REASONING_EFFORT`、`{SLOT}_LLM_EXTRA_BODY`，对话模型另加 `CHAT_LLM_CALL_REASONING_EFFORT`。不从对话模型回退到后台模型，和 `MAX_TOKENS` 一样各管各的。
- 实时配置照现有字段的存法，一个字段一行；旧数据没有这几行就取 `.env` 的值。

**按协议发什么（ADR-0019）**

| 档位 | chat-completions | Responses | Anthropic |
|---|---|---|---|
| 不设置 | 不发 | 不发 | 不发 |
| none | `reasoning_effort:"none"` | `reasoning:{effort:"none"}` | `thinking:{type:"disabled"}` |
| minimal | `reasoning_effort:"minimal"` | `reasoning:{effort:"minimal"}` | 不提供 |
| low … max | `reasoning_effort:<档>` | `reasoning:{effort:<档>}`，加 `include:["reasoning.encrypted_content"]` | `thinking:{type:"adaptive", display:"omitted"}` 加 `output_config:{effort:<档>}` |

- Responses 设了 minimal 时同样带上 `include`；none 和不设置时不带。
- Anthropic 不按模型名分写法。Claude 4.5 及更早的模型选了强度会在检查时报错（ADR-0019 Consequences）。
- 不改输出上限。选「高」及以上时，界面提示把输出上限留空或设宽裕一些，因为思考也算在上限里。

**额外请求参数**

- 必须是 JSON 对象。深合并进请求体，最后合并：对象和对象递归合并，其他类型直接覆盖。
- 拒绝这些顶层键：`model`、`stream`、`stream_options`、`messages`、`input`、`instructions`、`system`、`tools`、`tool_choice`。思考相关的键（`reasoning_effort`、`reasoning`、`thinking`、`output_config`、`include` 等）允许。
- 校验写一份，后台保存、自带密钥检查、自带 LLM 每次请求都用它。自带 LLM 的那份每次请求在后端再校验一次，因为它不经过后台保存。

**回合内回传思考内容**

- 模型流式输出的条目，除了文本和工具调用，多一种「思考内容」：对引擎不透明，只有产生它的适配器认识。引擎把一次请求收到的思考内容挂在那条助手消息上，下一次请求由适配器原样写回。
- 只在一个回合之内保留，不进对话历史、不落库。同一个回合用的是同一个模型，不需要处理跨模型转换。
- chat-completions：保留 `delta.reasoning_content` 拼成的全文，写回助手消息的 `reasoning_content`；保留每个工具调用上的 `extra_content`（Gemini 的 `google.thought_signature`），写回对应的工具调用。服务没发的字段不写。
- Anthropic：保留 thinking 和 redacted_thinking 块（含 signature），按原来的顺序放在助手消息的 text 和 tool_use 前面写回。
- Responses：保留 reasoning item（含 `encrypted_content`），按原来的顺序放在 function_call 前面写回。
- 计费、计量层原样透传这种条目。测试用的假模型要允许它。

**最后一轮保留工具**

- 模型接口的流式请求多一个「这一轮不许调用工具」的选项。引擎在最后一轮带着同样的工具列表，并打开这个选项。
- chat-completions 和 Responses 发 `tool_choice:"none"`，Anthropic 发 `tool_choice:{type:"none"}`。
- 不提供工具的请求（提炼记忆、起草人设等）不受影响。

**保存时的检查**

- 检查改成走完工具调用的两轮：第一轮提供 ping 工具；模型调用了，就把一个固定的工具结果带回去，带着同样的工具、不许再调用，再请求一次。第一轮没调用工具，就到此为止，不算失败。区分「不支持工具」和其他失败的现有逻辑保留。
- 部署者的对话模型：文字和通话两档各检查一次；两档相同只检查一次。被拒时报错前缀写明是哪一项、哪一档。
- 自带 LLM 的检查接口同样带上两档强度和额外参数。

**用户自带的 LLM**

- 浏览器本地存的自带 LLM 加三项：文字强度、通话强度、额外请求参数。解析本地存储时，没有这几项就当作不设置。
- 文字回合和通话的请求照现在的方式带上这些项。服务器为文字回合用文字强度；为通话用通话强度；提炼记忆一律用文字强度，所以通话时对话和提炼记忆是两份设置。
- 服务器仍然不保存这些项（ADR-0017）。

**运行记录与看板**

- 服务调用表加两列，都可以为空：首字耗时（毫秒）、思考强度。首字耗时只对 LLM 记，从发出请求到收到第一条文本或工具调用；不设置强度时思考强度列为空。照现有的加列方式在启动时补列，旧记录为空。
- 看板健康表里，LLM 服务除了现有的耗时，再显示首字耗时 p50 / p95，并按思考强度分行（「不设置」单独一行）。

**档位提示**

- 价格目录从 models.dev 抓数据时，一并解析每个模型的推理选项：支持哪些档、能否关闭。用现有的按地址和模型名匹配的逻辑查。
- 提供一个查询接口：给出协议、地址和模型名，返回查到的档位信息，查不到返回空。部署者和登录用户都能用；只返回公开目录里的信息，不需要密钥。
- 后台和设置页在每个档位旁边标注「目录里写着不支持」，并提示能不能关闭。不隐藏、不禁用、不拦保存。

## Testing Decisions

- 好的测试只看外部行为：给一份设置，断言发出去的请求体；给一段录好的模型流式响应，断言下一次请求带回了什么；给一次后台保存，断言保存成功还是被拒、报错写了什么。不断言适配器内部怎么存思考内容。
- **适配器**：从「打开模型」这一层进去，用 `httpx.MockTransport` 加录好的 SSE，断言请求体。每种协议覆盖：各档位的写法、不设置时请求不变、额外参数深合并和覆盖、思考内容回传、最后一轮不许调用工具。先例：`test_llm_protocols.py`（录制文件在 `tests/recordings/`）、`test_openai_compat.py`。思考内容的录制可以手写，形状以 `research.md` 里的官方文档为准。
- **检查**：走两轮的检查，用假服务断言第二轮的请求，以及第一轮不调用工具时不发第二轮。先例：`test_llm_config.py` 里的 `check_chat_llm` 测试。
- **引擎**：用 `FakeLLM` 断言最后一轮带着工具且不许调用，并且第一轮吐出的思考内容出现在第二轮收到的助手消息上。先例：`test_recall_story.py`。
- **后台配置**：通过 `admin_client` 发 PUT，断言字段保存、`.env` 回退、额外参数被拒时返回 422 和原因、检查失败时报错前缀。先例：`test_live_config.py`、`test_live_config_services.py`。
- **自带 LLM**：端到端测文字回合和通话分别用了哪一档、提炼记忆用文字档、非法额外参数被拒。先例：`test_own_llm.py`、`test_own_keys.py`。
- **运行记录**：真的 `ActivityLog` 写进临时库，断言首字耗时和强度两列，以及看板的分行；旧表补列有迁移测试。先例：`test_activity_records.py`、`test_call_records.py` 里的迁移测试。
- **前端**：只测纯函数：后台表单的行、表单、改动校验（`adminConfig.test.ts`），本地存储解析和请求体（`localOwnKeys.test.ts`），看板数据（`dashboard.test.ts`）。
- 每张票的验收里，有真实服务可用的，用 `.env` 里的 DeepSeek 和 Gemini 密钥实际调一次。

## Out of Scope

- 最大上下文（按 token 截断历史）：继续按轮数截。
- 在请求时自动补默认档或换成支持的档（ADR-0019）。
- 按服务地址或模型名维护兼容表，包括 Claude 4.5 及更早模型的预算写法。
- 思考内容跨回合保存、换模型时转换、在界面上展示思考过程。
- 自带 LLM 的输出上限。
- temperature、top_p 等采样参数。
- 判断模型：它走专用接口，不在这几种协议里。
- 解析服务方报错、自动提取「支持哪些档」。

## Further Notes

- 「未确认」的事实很多（见两份调研末尾），多半是「给某个模型发了它不认识的参数会怎样」。这正是检查要在保存时带上每一档的原因；实现时遇到能实测的就实测，结论补进对应票的 Comments。
- 通话该默认用哪一档，等票 06 上线、看板有了按档位分行的首字耗时以后再定，本轮不改默认值（仍是不设置）。
- 线上的 DeepSeek 默认开着思考。票 04 上线以后，部署者可以先试着把通话设成「关闭」，对比首字耗时。
