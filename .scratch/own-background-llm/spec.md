# 自带后台模型：自带 LLM 的用户可以另配一个提炼记忆用的模型

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准。遵守 ADR-0017（自带密钥只存在浏览器里）和 ADR-0019（思考强度只按协议原样传）。排在思考强度（`.scratch/reasoning-effort/`）合并之后做：它和那边的票 05 改同一批地方（浏览器本地存储、设置页、自带 LLM 的检查接口、回合和通话的请求体）。

## Problem Statement

部署者可以把扮演角色的 LLM 和提炼记忆的 LLM（后台模型）分开配：对话用好的模型，提炼记忆用便宜的。自带 LLM 的用户只能填一个 LLM，扮演角色和提炼记忆都用它（`own_keys.LLMService._llms`）。提炼记忆每个回合都跑，用户用贵的模型聊天时，这部分花费也按贵的模型算，而且没法给它单独调思考强度。

## Solution

自带 LLM 的用户可以在设置页另填一个「提炼记忆的 LLM」，写法和自带 LLM 一样：接口类型、地址、模型名、key，加上它自己的一档思考强度和额外请求参数。填了，提炼记忆就用它；不填，照旧用自带的那个 LLM（提炼记忆跟「文字」那一档强度走）。和其他自带密钥一样，只存在浏览器里，随每个回合和通话发给服务器，服务器不保存。

## User Stories

1. 作为自带 LLM 的用户，我想让提炼记忆用一个便宜的模型，对话照旧用我选的好模型，这样花费低一些。
2. 作为自带 LLM 的用户，我想给提炼记忆的模型单独设思考强度和额外请求参数，这样它不受我给对话设的档位影响。
3. 作为自带 LLM 的用户，我不填提炼记忆的模型时，希望一切照旧，提炼记忆用我自带的那个 LLM。
4. 作为自带 LLM 的用户，我保存提炼记忆的模型前，希望它和自带 LLM 一样先检查一遍，不支持就当场告诉我原因。
5. 作为自带 LLM 的用户，我删掉自带 LLM 时，希望提炼记忆的模型一起删掉，不留下一个用不上的 key。
6. 作为部署者，用户只自带提炼记忆的模型、不自带扮演角色的 LLM 的情况不存在，限额和免限额密钥的规则不用变。

## Implementation Decisions

- **只能附加在自带 LLM 上。** 没有自带 LLM 时，设置页不显示这一块；请求里只带了提炼记忆的模型、没带自带 LLM，服务器拒绝这个回合或这通电话。删掉自带 LLM 时一并删掉它。
- **限额不变。** 回合计不计入限额，仍然只看扮演角色的 LLM 是不是自带的；免限额密钥里的「LLM」也只看它。
- **自己的强度和额外参数。** 它有一项思考强度（八档之一或不设置，Anthropic 不列「极低」）和一段额外请求参数，校验用思考强度那边的同一份（`config.checked_extra_body`、`config.effort_problem`），服务器每次请求再校验一次。填了它，提炼记忆就用它自己的这两项，不再跟「文字」那一档走；没填，照旧跟「文字」那一档。
- **检查。** 和自带 LLM 走同一个检查（`check_chat_llm`，带着它的强度走完两轮），和部署者的记忆模型一样要求支持流式输出和工具调用。报错前缀写明是「提炼记忆的 LLM」。
- **浏览器本地存储。** `LocalOwnKeys` 多一项，形状和自带 LLM 一样；解析时这一项坏了只丢这一项，没有这一项（旧数据）等于没填。请求里的 `own_keys` 跟着多一项。
- **运行记录。** 提炼记忆的调用照旧记成 `memory_llm`、`own_key`，看板只显示「自带」，不显示它的地址和模型。
- **服务器不保存（ADR-0017）。**

## Testing Decisions

- 前端只测纯函数：`localOwnKeys` 解析（带这一项、不带、这一项坏了）、删掉自带 LLM 时一起删、请求体带上这一项。
- 端到端（`test_own_llm.py` 那种）：带了提炼记忆的模型时，提炼记忆的请求发到它、带它自己的强度和额外参数，对话的请求仍然发到自带 LLM；没带时和现在一样；只带它不带自带 LLM 时被拒；非法额外参数被拒。通话里同样。
- 检查接口：提炼记忆的模型检查失败时报错前缀正确。
- 实测：本地构建版的设置页，用 `.env` 里的 DeepSeek key 当自带 LLM，再用另一个模型（或同一个 key 换个模型名）当提炼记忆的 LLM，检查通过、保存；发一个回合，看运行记录里两种调用都记成自带。

## Out of Scope

- 只自带提炼记忆的模型、对话用部署者的。
- 自带 LLM 的用户给其他后台用途（起草人设等）配模型：那些只在部署者的命令行里用。
- 自带判断模型、向量化、重排。
