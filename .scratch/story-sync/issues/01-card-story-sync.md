# 01: 卡牌剧情同步（曳光弹）

**What to build:** 管理员运行 `eidolon story sync` 后，先导入 SCTranslationData 的汉化版，再从 ShinyColorsDB 镜像把剧情库里还缺的 P 卡、S 卡剧情作为原文剧情导入，带上真正的卡名和剧情标题。原文剧情遵循与现有导入相同的正式经历规则；已有汉化版的剧情不会被覆盖，之后到位的汉化版会取代原文剧情，而且仍在同一张卡下。没有变化的卡不重新下载，也不重新向量化。镜像连不上时，汉化版照常导入。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 新增 `eidolon story sync`，一次完成「导入汉化版 → 拉取并导入原文剧情」，结束时打印新增原文剧情数、保留的汉化版数、跳过的失败结局数和新向量化段数
- [ ] 通过镜像 API 列出全部卡牌，读取每张卡的剧本编号、卡名和剧情标题，从镜像下载剧本 JSON 到本地缓存
- [ ] 原文剧情的出处是卡名（与 SCTranslationData 的目录名同格式），标题是 API 给出的剧情标题
- [ ] 剧情库已有汉化版的剧情不被覆盖；之后导入的汉化版取代原文剧情，剧情目录中仍在同一张卡下
- [ ] 下载时记下 ETag，下次用条件请求；未变化的文件不重新下载，第二次同步零下载、零向量化
- [ ] 不存在的编号（404）不算错误；请求逐个发出，间隔约一秒
- [ ] 镜像或 API 连不上时报告错误、跳过原文剧情这一步，汉化版照常导入，退出码能区分部分失败
- [ ] 中断后重跑能接着做：已下载的剧本不重复下载，已保存的剧情不重复向量化
- [ ] 缓存目录不进入仓库（沿用 ADR-0003）
- [ ] 测试（切入点 B）：用 `httpx.MockTransport` 扮演 API 和镜像、用 `FakeEmbedder`，覆盖上面的行为，并通过 `StoryCorpus` 的查询检查结果
- [ ] 对真实镜像做一次小规模同步（例如一位偶像的几张卡），确认真实剧本 JSON 能正确导入，并在 Comments 中记录结果（顺带关闭 MVP 09 留下的「没有用真实 JSON 验证过」）
