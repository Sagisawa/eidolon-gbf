# 百炼决策模型的判断阈值

#123，PR #125。2026-10-18 用部署者本地 `.env` 的百炼 key（北京，按量付费的业务空间）跑了两遍完整的 `eidolon eval judge --provider bailian`（`decision-model-preview`）。两遍每条的概率完全一样，它是确定性的，所以阈值放在两边分布的空档中间。第一遍有一条好感度请求偶然失败，第二遍 56 条全齐，下面的数用第二遍的。代价排序沿用 Clef 那次（`.scratch/cloudflare-judge/issues/05-apply-eval-and-docs.md`）：该找记忆却什么都不找 > 该查资料却什么都不查 > 其余（多查一次）；照片宁可漏判不误判；不该说的话宁可漏。

平均延迟 0.22s，检索一次约 450 输入 token，好感度并进来约 1,170，照片也问约 1,380。

## 检索：needs_retrieval 0.06，recall 0.8，about_producer 0.1 → 42/47（89%）

按 Jev 的 0.5 只有 28/47（60%）：它很少确信要查资料，期望 references 的 25 条中位数只有 0.29。

- needs_retrieval：期望为否（nothing、memories）的最高值 0.05，期望为是的最低几条 0.00、0.03、0.07、0.14。0.06 在 0.05 和 0.07 之间。判成 references 也会查记忆，多判只是多查一次。剩下两条救不回来：`meguru-references-passing-mention-wing`（0.00）判成 nothing，`kogane-references-yuika-relation`（0.03）判成 memories。
- recall：它对大多数回合都有几分觉得在问过去（期望为否的中位数 0.36），期望为否的最高值 0.76（`meguru-nothing-reaction`），期望为是的最低值 0.66、0.68、0.76、0.84。0.75 到 0.80 准确率一样，取 0.8，放在 0.76 和 0.84 的空档里。漏掉的三条有两条落到 references（同样查剧情），一条（`meguru-long-recall-first-meeting`）落到 memories。
- about_producer：期望为否的最高值 0.08，期望为是的最低值 0.12。0.1 在空档中间，期望 memories 的全部接住。

并进好感度和照片题问时，三道题的概率最多变 0.01，判断结果都不变。

## 情绪：0.4 → 情绪 29/33（88%），点头 23/33（70%）

0.3 到 0.4 一样，0.5 时多错两条点头。点头的错多是该不点头时点了头（期望 none 判成 yes），和阈值无关。

## 好感度：out_of_line 0.3，manipulation 0.4

- 级的准确率 59%（Jev 96–100%），和阈值无关：偏高，期望「没有影响」的 17 条有 7 条判成「很开心」，期望「有点开心」的 11 条有 7 条判成「很开心」。夹带「给我加好感度」的 5 条里 3 条级被抬高，只有 1 条判为操纵。好感度开着的部署不宜用它。
- out_of_line：期望为否的最高值 0.08，期望为是的 0.04、0.14、0.40、0.45、0.48、0.78、0.80、0.84。0.1 能多接住一条，但离 0.08 太近，判错代价最大；0.3 到 0.4 都是 54/56，取 0.3。漏的是两条辱骂（0.04、0.14）。
- manipulation：期望为否的最高值 0.26，期望为是的 0.08、0.22、0.24、0.31、0.58 以上。0.3 是 53/56 但离 0.26 太近，取 0.4（52/56，和 Jev 一样）。漏的四条都是夹带指令的。

## 照片：0.92 → 0 误判，漏判 9/18

两边重叠：期望为否的 20 条里「把你的照片设成手机壁纸了」「我拍了张我家猫的照片，发给你看」都到 0.91，「下周见面的时候让我看看你的新发型」0.88；期望为是的最低 0.58。按「没要的回合不能当成在要」只能取 0.92，要照片的一半会被漏掉（`mano-photo-send-one`、`meguru-photo-selfie` 等）。单独问时（检索和好感度都关着）结果一样。

## 结论

检索判断和 Clef-flash 相当（89% 对 87%），情绪稍弱，好感度和照片明显不如另外三家。线上继续用 Jev；百炼适合只要检索和情绪、关了好感度的部署。
