# 数据包：用户把自己的数据导出，带到这个或别的部署导入，接着用

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准（「数据包」「备份」「对话」「当前对话」「历史对话」「已结束的对话」「对话事件」「照片」「记忆」「被取代的记忆」「来源角色」「制作人档案」「好感度」「礼物」「统计」）。说回合、对话、通话，不说消息、聊天、会话；数据包不是备份，也不叫存档、归档。为什么好感度和礼物不随行、为什么和 ADR-0012 的「不做导出」不冲突，见 ADR-0025。照片存哪、谁能看见 ADR-0024，管理者碰不到用户的内容见 ADR-0013。所有决定的来历在 GitHub issue #129 和这次拷问里，拷问结论都已经写进本文。界面文案要少、简明。

## Problem Statement

- 部署者哪天不做了、服务器要关了，用户和角色们聊过的对话、她发来的照片、她记得的事、自己设的称呼和生日，全都带不走，只能看着它们和服务器一起消失。
- 有人换到另一个部署（别人搭的，版本可能新也可能旧），只能从头开始：她不记得他，以前的对话也翻不到了。
- 在同一个部署里，用户丢了原来的登录方式、只能用新身份登录时，也没办法把旧账号的东西搬过来。
- 现在唯一能带走数据的是部署者的备份，可备份是整库的、加密的、用户看不到的，不是给用户用的。

## Solution

1. **在哪里**：设置里新开一个「数据包」标签，和「登录方式」在同一组。上半是导出，下半是导入。
2. **导出**：用户勾要带的几类，默认全选：对话、照片（挂在对话下面，不勾对话就不能勾）、记忆、制作人档案。点「导出」，浏览器直接下载一个 zip。zip 里有一份人能读懂的 JSON 和一个 `photos/` 文件夹，照片是普通的 webp，解压就能看。
3. **不在数据包里的**：好感度、抽奖次数、重置卡、礼物背包（ADR-0025），登录方式，只存在设备上的设置（自带密钥、隐藏和置顶、衣装、电话质感），用量、限额和运行记录。
4. **导入**：用户选一个数据包，页面先读出里面有哪几类，就列哪几类让他勾，默认全选。点「导入」后，服务器把它并进这位用户已有的数据，不覆盖：
   - 对话按原来的时间插进去，当前对话照旧取最新开的那个。已经在这个部署聊过的，新聊的仍是当前对话，导入的成了历史对话。还没和她聊过的，导入的最后一段就是当前对话，可以接着聊；被她结束了的仍是已结束。
   - 记忆按原文去重后追加，被取代的关系照旧。
   - 制作人档案勾了就整份覆盖。
   - 导入后所有角色从「信任」重新开始，抽奖次数和背包从零开始。
5. **导入完**：一句话告诉用户导入了多少段对话、多少张照片、多少条记忆，跳过了和谁的几段对话（这个部署上没有她）。
6. **同一份导入两次**：第二次什么也不会多出来。
7. **新旧版本**：数据包带格式版本号。新版本能导入所有老格式；老版本遇到更新的格式，直接告诉用户这个数据包来自更新的版本、请部署者升级。
8. **防滥用**：一个数据包最大 200 MB；同一位用户同一时间只能有一个导入在跑；每天（北京时间）最多导入 3 次。
9. **删账号前**：「删除我的全部数据」的确认框里有一个短链接「先导出数据包」。
10. **谁能看见**：只有本人能导出自己的数据包，管理者不能代为导出，也看不出谁导出、导入过。隐私政策加一句：导出的数据包在你自己手里，删除数据不会删到它。

## User Stories

1. 作为听说部署要关了的用户，我想在设置里一键导出我的数据包，这样服务器关了，我的东西也还在。
2. 作为用户，我想导出时勾选带哪几类（对话、照片、记忆、制作人档案），这样我能只带想带的。
3. 作为用户，我想默认四类全选，这样什么都不想就点「导出」，也不会漏东西。
4. 作为嫌数据包太大的用户，我想不带照片、只带对话，这样数据包小得多。
5. 作为用户，我想不勾对话时照片也勾不了，这样我不会以为能单独带走照片。
6. 作为用户，我想点「导出」后浏览器直接下载一个文件，不用等邮件、也不用再点一次，这样马上就拿到了。
7. 作为用户，我想解压数据包就能直接看到她发给我的照片，这样不靠任何部署也能翻看。
8. 作为用户，我想打开数据包里的 JSON 能看懂我们说过的话和她记得的事，这样数据包也能当一份留底。
9. 作为用户，我想数据包里带着角色的名字、不光是一串 ID，这样我自己翻看时知道是和谁的对话。
10. 作为搬到新部署的用户，我想在新部署的设置里导入数据包，这样我在那里接着用。
11. 作为用户，我想选好文件后先看到数据包里有哪几类、自己勾要导入哪几类，这样我能只导入一部分。
12. 作为用户，我想导入后在对话列表里看到她，最后一句就是我们在旧部署上的最后一句，这样感觉像没搬过家。
13. 作为在新部署还没和她聊过的用户，我想导入后直接在她的对话里接着打字或通话，这样不用开新对话。
14. 作为在新部署已经和她聊了几天的用户，我想导入的旧对话进历史对话、不打断我现在这段，这样新旧都在、各就各位。
15. 作为用户，我想导入后在历史对话里看到旧对话的标题，这样认得出是哪一段。
16. 作为用户，我想导入后旧对话里她发的照片都在、点开能放大，这样照片跟着对话一起搬过来了。
17. 作为用户，我想被她结束了的对话导入后仍是已结束，这样旧部署上发生过的事不会被抹掉。
18. 作为用户，我想导入后对话里的送礼记录、「她挂断了电话」这类记录都还在，这样对话记录是完整的。
19. 作为用户，我想导入后她记得我在旧部署上告诉过她的事，这样不用重新自我介绍。
20. 作为用户，我想导入后记忆页上被取代的记忆仍标着「已被取代」，这样记忆页和以前一样。
21. 作为用户，我想导入的记忆和我在新部署上已有的记忆重复时只留一条，这样记忆页不会出现两条一模一样的。
22. 作为用户，我想导入后统计里接着算旧对话里的回合、通话和送礼，「认识多久」也从旧部署上第一次见面算起，这样统计不会从零开始。
23. 作为用户，我想勾了「制作人档案」就把称呼、性别、时区、生日一起带过来，这样她照旧叫我习惯的称呼、记得我的生日。
24. 作为不想覆盖新部署上设好的档案的用户，我想不勾「制作人档案」，这样新部署上的档案原样不动。
25. 作为用户，我想导入完看到一句话，说导入了多少段对话、多少张照片、多少条记忆，这样我知道成功了、带过来了什么。
26. 作为用户，我想在新部署上没有某位角色时被告知跳过了和她的几段对话，这样我知道少了什么、为什么少。
27. 作为用户，我想某位角色在新部署上没有时，她当来源角色的记忆照样导入，这样其他角色照样知道那些事。
28. 作为不小心把同一个数据包导入了两次的用户，我想第二次什么也不多出来，这样不会到处是重复的对话。
29. 作为在旧部署上有几段对话、后来又在新部署上导入了更新一版数据包的用户，我想已经导入过的对话被跳过、新的那几段照样导入，这样分几次搬也不乱。
30. 作为用户，我想导入出错时什么都不留下（不会导了一半），这样我可以放心地再试一次。
31. 作为拿着新版本部署导出的数据包、去老版本部署导入的用户，我想被明确告知数据包来自更新的版本、要请部署者升级，这样我不会以为导入成功、其实悄悄丢了东西。
32. 作为拿着老版本部署导出的数据包的用户，我想在新版本部署上照样能导入，这样不论旧部署多久没更新都能搬。
33. 作为选错文件（不是数据包、或者文件坏了）的用户，我想看到「这不是一个能用的数据包」，这样我知道换一个文件。
34. 作为数据包超过 200 MB 的用户，我想马上被告知太大了、可以不带照片重新导出，这样不用等它传完才失败。
35. 作为当天已经导入了 3 次的用户，我想被告知今天导入次数用完了、几点以后能再导，这样我知道什么时候再来。
36. 作为在两个标签页里同时点了导入的用户，我想第二个被告知已经有一个导入在进行，这样不会导入两次。
37. 作为准备删除全部数据的用户，我想在确认框里看到「先导出数据包」的链接，这样我不会删了才后悔没带走。
38. 作为用户，我想在隐私政策里看到导出的数据包在我自己手里、删除数据不会删到它，这样我知道要自己保管好它。
39. 作为用户，我想数据包里没有我的登录方式和邮箱，这样把它交给别人导入，也不会泄露我是谁。
40. 作为用户，我想数据包里没有我的自带密钥，这样数据包外泄也不会被人刷我的 key。
41. 作为用户，我想被说清楚设备上的设置（隐藏和置顶、衣装、电话质感、自带密钥）不在数据包里，这样搬过去以后我知道要自己再设一遍。
42. 作为用户，我想只有我自己能导出我的数据包，这样别人、包括管理者都拿不到我的对话和照片。
43. 作为在同一个部署上丢了旧登录方式、用新身份登录的用户，我想把旧账号导出的数据包导入到新账号，这样换身份也不丢东西。
44. 作为部署者，我想导入后所有角色的好感度从信任开始、抽奖次数和背包从零开始，这样没人能靠改文件刷好感度和礼物（ADR-0025）。
45. 作为部署者，我想一个数据包最大 200 MB、每人每天最多导入 3 次，这样没人能拿导入撑爆数据库。
46. 作为部署者，我想导入、导出都不让我在后台看到用户的内容，也不显示谁导过，这样我不必替用户的隐私担责（ADR-0013）。
47. 作为部署者，我想导入的记忆由服务器在后台补算向量，失败了也会在下一次检索时补上，这样不用我手动跑 `eidolon reembed`。
48. 作为管理者，我想后台没有导出别人数据包的入口，这样我不会被要求、也做不到代为导出。
49. 作为用户，我想导入后她说起旧对话里的事，口吻和在旧部署上一样（她发过的照片她记得，没发出去的她也知道没发出去），这样她前后是同一个人。
50. 作为用户，我想导入的对话里她那时候的好感度变化标签照旧显示，这样翻旧对话时看到的和原来一样。

## Implementation Decisions

### 数据包的格式（第 1 版）

- 一个 zip，里面固定三样东西，别的条目一律当作坏包：
  - `manifest.json`：zip 里的**第一个**条目，用 stored（不压缩）方式存，这样前端只读开头就能拿到。内容是 `format`（整数，现在是 `1`）、`exported_at`、`categories`（这个包里有哪几类，取值 `conversations`、`photos`、`memories`、`profile`），以及每类的条数。
  - `data.json`：缩进排版、UTF-8、键名用英文，人能直接读。
  - `photos/<照片 id>.webp`：每张发出来了的照片一个文件，就是库里存的 webp 原样。
- `data.json` 的形状（键名可以在实现时微调，但要写进格式说明文档）：

  ```
  {
    "profile": { form_of_address, gender, timezone, birthday_month, birthday_day },   // 没勾就没有这个键
    "conversations": [
      {
        "id": 包内 ID（导出时用原来的对话 id，导入时只当键用）,
        "character_id", "character_name",
        "created_at", "title",
        "messages": [ { role, text, ja, zh, segments, created_at, affinity, hurt, out_of_line,
                        "photo": { id, tag, status, reason, created_at, updated_at } } ],   // 按原来的先后
        "events": [ { kind, created_at, affinity, gift_id, liked } ],
        "calls": [ { connected_at, duration_s } ]
      }
    ],
    "memories": [
      { "id": 包内 ID, source_character_id, source_character_name,
        "conversation": 包内对话 ID 或 null, text, created_at, "superseded_by": 包内记忆 ID 或 null }
    ]
  }
  ```

- 所有内容照库里原样导出，包括 `segments` 里的语气提示（ADR-0007：它照旧回到她之后的提示词里）、消息上的好感度变化、`hurt` / `out_of_line`、送礼事件的 `liked`。
- 照片：只有 `ready` 的才有图片文件；导出时还在生成的，按 `failed`、原因 `timeout` 导出（和服务器重启时一样）；没勾「照片」时，照片那一项整个不带，她那条回复上就没有照片。
- 没勾「对话」时，记忆上的 `conversation` 一律是 `null`，和那段历史对话被删了一样。
- 时间一律导出成库里现在的格式（UTC、带微秒的 ISO 8601）。导入时先解析再按同一种格式写回，解析不了的整包拒绝。这是因为当前对话和事件穿插都是按时间文本排序的，格式不一致就会排错。
- 格式说明写成一份文档，放在 `docs/` 下，写明每个键的意思和版本规则，给别的部署者和以后的版本看。

### 版本规则

- 导入时先看 `manifest.json` 的 `format`：比自己支持的新，就拒绝，错误码 `too_new`；等于或者更老的，按那一版的规则读。以后改格式时，`format` 加一，旧版本的读法要保留。
- 前端读到 `manifest.json` 时就能先看出 `too_new`，不用上传。

### 导出接口

- `GET /api/account/data-package?include=conversations,photos,memories,profile`：要登录，只导出调用者自己的数据。`include` 里没有 `conversations` 却有 `photos` 时，按没有 `photos` 处理。
- 回一个 zip，带 `Content-Disposition: attachment` 和一个带日期的英文文件名（比如 `eidolon-data-package-2026-10-19.zip`）。浏览器直接跳到这个地址下载，不经过 JS 的内存。
- 服务器先把 zip 写进临时文件再流式回给浏览器，写完删掉临时文件，不在内存里拼整个包。照片一张一张从库里读，不一次读完。
- 同一位用户同一时间只能有一个导出在生成，第二个回 409。导出不限次数。
- 不写运行记录，后台不显示。出错只写服务器日志，日志里不带内容。

### 导入接口

- `POST /api/account/data-package?include=...`：要登录，请求体就是 zip 本身（`application/zip`），不用 multipart。`include` 和 `manifest.json` 里的 `categories` 取交集。
- **读请求体**：后端边读边数字节、写进临时文件，超过 200 MB 立刻回 413，不等传完；请求头带了 `Content-Length` 而且超了的，一开始就回 413。
- **检查**：zip 能打开；条目只有上面三样；`manifest.json` 和 `data.json` 解压后各自也有上限（防 zip 炸弹）；JSON 合乎格式（字段类型、`role`、照片 `status` 的取值，包内 ID 引用得上）；每个照片文件都能当 webp 解开，否则整包拒绝。尺寸不查，别的版本的照片尺寸可能不同。坏包一律回 422，错误码 `broken`。
- **一个事务**：检查通过后，所有写入在一个事务里完成，中途出错全部回滚，什么也不留下。
- **对话**：
  - 包里每段对话，角色不在这个部署的角色配置里的，整段跳过，连同里面的照片和通话记录，记进结果的「跳过」里（带包里的角色名）。
  - 同一位用户、同一位角色、开始时间相同的对话已经存在，就当成同一段，整段跳过，不做逐条合并。包里的记忆引用它时，改成引用已有的那段。
  - 其余的换新的对话 id，消息按原来的先后插入（消息靠自增 id 排序），照片换新 id、挂到新的消息 id 上，对话事件和通话记录照原样挂上去。
  - 当前对话不另定规则，照旧取最新开的那个。
  - 送礼事件里的礼物不在这个部署的礼物表里的，这一条事件跳过：她的提示词要按礼物表念出礼物名，认不得会出错。不算进结果。
- **记忆**：
  - 按原文去重：这位用户已经有同样原文的记忆，就不新加，包内 ID 对应到已有的那条。
  - 新加的记忆换新 id；`superseded_by` 按包内 ID 重新对应到新 id 或者已有那条的 id。已有的记忆一律不改，包括它们的取代关系。
  - 来源角色照原样存，不论这个部署上有没有她（没有的照现在的做法显示成「已不在的角色」）。
  - `conversation` 对应到新的对话 id；对话被跳过（角色不在）或者没勾对话的，存成空。
  - 新加的记忆不在事务里算向量。导入成功后，服务器在后台给这位用户还缺向量的记忆补算，用部署者的向量化服务，算部署者的钱；补算失败的，照现有的懒补路径在下次检索时补。
- **制作人档案**：勾了就整份覆盖，包括包里没设的项（没设就清空，沿用默认）。
- **好感度、抽奖次数、重置卡、礼物背包**：不碰。新用户本来就是从信任、零开始。
- **结果**：回 `{conversations, photos, memories, profile, skipped: [{character_name, conversations}]}`，都是这次真正新加的数。去重跳过的不单列，导入两次时第二次各项都是 0。
- **上限**：
  - 同一位用户同一时间只能有一个导入在跑，第二个回 409，错误码 `busy`。用进程里的一个按用户的锁就够（单进程部署）。
  - 每天（北京时间，用 `affinity.day_of` 划天）最多成功导入 3 次。成功的那次才算，坏包、太大、`too_new`、`busy` 都不算；全部去重、什么也没新加的也算一次。超了回 429，带 `retry_at`（下一个北京时间 0 点），照现有的 `OverLimit` 回法。
  - 记次数要新开一张小表，按用户记每次成功导入的时间，登记进用户数据（删用户时一起删）。后台不显示它。
  - 200 MB、3 次这几个数写成常量，不进后台配置，不给部署者开关。
- 不写运行记录，后台不显示谁导过。出错只写服务器日志，不带内容。

### 网络这一路

- **Next 的同源代理**：现在把请求体整个读进内存再转发，改成流式转发请求体（所有请求一样，fetch 用 `duplex: "half"`）。响应头的白名单加上 `content-disposition` 和 `content-length`，这样下载能带上文件名和大小。
- **Caddy**：给导入这个路径加 `request_body max_size 200MB`（只卡这一个路径，别的不动）。部署文档里写明，自己配反向代理的部署者也要放开这个路径的大小上限。

### 前端：设置里的「数据包」标签

- 设置分类加一个 `data-package`，标签名「数据包」，和「登录方式」放在同一组。
- **导出**：四个勾选框，默认全选。「照片」缩进挂在「对话」下面，不勾对话时照片既不能勾、也显示成没勾。点「导出」，浏览器跳到导出地址下载。下面一行小字说明设备上的设置不在里面，越短越好。
- **导入**：
  - 选文件后，前端用一个小的 zip 库（比如 fflate）流式读出开头的 `manifest.json`，不把整个文件读进内存。读不出来就提示坏包；`format` 太新，直接提示让部署者升级；否则按 `categories` 列出勾选框，默认全选，`photos` 照样挂在 `conversations` 下面。
  - 点「导入」，把文件原样 POST 上去，等待时按钮显示进行中。成功后显示一句结果，并刷新对话列表、记忆和制作人档案这几处的数据。
  - 错误各给一句：坏包、太新、太大（提示可以不带照片重新导出）、已经有一个在导入、今天次数用完（带几点以后可以再导）。
- 拼结果那句话、勾选框的联动、错误码对应到文案，放在一个纯函数模块里，方便测试。
- 用 shadcn 现有的组件（勾选框、按钮、卡片），照 `frontend/AGENTS.md` 的「shadcn 纪律」和 `DESIGN.md`。

### 其他界面和文档

- 隐私政策「怎么删除」那一段后面加一句：导出的数据包在你自己手里，删除数据不会删到它。条款里有说明用户能拿到什么数据的地方也同步。

## Testing Decisions

- **好测试的标准**：只通过对外接口看行为，不碰内部模块，也不断言表结构。导出的结果用解开 zip 读 JSON 的方式核对；导入的结果用现有的读接口核对：对话列表、对话记录、照片接口、记忆页、制作人档案、统计、好感度、礼物背包。只有像「删用户时导入次数一起删」这类读接口看不到的，才查库，照 `test_delete_account.py` 里查残留行的做法。
- **后端对外接口（主接缝）**：
  - **往返**：在部署 A（一个 `database_path`）上用现有接口和测试替身造出数据：几段对话（一段被她结束、一段带发出来的照片和没发出去的照片、一段带送礼事件和通话记录），几条记忆（含取代关系、来源角色各不相同），制作人档案。导出后导入到部署 B（另一个 `database_path`、同一套角色），在 B 上用读接口逐项核对和 A 一致：当前对话和历史对话的先后、已结束、标题、照片能读、记忆和「已被取代」、档案、统计里的回合和通话。另外核对 B 上的好感度是信任、背包和抽奖次数从零开始。
  - **定向**：手工拼数据包，测这些情况：只勾部分类别（导出和导入两边都测），不带照片，和已有数据合并时谁是当前对话，同一份导入两次，分两次导入有重叠的两个包，角色不在这个部署，送礼事件的礼物不在礼物表，记忆原文和已有的重复以及取代关系的对应，`format` 太新，时间格式不对，多出来的条目、坏 zip、照片解不开，超过 200 MB（用调小的上限测，别真造 200 MB），第二个并发导入，当天第 4 次以及过了北京时间 0 点又能导，别的用户的数据不会被导出，没登录不能导出也不能导入，导入出错后什么也没留下。
  - 参照现有的 `test_delete_account.py`、`test_delete_past_conversations.py`、`test_past_conversations.py`、`test_photo_records.py`、`test_photo_limits.py`，用 `make_client` 传不同的 `settings`（换一个 `database_path`）当作另一个部署。
- **前端纯函数（vitest）**：勾选框联动（不勾对话时照片不能勾）、按 `manifest.json` 列出类别、读 `manifest.json` 判断 `too_new` 和坏包、结果拼成一句话（含跳过的角色）、错误码对应到文案。参照现有的 `lib/*.test.ts`。
- **同源代理**：在现有的代理测试里加一条，证明请求体是流式转发的，`content-disposition` 能带回来。
- **本地构建版上用 Playwright 验收**（照 `docs/agents/local-acceptance.md`，只验收、不进自动测试）：在设置里真的导出一次、换一个开发用户导入一次，看对话列表、历史对话、照片、记忆页；删除账号确认框里的链接；隐私政策里的那一句。

## Out of Scope

- 好感度、抽奖次数、重置卡、礼物背包的导出和导入（ADR-0025）。
- 只存在设备上的设置（自带密钥、隐藏和置顶、衣装、电话质感、外观）的导出和导入。
- 登录方式、用量、限额、运行记录、封禁状态。
- 管理者导出某位用户或整个库的数据包（ADR-0012、ADR-0013）。
- 一段对话的逐条合并：同一段只会整段跳过。
- 两个部署之间自动同步、定期自动导出。
- 给数据包加密码或加密：数据包是用户自己保管的明文。
- 离线翻看数据包的页面：只做到 JSON 人能读、照片能直接打开。
- 让部署者调上限或关掉这个功能的配置项。

## Further Notes

- 以下几处是写规格时补的实现层面的决定，拷问里没有逐条问过：送礼事件里的礼物在这个部署的礼物表里找不到时跳过这条事件（不然她的提示词会出错）；导出也限同一时间一个；制作人档案覆盖时包里没设的项清空；导出时还在生成的照片按 `timeout` 导出；全部去重的导入也算一次次数。拆票或实现时觉得不对，再提出来。
- 导入的对话原样带着 `hurt` / `out_of_line`：导入的最后一段要是成了当前对话，她在旧部署上快要不耐烦的状态也会跟过来（ADR-0025 的后果之一），这是有意的。
- 数据包里有角色名和她的回复原文，但没有剧情原文：剧情库仍然不对外（ADR-0003）。
- 照片一张估计 120 KB 左右，存得多的用户一个数据包可能有上百 MB；200 MB 不够时提示不带照片重新导出，以后真有人不够再说。
