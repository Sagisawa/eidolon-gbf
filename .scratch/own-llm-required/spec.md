# 必须自带 LLM

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，特别是「必须自带 LLM」「自带密钥」「限额」「运行记录」。相关决策见 ADR-0013（后台设置覆盖 `.env`）、ADR-0016（落地页静态渲染）和 ADR-0017（自带密钥只存在用户的浏览器里）。设计在 2026-10-11 的 grilling 中定下。这个开关随时可以关掉，所以不另写 ADR。

## Problem Statement

部署者希望公开部署上的用户自己出 LLM 的钱，部署者只负责语音合成、语音识别、向量化、重排和判断模型。现在做不到：

- 部署级的每小时回合数、通话次数设成 0，意思是「不限」，不是「只能自带」。
- 管理者可以把某位用户的单独限额设成 0，让他只能用自带密钥，但只能一个个用户设，新注册的用户不受影响。
- 被设成 0 的用户，通话要 LLM、语音合成、语音识别三项全部自带才放行。所以「只自带 LLM、语音由部署者出」这种用法根本打不了电话。

## Solution

加一项部署级的要求：**必须自带 LLM**。

- 由部署者打开：`.env` 给默认值，管理者可以在后台配置页改，从下一个回合、下一次通话起生效；进行中的通话不受影响，打到挂断为止。
- 打开后，没带 LLM 自带密钥的回合和通话都会被拒绝。被拒绝的回合和通话在运行记录里记作「被拒绝」，不计入限额。
- 带了 LLM 自带密钥的用户照常使用。语音合成、语音识别仍由部署者承担。
- 限额规则不变：自带 LLM 的文字回合不计入限额；只带了 LLM 的通话照常计入每小时通话次数，三项全部自带才不计入。
- 管理者不受这项要求约束，可以用部署者的 LLM。
- 管理者可以在后台用户详情的「单独限额」对话框里，给某位用户勾上「可以用部署者的 LLM」。被放行的用户用部署者 LLM 的回合和通话照常计入限额。单独限额设成 0 的用户，放行不起作用，对话框里这一项变灰。撤掉单独限额时，放行一起撤掉。
- 部署者自己的 LLM 照旧必须配，启动时照旧检查（管理者和被放行的人要用）。
- 前端提前拦住：要求打开、这位用户又没有放行、这个浏览器里也没存 LLM 自带密钥时，对话页的输入框和通话按钮换成一句提示和「去设置自带密钥」的链接；设置页把 LLM 标成必填。后端照样拒绝，作为兜底。
- 落地页第六幕和隐私说明的文案改成两种情况都适用的写法，不随开关变化。

## User Stories

1. 作为部署者，我希望打开一项设置，让用户必须自带 LLM 才能使用，这样 LLM 的费用由用户自己承担。
2. 作为部署者，我希望打开这项要求后，语音合成和语音识别仍由我提供，这样只带了 LLM 的用户照样能打电话。
3. 作为部署者，我希望在 `.env` 里给这项要求设默认值，这样新部署一启动就是我要的状态。
4. 作为管理者，我希望在后台配置页随时打开或关掉这项要求，不用重启服务。
5. 作为管理者，我希望改动从下一个回合、下一次通话起生效，正在进行的通话不被挂断。
6. 作为管理者，我希望配置页标出这项要求现在是跟随 `.env` 还是后台改过的，和其他配置项一样。
7. 作为部署者，我希望只带了 LLM 的通话照常计入每小时通话次数，这样限额还能管住我付钱的语音用量。
8. 作为部署者，我希望自带 LLM 的文字回合照旧不计入限额，规则和以前一样。
9. 作为管理者，我希望自己不受这项要求约束，直接用部署者的 LLM，这样我测试时不用另填 key。
10. 作为管理者，我希望能单独放行某位用户（比如朋友），让他用部署者的 LLM。
11. 作为管理者，我希望放行就在「单独限额」对话框里设，和单独限额一起管。
12. 作为管理者，我希望被放行的用户照常受限额约束，这样放行不等于不限量。
13. 作为管理者，我希望一位用户的单独限额设成 0 时，放行那一项变灰、不起作用，这样「只能用自带密钥」的意思不会被放行冲掉。
14. 作为管理者，我希望撤掉一位用户的单独限额时，放行也一起撤掉，这样不会留下一条看不见的放行。
15. 作为管理者，我希望在用户详情里看得出这位用户有没有被放行。
16. 作为用户，在要求必须自带 LLM 的部署上，如果还没填 LLM，我希望一打开对话页就看到提示，而不是打完一段话才被拒绝。
17. 作为用户，我希望提示里有一个按钮直接带我去设置自带密钥。
18. 作为用户，我希望设置页告诉我这个部署必须自带 LLM，语音可以不填。
19. 作为用户，我希望填好 LLM 以后，回到对话页就能直接发消息和打电话，不用刷新。
20. 作为用户，我希望只填了 LLM 也能打电话，语音用部署者的。
21. 作为用户，我希望设置页照实告诉我：只带 LLM 的通话仍计入每小时通话次数。
22. 作为用户，如果我开着页面的时候部署者刚打开这项要求，我希望发消息或拨号时看到明确的原因，并且有去设置的按钮，而不是一个笼统的错误。
23. 作为用户，我希望这样被拒绝的回合和通话不占我的限额。
24. 作为被放行的用户，我希望不填 LLM 也能照常使用，前端不拦我。
25. 作为管理者，我希望前端也不拦我，就算我没填 LLM。
26. 作为限额被设成 0 的用户，我希望看到的仍是「只能用自带密钥」的提示，和以前一样。
27. 作为访客，我希望落地页上关于费用和自带密钥的说法，不论这个部署有没有打开要求都是对的。
28. 作为用户，我希望隐私说明里关于语言模型服务的说法，不论我的对话发给部署者配的服务还是我自己的服务，都是对的。
29. 作为管理者，我希望在看板和运行记录里看得到因为没带 LLM 而被拒绝的回合和通话，和超出限额被拒绝的一样算「被拒绝」。
30. 作为部署者，我希望部署文档和 README 写明这项设置的变量名、默认值和效果。

## Implementation Decisions

- **开关**：后台配置里新增一项布尔值「必须自带 LLM」，放在「限额」那一节。`.env` 用一个新变量给默认值，默认关闭；后台改了以后覆盖 `.env`（ADR-0013）。实时配置对外给出「现在是否要求」，回合和通话开始时读一次。
- **放行**：存在单独限额那张表里，新加一列「可以用部署者的 LLM」。单独限额的读、写、撤接口带上这一项；撤掉单独限额时一起撤掉。只设放行、不设次数时，次数跟随全站。代码里不能叫 `exempt`（它已经表示「不计入限额」），用类似 `deployer_llm_allowed` 的名字。
- **判断规则**，只有一条，各处共用：一个回合或通话，如果要求已打开，没有带 LLM 自带密钥，这位用户既不是管理者也没有被放行，就拒绝。限额 0 照旧由限额那一关拦住，所以「放行但限额为 0」自然被拒绝，不用另写特例。
- **拒绝在哪里发生**：在 `Admissions` 里，和超出限额走同一条路：先取 key、开运行记录，再判断这条规则，不满足就把记录标成 rejected，放掉部署者的 key，抛出一个新异常（类似 `OwnLLMRequired`），不占限额。`Admissions` 需要能问「这位用户是不是管理者、有没有被放行」，从外面注入。
- **通话预检**：拨号前的 ICE 服务器预检也按同一条规则判断，不满足就抛同一个异常，这样还没开始花钱就被拦下。
- **HTTP**：新异常统一映射成 403，`detail` 写「这个部署需要你自带 LLM，可以在设置里填写」之类的话。不复用限额的 429。
- **账号接口**：`/api/account` 新增一个布尔字段，表示这位用户现在是否必须自带 LLM（要求已打开，而且不是管理者、没被放行）。前端只靠这一项和本地存的 key 判断，不自己推规则。
- **前端判断**：`lib/` 里加一个纯函数，输入是 account 和这个浏览器里的自带密钥，输出是拦不拦。对话页的输入框和通话按钮、设置页的必填标记都用它。本地 key 改了要立即重新判断。
- **前端兜底**：文字回合和通话收到 403 时显示 `detail`，按钮用「去设置自带密钥」，和限额 0、自带密钥出错的情况一样。通话结束原因里加一种，或者并进已有的某种原因，只要能落到「去设置自带密钥」就行。
- **后台**：配置页的「限额」一节加一个开关；「单独限额」对话框加一项勾选，选 0 时变灰；用户详情显示有没有被放行。
- **设置页说明**：要求打开时，自带密钥标签页把 LLM 标成必填，并说明只带 LLM 的通话仍计入通话次数。原有的豁免说明照旧。
- **文案**：落地页第六幕「可以免费使用……」「也可以填上你自己的 API 密钥……」两句，以及隐私说明「语言模型服务」那一条，改成不论开关开没开都对的写法，不随开关变化。落地页照旧静态渲染。
- **文档**：部署文档（三个语言版本）和 README 加上新变量和后台开关的说明。
- 部署者 LLM 的启动检查不动。判断模型、向量化、重排不动。

## Testing Decisions

- 好的测试只看外部行为：发了什么请求，回来什么状态和内容，运行记录、限额计数、后台看到什么。不测函数怎么拆、内部调用了谁。
- **后端只走 HTTP 这一个接缝**，用现有的 `make_client` 测试客户端，不直接打 `Admissions`。覆盖：
  - 要求关闭时，一切和现在一样。
  - 要求打开，没带 LLM 的文字回合得到 403，运行记录是「被拒绝」，限额计数不变；带了 LLM 的照常进行，也照常不计入限额。
  - 要求打开，通话预检和发起通话：没带 LLM 的得到 403；只带 LLM 的放行，计入通话次数；三项全带的放行，不计入。
  - 管理者不带 LLM 照常使用；被放行的用户不带 LLM 照常使用，并计入限额；被放行但限额为 0 的用户被拒绝。
  - `/api/account` 的新字段，在开关、管理者、放行三种情况下都对。
  - 后台配置能改开关，立即生效；`.env` 的默认值有效；非法值被拒绝。
  - 后台单独限额接口能写、读放行标记；撤掉单独限额时放行一起撤掉。
  - 进行中的通话不受开关改动影响。
- 参照：`test_exemption.py`、`test_rate_limit.py`、`test_admission.py`、`test_admin_users.py`、`test_live_config_limits.py`、`test_call_records.py`。
- **前端**：只测 `lib/` 里那个纯函数，用 vitest，参照 `lib/*.test.ts`（比如 `localOwnKeys.test.ts`、`api.test.ts`）。另外测 403 在 API 层被转成可读的错误。组件不另写测试，靠人工验证。

## Out of Scope

- 部署者不配自己的 LLM。
- 按用户强制自带语音合成或语音识别。
- 落地页根据开关动态显示不同文案。
- 新的「放行名单」独立页面。
- 改动现有限额规则和单独限额 0 的含义。
- 判断模型、向量化、重排改成可以自带。

## Further Notes

- 开关打开时，部署者的 LLM 只有管理者和被放行的用户在用，看板上 LLM 的花费会随之下降。
- 用户的自带密钥只存在浏览器里（ADR-0017），换设备要重填；前端提示要按「这个浏览器里有没有存 LLM」判断，不能按账号判断。
