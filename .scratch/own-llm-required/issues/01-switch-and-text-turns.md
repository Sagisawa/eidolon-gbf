# 01: 开关和文字回合

**What to build:** 部署者可以打开「必须自带 LLM」。`.env` 用一个新变量给默认值（默认关闭），管理者可以在后台配置页「限额」一节改，改了覆盖 `.env`（ADR-0013），从下一个回合起生效。打开后，用户没带 LLM 自带密钥的文字回合被拒绝：后端回 403，`detail` 说明这个部署需要自带 LLM、可以在设置里填写；这个回合在运行记录里记作「被拒绝」，不计入限额。对话页显示这个原因，并给出「去设置自带密钥」按钮，和限额设成 0 时一样。带了 LLM 的回合照常进行，照常不计入限额。管理者不受这项要求约束。

拒绝规则只写一处，后面的通话（02）、放行（03）、账号接口（04）都用它：要求已打开，回合或通话没带 LLM 自带密钥，这位用户既不是管理者也没被放行（放行由 03 加入，这张票里可以先当作没人被放行）→ 拒绝。判断放在 `Admissions` 里，和超出限额走同一条路：先开运行记录，再判断，被拒绝就记成 rejected、放掉部署者的 key，抛新异常。「是不是管理者」由外部注入，不让 `Admissions` 直接依赖后台模块。代码里不能用 `exempt` 给这个概念命名。

详见 `.scratch/own-llm-required/spec.md`。
