# 04: 前端提前拦，文案和文档

**What to build:** 用户不用打完一段话才被拒绝。`/api/account` 新增一个布尔字段，表示这位用户现在是否必须自带 LLM；它和后端拒绝用同一条规则判断，也就是要求已打开，而且这位用户不是管理者、没被放行。前端 `lib/` 里加一个纯函数，输入 account 和这个浏览器里存的自带密钥，输出拦不拦。被拦时，对话页的输入框和通话按钮换成一句提示和「去设置自带密钥」的链接；在设置页填好 LLM 后回到对话页，不用刷新就恢复。要求打开时，设置页的自带密钥标签页把 LLM 标成必填，并照实说明只带 LLM 的通话仍计入每小时通话次数。后端的 403 继续作为兜底。

文案改成不论要求开没开都对的写法，不随开关变化：落地页第六幕「可以免费使用……」「也可以填上你自己的 API 密钥……」两句（落地页照旧静态渲染，ADR-0016），以及隐私说明「语言模型服务」那一条。README 和三个语言版本的部署文档写明新变量、默认值、后台开关、放行和限额的关系。

**Blocked by:** 01、02、03。功能上只依赖 01；排在 02、03 后面是为了避开 `zh.ts` 的合并冲突（用户决定放到最后做）。

## Comments

2026-10-11 实现时的理解：

- 新字段叫 `own_llm_required`，直接取 `Admissions.own_llm_required(user_id)`，和拒绝同一条规则。被放行但单独限额为 0 的用户，这个字段是 false（前端不拦），由限额那一关照旧拦下、显示「只能用自带密钥」。
- 纯函数是 `lib/localOwnKeys.ts` 的 `needsOwnLLM(account, keys)`：账号说必须自带、这个浏览器里又没存 LLM 才拦；只存了语音 key 照样拦。「不受约束的用户」由后端把字段算成 false，前端不另看 `is_admin`。
- 「不刷新就恢复」：设置页在对话外壳之外，回到对话页时外壳重新挂载、重新拉账号；另外 `subscribeOwnKeys` 在这个标签页存删 key 时、别的标签页改了 key 时（`storage` 事件）通知对话页，对话页用 `useSyncExternalStore` 当场重判。
- 被拦时：输入栏换成和 403 兜底同一个提示块（`FailureNotice`，带「去设置自带密钥」），页首的电话键不显示（通话中照旧显示「回到通话」）。空对话里「打字，或者点右上角的电话」那句没改。
- 设置页：LLM 标题旁加「必填」Badge，没填时那一行写「未填写，填上以后才能发消息和打电话」，并加一段说明（语音可以不填，只带 LLM 的通话仍计入通话次数）；必须自带又没填 LLM 时，不再显示「现在用的是部署者的服务……」那句豁免说明。
- 落地页第六幕两句、隐私说明那一条的新文案需要用户审；落地页字体子集已经重新生成（新增 11 个字，去掉「免」「它」）。
- `.env.example` 里这个变量的注释原先只写了文字回合，顺手补上通话和放行。
