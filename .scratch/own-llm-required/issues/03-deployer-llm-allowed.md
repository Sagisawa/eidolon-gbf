# 03: 放行

**What to build:** 管理者可以在后台用户详情的「单独限额」对话框里，给某位用户勾上「可以用部署者的 LLM」。被放行的用户在要求打开时不带 LLM 也能发起回合和通话，照常计入限额。单独限额选成 0（「只能用自带密钥」）时，这一项变灰、不起作用，用户照样被拒绝；这一点由限额那一关自然拦住，不用另写特例。只勾放行、不设次数时，次数跟随全站。撤掉单独限额时，放行一起撤掉。用户详情里看得出这位用户有没有被放行。

放行存在单独限额那张表里，新加一列，旧数据默认没放行。单独限额的读、写、撤接口都带上这一项。01 的拒绝规则加入「被放行」这个条件；代码里用类似 `deployer_llm_allowed` 的名字，不用 `exempt`。

详见 `.scratch/own-llm-required/spec.md`。

## Comments

2026-10-11 代码审查后定下：「选 0 时变灰」理解成回合、通话**两项都**选「只能用自带密钥」时才变灰。只有一项是 0 时，另一项仍用部署者的 LLM，放行对它起作用，所以照样能勾；变灰时保存成不放行，不留看不见的放行。用户详情对「两项都是 0 却放行」（只可能经接口写入）显示「不起作用」。
