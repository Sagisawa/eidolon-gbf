# 架构加深（第四轮）：过期通话的事件一律挡住

Status: ready-for-agent

术语以 `CONTEXT.md` 为准，本轮不改词表。设计词汇（module、interface、seam、adapter、depth、locality）取自 `codebase-design` skill。2026-10-02 的架构审查列出了 12 个候选，经 grilling 决定这一轮只做候选 2「一通电话一道闸」。

## Problem Statement

一次通话结束以后（挂断、掉线、后端挂断、没接通、离开对话页），它的连接不会立刻断干净：挂断时对话页先把通话收起，然后才等连接关闭。这段时间里，数据通道里已经收到的消息照样会送进对话页。下一通通话开始之后，上一通的消息也可能才到。

「这条消息是不是当前这一通的」现在由每个 handler 各自判断，而且判断得不一样：
- **掉线、麦克风丢失**：判断「这一通还是不是当前的通话」，会挡住。
- **立绘**：判断「这次拨号还是当前的，而且通话还在进行」，会挡住。
- **对话记录里的事件**（用户说的话、回复的增量、回复记下、出错）：不判断，照样改动对话记录和错误状态。
- **后端说明为什么挂断**：不判断，照样改写结束原因。
- **正在听写的文字**：不判断，照样改写。

按代码推断（还没在真实通话里复现），用户会遇到：
- **一直转圈的回复**：挂断那一刻，后端刚好认出了用户的一句话。这句话在挂断之后才到，对话页因此新开一个回合，挂一条「正在回复」，一直转到下一个回合才消失。
- **下一通的回合被撤掉**：下一通已经在进行时，上一通迟到的一句话会撤掉下一通进行中的回合，换成那条假的回合。
- **过期的错误**：上一通迟到的出错消息，在通话结束后，或者下一通里，显示成当前的错误。
- **报错结束原因**：上一通迟到的「后端为什么挂断」，在下一通掉线时被当成这一通的原因。
- **闪一下旧转写**：拨号时不会清空正在听写的文字，所以下一通开头可能先闪一下上一通的转写。

第三轮把立绘指令拆成纯 reducer 时，commit 说「过期通话的事件统一挡住」，但实际只挡住了交给立绘的那一路。现有测试里也有一条送了上一通迟到的用户发言，只断言了立绘的心情，没有检查对话记录。

## Solution

通话的「过期」只有一个定义：**这次拨号已经不是当前这一通**。任何一种结束都让这次拨号过期，包括挂断、掉线、后端挂断后的掉线、没接通，以及离开对话页。过期的拨号，它的所有 handler 一律不做任何事。

这道闸只设在 `LiveConversation` 一处：每次拨号时，交给通话的那组 handler 都先过这道闸。闸后面的各个 handler 不再自己判断是不是当前这一通。

## User Stories

1. 作为用户，我想在说完一句话的同时挂断电话后，不会看到一条一直在转圈、永远等不到的「正在回复」，这样对话记录里只有真实发生的回合。
2. 作为用户，我想在挂断后马上重拨时，新通话里正在进行的回合不会被上一通迟到的消息撤掉，这样我刚说的话和她的回复不会凭空消失。
3. 作为用户，我想在挂断后不会冒出上一通的错误提示，这样我看到的错误总是属于当前这一通的。
4. 作为用户，我想在下一通掉线时，结束页显示的是这一通自己的原因，而不是上一通后端挂断的原因（例如「说了 20 轮了」），这样我能看懂这一通为什么结束了。
5. 作为用户，我想在新一通开头不会闪一下上一通的转写，这样通话层上显示的总是这一通里我说的话。
6. 作为用户，我想在通话层收起时挂断，也得到上面同样的保证，这样收起不收起都一样可靠。
7. 作为用户，我想在通话被后端挂断（时长或回合数到了上限）时，结束页仍然照常显示后端给出的原因，这样新的规则不会把当前这一通的正常消息也挡掉。
8. 作为用户，我想在拨号中途掉线时，仍然由「没能接通」说明原因，这样掉线不会抢在接通失败之前报出一个不准确的结束原因。
9. 作为用户，我想正常通话中的一切（字幕、回复、立绘、补充和打断、只看文字、麦克风静音和切换麦克风）都和以前一样，这样这次修改对我是看不见的。
10. 作为开发者，我想在一处读懂「什么样的通话事件不再算数」，这样以后给通话加新的 handler 时，不会又漏掉判断。
11. 作为开发者，我想用一条表驱动测试覆盖「各种结束方式 × 各种迟到的事件」，这样加一种事件或一种结束方式只要加一行。
12. 作为开发者，我想让 `LiveConversation` 里关于过期的判断只剩一种写法，这样不会再出现「立绘挡住了、对话记录没挡住」这种半套的规则。

## Implementation Decisions

- **只改 `LiveConversation`**。通话 adapter（Pipecat 那一层）不动：它管不到掉线和「下一通已经开始」这两种情况，而且没有测试。它的 port 和通话协议留给审查里的候选 6。
- **过期的定义**：一次拨号在开始时成为当前这一通。任何一种结束都清掉「当前这一通」，包括用户挂断、掉线、后端挂断后的掉线、拨号失败，以及离开对话页（这一条现在已经是这样）。
- **一道闸**：拨号时交给通话的每个 handler 都先判断「这次拨号还是不是当前这一通」，不是就什么都不做。覆盖的 handler：通话事件（包括用户说的话、增量、回复记下、出错、后端说明为什么挂断，以及只影响立绘的事件）、正在听写的文字、掉线、麦克风丢失。播放角色声音的那个 handler 原样直通 port，不在本轮范围。
- **闸后面的简化**：
  - 通话事件的处理里不再区分当前和过期；交给立绘的那一路不再自己判断。
  - 掉线和麦克风丢失不再各自比较「这一通还是不是当前的通话」。
- **保留的一条例外**：拨号中途掉线时，掉线 handler 仍然不做事，由拨号失败说明原因。这一条作为闸之后的第二个条件，留在掉线 handler 里。
- **挂断那一刻迟到的「回复记下」**：一律挡住。后端可能在收到挂断前已经记下了这个回合。
  - 现在：对话记录里这个回合已经被撤掉，本来就看不到；只是还会刷新一次对话列表。
  - 改了以后：列表也不刷新，要等下一次刷新或者重新加载。
  - 这是有意接受的取舍：窗口是毫秒级的，规则「过期的一律不做事」没有例外。
- **不变的**：快照的形状、`conversationLog` 和立绘指令这两个 reducer、通话层的收起和展开、只看文字和麦克风的行为、后端的一切。

## Testing Decisions

- 好的测试只经由 `LiveConversation` 的 interface 断言：用假 Ports 拨号、让 `FakeCall` 接通、经 handler 送事件，再看快照和 `onListChanged`。不检查私有字段。
- **新增一条表驱动测试**，两个维度：
  - **这一通怎么结束**：用户挂断；掉线；后端先说明原因、再掉线；下一通已经接通。
  - **迟到的是什么**：用户说的话、回复的增量、回复记下、出错、后端说明为什么挂断、正在听写的文字、麦克风丢失、一个只影响立绘的事件（如她开始出声）。
  - **断言**：迟到的事件前后，快照深相等，`onListChanged` 没有被再次调用。
- **新增一条**：下一通已经开始后，上一通的「后端说明为什么挂断」才到；下一通掉线时，结束原因仍是这一通自己的。它补充现有的「新一通掉线不沿用上一通的原因」：那条测的是两通先后发生，这条测的是上一通的消息在下一通里迟到。
- **替换，不叠加**：
  - 「her emotions」组里「上一通的事件不推动情绪」那条整条删掉，由新的表驱动测试覆盖。
  - 「the stand」组里「通话结束时清空立绘、下一通从平静开始」那条，只删掉最后「上一通迟到的她开始出声」那两句断言；「结束时回到平静」和「下一通从平静开始」保留。
- **现有测试要原样通过**：拨号中途掉线由接通失败说明原因、后端挂断后掉线报后端的原因、通话层收起时结束会展开等。
- 先写会失败的测试（`/tdd`），再改实现。参照现有 `liveConversation.test.ts` 里 `conversation()`、`connected()` 和 `attempts[n].handlers` 的写法。

## Out of Scope

- 通话 adapter 自己在挂断后停止回调；通话协议、消息校验、`muted` 改名为 `textOnly`（候选 6）。
- 挂断那一刻后端已经记下、但被挡住的回合，在对话页上补回来，或者通话结束时统一刷新一次列表。
- 审查里的其他候选（1、3–12），见 2026-10-02 的审查报告。候选 3（角色的声音交给 `LiveConversation`）也落在同一个文件上，等这一轮做完再拷问。
- 不改 `CONTEXT.md`，不写 ADR：「过期的拨号」是实现概念，按 `CONTEXT.md`，通话有结束点，结束之后发生的事本来就不属于这一通。

## Further Notes

- 迟到的消息在真实通话里很难故意触发，所以人工验收只确认日常流程没有变化，清单见 ticket 01。
- 第三轮 ticket 01 里写过「过期通话的事件由 `LiveConversation` 挡住」，当时只要求立绘这一路，并注明过期的用户发言仍会改动状态。这一轮把它补全成所有 handler。
