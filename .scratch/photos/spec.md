# 她发照片：制作人明确要时，她在回复里发来一张拍到她本人的照片

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准（「照片」「生图」「部署者」「自带密钥」「网络代理」「已知服务商」）。说回合、对话、通话，不说消息、聊天、会话；照片不是立绘，也不是插画。全年龄怎么守见 ADR-0023，照片存哪、谁能看见 ADR-0024，自带生图什么时候走代理见 ADR-0022。所有决定的来历都在 `.scratch/photos/map.md` 和它的 12 张票里，调研全文和原型在 `research/novelai-*`、`prototype/photos-*` 分支。界面文案要少、简明。

## Problem Statement

- 制作人想看看她：今天穿了什么、在哪、在干嘛。现在只能听她用文字描述，「发张照片给我看看」她只能说「下次吧」，或者假装发了。和偶像来往时最自然的一件事做不到。
- 部署者手上有 NovelAI 的订阅或中转，却没有地方把它接进来；用户有自己的 NovelAI token，也没法自带。
- 生成图片这件事本身有风险：NovelAI 不过滤内容，中转会悄悄改参数，图片里还带着我们拼的提示词。要是随手接进来，可能出越界的图、漏提示词，也可能被一个人刷光部署者的额度。

## Solution

1. **怎么要**：制作人在文字回合或通话里明确要照片（「发张照片」「自拍一张」「让我看看你今天的衣服」「拍一下你的便当」），判断模型认出来，她就知道这回合可以发。只问「你在干嘛」「你穿什么」「好想见你」不算。
2. **她决定发不发、怎么拍**：她愿意发，就在回复最前面写一个照片标签，写明拍法（自拍或别人帮她拍）、景别、地点和时间、服装、动作和表情。她也可以按人设和情境推掉；好感度在冷淡这一档时她一定不发。越界的要求她用自己的话推掉，或者换成全年龄的版本再拍。
3. **服务器生成**：标签一写完就开始生成，和她说话的时间重叠。服务器把她写的几栏清洗过、剥掉越界的 tag，拼上这位角色固定的角色 tag 和外貌 tag、部署者设的画风、写死的全年龄约束，发给 NovelAI（官方接入点或中转）。拿回来的图核对尺寸，转成 webp、去掉元数据，存进数据库，挂在她那条回复上。
4. **在对话记录里**：照片是她那条回复的第一块，在她的话前面。生成中先占一块同样大的位置，到了直接换上，点开整屏放大。没发出来时换成一块写着原因的说明。之后她记得自己发过一张什么样的照片，也知道哪张没发出去。
5. **在通话里**：电脑上台词卡上方有一张小卡，手机上是一颗胶囊，点开放大。通话层收起时，外壳顶上的通话条提示「新照片」。她挂断以后才到的照片不上结束卡，照样挂进记录。
6. **次数**：照片单独计次，每人每小时默认 5 张。用完时她用自己的话推掉，对话里另外出一颗胶囊，写明几点以后可以再要。用自带生图 key 的不计入。
7. **谁出钱**：部署者在后台新开的「生图」标签页配（NovelAI 官方格式或 OpenAI 图像格式），用户也能在设置页「自带密钥」里自带生图，和其他自带密钥一样只存在浏览器里。都没有时、或者部署没有判断模型时，没有照片，她也不知道自己能发，一切和现在一样。
8. **只有本人能看**：照片只有对话的主人能经同源接口读，管理者看不到。它跟着对话删除，不能单独删，会进加密备份。

## User Stories

1. 作为制作人，我想说「发张自拍给我」就收到她的一张照片，这样我能看到她此刻的样子。
2. 作为制作人，我想让「拍一下你的便当」这类要拍别的东西的请求也能收到照片（里面有她），这样我不用斟酌措辞。
3. 作为制作人，我想在只问「你在干嘛」「你今天穿什么」时她照常用话回答、不突然发图，这样照片只在我真想要时出现。
4. 作为制作人，我想让她按当时的时间和对话情境拍（深夜在房间、下午在事务所），这样照片和我们正在聊的事对得上。
5. 作为制作人，我想指定地点或服装（「穿着睡衣拍一张」），她在全年龄范围内照办，这样我能看到想看的样子。
6. 作为制作人，我想让她有时按人设推掉（害羞、正忙），这样她像一个有自己意愿的人，不是拍照机。
7. 作为好感度还在冷淡一档的制作人，我想她不给我发照片，这样关系的进展有分量。
8. 作为制作人，我想照片里一眼认出是她（发色、发型、瞳色都对），连冷门的偶像也一样，这样照片才有意义。
9. 作为制作人，我想自拍和别人帮她拍看起来不同（自拍是近景、半身，别人拍能到全身），这样照片有变化。
10. 作为制作人，我想在她的话还在一段一段出来时，就看到照片的位置先占好，这样我知道照片在路上，到了时位置也不跳。
11. 作为制作人，我想照片显示在她的话前面，这样读起来是「先发图，再说话」。
12. 作为制作人，我想点照片整屏放大，点外面或按 Esc 关掉，这样能看清细节。
13. 作为制作人，我想在照片没发出来时看到「照片没发出来」和简短的原因，这样我知道不是她在耍性子。
14. 作为制作人，我想在照片没发出来之后问「照片呢」，她能自然地接上（她知道没发出去），这样对话不会前后矛盾。
15. 作为制作人，我想以后提起「你上次发的那张」她知道是哪张，这样照片是我们共同的记忆。
16. 作为制作人，我想在照片还在生成时刷新页面，照样看到生成中的占位，之后换成照片或失败说明，这样刷新不会把照片弄丢。
17. 作为制作人，我想在照片生成时照样能发下一句话，这样我不用干等十几秒。
18. 作为制作人，我想在这一小时的照片用完时，看到一颗胶囊写着「这一小时的照片用完了，HH:MM 以后可以再要」，这样我知道什么时候再来。
19. 作为制作人，我想在次数用完时她用自己的话推掉，而不是系统报错，这样她不出戏。
20. 作为通话中的制作人，我想说「拍一张给我看」也能收到照片，这样通话和打字一样。
21. 作为在电脑上通话的制作人，我想照片出现在台词卡上方的一张小卡里、不挡她的脸，点开能放大，这样我边听边看。
22. 作为在手机上通话的制作人，我想照片先是一颗「发来一张照片 · 点开看」的胶囊，点了再放大，这样小屏上不挡画面。
23. 作为通话中的制作人，我想在生成中看到「正在拍照…」，失败时看到「照片没发出来 · 原因」，这样我知道进展。
24. 作为把通话层收起、在看别的页面的制作人，我想外壳顶上的通话条提示「新照片」，这样我不会错过；展开通话层或打开她的对话页后提示消失。
25. 作为通话里要了照片、她却先挂了电话的制作人，我想之后在对话记录里看到那张照片，这样照片不会因为挂断丢掉。
26. 作为制作人，我想在对话列表和历史对话里看到最后一句前面有一个相机图标（照片发出来时），这样一眼知道她最后发了照片。
27. 作为制作人，我想照片和那段对话一起删除，删历史对话、删账号时照片彻底没了，这样「删了就没了」是真的。
28. 作为制作人，我想没有人（包括管理者）能看到她发给我的照片，这样我放心。
29. 作为制作人，我想照片和对话一样进备份，这样服务器出事恢复以后照片还在。
30. 作为用自己 NovelAI token 的制作人，我想在设置页「自带密钥」里填上生图（接口形式、地址、key、模型），这样照片花我自己的钱、不占部署者的次数。
31. 作为自带生图的制作人，我想保存前真生成一张来检查，这样填错了当场就知道。
32. 作为自带生图的制作人，我想我的 key 只存在我的浏览器里，这样服务器不保存它。
33. 作为自带生图 key 失败的制作人，我想看到「你的生图密钥没能用」和一个「去设置自带密钥」的链接，而不是被悄悄换成部署者的 key，这样我知道问题在哪、去哪修。
34. 作为自带生图的制作人，我想用自己 key 生成的照片不计入每小时的次数，这样我想要多少张都行。
35. 作为只带了自带 LLM、没带生图 key 的制作人，我想回合照旧不计入、照片照常计入，这样规则一目了然。
36. 作为只能用自带的用户（限额为 0），我想没带生图 key 时她就当不能发照片，这样不会出现说了发却发不出来的情况。
37. 作为在没有判断模型的部署里的用户，我想自带生图的检查直接告诉我「这个部署发不了照片」，这样我不白花钱。
38. 作为部署者，我想在后台「生图」标签页填接口形式、地址、key、模型、同时生成几张、画风，保存时真生成一张来检查，这样配好就能用。
39. 作为部署者，我想只配 `.env`（`NOVELAI_*`）也能开照片，这样不进后台也能部署。
40. 作为用中转的部署者，我想选「OpenAI 图像格式」并手填中转的模型名，这样大多数中转都能接上。
41. 作为部署者，我想在会悄悄换尺寸的中转上保存时就被拦下，这样不会每张都出错。
42. 作为部署者，我想设一段画风（比如画师 tag 加权重），所有角色共用，自带生图的照片也生效，这样整个站的照片风格统一。
43. 作为部署者，我想仓库里默认不写任何画师名，这样公开仓库不替我承担模仿画风的风险。
44. 作为部署者，我想设「同时生成几张」（默认 1，官方 token 一次一张），这样用中转时可以调高、用官方 token 时不撞 429。
45. 作为部署者，我想在「限额与玩法」页设每人每小时几张照片（0 表示不限），这样控制花费。
46. 作为管理者，我想给单个用户设照片的每小时限额（跟全站、不限、只能用自带），这样和回合、通话的限额一样管。
47. 作为部署者，我想生图不能选进免限额密钥，这样打电话不会因为没带生图 key 就不能免限额。
48. 作为部署者，我想在看板上看到生图的调用、张数、失败原因和花费（官方预设每张 0.036 美元，中转自己填），这样知道钱花在哪。
49. 作为部署者，我想看到每次剥掉了越界 tag 的记录，这样知道照片说明要不要收紧。
50. 作为国内服务器的部署者，我想给部署者的生图和自带生图分开勾网络代理，这样两边各用各的通路。
51. 作为部署者，我想自带生图只在连 NovelAI 官方地址时才走代理、连中转时直连并做公网检查，这样服务器不会被借去访问内网。
52. 作为部署者，我想文档里写明 NovelAI 条款禁止把一个订阅给公众共用、中转随时可能断，这样我知道自己要负的责任。
53. 作为部署者，我想文档里写明需要什么样的中转（原样返回要求的尺寸，只支持两种接口形式），这样我选中转时心里有数。
54. 作为部署者，我想没配生图时一切和现在一样，她不提照片，这样不想开的部署不受影响。
55. 作为部署者，我想不论谁的 key，照片都只出全年龄内容，部署者和用户都改不了，这样站点不会出越界的图。
56. 作为部署者，我想黑名单命中时只剥掉那个 tag、照片照发，这样她说了发就一定有图（或者写明原因的失败）。
57. 作为部署者，我想官方 token 一次只跑一张、多人要时按先后排队，排不到 90 秒内的按超时失败，这样不撞限流也不无限等。
58. 作为部署者，我想超时不自动重试，这样不会因为上游还在生成而重复扣钱。
59. 作为部署者，我想图片里的提示词元数据被去掉，这样我们拼的提示词不会跟着照片流出去。
60. 作为维护者，我想 28 位偶像各有一个角色 tag 和一串外貌 tag，由代理写初稿、用户校对，这样每位都像。
61. 作为维护者，我想有一份本地 tag 表（白名单和改写表），运行时只查表，这样她写的同义词能改成模型认识的写法。
62. 作为维护者，我想判断模型新加的那道题有评测集和按模型校的阈值，这样漏判、误判都可以量出来。
63. 作为维护者，我想服务器重启时还在生成的照片被记成超时，这样记录里不会永远挂着「生成中」。
64. 作为用户，我想在隐私政策里看到照片存在哪、发给了谁、管理者看不到，这样我知道系统怎么对待它。
65. 作为用户，我想在使用条款里看到自带的 key 由我自己遵守那项服务的条款，这样我清楚自己的责任。

## Implementation Decisions

### 能不能发照片：这个回合的「照片资格」

- 每个回合（文字和通话一样）开始时，服务器先算出这个回合的照片资格：
  - **用谁的生图**：用户这次请求带了自带生图 key，就用自带的；否则部署者配了生图就用部署者的；都没有就是「没有生图」。
  - **能不能发**：没有判断模型、没有生图，或者用户的照片限额为 0 而又没带自带生图 key：这回合与照片无关，判断模型不问，她的提示词里也不提照片，和现在完全一样。
  - **次数够不够**：用部署者的生图时，按照片限额只查不扣，得到「还能发」或「用完了，`retry_at`」。用自带的不查。
- 前端不需要知道能不能发。对话页不加任何开关或提示。

### 判断模型：多答一道「是不是在要照片」

- 照片资格允许时，判断模型多答一道是非题：「制作人是不是在要她发一张照片或图片（拍什么都算）」。它和检索、好感度的几道题放在同一次请求里；检索和好感度都关着时单独问一次，和其他准备工作同时跑，照着好感度单独判断的做法。
- 阈值偏高，宁可漏判。`judge_thresholds` 加一项 `photo`，Jev、Clef、Clef-flash 各校一个；后台的阈值覆盖照旧能改它。判断失败时当作「否」，回合照常进行。
- 评测集加一类照片用例，要照片的和不算要照片的都有（「发张照片」「自拍一张」「让我看看你今天的衣服」「拍一下你的便当」/「你在干嘛」「你今天穿什么」「好想见你」），评测命令照旧能跑。
- 判断模型、检索、记忆提炼读的都是去掉标签的台词，不读照片的情境。

### 她的提示词：照片说明

- 判断说「是」时，ADR-0020 那条每回合都会变的系统消息里加一段照片说明，不动前面能缓存的部分。说明分三种：
  - **能发**：标签格式；照着现在的时间和对话情境拍，用户指定的地点、服装在全年龄范围内照办；哪些不拍（就是下面黑名单那几类），越界时可以推掉，也可以换成全年龄的版本；她可以不发。
  - **好感度在冷淡一档**：「他在要照片，你现在不想给」。
  - **次数用完**：「他在要照片，但你这会儿发不了」。
- 后两种情况下，她写了标签也丢掉。判断说「否」的回合，她写的标签一律丢掉。一个回合最多一张，写了多个只取第一个，其余丢掉。丢掉的标签不进记录。
- 系统说明里另加一句：历史里标了 `status="failed"` 的照片，对方没收到。

### 照片标签

- 她在回复的**最前面**、第一个 `<ja>` 之前写一个 `<photo>` 标签，一行一栏。栏名用英文，便于解析：

  ```
  <photo>
  shot: selfie            # selfie | other（别人帮她拍）
  framing: upper body     # portrait | upper body | cowboy shot | full body；selfie 只能 portrait、upper body
  place: cafe, indoors, afternoon, sunlight     # 2–4 个英文 tag：地点、室内外、时段或天气、光线
  outfit: white shirt, cardigan                 # 1–4 个英文 tag：一套衣服，只写这个景别里看得见的
  action: peace sign, smile                     # 2–4 个英文 tag：一个动作，1–2 个表情，不看镜头时加一个视线
  note: 在咖啡店给他拍的自拍                       # 一句中文，只给她自己回看，不进提示词
  </photo>
  ```

  三栏 tag 合计不超过 12 个。不许写外貌（发色、瞳色、发型、身材），也不许写画风或画师。栏名、注释的确切写法由实现定，照片说明里给她看的格式要和解析器一致。
- 回复解析器把标签单独拿出来，`</photo>` 一到就交出一个「照片标签」事件。标签不送去合成语音，也不当字幕显示；文字回合和通话里都一样。不在最前面的 `<photo>` 当作没写，从台词里剥掉。
- **她之后怎么知道**：照片表那一行存着她写的整个标签。之后的回合，历史里她那条回复前面照原样带回这个标签；照片没发出去的加上 `status="failed"`，还在生成的照常带回、不加标记。

### 拼提示词

- 正面依次是（来自票 04、05、06、11 的决定）：

  ```
  1girl, solo, <角色 tag>, idolmaster shiny colors, <画风>, <外貌 tag>,
  <拍法 tag>, <景别 tag>, <地点>, <服装>, <动作和表情>,
  rating:general, very aesthetic, masterpiece, no text
  ```

  - 拍法：`selfie` 换成 `selfie, looking at viewer`；`other` 时动作栏没写视线就补 `looking at viewer`。不用 `pov`、`holding phone`、`photo (medium)`。
  - 景别：`portrait` / `upper body` / `cowboy shot` / `full body`，自拍写了后两种就改成 `upper body`。
  - 画风是部署者配的那一段，原样插入、不清洗，可以带数值加权和多位画师；空着就整段不出现。
  - 末尾的质量 tag 照 V5 官方的 standard 写法，自己拼，不靠服务端开关。
- 负面依次是：`nsfw`、Human Focus 预设（Heavy 加 `@_@, mismatched pupils, glowing eyes, bad anatomy`）、`nude, nipples, underwear, bra, panties, bra strap, strap slip, see-through, pantyshot, cleavage`。
- 写死的参数：832×1216、23 步、scale 7、`k_euler_ancestral`、一次一张、随机种子。请求体统一按 V4 以后的格式（`v4_prompt` / `v4_negative_prompt`，单角色不写 `char_captions`）。后台和自带都不能配尺寸、步数、负面词和黑名单。
- **清洗她写的三栏**：剥掉语法字符（`{}`、`[]`、`::`、`|`、`#`、引号、`Text:`、数字权重），转小写、下划线换空格、去重，每栏超量截断；查本地 tag 表做改写（比如 `v sign` 改成 `peace sign`）；外貌、画风和黑名单里的 tag 剥掉。查不到的 tag 保留并写日志，不拦着出图。
- **黑名单**（ADR-0023，所有偶像一条线）：裸露和半裸、内衣和情趣服装（含 `micro bikini`、`sling bikini`、`slingshot swimsuit`、`school swimsuit`）、透视和走光（含 `wet clothes`、`downblouse`）、洗澡场景（`bath`、`shower`、`onsen` 等）、性化的镜头和姿势（`ass focus`、`from below`、`spread legs`、`bent over` 等）、性化的表情（`ahegao`、`seductive smile` 等）。泳装、睡衣、`lying`、`on bed`、`sleeping`、泳池、海边放行。代表词见票 06；实现时用官方 tag 建议接口（V5 Curated）把同义和相近的 tag 补全，负面细项也逐个核对是已知 tag。
  - 命中只剥掉那一个，剩下的照常生成。某栏剥空了补默认值：服装补 `casual`，地点补 `indoors`，动作补 `smile`。不算失败。
  - 每次剥掉都在那次生图调用上记下剥掉了几个、各属于黑名单哪一类，不记她写的其他 tag（管理者看不到对话内容，ADR-0013）。
- **本地 tag 表**：开发时用官方 tag 建议接口（按模型返回）批量生成白名单和改写表，连同补全的黑名单一起进仓库，运行时只查这份表，不调建议接口，也不用 Danbooru 词表。生成脚本也进仓库，以后能重跑。

### 角色配置

- `characters.toml` 每位角色加两项：`photo_tag`（角色 tag，Danbooru 写法，比如 `sakuragi mano`）和 `photo_appearance`（一串外貌 tag，只写发色、发型、瞳色，不写饰物和服装）。角色 tag 另存、不从 `name_romaji` 推，因为 Danbooru 的写法和我们的罗马字规则不是一回事。
- 28 位的初稿由代理对着存储桶里默认衣装的缩略图写，参考 Danbooru 共现 tag（不能直接用，团体图里会混进别人的特征），再用官方 tag 建议接口核对每个 tag 都是已知的，最后交用户校对。票 05 里的五位已经定稿，照用。
- 缺这两项的角色不能发照片（照片资格当作「没有生图」），启动时写一条警告。

### 生成：生图客户端

- 新加一个生图客户端模块，对外一个「生成一张」的接口：给它接入点配置（接口形式、地址、key、模型）、正面和负面提示词，它返回一张核对过的图，或者一个失败原因。只有服务器调它，前端从不直接调生图服务，自带的 key 也一样。
- **两种接口形式**，由配置的人选，不自动探测：
  - **NovelAI 官方格式**（官方接入点和原样转发的中转）：地址填到域名根，默认 `https://image.novelai.net`，服务器拼 `/ai/generate-image`，`Authorization: Bearer`，返回 ZIP。
  - **OpenAI 图像格式**：地址照 OpenAI 的惯例填到 `/v1`，服务器拼 `/images/generations`，带 `response_format: "b64_json"` 和顶层的 `size`、`negative_prompt`。收 `b64_json`（带不带 `data:` 前缀都行）；回 `url` 就用同一个客户端立刻下载（同样受公网检查和代理规则约束，耗时算进总时限）。chat 形状的返回不认。
  - 切换接口形式时不自动改地址。OpenAI chat 兼容和各家自定义的中转不支持。
- **核对图**：响应能解开、里面正好一张图、宽高是 832×1216。不满足就是「返回的图不对」。不做纯色检测。
- **转码**：转成 webp（质量 85 左右），尺寸不变，去掉全部元数据（PNG 里带着完整提示词）。不留原图，不做缩略图。Pillow 现在只是间接依赖，要写进后端的直接依赖。
- **排队**：按 token 排队，每个 token 有「同时生成几张」的上限，等不到的先进先出，不限队列长度。部署者的上限来自配置（默认 1），自带的固定 1。
- **总时限 90 秒**：从标签写完算起，包括排队、生成和下载 `url`，写死。超时就是「超时」；超时以后晚到的结果丢掉。不自动重试，也不给重试按钮。
- **网络**：部署者的生图走 `ProxiedService` 的 `image`，勾上就全走代理，接入点不受限制。自带的走 `own_image`，照 ADR-0022：只有 HTTPS 的 `image.novelai.net` 算已知服务商，勾上才走代理；其他地址一律直连。公开部署里自带的地址必须是 HTTPS 的公网地址，每次连接都查（复用现有的公网检查后端）。
- 自带 key 失败时，照现有规则不悄悄改用部署者的 key，错误里的 key 打码。

### 一张照片的生命周期

- **扣次数**：标签写完、要开始生成时，用部署者的生图才扣一张。这时恰好被别处用完（同一个人文字和通话同时在用），就按「次数用完」记成失败，不生成。用自带生图 key 的照样写一行用量，标记为不计入。
- **照片表**：新建一张照片表，一行对应她的一条回复。存所属对话、那条回复、她写的标签、状态（生成中 / 发出来了 / 没发出来）、失败原因、webp 图片和时间。
  - 失败原因是固定的几种：`timeout`（包括排队超时）、`service_error`、`bad_image`、`own_key_failed`、`used_up`。
  - 读记录、对话列表时不把图片一起读出来，图片只在读图的接口里取。
  - 登记进用户数据和「随对话删除」的名单：删历史对话、删用户时一起彻底删掉。不能单独删某一张。
- **挂到回复上**：标签写完时先在内存里开一个照片，拿到照片 id 推给前端；那条回复写进记录时，照片表同时写一行「生成中」挂在回复上；生成完再把这一行改成「发出来了」（带图）或「没发出来」（带原因）。生成比回复先完成时，等回复写进记录再落库。
- **回复不在了**：回复没写进记录（这回合失败了），或者生成完时那条回复已经不在（对话被删、账号被删），生成完直接丢掉，不存。这期间她结束了对话、用户开了新对话、通话挂了、页面关了，都不影响，照样存下、挂上去。页面关了也不中途取消，钱已经花了。
- **退还次数**：失败的照片把次数还回去（「次数用完」那种本来就没扣）。生成出来、却因为回复不在了被丢掉的不退。
- **服务器重启**：启动时，照片表里还是「生成中」的行一律改成「超时」。
- **计费**：每次真的发出去的生图请求都在运行记录里记一条生图调用，挂在那个回合的运行记录下面（同一个 `record_id`），回合已经结束也一样。失败的带上错误原因。只有确实拿到了图（包括尺寸不对的错误图）才记 1 张用量；HTTP 报错、超时记 0 张；排队超时的请求没发出去，不记调用。

### 接口和事件

- **文字回合（SSE）** 加两种事件：
  - `photo`：`{type: "photo", id, status: "pending"}`，标签写完时推，在她的第一段话之前。
  - `photos-used-up`：`{type: "photos-used-up", retry_at}`，照片资格是「次数用完」、而判断说她在要照片时推。
  - SSE 照旧在 `done` 时结束，不为照片多等，所以生成中也能发下一句。
- **通话（RTVI 服务器消息）** 加：`photo` 带 `reply` 编号，`status` 是 `pending`、`ready` 或 `failed`（带 `reason`），后两种在生成完、通话还连着时推。`photos-used-up` 同文字回合。
- **读记录**：对话记录里她那条回复带上 `photo: {id, status, reason}`（没有照片时没有这一项），这样刷新以后占位、照片、失败说明都还在。
- **读照片**：
  - `GET /api/photos/{id}`：返回 `{status, reason}`，前端在生成中时用它轮询。
  - `GET /api/photos/{id}/image`：返回 webp，`Cache-Control: private` 加长缓存，不让 CDN 缓存。
  - 两个都要登录，只有照片所在对话的主人能读，别人一律 404。CSP 的 `img-src` 已经有 `'self'`，不用改。后台不出任何查看照片的入口。
- **怎么等结果**：文字回合里、刷新以后，以及通话挂断后才到的照片，前端都靠轮询照片状态等结果（间隔约 2 秒，直到不是「生成中」）。通话还连着时，靠服务器推的 `photo` 事件。
- **对话列表的最后一句**：最后一条是带照片、而且照片发出来了的回复时，最后一句带上一个标记，前端在前面加相机图标。照片没发出来、还在生成时不带。

### 限额

- 用量表新加一种 `photo`，和回合、通话一样按人、按滑动一小时计数。
- 全站默认每小时 5 张，环境变量 `EIDOLON_PHOTOS_PER_HOUR`，后台「限额与玩法」页现有的限额卡加一项，0 表示不限。
- `user_limits` 加一列 `photos_per_hour`，管理者给单个用户设限额的弹窗加上这一项：空值跟全站，-1 不限，0 只能用自带。
- 文字回合和通话里的照片共用同一个次数。界面上不显示剩余几张。
- **免限额**：只看这张照片花的是谁的钱。带了自带 LLM 但没带生图 key，回合照旧不计入，照片照样计入。「生图」**不能**选进免限额密钥：`Service` 加上 `image`，但 `exempting_*` 和 `EIDOLON_EXEMPTING_*` 仍然只有 LLM、语音合成、语音识别三项，不要按服务列表自动生成出 `exempting_image`。

### 后台配置

- 新开一个「生图」标签页，放在「语音」后面，只有一张生图卡：接口形式、接口地址、key、模型、同时生成几张（默认 1，按 token 算）、画风（自由文本，默认空）。
- 模型是下拉加手填：下拉里放 V4 以后的官方模型名（V5 Curated/Full、V4.5 Curated/Full、V4 Curated/Full），默认 `nai-diffusion-5-curated`，原样发给接口。
- **保存时的检查**：只在这张卡改了时，真的生成一张图：用固定的提示词，带上画风，用正式的尺寸，验 key、接口形式、返回能不能解开、宽高对不对。这张图不计用量、不进运行记录。失败照现有的「试调失败，没有保存：…」。
- 只配 `.env` 时的环境变量：`NOVELAI_API_FORMAT`（`novelai` 或 `openai`，默认 `novelai`）、`NOVELAI_BASE_URL`（默认 `https://image.novelai.net`）、`NOVELAI_API_KEY`（没填就是部署者一侧没有生图）、`NOVELAI_MODEL`（默认 `nai-diffusion-5-curated`）、`NOVELAI_CONCURRENCY`（默认 1）、`NOVELAI_STYLE`（默认空）、`EIDOLON_PHOTOS_PER_HOUR`（默认 5）。`EIDOLON_PROXY_SERVICES` 新认 `image`、`own_image`，网络代理那张卡也加上这两项。
- 新加一项服务时照现有的那份清单都要动：设置、代理服务名、后台配置项、运行记录的服务名（`image`，中文「生图」）、单价、前端的后台配置和看板文案。

### 单价

- 计量单位新加「张」（`images`），单价按每张填，不按每百万。单价表的单位、后台设单价的接口和前端的单位文案都要加。
- 预设单价：官方 `nai-diffusion-5-curated` 每张 0.036 美元（832×1216、23 步、26 Anlas 的付费价），标上查价日期 2026-10-17。用 Opus 订阅时实际在额度内不花钱，这个预设偏保守。中转没有预设，由管理者自己填，没填就和现有没设单价的服务一样显示。自带 key 的调用照现有规则只统计用量、不计价。

### 自带生图

- 设置页「自带密钥」加一项生图，填接口形式、接口地址、key、模型四项，默认值和后台一样，只存在浏览器里。不出「同时生成几张」和画风。这一项一直显示。
- 保存前调 `POST /api/account/keys/image/check`：花用户自己的钱真生成一张，规则和后台的检查一样，不计用量、不进运行记录。部署没有判断模型时直接拒绝：「这个部署发不了照片」，不生成。
- 文字回合的请求体现在只带自带的 LLM，以后也带自带生图；通话本来就带全部。

### 前端

- **对话记录**（原型 A，见 `prototype/photos-presentation` 分支）：
  - 照片是她那条回复的第一块，和话同在一组：头像和名字在照片这块上，话的气泡紧接在下面，时间照旧只在最后一条气泡的外侧。宽 192px，按 832×1216 等比缩放，圆角同气泡，不投影、不描边。
  - 生成中：同样大小的占位，`bg-foreground/8`，中间是 muted 的相机图标（慢慢闪）加转圈，不写字，读屏读「照片正在生成」。到了直接换上，位置不跳。
  - 失败：同宽的一块矮说明，`bg-foreground/5`，左边 muted 的 `ImageOff`，右边「照片没发出来」，下一行用 Meta 字号写原因：超时「等太久了」、服务报错「生图服务出错了」、图不对「生成的图不对」、自带 key 失败「你的生图密钥没能用」加一行站内链接「去设置自带密钥」、次数用完「这一小时的照片用完了」。不给重试按钮。
  - 点开放大：整屏浮层，压 85% 黑，照片按比例放到最大，右上角 ✕，点外面、按 Esc 都能关。不加保存、分享按钮。
- **次数用完的胶囊**：收到 `photos-used-up` 时，在她推掉的那条回复后面插一行居中的胶囊，样子和变化胶囊一样（`bg-foreground/10`、Meta 字号、muted），muted 的 `CameraOff` 加「这一小时的照片用完了，HH:MM 以后可以再要」。这行也把前后分成两组。不存进库，刷新后就没了。通话里收到时也进对话记录，通话层上不另外提示。
- **通话层**（按通话层盖住的范围分）：
  - 电脑（只盖住对话栏）：台词卡上方一张毛玻璃小卡（`bg-white/12`、`backdrop-blur-md`、`rounded-2xl`、`p-1.5`），里面是 128px 宽的照片，点开放大。生成中是同样大小的占位加转圈和「正在拍照…」；失败写「照片没发出来 · {原因}」。卡一直留着，这通电话里有了下一张就换成下一张。
  - 手机（铺满整屏）：台词卡上方只出一颗毛玻璃胶囊：生成中「正在拍照…」加转圈，到了相机图标加「发来一张照片 · 点开看」、点了放大，失败「照片没发出来 · {原因}」。
  - 都放在台词卡和底栏上面，不挡她的脸，有没有立绘都一样。
  - 收起时到了照片：只有外壳顶上那条通话条（ADR-0018）在状态后面加一个相机图标和「新照片」，展开通话层或打开她的对话页后消失。她对话页页首下面那条通话条不提示。
  - 她挂断后才到：结束卡上不带照片，照片照常挂进记录。
- **对话列表和历史对话面板**：最后一句带照片标记时，前面加一个 14px 的 muted 相机图标，后面照旧是她的话，写法和对话事件「图标加原文」一样。
- **自带密钥和后台**：设置页的自带生图表单、后台的「生图」标签页和生图卡、限额卡的照片一项、单个用户限额弹窗的照片一项、代理卡的两项、看板的服务名和单位。
- 图标在语义别名表里加 `Camera`、`CameraOff`、`ImageOff`。`DESIGN.md` 补上照片这几处：对话记录、点开放大、次数用完的胶囊、通话层电脑和手机两种、外壳顶上通话条的「新照片」、列表最后一句。按 `frontend/AGENTS.md` 的 shadcn 纪律写，文案进中文文案表，界面上不加其他说明。

### 文档和条款

- `docs/configuration.md`（以及英文、日文版）加生图一节：两种接口形式怎么填、环境变量、画风怎么写（仓库默认空，不推荐具体画师）、需要什么样的中转（原样返回 832×1216、只支持这两种接口形式）、条款风险（NovelAI 禁止把一个订阅给公众共用，拿官方 token 对外开放由部署者自己负责；中转随时可能被封、断掉）。
- **隐私政策**改三处，更新日期跟着改：
  - 「我们保存哪些数据」→「对话」：她发给你的照片也存在对话里，只有你能看，随那段对话一起删除，也会进备份。
  - 「这些数据会交给哪些第三方处理」：新加「生图服务」。发出去的是描述照片的英文 tag（地点、服装、动作，由角色根据对话写出），不发你说的原话；发给部署者配置的生图服务，填了自带密钥就发给你自己选的服务。
  - 「管理者能看到什么」→「看不到」：加上她发给你的照片。
- **使用条款**加一条通用的「自带密钥」：你自带的 key 由你自己遵守那项服务的条款（例如年龄、用途），LLM、语音合成、语音识别、生图都适用。更新日期跟着改。界面上不加 18 岁提示。

## Testing Decisions

- 好的测试只测对外的行为：HTTP 接口和事件流给出什么、记录里留下什么、发给生图服务的请求长什么样，不测表结构和内部怎么拼。
- **后端只有一个接缝：外发的生图 HTTP 请求。** 照旧用 `make_client` 驱动真的应用（`FakeLLM`、假判断模型），在 httpx 传输层装一个假的生图服务。它按两种接口形式回图（官方格式回 ZIP，OpenAI 图像格式回 `b64_json` 或 `url`），能造出慢、HTTP 报错、尺寸不对、解不开这几种情况，并记下收到的每个请求。拼提示词、清洗、黑名单、写死的负面词和参数，都靠这些请求体断言，不另立模块测试。先例是 `test_text_turn.py`、`test_she_ends_conversation.py`、`test_affinity_turns.py`、`test_rate_limit.py`、`test_own_llm.py`、`test_proxy.py`、`test_live_config_services.py`、`test_delete_past_conversations.py`、`test_database.py`、`test_activity_records.py`、`test_cost_estimate.py`；通话用 `test_voice_call.py` 的夹具和 `browser.py` 的 RTVI 客户端。要测的有：
  - 照片资格：没有判断模型、没有生图、限额为 0 又没带生图 key 时，判断模型不问照片、她的提示词里没有照片说明。
  - 判断「是」时提示词里有照片说明，冷淡一档、次数用完各是对应的说明；判断「否」、冷淡、用完时她写的标签被丢掉、不生成、不进记录。
  - 标签不进字幕、不进语音、不在 `done` 的台词里；只取第一个；不在最前面的被剥掉。
  - 发给生图服务的提示词：前缀、角色 tag、外貌 tag、画风、拍法和景别的换写、清洗（语法字符、大小写、去重、截断、改写表）、黑名单剥掉和剥空补默认、`rating:general`、负面词和写死的参数。两种接口形式各一遍。
  - 成功：SSE 的 `photo` 事件、记录里的 `photo`、读状态和读图的接口、webp 里没有元数据。
  - 失败的每一种原因：超时（含排队超时）、服务报错、尺寸不对、自带 key 失败（不改用部署者的、key 打码）、扣次数时恰好用完。失败行刷新后还在；之后的回合历史里带 `status="failed"`。
  - 排队：部署者 token 一次一张时第二张等第一张；排队超过 90 秒按超时、请求没发出去、不记调用。
  - 回复不在了（对话删了、账号删了）时生成完不存；她结束对话、通话挂了以后照样存下。
  - 启动时把「生成中」改成超时。
  - 限额：每小时 5 张、回合开始只查不扣、生成时才扣、失败退还、自带生图不计入、带了自带 LLM 照片照样计入、文字和通话共用、单个用户的 `photos_per_hour`、`photos-used-up` 带 `retry_at`。
  - 免限额密钥里没有生图。
  - 运行记录：生图调用挂在回合下、张数和错误原因、剥掉 tag 的类别和个数、自带的不计价、官方预设单价。
  - 只有对话的主人能读照片（别人 404）；照片随历史对话、随用户删除；照片表登记在用户数据名单里。
  - 后台生图卡保存时真生成一张、失败不保存、尺寸不对被拦下；环境变量生效；代理的两项。
  - 自带生图检查：成功、失败、没有判断模型时拒绝；自带地址的公网检查和只对官方地址走代理。
  - 通话：RTVI 的 `photo` 三种状态、`photos-used-up`、挂断后才到的照片挂进记录。
- **判断模型那道题**：评测集里加照片用例，用评测命令给三个模型各校阈值，结果记进对应的票。不进单元测试。
- **前端**：Vitest 测 `lib/` 里的纯模块，组件不写测试。先例是 `conversationLog.test.ts`、`messageLines.test.ts`、`conversationList.test.ts`、`localOwnKeys.test.ts`、`adminConfig.test.ts`、`api.test.ts`、`callEnd.test.ts`。要测的有：
  - 对话状态收到 `photo`、`photos-used-up` 和通话的 `photo` 以后怎么变，轮询结果怎么并进去，刷新后从记录里还原；
  - 照片块和她的话怎么分组，胶囊怎么把前后分开；
  - 最后一句什么时候带相机图标；
  - 失败原因对应的文案；
  - 自带生图存取、随回合和通话带上；
  - 后台生图标签页的字段和校验；
  - 外壳顶上通话条的「新照片」什么时候亮、什么时候灭；
  - 结束卡不带照片。
- **验收**：按 `docs/agents/local-acceptance.md` 在本地构建版上用 Playwright，宽屏和手机都看，生图走假服务：
  - 要照片：生成中、发出来、点开放大、刷新时还在生成、各种失败说明、次数用完的胶囊；
  - 通话：电脑上的小卡、手机上的胶囊、收起时的「新照片」、挂断后才到；
  - 列表最后一句的图标；
  - 设置页自带生图、后台生图标签页。

  真出图（用 `.env.novelai` 里的中转）只留给用户看像不像、画风对不对，出图前先报张数、等用户点头。

## Out of Scope

- 多人同框（组合伙伴等别的偶像一起出现在照片里）：第一版只拍她本人。
- 她不经要求主动发照片。
- 用户给她发图、让模型看图。
- 对已发的照片改图、重拍、换姿势；重试按钮。
- 照片导出、保存按钮、做成分享图。
- 「衣装 → tag」对照表：用户点名某张卡的衣装时，她只用通用的服装 tag 描述大概的样子，像不像不保证。
- 她自己选机位角度、对镜自拍：只有拍法和景别两个枚举。
- 横图、可配的尺寸和步数。
- 角色参考图和 Vibe Transfer。
- 生成后检查图片（本地分级模型、外部审核接口）：以后要补就加本地分级模型，见 ADR-0023。
- OpenAI chat 兼容和各家自定义（异步任务加轮询等）形式的中转。
- 按年龄分开的规则。
- 显示剩余几张；按天的照片限额。
- 管理者查看照片的任何入口。
- 照片单独删除；每人存多少张的上限；把照片表搬到私有存储桶。

## Further Notes

- **要用户做的**：校对 28 位偶像的角色 tag 和外貌 tag（代理写好初稿以后）；在线上后台填生图卡和画风（用户的部署填 `0.7::artist:rella::`）；用中转真出几张看像不像。出图花用户中转的额度，先报张数、等点头。
- 判断那道题的阈值、照片说明的措辞，上线后看判断的结果和剥掉 tag 的次数再调。
- 备份会随照片变大：一张约 150 KB，按每天一份留 30 天，一千张约多 4.5 GB 备份存储（ADR-0024）。真的大到不合适时，再把照片表搬到私有存储桶。
- 残余风险（ADR-0023）：中转悄悄忽略负面词时没有兜底；V5 偶尔漏出吊带这类擦边的细节；换成 Full 模型更容易出擦边的图。
- 用户的中转（`v2.ninijoker-api.com`）两种形式都开着：官方格式参数全部生效；OpenAI 图像格式只认顶层的 `negative_prompt` 和 `size`，种子和步数会被换掉。保存检查只验尺寸，所以它两种形式都能过；推荐填官方格式，负面词才确定生效。
