# 04: 拍板：怎么触发、谁来写提示词

Type: grilling
Status: resolved
Blocked by: 01

## Question

- 谁认出「制作人明确要她发照片」：判断模型每个回合多答一道是非题，还是给扮演角色的 LLM 一个发照片的工具，由它决定调不调？两者在误触发、她能不能拒绝、自带 LLM 的兼容性、通话里的延迟上各有什么代价。
- 她能不能拒绝：好感度低的时候、要求越界的时候、刚发过一张的时候。拒绝是她嘴上说的话，不生成。
- 提示词谁来写：扮演角色的 LLM 写情境（自然语言还是直接写 tag），再和这位角色固定的外貌描述拼起来？还是另外调后台模型把情境翻成 NovelAI 的 tag？情境里能有什么（场景、服装、动作、表情、镜头），不能有什么。
- 照片和这个回合的关系：一个回合最多一张？她的话和照片谁先谁后？她之后的回复怎么知道自己发过什么（记录里留一段照片的描述？）。
- 用户说的是「发张照片」还是「你现在在干嘛」这种模糊的话，边界划在哪。

## Answer

2026-10-17 拷问定下（grilling + domain-modeling；`GLOSSARY.md`「照片」已补）。写提示词的依据是「调研：NovelAI 提示词写法」，在 `research/novelai-prompting` 分支（提交 `fcb0f40`）的 `.scratch/photos/research/novelai-prompting.md`；出图样张在仓库外的 `E:/tmp/nai-prompting/out/`。

**谁认出在要照片：判断模型。**

- 判断模型每个回合多答一道是非题：「制作人是不是在要她发一张照片或图片（拍什么都算）」。和检索、好感度的几道题放在同一次请求里，不多一次请求，也不多等待。检索和好感度都关着时，单独为这道题调一次判断模型，和其他准备工作同时跑（参照好感度单独判断的做法）。
- 只有这个回合确实能生图时才问：部署者配了生图，或者用户自带了生图。都没有时不问，她的提示词里也没有任何照片相关的说明，表现和现在一样。没有判断模型的部署不提供照片。
- 宁可漏判，不要误判：阈值偏高，Jev、Clef、Clef-flash 各校一个，评测集里补上要照片和不算要照片的例子。判断失败时这个回合就当没在要照片，回合照常进行。
- 边界是「只有用一张图才能回应的要求」。算的：「发张照片」「自拍一张」「让我看看你今天的衣服」「拍给我看看」，以及「拍一下你的便当」这类要拍别的东西的（拍出来的照样有她，拍成什么样由她决定，她也可以不拍）。不算的：「你现在在干嘛」「你今天穿什么」「好想见你」。
- 不做工具：工具要多跑一轮，首字会变慢；它还可能让她主动发照片；而且一轮工具已经给了回忆剧情。

**她怎么发、能不能拒绝**

- 判断说「是」时，那条每回合都会变的系统消息里加一段照片说明（不影响提示词缓存），分三块：标签的格式；照着现在的时间和对话情境来拍，用户指定的地点、服装在全年龄范围内照办；她可以不发。
- 她愿意发，就在回复的**最前面**写一个 `<photo>` 标签，标签一写完就开始生成，和她说话的时间重叠。标签不送去合成语音，也不当字幕显示，由解析器单独拿出来。照片显示在她的话前面还是后面，交给「怎么呈现」。
- 拒绝始终是她嘴上说的话，不生成图。好感度在冷淡这一档时写死不发：说明改成「他在要照片，你现在不想给」，她写了标签也丢掉。疏远及以上都由她按人设和情境决定，可以推掉。越界的要求由「拍板：全年龄怎么守」定；次数上限由「拍板：失败、限额和计费」定，到了上限她用自己的话推掉。
- 判断说「否」的回合，她写出的 `<photo>` 一律丢掉。一个回合最多一张，写了多个只取第一个。
- 通话里和文字回合完全一样。

**标签的栏目，以及谁写什么**

| 栏 | 谁定 | 内容 |
|---|---|---|
| 拍法 | 她选，二选一 | 自拍 / 别人帮她拍。服务器换成固定 tag：自拍是 `selfie, looking at viewer`；别人帮她拍时，动作栏没写视线就补 `looking at viewer`。不用 `pov`、`holding phone`、`photo (medium)` |
| 景别 | 她选，四选一 | 近景 / 半身 / 大腿以上 / 全身，对应 `portrait` / `upper body` / `cowboy shot` / `full body`；自拍只能选前两个 |
| 地点和时间 | 她写 2–4 个英文 tag | 地点、室内外、时段或天气、光线 |
| 服装 | 她写 1–4 个英文 tag | 一套衣服，只写这个景别里看得见的 |
| 动作和表情 | 她写 2–4 个英文 tag | 一个动作，1–2 个表情，不看镜头时加一个视线 |
| 说明 | 她写一句中文 | 只给她自己回看，不进提示词 |

- 她写的三栏合计不超过 12 个 tag。不许写外貌（发色、瞳色、发型、身材），也不许写画风或画师 tag。
- 服务器写死的部分：
  - 前面依次是 `1girl, solo`、角色 tag、`idolmaster shiny colors`，外貌 tag 由「原型：外貌一致性」定。
  - 接着是拍法和景别对应的 tag。
  - 最后是质量 tag 和 `rating:general`。
  - 负面是负面预设加全年龄黑名单，后者归「拍板：全年龄怎么守」。
  - 画风由「原型：画风」定。
- 服务器对她写的部分要清洗：剥掉语法字符（`{}`、`[]`、`::`、`|`、`#`、引号、`Text:`），转小写、去重，每栏超量就截断，外貌、画风和越界的词用黑名单挡掉。
- 本地 tag 表：开发时用官方 tag 建议接口（按模型返回）批量生成白名单和改写表（比如 `v sign` 改成 `peace sign`、`casual outfit` 改成 `casual`），运行时只查这份表。查不到的 tag 保留并记日志，不拦着出图。不用 Danbooru 词表。
- 用户点名要某张卡的衣装时，她用通用的服装 tag 去描述大概的样子，像不像不保证。

**她之后怎么知道自己发过什么**

- 她的那条回复里记下整个标签。之后的回合，她的提示词里照原样带回去，所以她知道自己发过一张什么样的照片。
- 判断模型、检索和记忆提炼读的都是去掉标签的台词，不读照片的情境。
- 照片和回复在记录里是不是同一条，交给「拍板：照片存哪、留多久、谁能看」。

**新开的票，和不做的事**

- 新开「原型：画风」，排在「原型：外貌一致性」之后，重点比画师 tag。
- 不做：用来认出用户点名的卡面衣装的「衣装 → tag」对照表；她自己选机位角度；对镜自拍。
