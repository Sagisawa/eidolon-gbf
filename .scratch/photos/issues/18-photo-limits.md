# 18: 照片次数

**What to build:** 每人每小时默认最多 5 张照片。用完时她用自己的话推掉，她那条回复后面出一颗胶囊，写着「这一小时的照片用完了，HH:MM 以后可以再要」。部署者能改全站的默认值，管理者能给单个用户另设。失败的照片会把次数还回去。规格见 `../spec.md`「限额」一节，以及「一张照片的生命周期」的扣次数一条。

**Blocked by:** 16

**Status:** ready-for-agent

- [ ] **计数**：用量表新加一种 `photo`，按人、按滑动一小时计数，文字回合和通话共用。
- [ ] **配置**：全站默认是环境变量 `EIDOLON_PHOTOS_PER_HOUR`，默认 5，0 表示不限。后台「限额与玩法」页现有的限额卡加这一项。
- [ ] **单个用户**：`user_limits` 加一列 `photos_per_hour`，管理者给单个用户设限额的弹窗加上这一项。空值跟全站，-1 不限，0 只能用自带。
  - 限额为 0 的用户（没有自带生图时）照片资格就是「不能发」：判断模型不问，她不知道自己能发。
- [ ] **回合开始时只查不扣**。用完了就用「次数用完」那种照片说明（「他在要照片，但你这会儿发不了」），她写了标签也丢掉。
- [ ] **提示用户**：判断说「是」时，SSE 推 `photos-used-up`（带 `retry_at`）。
- [ ] **生成时才扣一张**。这时恰好被别处用完，就记成 `used_up` 失败，不生成。
- [ ] **退还**：失败的照片把次数还回去；因为回复不在了被丢掉的不退。
- [ ] **胶囊**：
  - 收到 `photos-used-up` 时，在她推掉的那条回复后面插一行居中的胶囊，样子和变化胶囊一样。内容是 muted 的 `CameraOff` 加「这一小时的照片用完了，HH:MM 以后可以再要」。
  - 这行胶囊也把前后分成两组。不存进库，刷新后就没了。
  - 图标别名加 `CameraOff`。
- [ ] 界面上不显示剩余几张。
- [ ] **`DESIGN.md`**：补上次数用完的胶囊。
- [ ] **测试**：
  - 每小时 5 张；回合开始只查不扣、生成时才扣；失败退还。
  - 扣次数时恰好用完记成 `used_up`；`photos-used-up` 带 `retry_at`。
  - 单个用户的三种取值；环境变量和后台覆盖。
  - 先例是 `test_rate_limit.py`、`test_usage.py`、`test_user_limits.py`、`test_live_config_limits.py`。
  - 前端：胶囊怎么插、怎么分组。
- [ ] **验收**：本地构建版上用 Playwright，把限额调成 1，要两次照片看到胶囊。
- [ ] `uv run pytest`、`uv run pyright`、`npm test`、`npm run typecheck` 全部通过。
