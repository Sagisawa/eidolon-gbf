# 10: 拍板：条款之下谁出钱

Type: grilling
Status: resolved
Blocked by: 01, 02

## Question

定图时定的是「部署者在后台配（官方或中转），用户也能自带」。「NovelAI 官方图像 API 现状」查到：NovelAI 服务条款禁止把一个订阅给公众共用（除非另签书面协议，查不到公开渠道）；用户自带自己的 token 是官方写明的用法，但要求每次生成由人发起、token 主人年满 18 岁。中转本身多半就是在共用订阅，随时可能被封号断掉。

要重新定：

- 部署者那一侧还要不要：只允许填中转（部署者自己承担中转的风险），完全不提供（只能自带），还是照旧允许填官方 token、由部署者自己对条款负责、我们只在文档里写明？
- 自带那一侧：官方 token 和中转都能填？界面上要不要提示官方 token 的条件（年满 18 岁、每次由人发起）——本站声明的门槛是 13 岁。
- 如果部署者那一侧只剩中转或什么都没有，「谁出钱」这件事对「失败、限额和计费」「后台配置和自带密钥」意味着什么（没配时她怎么回应、限额还要不要）。
- 要不要记 ADR（照片的生图费用由谁承担、为什么不用部署者的官方订阅）。

## Answer

2026-10-17 的 grilling 定下：**照旧，部署者和用户两侧都能填官方 token 或中转，代码不拦；条款风险靠文档和使用条款讲清楚。** 不记 ADR。

- **部署者那一侧：官方和中转都能填。** 文档写明 NovelAI 条款禁止把一个订阅给公众共用，拿官方 token 对外开放由部署者自己负责。不拦 `image.novelai.net` 的理由：中转的 A 形态和官方接口完全一样，只差 base URL，拦住官方地址挡不住换个反代的人，反而误伤只给自己用的私人部署和签了书面协议的部署。也不砍成「只能自带」：线上站点的部署者手上只有中转，那样主用法就没了。中转随时可能被封、断掉的风险同样写进文档，由部署者自己承担。
- **自带那一侧：官方 token 和中转都能填**，协议集合和部署者那一侧一样（在「后台配置和自带密钥」里定）。自带官方 token 是唯一完全合规的路子；中转由用户自己选、自己担后果。
- **18 岁门槛：界面不加字。** 官方 token 要求 token 主人年满 18 岁，本站门槛是 13 岁；这是用户和 NovelAI 之间的约定，我们不替它把关。使用条款加一条通用的「自带密钥」：自带的 key 由你自己遵守那项服务的条款（年龄、用途），对 LLM、语音合成、语音识别、生图都适用。措辞写规格时定，条款的更新日期跟着改。「每次生成由人发起、不自动刷量」本来就满足：照片只在用户明确要时发，一个回合最多一张，她不主动发。
- **术语表**：「部署者」补了「并自己对所用服务的条款负责」，「自带密钥」的费用一句改成「费用和遵守那项服务的条款都由用户自己承担」。
- **不记 ADR**：结果和定图时一样，只多了文档提醒和一条使用条款，回头改不费事。
- **对后面两张票**：问题都不变，交接写进了「失败、限额和计费」和「后台配置和自带密钥」的 Comments。
