# 14: 文字回合里她发来一张照片（主干）

**What to build:** 部署者在 `.env` 里配好生图（NovelAI 官方格式）以后，制作人在文字回合里说「发张自拍给我」，判断模型认出他在要照片，她在回复最前面写一个 `<photo>` 标签。服务器马上开始生成，对话记录里她的话前面先占好一块照片的位置；生成完换上照片，点开能整屏放大，刷新以后也还在。之后的回合里，她记得自己发过一张什么样的照片。这是整条路的主干，只走成功的情况；失败、次数、全年龄的清洗、后台配置、自带生图、通话都在后面的票里。

规格见 `../spec.md`：「能不能发照片」「判断模型」「她的提示词：照片说明」「照片标签」「拼提示词」「角色配置」「生成：生图客户端」「一张照片的生命周期」「接口和事件」「前端」各节。呈现方式照原型 A（`prototype/photos-presentation` 分支，`12-presentation-prototype.md` 的 Answer）。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] **配置**：`.env` 认 `NOVELAI_API_KEY`、`NOVELAI_BASE_URL`（默认 `https://image.novelai.net`）、`NOVELAI_MODEL`（默认 `nai-diffusion-5-curated`）。没填 key，部署者一侧就没有生图。这张只做官方格式。
- [x] **角色配置**：`characters.toml` 加可选的 `photo_tag`、`photo_appearance`。先填票 05 定稿的五位，其余的等 13。缺这两项的角色发不了照片，启动时写一条警告。
- [x] **照片资格**：没有判断模型、没有生图、角色缺 tag 时，判断模型不问照片，她的提示词里也没有照片说明，和现在完全一样。
- [x] **判断模型**：照片资格允许时，多答一道「是不是在要照片」，和检索、好感度放在同一次请求里。检索和好感度都关着时单独问一次，和其他准备工作同时跑。`judge_thresholds` 加 `photo` 一项，三个模型族先给一个偏高的初值（正式校准在 23）。判断失败时当作「否」。
- [x] **照片说明**：判断「是」时，每回合都会变的那条系统消息里加照片说明（能发、好感度冷淡、次数用完三种里，这张做前两种）。前面能缓存的部分不变。
- [x] **标签**：解析器把回复最前面的 `<photo>` 单独拿出来，`</photo>` 一到就交出一个「照片标签」事件。
  - 不送去合成语音，不当字幕，不出现在 `done` 的台词里。
  - 判断「否」、好感度冷淡时丢掉；只取第一个；不在最前面的从台词里剥掉。丢掉的标签不进记录。
- [x] **拼提示词**：
  - 正面依次是前缀、角色 tag、作品 tag、外貌 tag、拍法和景别的换写、她写的三栏、`rating:general`、质量 tag。
  - 负面是 `nsfw`、Human Focus 预设和全年龄细项。
  - 参数写死：832×1216、23 步、scale 7、`k_euler_ancestral`、一次一张。
  - 这张只剥语法字符、转小写、去重、截断。改写表和黑名单在 17。
- [x] **生图客户端**：发官方格式的请求，解开 ZIP，核对正好一张、832×1216，转成 webp（质量 85 左右），去掉元数据。Pillow 写进后端的直接依赖。部署者一侧先一次一张（真正的排队在 16）。
- [x] **照片表**：照片表登记进用户数据和「随对话删除」的名单，删历史对话、删用户时一起删掉。
  - 标签写完时开一个照片，那条回复写进记录时写一行「生成中」挂在回复上，生成完改成「发出来了」并存下图。
  - 生成比回复先完成时，等回复写进记录再落库。
  - 读记录时不读图片。
- [x] **接口**：
  - SSE 的 `photo` 事件（`pending`）在她的第一段话之前推，SSE 照旧在 `done` 时结束。
  - 记录里她那条回复带 `photo: {id, status, reason}`。
  - `GET /api/photos/{id}` 返回状态，`GET /api/photos/{id}/image` 返回 webp（`Cache-Control: private`）。只有对话主人能读，别人 404。
- [x] **她记得**：之后回合的历史里，她那条回复前面照原样带回标签。判断模型、检索、记忆提炼读的仍是去掉标签的台词。
- [x] **前端**：
  - 照片是她那条回复的第一块：宽 192px，按 832×1216 等比缩放，圆角同气泡。
  - 生成中：同大的占位，muted 相机图标慢慢闪加转圈，读屏读「照片正在生成」。前端每 2 秒左右轮询状态，到了直接换上、位置不跳。
  - 刷新后从记录里还原。生成中也能发下一句。
  - 点开是整屏浮层，压 85% 黑，右上角 ✕，点外面、按 Esc 都能关。
  - 图标别名加 `Camera`。
- [x] **`DESIGN.md`**：补上对话记录里的照片块和点开放大。
- [x] **测试**（后端只有一个接缝：在 httpx 传输层装一个假的生图服务，记下请求体）：
  - 照片资格三种「不问」的情况；判断「是/否」和好感度冷淡时的提示词和标签去留。
  - 标签不进字幕和语音。
  - 发给生图服务的请求体（前缀、换写、负面、参数）。
  - SSE 事件、记录里的 `photo`、两个读照片的接口和权限（别人 404）、webp 里没有元数据。
  - 历史里带回标签；照片随历史对话、随用户删除；照片表登记在用户数据名单里。
  - 前端：`conversationLog`、`messageLines` 的照片相关部分。
- [x] **验收**：本地构建版上用 Playwright，生图走假服务，宽屏和手机都看：生成中、发出来、点开放大、刷新时还在生成。
- [x] `uv run pytest`、`uv run pyright`、`npm test`、`npm run typecheck` 全部通过。

## Comments

**做完了（2026-10-17）。** 后端 `uv run pytest` 1659 个、`uv run pyright`，前端 `npm test` 937 个、`npm run typecheck` 全部通过。本地构建版上用 Playwright 验收过宽屏和手机：真的判断模型（Jev）认出「发张自拍给我看看嘛」、真的对话模型写了标签，假生图服务 12 秒出图；生成中的占位、刷新时还在生成、生成中照样发下一句、换上照片位置不跳（占位和照片都是 192×280.6）、点开放大，Esc、点外面、✕ 都能关，点照片本身不关。

几处和票面不完全一样的：

- **`messageLines`**：没有要改的。她的回复前面总有一条制作人的话或一条对话事件，所以她的回复总是一组的第一条，照片块就画在这条回复里、名字下面，分组规则不变；只给测试里的条目补了 `photo: null`。照片的分组测试留给 18 的胶囊。
- **后台阈值覆盖**：`judge_thresholds` 加了 `photo` 以后，后台的阈值卡（`admin_config_api.JudgeThresholdsInput`、前端 `adminConfig.ts`）也加了「要照片」一项，否则保存阈值会被 422。
- **失败**：生成失败、超时时后端已经按原因记成 `failed`（`timeout` / `service_error` / `bad_image`），前端的照片块对 `failed` 先什么都不画，失败说明在 16。
- **历史对话面板里打开的历史对话**不轮询，还在生成的照片停在占位，回到当前对话或刷新后才换上。
