# 08: 拍板：失败、限额和计费

Type: grilling
Status: open
Blocked by: 01, 04, 10

## Question

- 生图失败（超时、中转报错、被内容检查拦下）时：这个回合算失败（不留记录、不计入限额），还是她的话照常记下、只是照片没发出来（她说「拍坏了」）？自带 key 失败时按现有规则不悄悄改用部署者的，那照片怎么办。
- 限额：照片要不要单独的每小时上限（和回合数分开），默认多少，管理者能不能单独给某位用户设；计不计入、怎么在界面上体现。
- 免限额密钥：生图能不能被选进免限额密钥；文字回合现在「用了自带 LLM 就不计入」，带了自带 LLM 但没带生图 key 的回合发照片，算不算计入。
- 并发：一个 NovelAI 账号一次只能跑一张（以「NovelAI 官方图像 API 现状」查到的为准）时，部署者那一侧多人同时要照片怎么排队、排队多久算超时。
- 花费：生图按什么单位记（张？Anlas？），单价怎么填，看板上怎么显示；运行记录的服务名。
- 部署者没配生图时：她怎么回应要照片的请求（说手机没电？直接不提供这个能力？）。

## Comments

- 实测（「准备测试用的中转地址和 key」）：用户的中转 key 错误在 1 秒内回 401/403；A 形态模型名错误回 400；B 形态模型名错误 60 秒还没返回，所以超时一定要有。同时发 3 张都成功、没有 429，中转一侧不是严格的一次一张。单张 5–9 秒，并发时 13–16 秒。
- 「拍板：怎么触发、谁来写提示词」已定：部署者没配生图、用户也没自带时，不问判断模型、提示词里也不提照片，她不知道自己能发，表现和现在一样。所以「没配时她怎么回应」不用再定。到了照片的次数上限时，她用自己的话推掉，服务器要在回合开始前就知道这个回合还能不能发，好决定告诉她什么。生成是在她回复最前面的 `<photo>` 标签写完时开始的，和她说话的时间重叠。
- 「原型：外貌一致性」已定：用 V5 Curated，不用角色参考图。按「NovelAI 官方图像 API 现状」，Opus 免费只要 ≤1024×1024 像素、≤28 步、不带参考图、一次一张，所以单张费用不会因为参考图多出 5 Anlas。但 V5 会扣 Opus 用量条。用户中转的计费方式还不知道。
- 「拍板：全年龄怎么守」已定：生成后不查图，所以失败里没有「被内容检查拦下」这一种。黑名单命中时只剥掉那个 tag，照片照发，也不算失败。剩下要定的失败只有超时、中转或官方报错，还有中转回 200 却是错误图。
