# 记忆升级：过时的记忆在写入时被取代，提炼得更准，想起时看得懂上文

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准；本轮在 grilling 时已改好「记忆」的定义，并新增「被取代的记忆」。设计决定见 ADR-0014（过时的记忆在写入时标为被取代，保留在记忆页上，不改写也不删除），并遵守 ADR-0002（共享记忆、来源角色、转述口吻）和 ADR-0006 / ADR-0012（真删）。调研材料见同目录的 `research.md`。

## Problem Statement

- **想起的是过时的事。** 用户搬了家，角色还会提起旧的住处。现在情况变了只会再记一条新的，旧的原样保留，召回时旧的那条措辞往往更贴近，照样被想起。
- **记忆页里重复、没意义的记忆越来越多。** 背景模型只看得到最近 50 条记忆，更早的它不知道，于是意思相同、措辞不同的记忆反复写入；「制作人今天很累」这种当天就过去的状态也被记下来，因为现在的提炼标准里「近况」要记、「一时的情绪」不记，状态卡在两者之间。
- **代词找不到对象。** 想起记忆时只拿用户这一句去找，「它昨晚又叫了一夜」里的「它」找不到那只猫。
- **没法知道改动是不是有用。** 现有评测只覆盖判断模型的路由和重排阈值，没有任何东西回答「这样改以后，角色是不是更记得住、更不会说错」。

## Solution

- 先做一个记忆评测（`eidolon eval memory`），分提炼和召回两段，判分确定，在现有代码上跑出基线并提交。之后每项改动都要在评测上看到改善才算数。
- 提炼时，背景模型看到的是和这轮对话最相关的有效记忆。它写下新记忆的同时，指出这条新记忆取代了哪些旧的。被取代的记忆不再被想起，在记忆页上标为「已被取代」，用户可以删；删掉取代它的那条，它就恢复。
- 提炼标准收紧：只记过后仍有意义的事，当天就会过去的状态不记。
- 想起记忆时，用用户这句话加上角色的上一条回复去找。
- 如果基线显示专有名词常常想不起来，再补关键词检索（条件项）。

## User Stories

1. 作为用户，我搬家以后，希望角色提起的是我现在住的地方，而不是以前的。
2. 作为用户，我换了新工作、换了爱好、和朋友的关系变了以后，希望角色按现在的情况和我说话。
3. 作为用户，我补充了细节（「猫叫小白」）以后，希望角色记住的是完整的一条，而不是零散的两条。
4. 作为用户，我说了一件事的一部分变了（「狗去世了」），希望角色仍然记得没变的那部分（「还养着那只猫」）。
5. 作为用户，我说了两件同时成立的事（喜欢咖啡，最近也开始喝茶），希望角色两件都记得，不会把旧的那件当成过时。
6. 作为用户，我把同一件事对不同的角色说了好几遍，希望记忆页里只有一条，而不是好几条措辞不同的。
7. 作为用户，我很久以前说过的事，希望新说的话和它重复或冲突时，同样能被认出来，而不只是最近说过的那些才算数。
8. 作为用户，我对灯织说过住在大阪，后来对真乃说搬到了东京，希望灯织也知道我搬了家，并用「听真乃说……」的口吻提起。
9. 作为用户，我希望在记忆页上看到哪些记忆已被取代，它们照常列出、样式淡一些，排序不变。
10. 作为用户，我发现角色把一件仍然成立的事错当成过时时，希望删掉那条错的新记忆，旧的就重新被想起。
11. 作为用户，我顺手删掉一条已被取代的旧记忆时，希望更早的那条不会因此复活，现状仍以最新的那条为准。
12. 作为用户，我希望被取代的记忆也能逐条删除、能被清空，删号时和其他记忆一样彻底删除。
13. 作为用户，我说「今天好累」「有点困」「心情不好」这类当天就过去的话时，不希望它们出现在记忆页上。
14. 作为用户，我说生病了、要考试、要面试、要搬家、要出差这类会持续几天的事时，希望角色记下，过后会问起。
15. 作为用户，我说「它昨晚又叫了一夜」时，希望角色知道「它」指的是刚才聊到的那只猫，想起关于猫的记忆。
16. 作为用户，我希望通话时角色开口的速度不因为这些改动变慢。
17. 作为用户，我希望角色知道的关于我的一切，都能在记忆页上看到、删掉。
18. 作为自带 LLM 密钥的用户，我希望提炼记忆仍然用我的 key，和现在一样，不多出别的由我付费的后台任务。
19. 作为部署者，我希望这次改动不增加后台任务，费用只多出每轮一次向量化。
20. 作为部署者，我希望线上已有的记忆不被批量改动。
21. 作为维护者，我希望用一条命令跑记忆评测，看到提炼和召回各类题的通过情况。
22. 作为维护者，我希望评测走的是线上真实的记忆路径（真模型、真接口），而不是另一套模拟实现。
23. 作为维护者，我希望评测的判分是确定的：提炼看关键词和取代关系，召回看想起了哪些、没想起哪些，不靠 LLM 当评委。
24. 作为维护者，我希望评测的用例按题型分类：取代、重复、短期状态、代词、专有名词、打招呼时接上前情。
25. 作为维护者，我希望召回题同时报出判断模型的结论，这样能分清「判断没让查」和「查了没找到」。
26. 作为维护者，我希望提炼题每个用例跑 3 次取多数，减少模型随机性带来的噪声。
27. 作为维护者，我希望在现有代码上跑出的基线结果提交在仓库里，后面每项改动都和它比。
28. 作为维护者，我希望评测用例和现有两套评测一样，由 agent 起草、人工校对，带 `reviewed` 标记，可以提交（不含剧情原文）。
29. 作为维护者，我希望专有名词类召回题在基线里失败超过 30% 时，才去做关键词检索。
30. 作为维护者，我希望检索的 query 改了以后，记忆的重排阈值按新的 query 重新校准。
31. 作为开发者，我希望「取代」的规则都在记忆模块里，用现有的记忆模块接口就能测全。
32. 作为开发者，我希望背景模型编造或写错记忆编号时不会出错，也不会碰到不该碰的记忆。
33. 作为开发者，我希望用户在提炼进行中删除或清空了记忆时，取代的标记不会把已删的东西写回来，也不会指向已经不在的记忆。

## Implementation Decisions

### 记忆评测（`eidolon eval memory`）

- 和 `eval rerank`、`eval judge` 同一种做法：一份可提交的 TOML 用例文件放在 `backend/eval/` 下，一个评测模块，一个 CLI 子命令。文件开头的注释写清格式、标注规则和用法，仿照现有两份。
- 评测走记忆模块的真实接口：用部署者配置的背景模型、向量化、重排和判断模型，临时数据库，一位虚构的用户。预先放进的记忆通过模块写入，不直接拼 SQL。
- **提炼题**：给出预先放进的记忆（每条有 key、来源角色、文字，可以写明它已被哪条取代）、上文、用户这句话和角色的回复，然后跑一次写入。可以检查：
  - `must`：几组关键词，每组都必须出现在某条新记忆里（组内任一即可）；
  - `must_not`：任何新记忆都不能出现的关键词；
  - `supersedes`：这些 key 的记忆必须变成被取代；
  - `keeps`：这些 key 的记忆必须仍然有效；
  - `nothing = true`：这一轮不该写下任何记忆。

  每个用例跑 3 次（每次都用新的临时库），取多数作为结果。
- **召回题**：给出预先放进的记忆（可以带取代关系）、上文（至少包含角色的上一条回复）和用户这句话，走和真实回合一样的路径：判断模型 → 找记忆。可以检查：
  - `found`：必须想起的 key；
  - `not_found`：不许出现的 key。

  同时报出判断模型的结论。
- **题型**（每题标一个 `category`）：取代、重复、短期状态、代词、专有名词、前情（打招呼、闲聊时该接上之前说过的事）。前情题只用来给以后要不要做常驻层提供依据，不作为这一轮任何改动的门槛。
- **报告**：按题型列出通过数和失败的用例，召回题再附上判断模型的结论。可以输出 JSON，基线结果以 JSON 提交在用例文件旁边。
- **门槛**：一项改动针对的那一类题，通过数必须多于基线；其他类最多允许比基线少 1 个用例。每项改动完成后重跑评测，更新提交的结果。
- 评测模块本身用假的模型做单元测试（加载、校验、判分、报告），不在单元测试里调真模型。
- 被取代这个状态，在取代功能做好之前，所有记忆都算有效：基线里取代类题会失败，这是预期的。

### 取代（ADR-0014）

- `memories` 表加一列 `superseded_by`：可以为空，指向取代它的那条记忆。为空就是有效记忆。旧库在启动时补上这一列，已有的记忆全部有效。
- **提炼的输入**：用用户这句话（加上角色的上一条回复，和召回用同一种 query）做向量，从这位用户的有效记忆里取最相近的 20 条，按 1…N 编号交给背景模型，替换掉原来的「最近 50 条」。向量化失败时退回取最近的 20 条有效记忆。被取代的记忆不交给背景模型。
- **提炼的输出**：`{"memories": [{"text": "…", "supersedes": [1, 3]}]}`。`supersedes` 只能写给它看过的编号，写了别的编号的直接忽略。为了兼容，列表里的元素如果是纯字符串，当作没有取代。每条记忆的长度上限、每轮的条数上限、同一批内去重都照旧。
- **提炼指示**按 grilling 定下的规则改写：
  - 和已经记住的完全一样的，不写；
  - 更新或修正了旧的，写一条单独看也完整的新记忆，写清「从什么变成什么」，并标出取代哪几条，可以一次取代多条；
  - 一件事只变了一部分的，新记忆要把仍然成立的部分也写进去；
  - 两件事都成立的，都留着，谁也不取代谁。
- 取代可以跨来源角色。新记忆的来源角色就是这一轮对话的角色。
- 写入新记忆和设置取代在同一个事务里完成。目标记忆在提炼期间已被删除的，这一条取代自然不生效。被清空的回合整批丢弃，规则照旧。
- 新记忆的文字和这位用户的某条被取代记忆完全相同时，不新建，直接让那条恢复为有效，并对它应用这次的取代。和某条有效记忆完全相同时，照旧忽略。
- **想起**：找记忆时只在有效记忆里找。向量的补齐和清理仍然按这位用户的全部记忆来做。
- **删除**：删掉一条记忆时，原来指向它的记忆改为指向它自己的 `superseded_by`。它是有效记忆的，那些记忆就恢复有效；它已被取代的，它们就接着被取代它的那条取代。清空记忆和删号照旧全部删除，`secure_delete` 照旧生效。
- **记忆模块接口**：`Memory` 多一个字段，表示被哪条记忆取代（或者是否已被取代）；`entries` 照旧返回全部记忆，包括被取代的，新的在前。

### 接口和记忆页

- `GET /api/memories` 的每条记忆多一个字段，表示是否已被取代。删除和清空的接口不变。
- 记忆页上，被取代的记忆原地列出，排序不变，样式淡一些，并用 Astryx 组件（例如 Token）标出「已被取代」，不手写样式。可以照常删除。文案放在 i18n 里。

### 提炼标准：短期状态

- 「要记的」和「不要记的」改成以「过后仍有意义」为界：会持续几天、朋友过后会问起的近况（生病、考试、面试、搬家、出差）要记；当天就会过去的状态（累、困、饿、无聊、心情不好）和一时的情绪不记。和 `GLOSSARY.md` 里「记忆」的定义一致。
- 和取代的提示改写在同一个提炼指示里，但作为单独的一项改动，在评测上单独验证（短期状态类）。

### 想起时带上文

- `MemoryTurn.find` 多拿到这一轮的上文。query 是角色的上一条回复（中文字幕，去掉语气提示）加上用户这句话；没有上一条回复时，只用这句话。`Retrieval.retrieve` 把手里的 history 传过去。
- 重排的 query 也用同样的内容。
- 重排校准集的记忆类题加上可选的「上一条回复」，`eval rerank` 按同样的方式拼 query。重新校准记忆阈值，更新预设的阈值和校准记录。
- 不增加串行的网络往返：向量化和重排的调用次数都和现在一样。

### 关键词检索（条件项）

- 只有当基线里专有名词类召回题失败超过 30% 时才做，否则这张 ticket 记为不做，并写明基线数据。
- 要做的话：给记忆加一个全文索引，中文分词方式先在评测上验证（候选：SQLite FTS5 的 trigram 分词器），和向量候选合并后一起交给重排。删除、清空、删号要同步删掉全文索引，`secure_delete` 也要覆盖到。不增加网络往返。

### 约束

- 通话里不增加串行等待。新增的向量化发生在后台提炼时，不在回合的关键路径上。
- 不新增后台任务。提炼用的模型照旧（用户自带 LLM 密钥时用用户的）；向量化照旧由部署者承担。
- 线上已有的记忆不做批量清理，也不补算取代关系。

## Testing Decisions

- **好的测试**经由 module 的 interface 断言可以观察到的结果：写下了哪些记忆、哪些被取代、找到了哪些、背景模型收到的 prompt 里有哪些记忆、接口返回什么、页面显示什么。不检查表结构和内部状态。先写会失败的测试（`/tdd`），再改实现。
- **记忆模块**（仿 `test_memories.py`，用 `FakeBackgroundLLM`、`FakeEmbedder`、`FakeReranker`）：
  - 背景模型收到的是最相关的有效记忆，不再是最近的；被取代的不在里面；向量化失败时退回最近的那些；
  - 新记忆取代旧的，一次取代多条，跨来源角色也能取代；
  - 编号写错、编号越界、输出旧格式（纯字符串）时都不出错，也不会取代不该取代的；
  - 被取代的记忆不再被找到，但在 `entries` 里列出并标明被取代；
  - 按 Q14 的删除规则：删掉取代者，被取代的恢复；删掉链中间的那条，更早的那条不复活；
  - 提炼期间旧记忆被删，取代不生效；提炼期间被清空，整批丢弃；
  - 新记忆和被取代的记忆文字相同时，旧的那条恢复为有效；
  - 找记忆的 query 带上角色的上一条回复，重排也用同样的 query。
- **检索**：在 `test_retrieval.py` 或 `test_shared_memory.py` 里补一条，确认上文从 `Retrieval.retrieve` 传到了找记忆那一步。
- **接口**（仿 `test_memory_management.py`）：列表里带被取代的标记；删除取代者以后，被取代的那条恢复为有效。
- **前端**（仿 `memories.test.ts`，Vitest）：被取代的记忆显示「已被取代」的标记。
- **评测模块**（仿 `test_rerank_eval.py`、`test_judge_eval.py`）：用例文件的加载和校验（重复 id、未知 key、未知题型都报错），提炼和召回的判分规则，3 次取多数，按题型汇总，JSON 输出。不调真模型。
- **重排校准**：`test_rerank_eval.py` 补上带「上一条回复」的记忆题的 query 拼法。
- **评测结果**：基线和每项改动之后的结果用真模型跑，由维护者执行，结果提交进仓库。这一步写进人工验收清单，不进 pytest。
- `backend/` 下 `pytest` 全部通过，`ruff` 和 `pyright` 没有新的报错；`frontend/` 下的测试、lint 和类型检查都通过。

## Out of Scope

- 常驻的制作人小档案。等评测里前情类题的基线出来再决定，见 `research.md` §8.2。
- 后台整理记忆（合并、淘汰），见 ADR-0014 的 Considered Options。
- 事件日期、有效期、按时间召回（`research.md` §8.7）。
- 记下角色这边说过的话、承诺（§8.8）。
- 对话超过 20 轮时留一份摘要（§8.9）。
- 用户在对话里口头说「记住」「忘掉」（§8.10）。
- 线上已有记忆的批量清理和取代关系的补算。
- 用 LLM 当评委的端到端评测。
- 注入 prompt 的格式（只是不再带被取代的记忆）、想起的条数上限、记忆阈值以外的检索参数。
