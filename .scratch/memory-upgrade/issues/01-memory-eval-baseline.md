# 01: 记忆评测和基线

**What to build:** 维护者用一条 `eidolon eval memory`，就能知道角色「记得对不对」：提炼题看这一轮该记的记了没有、不该记的有没有记、该取代的取代了没有；召回题看该想起的想起来没有、不该出现的有没有出现，并附上判断模型的结论。结果按题型汇总，可以输出 JSON。在现有代码上跑出基线并提交进仓库，后面每张 ticket 都和它比。背景见 `../spec.md`「记忆评测」一节。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

## 已定的设计（详见 spec）

- 和 `eval rerank`、`eval judge` 同一种做法：一份可提交的 TOML 用例文件放在 `backend/eval/` 下，开头的注释写清格式、标注规则和用法；一个评测模块；一个 CLI 子命令。
- 评测走记忆模块的真实接口：用部署者配置的背景模型、向量化、重排和判断模型，临时数据库，一位虚构的用户。预先放进的记忆通过模块写入，不直接拼 SQL。
- **提炼题**：预先放进的记忆（key、来源角色、文字，可以写明被哪个 key 取代）、上文、用户这句话、角色的回复。检查项有 `must`（几组关键词，每组都要出现在某条新记忆里，组内任一即可）、`must_not`、`supersedes`、`keeps`、`nothing = true`。每个用例跑 3 次，每次用新的临时库，取多数。
- **召回题**：预先放进的记忆（可以带取代关系）、上文（至少包含角色的上一条回复）、用户这句话，走和真实回合一样的路径（判断模型 → 找记忆）。检查项有 `found`、`not_found`，同时报出判断模型的结论。
- **题型**：每题标一个 `category`，取值为取代、重复、短期状态、代词、专有名词、前情。每类至少 5 题；前情题只作参考，不作为任何 ticket 的门槛。
- 用例由 agent 起草，标 `reviewed = false`；只含虚构用户的话，不含剧情原文。
- 取代功能（02）做好之前，所有记忆都算有效，基线里取代类题失败是预期的。评测读「是否被取代」的方式要让 02 接上以后不用改评测。
- **门槛**（写进用例文件的注释）：一项改动针对的那一类题，通过数必须多于基线；其他类最多允许比基线少 1 个用例。

## 验收

- [x] 评测模块有单元测试，用假模型：用例文件的加载和校验（重复 id、未知 key、未知题型、缺必填项都报错）、提炼和召回的判分规则、3 次取多数、按题型汇总、JSON 输出。
- [x] `eidolon eval memory --help` 能看到用法；没有配置记忆所需的服务时给出清楚的报错。
- [x] 用例文件覆盖 6 个题型，每类至少 5 题；召回题里有一组「上一条回复里提到了猫，用户说『它……』」这样的代词题，以及只出现过一次的宠物名、人名这样的专有名词题。
- [x] `backend/` 下 `pytest` 全部通过，`ruff` 和 `pyright` 没有新的报错。
- [ ] **人工验收（留给用户）**：
  - 逐条校对用例，改成 `reviewed = true`；
  - 用真模型跑 `eidolon eval memory --json …`，把基线结果提交在用例文件旁边；
  - 在本 ticket 的 Comments 里记下基线各类题的通过数，特别是专有名词类召回题的失败比例（05 会用到）。

## Comments

- 2026-10-08（实现）：评测模块是 `backend/src/eidolon/memory_eval.py`，用例在 `backend/eval/memory.toml`（44 题：取代 9、重复 6、短期状态 9、代词 7、专有名词 8、前情 5，全部 `reviewed = false`），命令是 `eidolon eval memory [--file …] [--characters …] [--json …]`。基线 JSON 约定放在 `backend/eval/memory-baseline.json`（`docs/deploy.md` 和用例文件开头都这样写了），等人工跑完再提交。
  - 预置的记忆通过 `MemoryTurn.write_down` 写入：背景模型换成只写下这一条的脚本，等写完用的是 `begin` 的 `hold` 回调，不受 5 秒的 settle 上限影响。每条预置记忆一个回合，按文件里的顺序写，所以 `superseded_by` 指向的记忆要写在后面（加载时校验）。
  - 召回题走 `Retrieval.retrieve`（参考资料来源为空，只找记忆），04 把上文传给找记忆以后评测不用改。想起了哪些，是从记忆那一节提示词里按「- 文字（」认出来的；格式变了、认不出来时评测直接报错，不会悄悄全判成没想起。
  - 「是否被取代」从 `Memory.superseded_by` 读，这个字段这次先加上，02 之前恒为空。**预置记忆的 `superseded_by` 现在不生效**，要 02 在 `_Scratch.start_with` 里让写下取代者的那个回合标出取代（见代码里的注释）；不然两道取代类召回题在 02 之后也过不了。
  - 评测时的「今天」固定为 2026年10月8日（Asia/Shanghai），用例里的日期按这一天写。
  - 提炼题背景模型出错、或没有给出记忆的 JSON 时，这一次算不通过（`nothing = true` 的题不会因为模型出错而白白通过）。
  - 用例文件里写了不认识的项（例如把 `must_not` 拼错）时加载报错，避免一项检查被悄悄丢掉。
  - 和真实回合的一处差别：真实回合交给判断模型的上文按对话的回合上限截过，评测直接用用例里的上文；现在的用例都很短，没有影响。
