# 02: 取代：过时的记忆被新的取代，不再被想起

**What to build:** 用户搬了家、换了工作、补充了细节以后，角色想起的是现在的情况。提炼时，背景模型看到的是和这轮对话最相关的有效记忆，写下新记忆的同时标出它取代了哪些旧的。被取代的记忆不再被想起，但仍然列在记忆页上，标为「已被取代」，用户可以删；删掉取代它的那条，它就恢复。意思相同的不再重复写入，即使原来那条是很久以前说的。背景见 `../spec.md`「取代」「接口和记忆页」两节和 ADR-0014。

**Blocked by:** 01（记忆评测和基线）

**Status:** ready-for-agent

## 已定的设计（详见 spec）

- `memories` 表加一列 `superseded_by`，可以为空，指向取代它的记忆；为空就是有效记忆。旧库在启动时补上这一列。
- **提炼的输入**：用用户这句话加上角色的上一条回复做向量，从这位用户的有效记忆里取最相近的 20 条，编号 1…N 交给背景模型，替换掉「最近 50 条」。向量化失败时退回最近的 20 条有效记忆。被取代的不交给背景模型。这次新增的向量化发生在后台提炼时。
- **提炼的输出**：`{"memories": [{"text": "…", "supersedes": [1, 3]}]}`。不认识的编号忽略；纯字符串元素当作没有取代。长度上限、条数上限、同批去重照旧。
- **提炼指示**按 grilling 的规则改写：完全一样的不写；更新或修正的写一条单独看也完整的新记忆（写清「从什么变成什么」），并标出取代哪些，可以多条；部分变化的要把仍成立的部分写进去；两件事都成立的都留。短期状态的标准不在这张改（见 03）。
- 取代可以跨来源角色。写入新记忆和设置取代在同一个事务里；目标在提炼期间已被删除的，取代不生效；被清空的回合整批丢弃。
- 新记忆的文字和某条被取代记忆完全相同时，不新建，让那条恢复为有效，并对它应用这次的取代。
- 找记忆只在有效记忆里找；向量的补齐和清理仍按全部记忆。
- **删除**：原来指向被删记忆的，改为指向被删记忆自己的 `superseded_by`。清空、删号照旧全部删除，`secure_delete` 照旧生效。
- `Memory` 带上被取代的信息；`entries` 照旧返回全部记忆，新的在前。`GET /api/memories` 每条多一个「是否已被取代」的字段。
- 记忆页：被取代的原地列出，排序不变，样式淡一些，用 Astryx 组件（例如 Token）标出「已被取代」，文案放在 i18n 里，照常可以删除。

## 验收

- [x] 记忆模块的测试（仿现有记忆测试，用假模型），每条先写会失败的版本：
  - 背景模型收到的是最相关的有效记忆，不再是最近的；被取代的不在里面；向量化失败时退回最近的那些；
  - 新记忆取代旧的，一次取代多条，跨来源角色也能取代；
  - 编号写错、越界、旧格式输出都不出错，也不会取代不该取代的；
  - 被取代的不再被找到，但在 `entries` 里列出并标明；
  - 删掉取代者，被取代的恢复；删掉链中间那条，更早的那条不复活；
  - 提炼期间旧记忆被删，取代不生效；提炼期间被清空，整批丢弃；
  - 新记忆和被取代的记忆文字相同时，旧的那条恢复为有效。
- [x] 接口测试：列表里带被取代的标记；删除取代者以后，被取代的那条变回有效。
- [x] 前端测试（Vitest）：被取代的记忆显示「已被取代」的标记。
- [x] 旧库（没有 `superseded_by` 列）启动后自动补上，已有记忆全部有效，有测试覆盖。
- [x] `backend/` 下 `pytest` 全部通过，`ruff` 和 `pyright` 没有新的报错；`frontend/` 下的测试、lint、类型检查都通过。
- [ ] **人工验收（留给用户）**：
  - [x] 用真模型跑 `eidolon eval memory`：取代类和重复类的通过数多于基线，其他类最多少 1 个用例；更新提交的结果，在 Comments 里记下对比；
  - [ ] 本地起服务：先对一位角色说住在大阪，再对另一位说搬到了东京，记忆页上旧的那条标为「已被取代」；问起住处时角色说东京，并用转述的口吻；删掉东京那条以后，大阪那条恢复。

## Comments

- 2026-10-08（01 实现时留的）：记忆评测预置记忆时还不会设置取代：`memory_eval._Scratch.start_with` 里写下取代者的那个回合，要按这张 ticket 定的输出格式标出它取代哪几条（预置记忆的 `superseded_by`），否则两道取代类召回题（旧的在 `not_found` 里）在这张做完以后也过不了。评测读「是否被取代」用的是 `Memory.superseded_by`（01 已加上，现在恒为空），这张把它填上即可，评测的判分不用改。
- 2026-10-08（实现）：
  - 提炼时交给背景模型的是 `memory_query`（和 04 找记忆用的同一个函数：角色的上一条回复加用户这句话）向量化后最相近的 20 条有效记忆（`SHOWN_MEMORIES`），按 1…N 编号；向量化失败时退回最近的 20 条有效记忆。这一次向量化在后台提炼里，每轮多一次（文字回合里的 `embedder.queries` 因此多了一条，两条闲聊测试跟着改了断言）。
  - 输出 `{"memories": [{"text": …, "supersedes": [编号]}]}`（`memory.NewMemory`）。编号只认整数（`true`、`1.0`、`"1"` 都不算），越界、指向自己、指向已删或已被取代的都忽略；纯字符串元素当作不取代。
  - 写入和取代在 `_add` 的同一个事务里。只取代当时仍有效的记忆，所以取代链不会成环。新记忆的文字和一条被取代的记忆相同时，那条恢复为有效，并应用这次的取代；它不算「新写下的」，不会重新向量化（向量还在），评测里也不算 written。
  - 删除：指向被删记忆的改指向它自己的 `superseded_by`（`_delete`）。清空、删号照旧。
  - `GET /api/memories` 每条多一个 `superseded`（布尔）。记忆页上被取代的文字用 `secondary` 颜色，旁边一个灰色的 Token「已被取代」，说明文字补了一句。删除成功后重新取一次列表（被取代的可能恢复了），连着删几条时只用最后一次取到的。
  - 评测：`_Scratch.start_with` 写下取代者的那个回合，按 prompt 里的编号标出它取代哪几条；要取代的记忆不在交给背景模型的 20 条里时直接报错。
  - code review 提到、没有改的：恢复一条被取代的记忆时，原来取代它的那条要不要跟着被取代，取决于背景模型有没有在 `supersedes` 里写上（例如又搬回大阪时写了取代「搬到东京」那条），代码不替它补；人工验收时可以留意。`_write` 在锁外检查「是否已被清空」的窗口是原来就有的，这次没变。
