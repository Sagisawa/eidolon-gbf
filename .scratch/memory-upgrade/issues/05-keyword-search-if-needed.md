# 05: 关键词检索（条件项）

**What to build:** 只说过一次的宠物名、人名（「小白」「豆太」），用户再提起时角色能想起来。只有当基线显示这类题确实答不好时才做；否则这张记为不做，写明数据。背景见 `../spec.md`「关键词检索（条件项）」一节。

**Blocked by:** 01（记忆评测和基线：决定做不做）、04（想起时带上文：都改找记忆那一步，阈值也在 04 之后才定）

**Status:** ready-for-agent

## 已定的设计（详见 spec）

- **先判断**：读 01 的 Comments 里记下的基线，专有名词类召回题失败不超过 30% 的，这张改成 `Status: wontfix`，在 Comments 里写明基线数据和 04 之后的数据，结束。
- **要做的话**：
  - 给记忆加一个全文索引。中文分词方式先在评测上验证，候选是 SQLite FTS5 的 trigram 分词器；如果效果不好，在 Comments 里写明，交给用户决定。
  - 关键词命中的候选和向量候选合并、去重以后一起交给重排；只在有效记忆里找（如果 02 已经合并）。
  - 删除、清空、删号同步删掉全文索引里的内容，`secure_delete` 也要覆盖到；旧库启动时为已有记忆补建索引。
  - 不增加网络往返。
