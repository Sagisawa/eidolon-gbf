# 免限额密钥

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，特别是「免限额密钥」「自带密钥」「限额」「运行记录」「看板」。相关决策见 ADR-0013（后台设置覆盖 `.env`）、ADR-0016（落地页静态渲染）和 ADR-0017（自带密钥只存在用户的浏览器里）。设计在 2026-10-13 的 grilling 中定下。开关随时可以改回去，「必须自带 LLM」也不难恢复，所以不另写 ADR。

## Problem Statement

部署者想灵活地控制成本，现在只有两种粗糙的办法：

- 「必须自带 LLM」打开后，没带 LLM 自带密钥的用户什么都用不了。部署者希望网站总能让人来体验一下，不想把没带 key 的人挡在门外。
- 不打开它时，一通电话要 LLM、语音合成、语音识别三项全都自带才不计入限额。部署者愿意替带了 LLM 的用户出语音的钱，却没法表达「只带 LLM 就不受限额」。

## Solution

用**免限额密钥**取代「必须自带 LLM」：

- 部署者从 LLM、语音合成、语音识别里选几项，至少一项。用户在一次通话里把这几项都用了自带密钥，这通就不计入限额，没选的那几项由部署者承担。
- 文字回合只用 LLM，不看这项设定：用了自带 LLM 的回合照旧不计入。
- 默认三项都选，和现在的规则一样：已经部署的实例升级后行为不变。
- 不论选了哪几项，没带自带密钥的用户照样能发起回合和通话，只是计入限额。
- 「必须自带 LLM」整个去掉：拒绝、前端提前拦截、后台的「放行」都不再存在。
- 由部署者在 `.env` 设默认值，管理者可以在后台配置页的「限额」一节改，从下一个回合、下一次通话起生效；进行中的通话不受影响。
- 设置页和超限提示点名这个部署要带哪几项；落地页和隐私说明只用通用说法。

典型用法：只选 LLM。没带 key 的人按限额体验；带了自己 LLM 的人不受限额约束，语音合成和语音识别由部署者出。

## User Stories

1. 作为部署者，我希望选定带哪几项自带密钥的通话不计入限额，这样我可以只承担我愿意承担的那部分服务。
2. 作为部署者，我希望只选 LLM，这样带了自己 LLM 的用户可以不受限额地打电话，语音由我出。
3. 作为部署者，我希望只选语音合成，这样带了 Fish Audio key 的用户通话不受限额，LLM 和语音识别由我出。
4. 作为部署者，我希望可以同时选两项或三项，这样用户要带齐这几项才不受限额。
5. 作为部署者，我希望不改任何设置时规则和现在一样（三项全带才不计入），这样升级不会改变我现有部署的花费。
6. 作为部署者，我希望在 `.env` 里给这三项设默认值，这样新部署一启动就是我要的状态。
7. 作为部署者，我希望 `.env` 里三项全关时服务拒绝启动并说明原因，这样我不会无意中取消所有人的限额。
8. 作为部署者，我希望 `.env` 里写了无法识别的值时服务拒绝启动并说明原因。
9. 作为管理者，我希望在后台配置页「限额」一节用三个开关改免限额密钥，不用重启服务。
10. 作为管理者，我希望关不掉最后一个开着的开关，并看到原因，这样不会误把限额整个取消。
11. 作为管理者，我希望开关旁边写清楚它的意思：自带了打开的这几项，通话就不计入限额，其余由部署者承担。
12. 作为管理者，我希望配置页标出这三项现在是跟随 `.env` 还是后台改过的，能恢复成 `.env` 的设置，和其他配置项一样。
13. 作为管理者，我希望改动从下一个回合、下一次通话起生效，进行中的通话按开始时的规则打到挂断。
14. 作为部署者，我希望没带任何自带密钥的用户照样能聊天和打电话，只是计入限额，这样任何人都能来体验。
15. 作为部署者，我希望「必须自带 LLM」从后台、`.env` 和文档里都消失，不留一个已经不起作用的开关。
16. 作为部署者，如果我的 `.env` 里还留着 `EIDOLON_OWN_LLM_REQUIRED`，我希望启动时看到一条警告，说它已经不起作用，而不是服务起不来。
17. 作为管理者，我希望「单独限额」对话框里不再有「可以用部署者的 LLM」这一项，用户详情里也不再显示放行。
18. 作为管理者，我希望把某位用户的单独限额设成零时，对话框写清楚现在设零意味着什么：他只能发起不计入限额的回合和通话，也就是带齐了哪几项。
19. 作为管理者，我希望要彻底挡住某个人时用封禁，单独限额设零只管限额。
20. 作为用户，我希望文字回合用了自己的 LLM 就不计入限额，不论部署者选了哪几项。
21. 作为用户，在只选 LLM 的部署上，我希望带上自己的 LLM 后打电话不计入限额，语音合成和语音识别不用填。
22. 作为用户，我希望多带几项（比如三项全带）也照样不计入，不会因为带多了反而被算进去。
23. 作为用户，我希望设置页告诉我这个部署上带哪几项就不计入限额，指名到具体服务。
24. 作为用户，我希望设置页根据我这个浏览器里存了哪几项，告诉我现在的文字对话和通话计不计入限额。
25. 作为用户，文字回合超出限额时，我希望提示告诉我带上自己的 LLM 就不受限额，并有去设置的按钮。
26. 作为用户，通话因超出限额没能打出去时，我希望结束卡告诉我这个部署要带哪几项才不计入，并有去设置的按钮。
27. 作为用户，我希望再也不会因为「没带 LLM」被拒绝；以前被拦住的输入框和电话键恢复可用。
28. 作为开着旧页面的用户，部署更新后我希望发消息和打电话照常可用，不会看到已经不存在的提示。
29. 作为访客，我希望落地页上关于限额和自带密钥的说法，不论部署者选了哪几项都是对的。
30. 作为用户，我希望隐私说明里关于第三方服务的说法，不论我用的是部署者的还是自己的服务都是对的。
31. 作为管理者，我希望运行记录里通话的「用了自带密钥」表示这通带齐了免限额密钥、不计入限额，和限额的计数一致。
32. 作为管理者，我希望看板上的用语和这个含义一致，不再说「全用自带密钥」。
33. 作为管理者，我希望花费估算照旧按每次服务调用是不是自带的来算，不受开关影响。
34. 作为部署者，我希望部署文档（三种语言）、README 和 `.env.example` 写明这三个变量、默认值、不能全关和效果，并删掉「必须自带 LLM」那一节。

## Implementation Decisions

- **开关**：后台配置「限额」那一项里，原来的布尔字段「必须自带 LLM」换成三个布尔字段，分别对应 LLM、语音合成、语音识别。`.env` 用三个变量给默认值：`EIDOLON_EXEMPTING_LLM`、`EIDOLON_EXEMPTING_TTS`、`EIDOLON_EXEMPTING_STT`。不填或 `1` 是开，`0` 是关，其他值启动时报错（和现有的布尔开关不同，这里不填的意思是**开**）。三个都是 `0` 时启动报错。后台改了覆盖 `.env`（ADR-0013）。
- **不能全关**：后台保存时校验，三项全关就拒绝并说明原因（「至少要选一项；想取消限额请把限额设成不限」之类）；后台表单也不让关掉最后一个。
- **实时配置**对外给出「现在的免限额密钥」，一个服务名的集合，至少有一项。回合和通话开始时读一次，进行中的通话不再读。
- **判断规则**，仍然只有一处（现在判断「是否计入限额」的那个方法），各处共用：文字回合带了 LLM 就不计入；通话带了的服务包含当前所有免限额密钥就不计入。它需要能读当前的免限额密钥，从外面注入（和现在 `Admissions` 读开关的方式一样）。通话预检、设置页的豁免查询接口和发起通话都走这一处，所以自动一致。
- **账号接口**：`/api/account` 去掉 `own_llm_required`，新增免限额密钥列表（按固定顺序的服务名，比如 `["llm"]`）。前端拼提示只靠这一项，不自己推规则；「现在计不计入」仍问豁免查询接口。
- **去掉「必须自带 LLM」**：
  - 后端：`Admissions` 里的这条规则和相应注入、`OwnLLMRequired` 异常和它的 403 映射，回合、通话、拨号预检里的这道检查都去掉。被拒绝的就只剩冷却（409）和超限（429）。
  - 单独限额：去掉「可以用部署者的 LLM」，单独限额接口不再读写它。迁移时删掉 `user_limits` 表的 `deployer_llm_allowed` 列，并删掉 `config_overrides` 里 `limits.own_llm_required` 那一行。
  - `.env`：不再读 `EIDOLON_OWN_LLM_REQUIRED`；它还在时启动打一条警告，不拒绝启动。
  - 前端：对话页的提前拦截、设置页的「LLM 必填」、API 层对这种 403 的识别、通话结束原因 `own_llm_required` 和对应文案、后台「单独限额」对话框和用户详情里的放行，全部去掉。
  - 文档：部署文档里「必须自带 LLM」一节、`.env.example` 的变量、`docs/agents/local-acceptance.md` 里那一行 403，都去掉。
- **运行记录**：通话那一栏存的本来就是「免不免」，含义改成「带齐了免限额密钥、不计入」，数据结构不变，历史记录不迁移。回合那一栏仍是「扮演角色的 LLM 是否自带」。看板的用语跟着改（比如「其中 n 次不计入限额」）。花费估算按每次服务调用的 `own_key` 计算，不动。
- **单独限额设零**：含义不变，就是「只能发起不计入限额的回合和通话」，随免限额密钥变化。「单独限额」对话框选零时，按后台配置里当前的免限额密钥写一句说明（比如「只能用自带 LLM 的文字对话，和带上 LLM 的通话」）。
- **文案**：
  - 设置页自带密钥区：开头点名「这个部署上，带上 X、Y 的通话不计入限额；文字对话带上 LLM 就不计入」；下面按豁免查询的结果说现在计不计入，三种情况的文字改成不写死「三项」。
  - 文字回合超限（429）的提示和通话超限结束卡：点名需要带哪几项，按钮仍是「去设置自带密钥」。
  - 后台三个开关的标签和说明；「单独限额」对话框的说明（原来写「用自带密钥、免计入的回合和通话照常放行」）跟着核对。
  - 落地页第六幕两句和隐私说明核对一遍：本来已经是通用说法，只需去掉提到「必须自带 LLM」的注释，确认不点名哪几项。落地页照旧静态渲染。
  - 给人读的文案要拼出服务名列表，这个拼法写成 `lib/` 里的纯函数。
- 判断模型、向量化、重排始终由部署者承担，不在开关里。部署者 LLM、语音合成、语音识别的启动检查不动。

## Testing Decisions

- 好的测试只看外部行为：发了什么请求，回来什么状态和内容，运行记录、限额计数、后台看到什么。不测函数怎么拆、内部调用了谁。
- **后端只走 HTTP 这一个接缝**，用现有的 `make_client` 测试客户端。覆盖：
  - 默认（三项都开）时，文字回合和通话的计数和现在完全一样。
  - 只开 LLM：带 LLM 的通话不计入，运行记录标成不计入，语音用部署者的 key；没带的计入；三项全带的也不计入。只开语音合成：只带 Fish Audio key 的通话不计入，只带 LLM 的计入。
  - 文字回合在任何开关组合下都是「带 LLM 就不计入」。
  - 豁免查询接口和通话预检给出的「是否计入」与实际一致。
  - 开关改动从下一个回合、下一次通话起生效；进行中的通话不受影响。
  - 后台能改、能恢复成 `.env`；全关和非布尔值被拒绝并说明原因；`.env` 不填时三项都开，全 `0` 或非法值启动报错。
  - `/api/account` 返回当前的免限额密钥列表，不再有 `own_llm_required`。
  - 没带 LLM 的回合和通话不再被拒绝，在任何部署上都只受限额约束；`.env` 里留着旧变量时启动照常，并打警告。
  - 单独限额接口不再读写放行；旧库升级后那一列和那条覆盖值不在了，单独限额照常可读写。
- 参照：`test_exemption.py`、`test_live_config_limits.py`、`test_own_llm_required.py`、`test_own_llm_required_calls.py`（拒绝、计数、进行中的通话的写法，这两份随后删掉）、`test_user_limits.py`、`test_admission.py`。
- **前端**：只测 `lib/` 里的纯函数，用 vitest，参照 `lib/*.test.ts`（`localOwnKeys.test.ts`、`adminConfig.test.ts`、`api.test.ts`、`callEnd.test.ts`）：服务名列表拼成提示文字、后台表单三个开关不能全关、去掉的 403 和结束原因不再出现。组件不另写测试。
- **本地构建版用 Playwright 验收**（见 `docs/agents/local-acceptance.md`）：后台三个开关和「不能全关」、设置页点名的说明、超限的文字回合提示和通话结束卡、没带 LLM 也能发消息和拨号。

## Out of Scope

- 「必须自带」某项服务（不带就不能用）的任何形式。
- 判断模型、向量化、重排改成可以自带或放进开关。
- 按用户单独设定免限额密钥。
- 落地页、隐私说明根据开关动态显示不同文案。
- 改动单次通话的时长和回合上限。
- 为只带一部分 key、但不计入的通话另设一道总量上限。

## Further Notes

- 只选 LLM 时，带了自己 LLM 的用户可以无限次打电话，语音合成和语音识别都由部署者出；单次通话的时长和回合上限照旧约束每一通。这是有意的取舍，上线后从看板看语音的花费。
- **部署前**：VPS 上如果打开过「必须自带 LLM」，新版上线后没带 LLM 的用户就能用了（计入限额），上线前看一眼默认限额。部署后从 `.env` 删掉 `EIDOLON_OWN_LLM_REQUIRED`，再按需要设三个新变量或在后台改。
- 用户的自带密钥只存在浏览器里（ADR-0017），所以设置页「现在计不计入」按这个浏览器里存了哪几项来问。
