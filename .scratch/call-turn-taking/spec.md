# 通话中的补充与打断

Status: ready-for-agent

术语以 `CONTEXT.md` 为准，尤其是「回合」「补充」「打断」三条（2026-09-27 grilling 中定下）。

## Problem Statement

语音通话中，用户一句话想一想再说，中间停顿稍长就会被 Soniox 的端点检测切成两句。现在每一句都是单独的回合：后一句要排队，等前一句的回复**整条生成完**（`CallTurns._take_turns` 只有一个工作协程，`backend/src/eidolon/call.py:571-585`）才开始处理。我们一次回复要十几秒（issue mvp/20 实测到 `done` 约 18 秒），所以用户补的后半句会被晾很久，角色还会先对半句话作答。

用户开口时，现在只会停掉声音，不会停掉生成（`call.py:547-549`、`610`）。所以即使角色已经在说话，被打断后新的话也要等旧回复生成完。这是已知限制，见 `.scratch/mvp/issues/04-voice-call.md:35`。

## 参考：LAPLACE Eidolon 的行为（2026-09-27 实测）

我们在 https://laplace.live/ai 用 Playwright 挂钩 RTCPeerConnection 的数据通道，录下 RTVI 事件时间线。对方同样是 Pipecat + SmallWebRTC + Soniox + Fish Audio（服务端 `laplace-eidolon 0.2.0`）。时间单位为秒：

```
82.58  user-transcription FINAL「哎，我有点受不了了，测这个。」→ user-stopped-speaking
82.88  bot-llm-started
85.33  user-started-speaking → bot-interrupted → bot-llm-stopped（还没吐出任何文字就被取消）
86.88  user-transcription FINAL「好了，我们现在再说一句话试一试。」
87.07  bot-llm-started → 回复「辛苦啦，测来测去确实很折磨人。那现在这句听着还顺耳嘛？」（两句一起回应）
```

「OK，OK，等一下」（100.98 定稿）→ 101.17 开始生成 → 101.31 用户又开口，生成取消 →「我想问别的」→ 一条回复。

角色说话时插话（99.47、110.48）：`bot-interrupted` 与 `bot-stopped-speaking` 同时出现，声音立刻停下，新的话作为新回合。只说一个「OK」也会打断，没有附和过滤。对方同样用 Soniox 默认端点参数，停顿约 2 秒也会被切开。

气泡：两句合成一个气泡还是分成两个，是 `@pipecat-ai/client-react` 对话 store 的显示规则，不是 LAPLACE 的设计。`UserStoppedSpeaking` 后开 3 秒定时器，到点把用户消息封口；3 秒内再开口就续在同一个气泡里。无论显示几个气泡，模型都收到两句并只回复一次。

## Solution

当前回合**还不能被打断**时，用户又说的话或打的字是**补充**。补充会立刻放下正在进行的回复，把这些话并进当前回合，然后重新回复。当前回合**已经可以被打断**时，用户开口就是**打断**：立刻停止发声和生成，只记下已经完整的几段，新说的话马上开始新回合。

- **可以被打断** = 角色已经**开口**，并且回复已经有**完整的一段**。
- **开口**：声音开始播放。通话静音时，指回复的第一句出现。回复已经记下的，也算开口。
- **完整的一段**：一段日语连同它的字幕都已经出现。

## Decisions

- 照搬 LAPLACE 的「事后合并」，**不调** Soniox 的断句参数（`max_endpoint_delay_ms` 等）。调大会让每句话都变慢，而且停得更久照样会被切开。
- **补充**
  - 用户**一开口**（`InterruptionFrame`）就取消当前回复：检索、工具调用、LLM 全部中止。不写对话记录，不写记忆，不计入单次通话的回合数。每小时限额按通话计，不受影响。
  - 已经送去合成、还没播出的日语要一并清掉。
  - 合并后的用户文本用**换行**把各句接起来，存成一条用户消息，一个气泡。补充次数不设上限。
  - 已经显示的角色字幕撤回，用户气泡原地更新为合并后的全文。
  - 如果一开口就取消了，但这句话最后定稿是空的（咳嗽、杂音），就用原来那段话**重新生成**。
  - 通话中打字也算补充，规则相同。打字本身不会触发打断。
- **打断**
  - 停止发声，也停止生成。只记下已经完整的段落，半截的丢掉。之后照常写记忆，照常算一个回合，新说的话马上开始处理。
  - 已经可以被打断时打的字不打断角色，排在这条回复**生成完**之后。
- 用户挂断或通话掉线时，进行中的回合照旧不留记录（`CONTEXT.md`「回合」）。
- 不做附和或噪音过滤，一个「OK」也会触发补充或打断，和 LAPLACE 一致。
- 合并后超过 `MAX_INPUT_LENGTH`，就和打字超长一样，回合失败，不另做处理。
- 不写 ADR：这个决定将来想改回来的成本不高。

## Out of Scope

- 附和、噪音过滤（例如角色说话时，少于 N 个字不算打断）。
- 调整 Soniox 端点参数，接入本地 VAD 或 smart-turn 模型。
- 文字对话（非通话）里的补充。文字回合仍然一次一个，回复完之前不能再发。
- 打字打断角色。
