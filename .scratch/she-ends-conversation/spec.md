# 她结束对话：文字对话套用通话的挂断规则

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准（新增「已结束的对话」，「不该说的话」「冷却」「对话事件」随之改过）。通话里的挂断规则是 PR #88 做的（「通话中频繁惹她不快也挂断」）。

## Problem Statement

- 用户在通话之外一直打字说让她不快的话，她嘴上说「要挂了」「不想聊了」，却什么也不会发生：文字对话只有「跌进冷却」这一条规则，警告、接连不快、不该说的话说多了都只在通话里算。用户只能一路说到好感度清零才会被挡住，和通话里「她真的会挂断」对不上。
- 她说「要挂电话」本身也不对：现在没有任何规则让她在文字对话里这么说，是回复格式里「像真人当面或打电话那样说话」、以及同一个对话里通话留下的历史让模型自己以为在打电话。

## Solution

1. **规则**：通话里会让她挂断的，在通话之外的回合里就让她结束对话，用同一套常量：这一轮把好感度扣进冷却；最近 8 个文字回合里不该说的话说到第 2 次；最近 8 个文字回合合计扣掉 12 分。合计扣到 6 分时她先警告「再这样下去就不想聊了」，回落到 6 分以下才会再警告。窗口只按轮数算，不限时间；只看这个对话里通话之外的回合，通话里的回合（包括通话中打的字）照旧只算那一通电话，通话被挂断也不锁对话。好感度没生效时她不会结束对话。
2. **已结束的对话**：她先说完最后一句（「先回应，再用你自己的方式表明你现在不想聊下去」），回合记下，对话里留一条「她结束了对话」的对话事件，对话从此只能翻看：不能再打字、不能通话、不再添任何记录；重置卡、冷却结束都不让它重新开放。打开她的页面时照样显示这个已结束的对话，输入框换成结束卡：「她结束了对话」和「开个新对话」；处在冷却中时再写上冷却到什么时候，加「送她一件礼物」。卡上不写原因。
3. **送礼**：送给已结束对话的礼物改记进一个新对话（没有就当场开一个），她在新对话里的第一句回应礼物。
4. **她知道这是打字还是通话**：每个回合告诉她是在打字还是在通话；回复格式里的「像真人当面或打电话那样说话」改成「像真人当面说话那样」。文字对话里她不再提挂电话。
5. **看板**：「好感度」一节按角色、按原因（冷却、不该说的话、接连不快）显示她结束对话的次数。

上线后从零开始算：老对话里上线前的回合不进窗口。

## User Stories

1. 作为用户，我在文字对话里接连说让她不快的话时，想先听到她警告「再这样我就不想聊了」，这样我知道再说下去会发生什么。
2. 作为用户，警告过后我继续说让她不快的话、最近几轮合计扣得够多时，想看到她说完最后一句就结束这个对话，这样她说「不想聊了」是真的。
3. 作为用户，我在文字对话里第二次说不该说的话时，想看到她结束对话，和通话里一样。
4. 作为用户，某一轮把她扣进冷却时，想看到她说完最后一句、这个对话随之结束，并看到冷却到什么时候。
5. 作为用户，我偶尔说一句让她不快的话、中间夹着好好说话时，不想被结束对话，因为只看最近 8 轮。
6. 作为用户，很久以前在这个对话里说过的不该说的话，不想在今天被翻出来算第二次。
7. 作为用户，我昨天在这个对话里伤过她、今天又接着惹她时，接受她结束对话：窗口不限时间。
8. 作为用户，我通话时被挂断后，想照样能在这个对话里打字，因为通话被挂断只结束那一通。
9. 作为用户，通话里说过的让她不快的话，不想被算进文字对话的窗口，反过来也一样。
10. 作为用户，在通话里把她扣进冷却时，冷却结束后想照样能在原来的对话里打字。
11. 作为用户，对话结束后想还能往上翻看整段历史，这样我知道发生了什么。
12. 作为用户，对话结束后在输入框的位置看到「她结束了对话」和「开个新对话」，这样我知道该怎么继续。
13. 作为用户，对话结束后不能在里面拨电话，这样不会用打电话绕过去。
14. 作为用户，关掉页面第二天再打开她的对话，想看到的还是那个已结束的对话和结束卡，而不是被悄悄换成新对话。
15. 作为用户，点「开个新对话」后想马上能和她聊，好感度照旧是现在的档位。
16. 作为用户，对话因冷却结束时，想在结束卡上看到冷却到什么时候，并能点「送她一件礼物」。
17. 作为用户，在冷却中点「开个新对话」时，想照样开得了，只是要等冷却结束才能发消息。
18. 作为用户，在已结束的对话页上送礼时，想看到礼物记进一个新对话、页面换到新对话，她第一句回应这份礼物，像送礼和好。
19. 作为用户，用了重置卡后，想照样看到已结束的对话没有重新开放，要继续就开新对话。
20. 作为用户，在新对话里不想被她翻旧账：她只从好感度档位上表现出冷淡，不知道上次是她结束的。
21. 作为用户，在文字对话里不想听她说「挂电话」，因为我们没在通话。
22. 作为用户，在通话里照旧听到她警告「再这样我就挂电话了」，和以前一样。
23. 作为用户，在对话列表里照旧看到她在这个对话里的最后一句。
24. 作为用户，开着两个标签页时，在对话结束后才记下的回合不想被记进已结束的对话，而是被告知「她已经结束了对话」。
25. 作为用户，部署者没开好感度时，不想被结束任何对话。
26. 作为用户，判断模型这一轮失败时，不想因为这一轮被结束对话；这一轮照样占窗口里的一格。
27. 作为用户，上线前在老对话里说过的话，不想在上线后被算进窗口。
28. 作为用户，结束对话的那一轮照常计入限额、照常写进记忆。
29. 作为管理者，想在看板「好感度」一节看到每位角色因冷却、不该说的话、接连不快各结束了多少次对话，这样上线后能对照通话的挂断次数，决定常量要不要调。
30. 作为管理者，想在运行记录里看到某个回合是否让她结束了对话、为什么，不含对话内容。
31. 作为部署者，想让文字对话和通话共用一套常量，这样调一处两边都变。

## Implementation Decisions

- **规则放在好感度模块，和通话共用一套判断**。现在的「她挂断吗」「她警告吗」接收通话里的「不该说的话次数」和「各回合扣了多少」；文字对话传入自己的窗口，结果同样是「冷却 / 不该说的话 / 接连不快」三种原因之一。不同之处只有计数范围：通话里不该说的话按整通电话计，文字对话按最近 8 个文字回合（含这一轮）计；合计扣分两边都是最近 8 轮。常量不新增。
- **引擎的回合多一种「在哪里说的」**：现在回合可以带「在通话中」（带着通话的计数）；不带时就是文字回合，引擎自己从对话记录里读出窗口。文字回合的告别用现有的「不想聊下去」那句，三种原因都一样；警告是新的一句，说「不想聊了」而不是「挂电话」。通话的告别和警告不变。
- **每个文字回合记下它的计数**：用户那条消息上多记两样：这一轮扣了多少（和通话里一样，是钳到下限之前的扣分，没判断的记 0）和是不是不该说的话。通话里的回合和上线前的回合不记（空），窗口跳过它们，所以通话不进窗口、老对话从零开始。改的是 messages 表，旧库启动时补列。
- **结束是一条对话事件**：对话事件多一种「她结束了对话」。对话是否已结束只看记录里有没有这条事件，对话表不加状态列。这条事件和结束的那个回合一起记下（回合记下时事件在它之后），她先说完、再结束。
- **已结束的对话不再添任何记录**：文字回合、通话、送礼都在入口检查。文字回合被拒绝，像被拒绝的回合一样不留记录、不计入限额，告诉用户「她已经结束了对话」；回合进行到一半对话被别处结束了，记下时同样不记入、按被拒绝处理。拨电话被拒绝（409）。对话结束时这个对话里如果还有通话（只在两个标签页同时操作时发生），她挂断那通电话，原因按她挂断计。
- **浏览器怎么知道**：结束对话的那一轮，`done` 里多带「对话已结束」，冷却的话照旧带着冷却到什么时候；对话记录里出现那条事件。原因不告诉浏览器，只进运行记录。打开对话时，浏览器从记录里的事件判断它已结束。
- **前端**：对话进入「已结束」后不能发消息、不能拨电话；输入框的位置换成结束卡，普通版「她结束了对话」加「开个新对话」，冷却中再加冷却到什么时候和「送她一件礼物」。现在冷却时输入框换成的那一行（冷却图标加文案加送礼按钮）是最接近的先例。「开个新对话」走现有的「新对话」，已结束的对话算空闲。按 `frontend/AGENTS.md` 的 shadcn 纪律和 `DESIGN.md` 写。
- **送礼**：礼物页传来的对话已经结束时，送礼事件记进她最新的、没结束的对话；没有就当场开一个。浏览器随后打开的就是这个新对话（页面本来就打开最新的对话）。好感度照常加，跟记进哪个对话无关。
- **提示词**：每个回合在随回合变化的那段系统消息里说明现在是打字还是通话，不放进开头缓存的部分。回复格式（会被缓存）里那句改成「像真人当面说话那样」，改一次缓存会失效一次，可以接受。
- **运行记录和看板**：回合的运行记录多一项「让她结束了对话的原因」（没有为空）。看板「好感度」一节按角色、按三种原因统计。
- **表结构改动**：messages 表加两列、对话事件多一种。部署前照例手动备份数据库。

## Testing Decisions

- 只测对外的行为：接口返回什么、对话记录里有什么、她的提示词里有什么，不测内部怎么数的。
- **后端**：通过后端对外的接口，判断模型逐轮伪造。文字回合的流式事件、对话记录、拨电话、送礼、看板。先例：`test_affinity_cooldown.py`（文字回合跌进冷却、冷却中被拒绝）、`test_she_hangs_up.py`（通话里的三种挂断、警告、只看最近几轮、失败的回合不算）、`test_conversation_events.py`（事件在记录里的位置）、`test_affinity_prompt.py`（提示词里她被告知了什么）、`test_activity_records.py` 的看板辅助。通话里的行为不变，原有测试照旧通过。
- **前端**：`liveConversation.test.ts` 测对话状态：这一轮的 `done` 说已结束，或打开的对话记录里有结束事件，就进入「已结束」，发消息、拨电话都不可用；「开个新对话」后回到可用。
- **验收**：按 `docs/agents/local-acceptance.md` 在本地构建版上用 Playwright 看结束卡两种样子、「开个新对话」、送礼换到新对话。

## Out of Scope

- 翻看更早对话的入口：开了新对话后，已结束的对话照旧看不到（数据还在）。
- 文字对话单独的一套常量。
- 新对话里告诉她上次是她结束的。
- 对话列表里给已结束的对话换预览文案。
- 通话被挂断时锁对话。
- 从运行记录还原老对话的窗口。
- 上线公告：上线后另外起草给用户确认，不在票里。
