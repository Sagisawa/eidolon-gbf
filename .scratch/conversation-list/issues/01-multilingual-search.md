# 01: 多语言搜索

**What to build:** 对话列表的搜索框能用日文原名、中文简体译名、假名（平假名或片假名）、罗马字搜到角色，只输姓或只输名也行；繁体、日文字形和简体可以混着输。输组合名（原名、假名读音、简体写法）会搜出整组成员。规则见 spec「角色的几种名字（后端）」「搜索（前端，纯逻辑）」。

需要做的几件事：

- 角色配置为每位角色加 `name_zh`、`name_kana`、`name_romaji` 三项（可选），并把仓库里 28 位的初稿填好。
- 角色列表接口多给这三项和 `unit_reading`。
- 前端新增一个纯逻辑的角色搜索模块，换掉列表组件里现在那个只比较日文原名的匹配。
- 搜索框的提示文字改成「搜索名字或组合」。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 角色配置接受 `name_zh`、`name_kana`、`name_romaji` 三项，都是可选的单行字符串。写成不是字符串或空字符串时，后端启动就报配置错误，并指出是哪位角色；不写也能照常启动。
- [x] 角色配置开头的说明写清楚这三项的写法：
  - 中文用社区通行的简体译名，姓名之间不空格；
  - 假名用平假名，姓和名之间空一格；
  - 罗马字写成「姓 名」，用平文式、不加长音符号；官方拼法和平文式不同时以官方为准。
- [x] 仓库里 28 位角色的三项全部填好。中文译名用国内社区通行的版本，查证时以萌娘百科等中文资料为准。有一条仓库测试保证每位角色都写了这三项。
- [x] `/api/characters` 每位角色多给 `name_zh`、`name_kana`、`name_romaji`（没配置时为 null）和 `unit_reading`（她所在组合在世界设定里的假名读音，和 `unit` 一起为 null）。后端测试覆盖有值和为 null 两种情况。
- [x] 前端新增角色搜索模块：给一位角色和搜索框里的文字，回答她留不留下。折叠规则和候选写法照 spec。列表组件只调用它。
- [x] 单测覆盖 spec 用户故事 1 到 18 里的每一种写法，用测试里构造的角色数据，至少包括：
  - 「樱木」「真乃」「八宫巡」「巡」「朝日」「圆香」「恋钟」「恋鐘」「戀鐘」「櫻木」；

  - 「L'Antica」「lantica」「アンティーカ」「あんてぃーか」「放课后」，这些都搜出整组成员；
  - 摩美々 / 摩美美；
  - 前后有空格的输入、空输入；
