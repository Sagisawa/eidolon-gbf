# 对话列表：多语言搜索、按最近往来排序、隐藏和置顶

Status: ready-for-agent

## Problem Statement

对话列表（GLOSSARY.md「对话列表」）里有 28 位角色，用户觉得不好用：

- **搜索太弱**：搜索框只拿输入去日文原名（`櫻木真乃`）里找子串。中文用户输「樱木」「真乃」能不能搜到，要看字形碰不碰得上；输「八宫巡」「朝日」这样的中文译名、输「mano」「Sakuragi」这样的罗马字、输「まの」「マノ」这样的假名都搜不到；输组合名也找不到成员。
- **顺序固定**：列表永远按原作的偶像编号排。刚聊过的人可能在第 20 行，每次都得滑下去找；不像 LINE，最近聊过的会自动到上面。
- **人太多**：28 位全都显示。只常聊其中几位的用户没法把其他人收起来，也没法把最常聊的人钉在最上面。

## Solution

1. **多语言搜索**：用日文原名、中文简体译名、假名（平假名或片假名）、罗马字（姓名先后都行、长音写法随意）都能搜到她，只输姓或只输名也行；繁体、日文字形和简体可以混着输。输组合名（原名、假名读音、简体写法）会搜出整组成员。中文译名和罗马字没法从现有数据推出来，由维护者在角色配置里为每位角色手写。
2. **按最近往来排序**：最近有过往来的排在上面，开了新对话也算往来；从没聊过的排在最后，按原作的偶像顺序。
3. **隐藏和置顶**，都只存在这台设备上：
   - **置顶**：电脑上右键、手机上长按一行，在弹出的菜单里置顶或取消置顶。置顶的排在所有人前面，她们之间也按最近往来排，时间旁边有个小图钉。
   - **隐藏**：同一个菜单里可以把她从列表里隐藏。搜索框右边还有一个筛选按钮，打开一个按组合分组的勾选清单，整组或单人勾掉就隐藏。
   - 隐藏的人照样能搜到；正打开着的和正在通话的人照样留在列表里。
   - 有人被隐藏时，筛选图标上有个不显眼的小点，列表底部有一行「已隐藏 n 位」。

## User Stories

### 搜索

1. 作为中文用户，我希望输入简体中文译名（「樱木真乃」）就能找到她，这样不用会打日文汉字。
2. 作为中文用户，我希望只输名字（「真乃」「圆香」）或只输姓（「樱木」）也能找到她，这样少打几个字。
3. 作为中文用户，我希望输入社区通行的中文译名能找到名字是假名的角色（「八宫巡」「巡」找到八宮めぐる，「朝日」找到芹沢あさひ），这样不用知道她日文怎么写。
4. 作为用繁体或日文字形打字的用户，我希望「櫻木」「戀鐘」「恋鐘」「恋钟」都能找到同一个人，这样不管我的输入法出哪种字形都行。
5. 作为日语用户，我希望照旧用日文原名搜到她，这样原来的用法不受影响。
6. 作为日语用户，我希望输入假名读音（「まの」「さくらぎ」）就能找到她，这样输入法还没转成汉字也能搜。
7. 作为日语用户，我希望平假名和片假名都算（「マノ」也能找到真乃），这样不用在意输入法当前的模式。
8. 作为英文用户，我希望输入罗马字（「mano」「Sakuragi」「Sakuragi Mano」）就能找到她，这样不用会输入日文或中文。
9. 作为英文用户，我希望姓名先后都行（「Mano Sakuragi」也能找到），这样按英文习惯输入也行。
10. 作为英文用户，我希望长音的几种写法都认（「toru」「tooru」「tōru」都找到浅倉透），这样我不用猜系统用的是哪种罗马字。
11. 作为英文用户，我希望搜索不分大小写、不在意空格（「sakuragimano」也行），这样随手输入就能找到。
12. 作为用户，我希望输入组合名（「L'Antica」「lantica」「アンティーカ」「あんてぃーか」）就列出整组成员，这样想找某个组合的人时一次全看到。
13. 作为中文用户，我希望用简体写组合名（「放课后」）也能搜出那一组，这样不用输入日文汉字。
14. 作为用户，我希望搜索框前后多打的空格不影响结果，清空搜索框就回到完整列表，这样搜索框的行为和现在一样。
15. 作为用户，我希望什么都没搜到时，照旧看到「没有找到这位偶像」，这样知道不是列表坏了。
16. 作为用户，我希望搜索框的提示文字告诉我可以搜名字或组合，这样知道能用哪些东西搜。
17. 作为用户，我希望搜索结果也按最近往来排、置顶的在前，这样常聊的人在结果里也排在前面。
18. 作为用户，我希望搜索不会因为只输一个字母就出错，最多是结果多一点，这样边打边看也没问题。

### 按最近往来排序

19. 作为用户，我希望刚聊过的角色排在最上面，这样回到对话列表时不用滑下去找她。
20. 作为用户，我希望我发出一句话、她回复记下之后，她那一行马上排到最上面，这样列表顺序和我的实际往来一致。
21. 作为用户，我希望给一位角色开了新对话、还没说话时，她也排到最上面，这样刚开的对话也好找。
22. 作为用户，我希望从没聊过的角色排在所有聊过的人后面，并且按原作的偶像顺序排，这样没聊过的人也有固定、好找的位置。
23. 作为用户，我希望一行排到最上面时直接跳过去，不播放动画，这样列表不会晃来晃去。
24. 作为正在通话的用户，我希望通话中每记下一个回合，她那一行就排到最上面，这样她在列表里随时好找。
25. 作为用户，我希望列表照旧是一整列平铺，不按组合分段，这样「最近往来」的顺序不被打断。

### 置顶

26. 作为常聊几位角色的用户，我希望能把她们置顶，这样即使最近一阵没聊，她们也始终在最上面。
27. 作为用电脑的用户，我希望右键一行就弹出「置顶」「取消置顶」，这样操作就在手边。
28. 作为用手机的用户，我希望长按一行弹出同一个菜单，并且长按不会顺便打开她的对话，这样置顶不会误操作。
29. 作为用键盘的用户，我希望聚焦一行时，按菜单键或 Shift+F10 也能打开这个菜单，这样不用鼠标也能置顶。
30. 作为用户，我希望置顶的人数没有上限，这样想钉几个就钉几个。
31. 作为用户，我希望几位置顶的角色之间也按最近往来排，这样置顶区里也是最近聊的在上面。
32. 作为用户，我希望置顶的那一行在时间旁边有个小图钉，这样一眼分得清谁是置顶的。
33. 作为用户，我希望取消置顶后，她回到按最近往来该在的位置，这样列表不会乱。

### 隐藏

34. 作为只聊其中几位的用户，我希望能把其他人从列表里隐藏，这样列表短一点，常聊的人一眼就能看到。
35. 作为用户，我希望在右键或长按菜单里就能隐藏一位角色，这样不用打开别的面板。
36. 作为用户，我希望搜索框右边有一个筛选按钮，打开后按组合分组列出所有人，每人一个勾选框，这样能一次整理整个列表。
37. 作为用户，我希望筛选清单里组合的顺序和组内成员的顺序都是官方顺序，这样和原作的认知一致。
38. 作为用户，我希望点组合标题前的勾选框就能整组显示或整组隐藏，这样不用一个个勾。
39. 作为用户，我希望组里只隐藏了一部分人时，组合的勾选框显示「部分勾选」，这样一眼看出这组的状态。
40. 作为用户，我希望清单里每个人旁边有小头像，这样不认得名字时也认得出她。
41. 作为用户，我希望在清单里勾选、取消立即生效，没有「确定」键，这样改动马上看得到。
42. 作为用户，我希望清单右上角有「全部显示」，一下把隐藏的人都恢复，这样不用一个个勾回来。
43. 作为用户，我希望「全部显示」不动我的置顶，这样恢复隐藏不会顺带打乱我钉好的人。
44. 作为用电脑的用户，我希望筛选清单是挂在按钮下面的弹出面板，点外面就关上，这样不离开列表。
45. 作为用手机的用户，我希望筛选清单从屏幕底部弹出，可以滚动，这样小屏幕上也放得下 28 个人。
46. 作为用键盘或读屏的用户，我希望筛选按钮有名字，清单里每个勾选框读得出是谁、组合的勾选框读得出是哪个组合以及当前状态，这样不看屏幕也能整理列表。
47. 作为用户，我希望隐藏了的角色照样能被搜到，这样想找她时不用先去筛选里把她勾回来。
48. 作为用户，我希望在搜索结果里右键或长按一个隐藏的角色，菜单里是「在列表中显示」，这样搜到她就能顺手恢复。
49. 作为用户，我希望把一个隐藏的角色置顶时，她同时恢复显示，这样不会出现「置顶了却看不到」的情况。
50. 作为用户，我希望隐藏一个置顶的角色时，她的置顶也一并取消，这样以后恢复显示时她不会突然出现在最上面。
51. 作为正在和某位角色通话的用户，我希望即使隐藏了她（或她所在的组合），她那一行也照旧留在列表里，显示「通话中 mm:ss」，这样我随时能回到通话。
52. 作为正打开着某位角色对话的用户，我希望隐藏她以后，她那一行在我离开她的对话之前照旧留着，并且仍是选中状态，这样左栏不会突然找不到当前对话。
53. 作为用户，我希望离开那位隐藏了的角色的对话后，她就从列表里消失，这样隐藏照常生效。
54. 作为隐藏了几位角色的用户，我希望筛选图标上有个不显眼的小点，这样过了很久也记得自己隐藏过人。
55. 作为隐藏了几位角色的用户，我希望列表最底下、免责声明上面有一行「已隐藏 n 位」，点一下打开筛选清单，这样滑到底找不到人时马上知道去哪里找。
56. 作为正在搜索的用户，我希望搜索时不显示「已隐藏 n 位」那一行，这样不会和搜索结果混在一起（隐藏的人本来就能搜到）。
57. 作为把所有人都隐藏了的用户，我希望列表显示「所有角色都隐藏了」，下面一个按钮打开筛选清单，这样不会以为列表坏了。
58. 作为用户，我希望以后新加的角色默认显示在列表里，这样我不会错过新角色。
59. 作为用户，我希望隐藏和置顶在我刷新、关掉浏览器再打开后都还在，这样整理一次就够了。
60. 作为和别人共用一台电脑的用户，我希望我的隐藏和置顶与别人的分开，这样换个账号登录看到的是那个人自己的列表。
61. 作为换了一台设备的用户，我知道隐藏和置顶不会跟过去，需要在新设备上重新整理（GLOSSARY.md「隐藏 / 置顶」）。
62. 作为用户，我希望隐藏和置顶只改变列表里显示谁、谁在前面，不影响我和她的对话和记忆，这样整理列表没有副作用。
63. 作为用户，我希望这台设备上的隐藏和置顶数据坏了或者读不到时（比如隐私模式），列表照常显示所有人，只是记不住我的整理，这样列表不会因此打不开。

### 维护

64. 作为维护者，我希望每位角色的中文译名、假名读音和罗马字写在角色配置里，和名字、简介放在一起，这样加新角色时一处改完。
65. 作为维护者，我希望这三项写错格式（比如不是字符串、是空字符串）时，后端启动就报错并指出是哪位角色，这样不会悄悄搜不到。
66. 作为维护者，我希望有测试保证仓库里配置的每位角色这三项都写了，这样不会漏掉一位。
67. 作为部署者，我希望自己加的角色不写这三项也能启动，只是搜不到这几种写法，这样老配置不会因为升级就起不来。
68. 作为维护者，我希望角色配置文件开头的说明写清楚这三项的写法，这样别人照着写不会错。

## Implementation Decisions

### 角色的几种名字（后端）

- 角色配置每位角色新增三项，**都是可选的单行字符串**，不能是空字符串：
  - `name_zh`：中文简体译名，用国内社区通行的那一版，姓和名之间不空格，例如 `樱木真乃`、`八宫巡`。
  - `name_kana`：全名的平假名读音，**姓和名之间空一格**，例如 `さくらぎ まの`。
  - `name_romaji`：全名的罗马字，写成「姓 名」，中间空一格，首字母大写。用平文式，长音不加长音符号，例如 `Sakuragi Mano`、`Asakura Toru`。官方给了不同拼法的，以官方为准（例如斑鳩ルカ的 `Luka`）。
- 写错（不是字符串、空字符串）就报配置错误，并指出是哪位角色。这和现有字段的校验是一个风格。
- 不写这几项时，角色照常启动，只是搜不到这几种写法。仓库里的 28 位全部要写，有一条仓库测试保证。
- 不从读音文件里读假名。读音文件是给语音合成用的，`eidolon reading draft` 会重写它；搜索用的读音单独写在角色配置里。
- 角色列表接口每位角色多给四项：`name_zh`、`name_kana`、`name_romaji`（没配置时为 null），以及 `unit_reading`。`unit_reading` 是她所在组合的假名读音，取自世界设定，和 `unit` 一起为 null。
- 角色配置开头的说明里补上这三项的写法。
- 28 位的初稿由实现 01 的人填写，中文译名交给用户人工校对。

### 搜索（前端，纯逻辑）

- 新增一个纯逻辑的**角色搜索模块**：给一位角色和搜索框里的文字，回答她留不留下。列表组件只调用它，不自己比较字符串。
- 空输入（去掉前后空格后）全部留下。
- 输入和每个候选写法都先经过同一套**折叠**，再看折叠后的输入是不是某个候选的子串：
  - Unicode NFKC 规整，转小写；
  - 去掉空白和常见的分隔符号（`・`、`'`、`’`、`-`、`·`、`.`）；
  - 片假名转平假名；
  - `々` 展开成它前面那个字（`摩美々` → `摩美美`）；
  - 汉字字形折叠：把繁体字和日文字形折成简体（`櫻` → `樱`、`鐘`/`鍾` → `钟`、`円`/`圓` → `圆`、`課` → `课`、`後` → `后`……）。用一张手写的小表，覆盖目前所有角色名和组合名里会碰到的字；加角色时如果有新字，就往表里补；
  - 拉丁字母的长音折叠：`ō`/`ô`/`oo`/`ou`/`oh` → `o`，`ū`/`uu` → `u`，`ā`/`aa` → `a`，`ī`/`ii` → `i`，`ē`/`ee` → `e`。
- 候选写法：
  - 日文原名；
  - `name_zh`；
  - `name_kana` 和 `name_romaji` 的「姓名」「名姓」两种顺序（按空格拆开再拼）；
  - 组合名、组合读音。
  
  只输姓或只输名，靠子串匹配自然就能命中。命中组合名或组合读音时，整组成员都留下。
- 不做昵称、拼音、错字容忍，不高亮命中的是哪种写法。
- 搜索框的提示文字改成「搜索名字或组合」，文案放在 `copy.conversationList`。

### 排序（前端，纯逻辑）

- 新增一个纯逻辑的**列表编排**函数，放在现有的对话列表逻辑模块里，和 `previewOf`、`dayOf` 放在一起。它决定显示哪些角色、按什么顺序；列表组件只渲染它的结果。
- 02 里它只管排序：
  - 每位角色的「最近往来时间」就是 `previewOf` 给出的那一行时间：最新一次对话的最后一句的时间，对话还没有话时取开对话的时间。
  - 有这个时间的角色按时间从新到旧排；时间相同的，按接口给的顺序（即原作的偶像顺序）。
  - 没有这个时间的角色（从没聊过）排在后面，保持接口给的顺序。
  - 搜索结果用同一套排序。
- 列表本来就会在每个回合记下后、开新对话后刷新摘要，排序跟着刷新走，不需要新的接口；一行跳上去时不做位移动画。
- 03 给这个函数加上置顶、隐藏和「始终留下」的角色（见下）；01 的搜索也通过它生效。

### 隐藏和置顶（前端）

- 新增一个**列表偏好**模块，管这台设备上的隐藏和置顶。
  - 存在 localStorage 里，按用户分开存，键里带用户 id。做法参照浏览器里存自带密钥的那个模块。
  - 存的是「隐藏了谁」「置顶了谁」两组角色 id，不存「显示了谁」，所以新加的角色默认显示。
  - 配置里已经不存在的角色 id，读的时候忽略。
  - 读不到或者数据坏了，就当作什么都没隐藏、没置顶；存不进去（隐私模式）时，改动只在这次页面里生效，不报错。
  - 操作有这几个：
    - 隐藏一位角色，同时取消她的置顶；
    - 显示一位角色；
    - 置顶一位角色，同时取消她的隐藏；
    - 取消置顶；
    - 隐藏或显示整个组合；
    - 全部显示：只清空隐藏，置顶不变。
- 列表编排函数的输入加上：列表偏好、搜索文字、**始终留下**的角色（当前打开的那位、正在通话的那位）。规则：
  - 没有搜索时：去掉隐藏的人，但始终留下的那几位不去掉。
  - 有搜索时：在所有角色里搜，隐藏的人照样出现。
  - 置顶的排在前面，她们之间按最近往来排；其余的按 02 的规则排。
  - 每一行带上「是否置顶」「是否隐藏」，供菜单和图钉使用。
  - 另外给出这台设备上隐藏的人数，只数配置里还存在的角色。
- **行菜单**：加装 shadcn 的 `context-menu`（底层 Base UI 的 ContextMenu，电脑上右键、触屏上长按、键盘的菜单键都能打开）。
  - 菜单项：「置顶」或「取消置顶」，以及「在列表中隐藏」或「在列表中显示」，按她当前的状态显示。
  - 长按打开菜单时，不能同时触发打开对话。
  - 菜单是中性色，不带她的颜色，遵守 DESIGN.md 里浮层的规则。
- **筛选按钮**：在搜索框右边，是一个图标按钮。
  - 有人被隐藏时，图标右上角有一个小圆点，用中性的次要文字色（`muted-foreground`），不用她的颜色，也不用醒目的强调色。
  - 读屏读出的名字里带上隐藏的人数。
- **筛选面板**：宽屏用 `Popover`，挂在按钮下面；窄屏用 `Drawer`，从底部弹出。判断宽窄用现有的 `useWide`。
  - 标题「列表里显示谁」，右上角「全部显示」，没人隐藏时禁用。
  - 按 `unit_order` 分组，组标题是组合名，前面是三态勾选框（全勾、部分勾、全不勾）；组内按接口顺序，每人一行：勾选框、小头像、名字。
  - 没有组合的角色（世界设定缺失或资料对不上）放在最后的「其他」组。
  - 面板可以滚动；改动立即生效，没有确定键。
  - 面板里不放搜索框，也不放置顶开关。
- **置顶图钉**：置顶的那一行，在时间旁边放一个小图钉图标，用次要文字色。正在通话、不显示时间的那一行，图钉照样显示。
- **「已隐藏 n 位」**：有人被隐藏、搜索框为空时，在列表最底下、免责声明上面显示这一行，用 Meta 字号、次要文字色，整行可以点，点了打开筛选面板。
- **全部隐藏**：所有人都被隐藏、也没有始终留下的人时，列表区显示空状态：「所有角色都隐藏了」，下面一个按钮打开筛选面板。
- 新增的文案全部放在 `copy.conversationList`。
- DESIGN.md「Conversation list」一节写进下面这些：
  - 搜索框右边的筛选按钮和小点；
  - 行菜单；
  - 置顶图钉；
  - 「已隐藏 n 位」那一行；
  - 全部隐藏时的空状态；
  - 筛选面板的样子（宽屏 Popover、窄屏 Drawer，按组合分组、三态勾选）；
  - 列表按最近往来排序、不分段。

## Testing Decisions

- 好的测试只看对外的行为：给定输入，得到什么结果。不去断言内部用了什么折叠步骤、存储里存的是什么具体格式（偏好模块的读写往返除外）。
- 测试的接缝，从高到低：
  1. **角色列表接口**（后端）：三项名字和 `unit_reading` 原样给出，没配置时为 null；配置校验报错的几种情况；仓库测试保证 28 位都写了三项。参照现有角色测试里对角色列表接口的断言，以及「idol_id 必须是正整数」那类配置校验测试。
  2. **角色搜索模块**（前端纯逻辑）：用户故事 1 到 18 里的每一种写法各有一个用例，包括组合名搜出整组、繁简日字形混输、长音变体、姓名颠倒、只输一个字母、空输入。用例的角色数据在测试里构造，不读仓库配置。
  3. **列表编排函数**（前端纯逻辑）：
     - 排序：最近往来、开新对话算往来、没聊过的按接口顺序、时间相同时的次序；
     - 置顶：置顶在前、置顶之间按最近往来；
     - 隐藏：没有搜索时去掉隐藏的人，始终留下的不去掉，有搜索时隐藏的照样出现；
     - 隐藏人数只数还存在的角色；
     - 全部隐藏时结果为空。
     
     参照现有对话列表逻辑测试（`previewOf`、`dayOf`）的写法。
  4. **列表偏好模块**（前端，localStorage）：
     - 按用户分开；
     - 读写往返；
     - 隐藏和置顶互斥，后做的说了算；
     - 「全部显示」不动置顶；
     - 数据坏了当空；
     - 存不进去时不抛错；
     - 已不存在的角色 id 被忽略。
     
     参照浏览器里存自带密钥那个模块的测试。
- 组件层（菜单、面板、小点）不写组件测试，靠人工验证清单。这和项目一贯的做法一致：前端只测纯逻辑，界面靠人工验收。
- 每张票做完都跑前端单测、后端相关测试和 shadcn 纪律检查。

## Out of Scope

- 隐藏和置顶跨设备同步，或者存到服务器上。
- 粉丝昵称、拼音、错字容忍、搜索结果高亮。
- 列表按组合分段。
- 筛选面板里的置顶开关、面板里的搜索框。
- 一行移动时的位移动画。
- 同一个浏览器开了几个标签页时，隐藏和置顶即时同步（别的标签页在下次载入时生效）。
- 未读数、免打扰等 LINE 的其他列表功能。

## Further Notes

- 第一波 01（多语言搜索）和 02（按最近往来排序）互不依赖，可以并行。两张票都会改列表组件里过滤和排序的那一两行，合并时注意。第二波 03 依赖 02 的列表编排函数，也依赖 01 的搜索模块，因为编排函数要在搜索结果里排序。
- 罗马字只存一种写法。官方拼法和平文式不同的（`Luka` / `Ruka`），只认官方那种；用户仍然可以用假名或中文名搜到她。
- 汉字折叠表是手写的小表，不引入简繁转换库：要覆盖的只有几十个名字里的字，引入库会把前端包撑大很多。
- 前端写代码前先读 `frontend/AGENTS.md` 的「shadcn 纪律」；加装 `context-menu` 时按那里写的办法绕开本机的 `EALLOWSCRIPTS`。
