# 01: 保留期可调、空间提醒、备份记录和锁

**What to build:** 部署者可以用 `EIDOLON_BACKUP_KEEP_DAYS` 把保留期调短到 1–30 天，用 `EIDOLON_BACKUP_WARN_GB` 在桶里备份太多时收到提醒；每次备份的日志里能看到桶里还剩几份、共多大。cron、手动和（下一张票的）后台按钮共用一个「备份运行」入口：每次运行在数据库里留一条备份记录，正在进行的那条同时是锁，同一时间只有一次备份。见 `../spec.md`「保留期和空间」「备份记录与锁」和 ADR-0012 的 2026-10-15 修订。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 保留期和空间

- [ ] 备份设置多读 `EIDOLON_BACKUP_KEEP_DAYS`（整数 1–30，空着为 30）和 `EIDOLON_BACKUP_WARN_GB`（正数，可以是小数，空着不提醒）；其他值是配置错误，`eidolon backup` 以退出码 1 结束，错误信息说明允许的范围（保留期写明「最长 30 天，是隐私政策的承诺」）
- [ ] 清理按保留天数判断；最新的一份永远保留、名字不符的对象不动，都不变
- [ ] 列出桶里的对象时带上大小；报告里多出桶里剩下的备份的总字节数（只算备份对象）；`eidolon backup` 的输出里写出剩几份、共多大
- [ ] 总量超过阈值时输出一条「注意」，退出码不变、心跳照发

### 备份记录与锁

- [ ] 新的备份记录表：开始、结束（进行中为空）、来源（`cron` / `manual` / `admin`）、退出码、对象名和大小、桶里剩下的份数和总字节数、是否超过阈值、错误原因；不含用户内容；写新记录时顺带删掉 90 天前的
- [ ] 「备份运行」入口：插入进行中的记录作为锁（已有开始不到 1 小时、没结束的记录就放弃）→ 现有的备份、清理、心跳 → 把结果写回；用数据库而不是文件锁（本地开发在 Windows 上跑）。配置不全也留一条记录
- [ ] 提供「把所有没结束的记录标成已放弃」，供 03 的恢复使用
- [ ] `eidolon backup` 走这个入口，撞上锁时以退出码 6 结束；接受来源（默认 `manual`）
- [ ] `deploy/db-backup.sh`：区分 cron 和手动，把来源交给 `eidolon backup`；容器里返回的 6 照原样传出，日志里的含义不变；脚本开头的退出码说明同步更新
- [ ] 留出给后台按钮用的入口：在后端进程里跑一次备份运行时，导出、压缩、加密放进线程，不卡事件循环（02 直接调用）

### 配置与文档

- [ ] `.env.example` 加上两个变量和说明
- [ ] `docs/deploy.md`「备份」：新变量、日志里多出的份数和总量与「注意」、退出码 6 现在也可能是后台按钮在备份；ADR-0012 正文里的「30 天」改成「保留期（默认 30 天）」的地方按需调整

### 测试

- [ ] 照 `backend/tests/test_backup.py`（`FakeBucket` + `httpx.MockTransport`，固定 `now`）：保留天数 7 时删掉 7 天前的、留下最新一份；0、31、非整数是配置错误；阈值超过时有提醒、退出码 0、心跳照发；没设阈值没有提醒；总量只算备份对象
- [ ] 锁：进行中的记录挡住第二次运行（退出码 6）；开始超过 1 小时没结束的不挡；每次运行（包括配置不全）都留一条记录、来源正确；90 天前的记录被删掉；「标成已放弃」之后不再挡
- [ ] `eidolon backup` 命令行照 `tests/conftest.py` 的 `Admin` 驱动：新变量配置错误时退出码 1
