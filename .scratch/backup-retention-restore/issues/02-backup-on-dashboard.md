# 02: 看板上的备份状态和「立即备份」

**What to build:** 管理者打开看板，在服务健康状态旁边看到备份：上一次成功的时间和大小、桶里的份数和总量、保留期、最近一次失败的原因和来源；超过 26 小时没有成功、从没成功过、未配置或配置错误都标异常，总量超过阈值也标出来。点「立即备份」后马上显示「备份中…」，几分钟后自动变成新结果；无论正在进行的备份是谁发起的都显示「备份中…」。见 `../spec.md`「后台接口与看板」。

**Blocked by:** 01

**Status:** ready-for-agent

### 后端

- [ ] 读备份状态的管理者接口：是否配置（只看设置齐不齐，错误附原因）、保留天数、阈值、进行中的那一次（开始、来源）、最近一次成功、最近一次（可能失败）、是否异常（未配置、配置错误、最近一次成功超过 26 小时或从没成功）；全部由后端算好
- [ ] 立即备份的管理者接口：已有一次在进行就返回冲突；配置不全直接返回错误；否则在后端进程里起后台任务跑一次备份运行（来源 `admin`）并立刻返回。用 01 留出的入口，导出不卡事件循环；输出进后端日志
- [ ] 非管理者访问两个接口都是 404

### 前端

- [ ] 看板在服务健康状态旁边加「备份」一块：正常、异常（各种原因的文案）、未配置、备份中几种状态；保留期、份数、总量、上一次成功的时间和大小、最近一次失败的原因和来源
- [ ] 「立即备份」按钮：点了马上变成「备份中…」并禁用；接口返回冲突时同样显示「备份中…」；轮询频率同「进行中的通话」（每分钟），备份进行中时更快，结束后停下快轮询
- [ ] 文案进 `i18n/zh.ts`；照 `frontend/AGENTS.md`「shadcn 纪律」和 `DESIGN.md`；窄屏下照样能用

### 文档

- [ ] `docs/deploy.md`「备份」加一段：看板上的备份状态、26 小时标异常、「立即备份」，以及按钮那次的输出在 `docker compose logs backend`、不在 `logs/db-backup.log`

### 测试

- [ ] 照 `backend/tests/test_activity_records.py` 用测试客户端：非管理者 404；未配置、配置错误、从没成功、26 小时以内、超过 26 小时；进行中时立即备份返回冲突；立即备份的任务跑完后记录的来源是 `admin`
- [ ] 前端如有状态判断逻辑，照 `frontend/src/lib/dashboard.ts` 旁边的单测
- [ ] 本地构建版上用 Playwright 验收（`docs/agents/local-acceptance.md`）：拦截状态接口造出正常、异常、未配置、备份中，各截一张；点「立即备份」后按钮变成「备份中…」

### 人工验收
