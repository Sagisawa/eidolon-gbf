# 01: 检索查询带上她的上一句

**What to build:** 用户刚和真乃聊完写真集，接着问「那时候累吗」，真乃查到的剧情和资料是写真集那段。剧情、角色资料、作品资料的检索，以及判断模型认定为「回顾剧情」时的那次回忆，都改用和找记忆相同的查询：角色的上一句回复（中文字幕，去掉语气提示）加上用户这句话；没有上一句时只用这一句。回顾剧情工具的查询仍是对话模型写的那句。重排校准集补一批短追问用例，确认分数线仍然合适。打字和通话都生效。背景见 `../spec.md`「查询（票 01）」一节。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

## 已定的设计（详见 spec）

- 查询沿用找记忆的拼法（`memory_query`），向量化和重排都用这同一个文本。不采用「最近两三句用户发言」。
- 判断模型看到的内容不变。
- 重排校准集的 `previous` 放开到所有题型，`eval rerank` 用同一个拼法。新补的短追问题标 `reviewed = false`：上一句聊某段剧情或某个人、这一句省略主语或用代词追问；再加一两道上一句和这一句话题无关的，看会不会被旧话题带偏。

## 验收

- [x] 文字回合测试：有上一句回复时，假向量化服务和假重排服务收到的查询都是「上一句字幕 + 这一句」，字幕里没有语气提示；对话的第一句只用这一句。
- [x] 文字回合测试：判断模型判为回顾剧情时，回忆用拼好的查询；对话模型调用回顾剧情工具时，查询是它写的那句。
- [x] 重排校准的测试：剧情、资料、作品资料题写了 `previous` 时按新拼法拼查询；不写的和以前一样。
- [ ] `backend/` 下 `pytest` 全部通过，`ruff` 和 `pyright` 没有新的报错。
- [ ] **人工验收**（agent 可以先代做，结论给用户过目）：校对新补的校准题；用真模型跑 `eidolon eval rerank`，参考资料组的分数线要不要调，结论写进 `rerank.py` 的校准记录和本票 Comments。

## Comments

**实现（2026-10-14，agent）**

- `Retrieval._look_up` 用 `memory_query(history, text)` 拼一次查询，剧情、角色资料、作品资料的向量化和重排、判断模型触发的回忆都用它；找记忆本来就用它。判断模型看到的内容没动。
- 回忆的提示词标题（「# 回顾剧情：……」和「没有想起和「……」有关的剧情」）仍写用户这句话，不写拼好的两行：上一句回复就在对话里。回顾剧情工具仍只查模型写的那句。
- `rerank_eval`：去掉「只有 memory 类问题可以写 previous」的检查，所有题都按 `joined_query(previous, query)` 拼；报告逐条里有上一句时多打一行「上一句：……」。
- 校准集末尾补了 11 道短追问（id 带 `-followup-`，`reviewed = false`）：9 道上一句聊剧情、人物、歌或演出，这一句省略主语或用代词；2 道换了话题（猫头鹰 → 生日，长崎美食 → 足球）。标注沿用已校对题里的剧情编号和资料标题，`previous` 是自己写的台词。
- 新测试：`test_retrieval.py` 两条（带上一句、第一句只用这一句），`test_recall_story.py` 两条（判断模型触发的回忆用拼好的查询、工具只用模型写的那句），`test_rerank_eval.py` 一条（剧情、资料、作品资料题带 previous），删掉了「非 memory 题写 previous 报错」那条参数。
- 只跑了改动相关的单个测试文件、`ruff check`、`pyright`；完整 `pytest` 留给合并后统一跑，所以第四项还没勾。

**用真模型跑 `eidolon eval rerank`（2026-10-14，agent 代做，待用户过目）**

在本地库的快照上跑，0.6B 和 4B 各跑两遍：短追问带上一句，以及把短追问的 `previous` 去掉（等于改动前的查法）。

- 带上一句以后短追问查得到了：11 道题标了 14 个相关候选，只用这一句时 10 个连向量检索都没进；带上一句后进了 10 个。0.6B 上它们最低 0.33（两个 1stLIVE 演出日 0.33、0.35，爸爸后来的态度 0.36），其余 0.94 以上；4B 全部 0.83 以上。
- 分数线不调：0.6B 的 0.3 全部放进；调到 0.4 会丢这三个，误放只从 68/348 降到 60/348。4B 的 0.7 也全部放进。原有题都没写 previous，查法没变，两遍的分数只有服务本身的小抖动（0.6B 在 0.3 上相关命中都是 46/48，误放 116/1026 对 117/1025）。结论写进了 `rerank.py` 的校准记录。
- 要注意的代价（分数线解决不了）：
  - 同一话题的其他事件会一起进来，分数 0.9 以上：追问便当时另几次做饭的剧情，追问灯织时 illumination STARS 的其他活动。
  - 换了话题时旧话题会被拉进来：上一句聊猫头鹰、这一句问生日，0.6B 给猫头鹰的资料和花鸟园剧情 0.85～0.9996，「档案 / 基本信息」反而没进候选；上一句聊长崎美食、这一句问足球，长崎的剧情和资料 0.99 以上。spec 里「不被上一个话题带偏」这条，单靠拼查询做不到。要缓解得另想办法（例如这一句够完整时不拼上一句，或者只在向量检索时拼、重排只用这一句），已超出本票，需要拷问后再定。
  - 顺带发现：0.6B 对「对了，你生日是几号来着？」只给「档案 / 基本信息」0.08（不带上一句时），而恋钟的同类题是 0.9997，和本票无关。
