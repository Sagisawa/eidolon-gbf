# 02: 判断时先算好查询向量

**What to build:** 需要查剧情或资料的回合，角色开口更快。回合一开始就把查询向量化一次，在剧情库（只限她出场的剧情）、角色资料、作品资料和用户有效的记忆里各取候选，和判断模型同时进行；判断模型说要查，就拿这些候选直接重排；说不用，就取消、丢掉。剧情、资料、记忆和回忆共用这一个查询向量。重排仍然只在判断模型作答后做，次数不变。背景见 `../spec.md`「提前向量化（票 02）」一节。

**Blocked by:** 01（查询统一以后，资料和记忆才能共用一个向量）

**Status:** ready-for-agent

## 已定的设计（详见 spec）

- 选 B：只抢跑向量化和向量检索，不抢跑重排。
- 判断模型作答后：「查资料」重排资料候选和记忆候选；「只想起记忆」只重排记忆候选；「回顾剧情」复用查询向量和剧情库候选，加上作品资料里演出和唱片的候选一起重排；「不用查」取消还没做完的部分。
- 判断模型出错或超时照旧按「查资料」处理。
- 被丢掉的那次向量化照常记进看板。
- 通话中因补充重新开始的回合，旧回合提前做的部分随回合一起取消。
- 找记忆要能用算好的查询向量；接口怎么切由实现决定，但一个回合只向量化一次。

## 验收

- [ ] 文字回合测试：需要查资料的回合，假向量化服务只收到一次查询，资料和记忆都照常带上。
- [ ] 文字回合测试：判断模型拖着不答时，向量化已经开始；放行以后回合照常完成。（假判断模型加一个能拖住、再放行的开关。）
- [ ] 文字回合测试：判断为「不用查」时假重排服务没有被调用，系统提示词里没有资料和记忆；判断为「只想起记忆」时只重排记忆。
- [ ] 文字回合测试：判断为回顾剧情时，回忆结果和改动前一致（剧情、剧情目录、演出或唱片条目），向量化仍只有一次。
- [ ] 文字回合测试：判断模型出错时照常带上资料。
- [ ] 通话层的已有测试（补充、打断、回合收尾）全部通过；补充让回合重新开始时，旧回合的检索被取消。
- [ ] `backend/` 下 `pytest` 全部通过，`ruff` 和 `pyright` 没有新的报错。
- [ ] **人工验收（留给用户）**：线上部署几天后，对比看板上需要查资料的回合开口时间。
