# 通话层的台词卡按她说话的节奏换段

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，特别是「段」「通话层」「只看文字」「补充」「打断」「立绘指令」。设计在 2026-10-11 的 grilling 中定下。这件事改回去不难，所以不写 ADR。

## Problem Statement

她在通话里的回复通常有两段以上。台词卡上显示的「当前这段」取的是文字最新到达的那段，而文字是 LLM 流式生成的，比她的声音快得多。结果她还在念第一段，台词卡几秒内就翻到了最后一段。用户只看得清最后一段的日语和字幕，前面几段一闪而过。

「只看文字」时也一样：每段一到就换，回复几秒就放完了，用户来不及读。

把整条回复都堆在台词卡上也不行：内容太多，会压住立绘，也不像打电话。

## Solution

台词卡一次仍然只显示一段，换段的节奏改成跟着她说话走：

- **有声音时**：她开始念哪段，台词卡就显示哪段。字幕不会比声音快，每段停留的时间就是她念这段的时间。后端已经在每段开始出声时发出 `segment-playing`，立绘现在就靠它，台词卡改为用同一个信号。
- **「只看文字」时**：没有声音可以跟，就按估算的朗读时长换段。每段停留的时间大约等于她念这段要的时间，开不开「只看文字」，节奏差不多。立绘的表情跟台词卡显示的那段走。
- **声音出岔子时**：某段没有出声，后面那段一开始念就直接换过去。整条回复已经记下、却再也没有声音的，剩下的段按估算节奏放完。字幕不会因为声音出故障就卡住或消失。
- **下一条回复来了**：新回复的第一段一出现，台词卡就换到新回复，旧回复没放完的段跳过（文字记录里都在）。在那之前，台词卡停在旧回复当前那段，不清空。

一段之内不做逐字高亮（卡拉 OK）。Fish Audio 不提供逐字时间，估算出来的高亮会和声音对不上。

## User Stories

1. 作为通话中的用户，我希望台词卡显示的正是她此刻在念的那段，这样我边听边看，两边对得上。
2. 作为通话中的用户，我希望她回复有好几段时，每段都在台词卡上停留到她念完，这样前面几段我也看得清日语和字幕。
3. 作为通话中的用户，我希望台词卡不会跑到她声音的前面，这样我不会先看到她还没说出口的话。
4. 作为通话中的用户，我希望台词卡也不会明显落后于她的声音，这样字幕帮得上忙。
5. 作为通话中的用户，我希望一段之内整段同时显示，而不是带着和声音对不上的逐字高亮。
6. 作为通话中的用户，我希望她一段还没说完时，这段的日语和字幕随文字到达逐渐补全，和现在一样。
7. 作为通话中的用户，我希望她开口前台词卡不提前显示她的回复，停在她上一条回复最后显示的那段（或者通话刚接通时的提示）。
8. 作为通话中的用户，我希望有声音时台词卡上只有当前这段，不多出浅色的上一段，这样台词卡不会变高、多压住立绘。
9. 作为开着「只看文字」的用户，我希望她的回复一段接一段出现，每段停留的时间大约是她念这段要的时间，这样我读得完。
10. 作为开着「只看文字」的用户，我希望很短的段（例如「うん！」）也至少停留一会儿，不一闪而过。
11. 作为开着「只看文字」的用户，我希望上一段仍以浅色留在当前这段上面，这样我跟得上。
12. 作为开着「只看文字」的用户，我希望浅色的上一段是台词卡刚刚显示过的那段，而不是我从没见过的、被跳过的段。
13. 作为开着「只看文字」的用户，我希望她的表情跟着台词卡显示的那段变化，而不是提前换成还没显示出来那段的表情。
14. 作为开着「只看文字」的用户，我希望第一段一到达就显示，不用多等。
15. 作为通话中的用户，我希望在她念到一半时打开「只看文字」，这条回复的台词卡仍按她原来念的节奏换段，只是我听不见。
16. 作为通话中的用户，我希望在她回复到一半时关掉「只看文字」，这条回复（本来就没有声音）仍按估算的节奏放完；下一条回复起跟着声音走。
17. 作为通话中的用户，如果某段因为语音服务出错没有出声，我希望台词卡在她念下一段时直接换过去，不卡在这里。
18. 作为通话中的用户，如果整条回复的声音都出了问题，我希望台词卡仍然按估算节奏把这条回复放完，而不是停在第一段或者什么都不显示。
19. 作为通话中的用户，我希望我打断她之后，台词卡停在她被打断时的那段，等她的下一条回复开始再换，不会把她没说出口的段补放出来。
20. 作为开着「只看文字」的用户，如果台词卡还没放完，我就说了话、她的下一条回复也已经开始出现，我希望台词卡直接换到新回复，不必等旧回复放完。
21. 作为通话中的用户，我希望收起通话层再展开时，台词卡显示的仍是她此刻在说的那段。
22. 作为通话中的用户，我希望重新拨号后，台词卡上没有上一通电话的话，和现在一样。
23. 作为用户，我希望被台词卡跳过的段照样出现在对话页的文字记录里，内容和以前一样。
24. 作为用户，我希望打断时记下哪些段的规则和以前一样（文字已经完整的段都记下）。
25. 作为用户，我希望补充时被放下的回复照样不在台词卡上留下任何东西，包括浅色的上一段。
26. 作为维护者，我希望估算的语速是一个常量，以后看实际效果容易调。

## Implementation Decisions

- **只改前端**。后端已经在每段开始出声时发出 `segment-playing`（带回复号和段号）。这条消息和音频排在同一个队列里，由传输层在这段音频开始播放时发出，比用户听到略早一点。「只看文字」由后端决定这条回复合不合成语音，前端不用配合改。
- **台词卡显示哪段，由 LiveConversation 决定**。快照的 `line`、`previousLine` 不再取「这通电话里最新到达的那段」，而是「台词卡现在该显示的那段」和「台词卡上一个显示过的那段」。决定这件事的逻辑可以拆成 `lib/` 里的内部模块，但对外只通过快照暴露。
- **一条回复是「有声音」还是「没声音」**，按这条回复开始时的模式走到底，和后端「切换只对之后的回复生效」一致。有声音的回复，即使中途静音了，台词卡也一直跟 `segment-playing`。没声音的回复，台词卡一直用估算节奏。
- **跟着声音换段**：收到某条回复第 N 段的 `segment-playing`，台词卡就换到这段。这段的文字还在到达的，随到随补。台词卡只往前走，不退回；中间没出声的段直接跳过。
- **估算节奏**：每段停留时间 = max(1.5 秒, 这段日语的字数 ÷ 5 字/秒)。字数是这段显示出来的日语（不含语气提示）里所有非空白字符，标点也算，「……」算两个字。两个数都是前端常量。下一段的显示时刻 = max(下一段到达的时刻, 当前段开始显示的时刻 + 当前段按完整长度算的停留时间)。第一段一到达就显示。
  - 语速来源：28 位角色落地页招呼的真实音频，连标点一起数，中位数约每秒 4.9 字（去掉首尾静音后约 5.1）。满是「……」的角色（甜花、雾子）在 3.3～4 之间，活泼的（智代子、明日香）在 6～6.6 之间。取 5 作为全局值，不按角色区分。
- **兜底**：有声音的回复已经记下（`done`），她也已经不在说话，台词卡却还没走到最后一段，就从当前这段起按估算节奏放完剩下的段。**被打断的回复不走兜底**：打断后台词卡停在被打断时的那段。注意 `done` 可能比用户新一轮的 `user` 事件先到，判断「被打断」不能只靠新回合开始。
- **换到新回复**：新回复的第一段开始显示时（有声音时是收到它的第一个 `segment-playing`，没声音时是第一段到达），台词卡直接换过去，旧回复剩下没显示的段放弃。补充时被放下的回复，规则和现在一样，不留任何痕迹。
- **立绘**：有声音的回复，立绘照旧跟 `segment-playing`。按估算节奏换段的（「只看文字」的回复、兜底补放的段），立绘的「正在说哪段」跟台词卡走：台词卡换到哪段，立绘就换成那段的情绪。现在「只看文字」时，立绘在某段第一个字到达时就切换，这一点要改。
- **上一段**：`previousLine` 是台词卡上一个显示过的段，可以跨回复，不包括被跳过的段，重拨后清空。通话层仍然只在「只看文字」开着时显示它。
- **通话层组件不改结构**：台词卡照旧显示快照给的 `line` 和 `previousLine`。DESIGN.md「Call layer」里台词卡的说明补上换段节奏。
- **不变的**：文字记录（对话页的气泡）照旧随文字到达显示完整回复；打断时记下哪些段不变；补充、打断的判断时机不变。「只看文字」时「开口」指第一段出现，第一段一到达就显示，所以判断时机和现在一样。

## Testing Decisions

- **只有一个接缝：LiveConversation 的快照**（`line`、`previousLine`、`stand`）。沿用 `liveConversation.test.ts` 的写法：用假通话的 `handlers.onEvent` 推 `user`、`delta`、`segment-playing`、`emotion`、`done`、`bot-started-speaking` / `bot-stopped-speaking`，看快照。估算节奏用 vitest 的假计时器推进，不新增端口。拆出来的内部模块不单独测。
- 好的测试只看外部行为：在某个事件或某个时刻之后，台词卡显示的是哪段、上一段是哪段、立绘在说哪段、是什么情绪。不断言内部状态和计时器的数量。
- 现有的「the line before」「shows her latest line in this call」这几条测试的前提会变：有声音时台词卡要等 `segment-playing` 才换。按新规则改写，不删掉它们守的东西（同一段变长不算换段、补充放下的回复不成为上一段、重拨清空）。
- 立绘规则（`standDirection`）的单元测试已有先例；「只看文字」时立绘跟台词卡，在 LiveConversation 层面测（快照的 `stand`），因为是 LiveConversation 决定台词卡什么时候换段。
- 遵守 `CODING_STANDARDS.md` 里关于测试的条款，同一条路径不在两处重复测。

## Out of Scope

- 一段之内的卡拉 OK 式逐字高亮，以及任何依赖逐字时间的效果。
- 按角色分别设语速。
- 改打断时记下哪些段的规则（仍是文字已经完整的段都记下，哪怕她还没念到）。
- 有声音时显示浅色的上一段。
- 后端的任何改动，包括让 Fish Audio 返回时间信息。
- 对话页文字记录（气泡）的显示节奏。

## Further Notes

- 用户在对话页的文字记录里仍能看到完整回复，包括台词卡跳过的段，所以跳过不会丢信息。
- 语速样本只有每位角色一句短招呼（15～32 字），上线后看实际效果再调常量。
- 「只看文字」的节奏已经写进 GLOSSARY「只看文字」；具体数字只在这份 spec 里。
