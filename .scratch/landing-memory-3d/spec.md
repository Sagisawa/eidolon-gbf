# 落地页第 5 幕「记忆」重做成 3D 纪念碑谷式场景

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，特别是「落地页」「记忆」「来源角色」「立绘」。相关决策见 ADR-0002（所有角色共享记忆，标注来源角色）、ADR-0003（素材不进仓库，放存储桶）、ADR-0016（落地页是独立的视觉世界，及 2026-10-12 修订：three.js）。设计由原型定下：本地分支 `prototype/landing-memory-3d`（`cd561b4`，永不合并），2026-10-15 至 16 日的几轮评审。

## Problem Statement

落地页第 5 幕「记忆」现在是一道光亮起，射出一条弧线落到另一道光上，再从那里分出三条弧线落到别的光上。它是抽象的光，访客看不出「我对一位偶像说的事，她会记住，别的偶像之后也会知道，还知道是听谁说的」。前几幕已经有立绘、她的声音、一台实体的手机，到这一幕又退回几条线，讲得最弱。

部署者想把这一节完全重做成 3D：像《纪念碑谷》那样等距视角、漂在夜空里的建筑，几位偶像做成方块小人站在上面，仍然是滚动叙事，滚动会转镜头、触发机关。画面要讲清楚一件事被一位偶像收进记忆、传给另一位、再从她那里传开，传到谁那里都还认得出是谁先听到的。作为 AI 角色扮演项目，场景里可以藏一些 AI 的梗，但只作点缀，主体是闪耀色彩的东西。

## Solution

**场景。** 第 5 幕钉住约 8 屏。画面是正交相机斜着俯看的一片夜空：四座浮在空中的石柱，柱顶各站一位偶像（樱木真乃、小宫果穗、黛冬优子、幽谷雾子），脚下一块她印象色的地砖，身边两根她颜色的应援棒路灯、一根数据库图标样子的「记忆柱」。各人岛上有自己的东西：真乃的樱花树和飘落的花瓣、果穗身后的拱门、冬优子的尖塔和自拍补光灯、雾子的小房子和花箱。远处是 283 事务所的楼。AI 的梗压得很淡：天上漂着一台制作人的手机，柱子像数据库，背景是一层淡淡的 embedding 星图，拱门里隐约滚着分词器样的 token，转台的把手一闪而过「temperature」，角落一块刻着「Attention Is All You Need」的石碑，空中飘着细小的 token 粒子。

**叙事。** 随滚动：

1. 全景，左边是这一幕的标题和正文。
2. 天上的手机亮起，制作人的一句话（深蓝气泡）落到真乃头顶，她抬手接住。
3. 她头上冒出「思考中…」，说「うん、覚えておきますね／我记住了。」，消息变成她颜色的一块发光方块，收进她的记忆柱，柱上的小灯闪成她的颜色。
4. 镜头拉远转向，她和果穗之间的转台转过 90°，桥接上。
5. 一份副本沿桥走到果穗那里，走过的桥面亮起她的颜色。
6. 果穗的柱上冒出「想起 1 条记忆 · 来自真乃」，她说「真乃さんから聞きました！ファイトです！」。
7. 两段台阶从下面一级级升起来。
8. 两份副本一级级跳着，传给冬优子和雾子，她们也都想起来，说「听真乃说的」。
9. 全景：四根记忆柱顶上都是真乃颜色的方块，几根光线把它们连起来；最后一句「她们会记住你的事情，然后在所有人之间传开。」

往回滚，一切倒着走。

**角色。** 四个人是从官方立绘做出来的方块（体素）小人：维护者用生图模型画出 Q 版三视图，取正面交给混元 3D 生成带贴图的网格，再用仓库里的脚本转成约 96 格高的体素。体素文件和立绘一样放在存储桶，不进仓库。加载不到时，她站的地方是一块她印象色的小方块和名字。

**不播放动画的档位。** 定格档、静态档，以及 3D 画布出问题时，这一幕是一张事先渲染好的终局全景图，下面按顺序列出几个人说的话。

## User Stories

1. 作为访客，我想在第 5 幕看到几位我认识的偶像站在一片立体的场景里，以便一眼知道这一节在讲她们。
2. 作为访客，我想看到天上的手机亮起、一句话落到真乃那里，以便明白「这是我对她说的话」。
3. 作为访客，我想看到真乃想了想、说「我记住了」，再把它收进身边的柱子里，以便明白她会记住。
4. 作为访客，我想看到收进去的那块是真乃的颜色，以便之后认得出这件事是对谁说的。
5. 作为访客，我想看到转台转动、桥接上，以便感觉这件事要「传出去」了。
6. 作为访客，我想看到一份副本沿桥走到果穗那里、她说「听真乃说的」，以便明白别的偶像也会知道、还知道是听谁讲的。
7. 作为访客，我想看到台阶一级级升起，副本跳着传给冬优子和雾子，以便明白它会在所有人之间传开。
8. 作为访客，我想在最后的全景里看到四根柱子顶上都是真乃颜色的方块，以便一眼看懂「传到谁那里都还是她的颜色」。
9. 作为访客，我想读到「她们会记住你的事情，然后在所有人之间传开」，以便用一句人话收住这一节。
10. 作为访客，我想镜头随滚动推近、拉远、转向，以便像在纪念碑谷里一样看这片场景。
11. 作为访客，我想往回滚时一切倒着走，以便来回看这一段。
12. 作为访客，我想滚动停下时画面也停在那一刻（只有花瓣、粒子这类轻微的动），以便看清楚。
13. 作为访客，我想她们说的话是日语原文在上、中文字幕在下，以便和前几幕一样「日语原声，中文字幕」。
14. 作为访客，我想制作人的话是深蓝的气泡，她们的话是白色的气泡，以便分得清谁在说话。
15. 作为访客，我想气泡跟着说话的人的头顶走，以便知道是谁说的。
16. 作为访客，我想收到的人跳一下、转过身朝着传话的人，以便画面是「活的」。
17. 作为访客，我想认得出这四个方块小人分别是谁（真乃头上的鸽子、果穗的呆毛和腰上的外套、冬优子的丸子头、雾子的双马尾和创可贴），以便感觉这是她们，不是随便的小人。
18. 作为访客，我想她们的脸有眼睛、有表情，而不是一块空白，以便觉得可爱而不是吓人。
19. 作为访客，我想每座岛上有她自己的东西（樱花、拱门、补光灯、花箱），以便场景不简陋。
20. 作为喜欢闪耀色彩的访客，我想看到 283 事务所的楼、她们印象色的应援棒路灯，以便会心一笑。
21. 作为对 AI 有兴趣的访客，我想在角落里发现几个 AI 的梗（数据库、embedding、token、temperature、Attention Is All You Need），以便会心一笑，但它们不抢主体。
22. 作为访客，我想第 4 幕的手机离开后，这片夜空自然地接上来，以便两幕之间不突兀。
23. 作为访客，我想这一幕结束时画面暗下去，接上第 6 幕，以便全页的节奏不乱。
24. 作为手机上的访客，我想在竖屏上也看到同样的场景，镜头取景照顾到窄屏，气泡不出屏幕，以便手机上也能看懂。
25. 作为手机上的访客，我想这一幕流畅不卡，以便不想划走。
26. 作为设备掉帧的访客，我想场景照常，只是阴影、泛光这类效果关掉，以便页面不卡。
27. 作为开了「减少动态效果」的访客，我想看到一张静止的终局全景图和按顺序列出的几句话，以便不看动画也能看懂。
28. 作为省流量或浏览器不支持 WebGL 的访客，我想看到同样的静止图和文字，以便不错过这一节。
29. 作为访客，如果这一幕的 3D 画布出了问题，我想看到静止图，而不是一块空白，以便页面不坏。
30. 作为手机 4G 上的访客，我想首屏打开速度不受这一幕影响，以便落地页还是秒开。
31. 作为用读屏器的访客，我想按顺序听到标题、正文、几个人说的话和最后一句，以便知道这一幕讲了什么。
32. 作为用页内查找的访客，我想查到气泡里的一句话时，页面滚到这句话显示出来的地方，以便查找照常好用。
33. 作为用键盘的访客，我想 Tab 一路走过这一幕不被卡住，以便能接着到第 6、7 幕。
34. 作为部署者，我想体素小人放在存储桶、不进仓库，以便收到权利方要求时清空存储桶就能把它们和立绘、招呼一起下线。
35. 作为部署者，我想存储桶里没有某位的体素文件时，她的位置显示一块她印象色的方块和名字，以便本地开发和没配存储桶的部署不出现破图或空位。
36. 作为部署者，我想事先渲染的静止图也放在存储桶，以便它和体素小人一起下线。
37. 作为维护者，我想有一个脚本把混元 3D 导出的 GLB 转成体素文件，以便换角色、重做模型时照着跑一遍就行。
38. 作为维护者，我想文档写清楚从立绘到体素文件的每一步（生三视图、取正面、混元 3D 的设置、跑脚本、上传），以便下次不用重新摸索。
39. 作为维护者，我想有一个脚本渲染静止图，用的是和页面同一套场景代码，以便改了场景时重新出一张就行。
40. 作为维护者，我想场景每一刻的状态（镜头、节拍、方块在哪、谁收到了、气泡何时出现）都由落地页模型算出来，以便用单元测试守住叙事，而不是只能截图看。
41. 作为维护者，我想旧的第 5 幕（光路弧线、光点、指针痕迹）连同它的着色器代码一起删掉，以便不留死代码。
42. 作为维护者，我想素材的出处和做法写在 CREDITS 里，以便日后查得到。

## Implementation Decisions

**结构和加载（ADR-0016 补修订）。**

- 第 5 幕是一块单独的 three.js 画布（WebGL 渲染器），和第 4 幕的手机一样：只在运动档加载，滚到第 5 幕前约一屏时动态下载场景代码和四个人的体素文件、建画布；离开第 5 幕那一段就不画，手指操作的设备上离开时释放 WebGL 上下文，回来重建；画布丢了上下文、建不起来时收起，换成静止图，不连带落地页降档。three.js 和手机共用一个包，场景代码单独打包，都不算首屏。
- 光层（OGL）在第 5 幕不再画这一幕的东西：她们的光在第 4 幕末尾收掉，第 5 幕是 3D 画布自己的夜空；第 5 幕最后一屏（解开钉住）画布淡出，接上全页最暗的第 6 幕。
- 舞台的主循环（LightStage）每帧把滚动位置交给落地页模型，模型给出第 5 幕的场景状态，3D 层和 DOM 上的气泡都按它摆；按帧降档照旧把这块画布的开销算进去。
- 运动档里的画质：完整档有阴影和泛光；简化档、basic 档没有阴影和泛光，粒子减半；DPR 按档位封顶（沿用落地页的画质表，加一项「阴影和泛光」）。
- 每个人的体素按露在外面的面合成一份网格（顶点色），不用一个方块一个实例。

**落地页模型。**

- 时间线：第 5 幕加长到约 8 屏（原型的长度，实现时可微调），钉住一段，最后一屏解开钉住。
- 场景描述里第 5 幕的部分换成新的形状。它包括：镜头（注视点、取景半径、方位角，正交投影、仰角固定 35.264°）；当前节拍；制作人那句话（消息）的位置和它从气泡变成方块的进度；转台的转角；每级台阶升起的程度；几份副本的位置和是否可见；每个人收进记忆柱的时刻（之后柱顶留一块）；每个人的跳动、举手、朝向；连线的不透明度；每个气泡和「想起」标签的锚点（世界坐标）和不透明度；标题正文、最后一句的不透明度；画布的不透明度（进场、退场）。
- 投影是模型里的纯函数：给镜头、视口、世界坐标，算出屏幕坐标。3D 层的相机和 DOM 气泡用同一个出处。
- 竖屏另有取景：镜头半径按画面宽高比放大，保证每个节拍里要看的人和她的气泡都在画面里、离边缘有余量。
- 节拍和镜头关键帧沿用原型（幕内进度 0–1；下面是原型里的值）：

  ```ts
  // 来自原型：节拍
  const BEATS = [
    { at: 0, name: "全景" },
    { at: 0.08, name: "你给真乃发了条消息" },   // 手机亮起，消息落到她头顶，0.13–0.23 她举手

    { at: 0.3, name: "转台转动，桥接上" },      // 0.31–0.40 转 90°
    { at: 0.42, name: "记忆沿桥传给果穗" },     // 0.43–0.53 沿桥走

    { at: 0.74, name: "传给冬优子和雾子" },     // 0.75–0.84、0.76–0.85 跳着走
  ```

- 布景（四座岛的位置、高低、转台、台阶、记忆柱、路线）是模型里的常量：真乃 (0,0,0)、果穗 (5,0,0)、冬优子 (5,−2,5)、雾子 (10,2,0)，柱顶 3×3；转台在真乃和果穗之间，转过 90° 才接上；台阶从果穗往南下到冬优子、往东上到雾子，各四级。
- 静止版式（定格档、静态档）里第 5 幕不钉住，模型不给这一幕的场景状态。

**演员和文案。**

- 演员固定写在落地页文案里，和第 3、4 幕说话的人一样：发送的人真乃，接收并传开的人果穗，再传到的冬优子、雾子。某位不在名单里时，她的岛上没有人、她的话不出现；真乃不在名单里时第 5 幕只剩场景和文字。
- 记忆方块、记忆柱的灯、走过的桥面、连线都用真乃的印象色：传到谁那里都是她的颜色（来源角色）。各人的地砖、路灯用各自的印象色。颜色只用官方印象色推出来的值（落地页的颜色模型），不另取。
- 文案（中文进文案目录，日语原文和字幕成对；不出声，只是气泡里的字）：
  - 制作人：「下周要考试了，有点紧张。」
  - 真乃：「うん、覚えておきますね」／「我记住了。」
  - 果穗：「真乃さんから聞きました！ファイトです！」／「听真乃说你要考试了，加油！」
  - 冬优子：「テストでしょ？真乃から聞いたわよ」／「考试？真乃跟我说了。」
  - 雾子：「真乃ちゃんから……聞きました……」／「听真乃说了……别太勉强……」
  - 标签：「想起 1 条记忆 · 来自{名字}」；思考气泡：「思考中」。
  - 最后一句：「她们会记住你的事情，然后在所有人之间传开。」
  - 标题和正文不变。
  - 日语台词实现前请部署者照人设过一遍（尤其冬优子在制作人面前的口吻）。改完重新生成落地页字体子集。
- 气泡：制作人的是深蓝底白字；她们的是白底，日语原文在上、中文字幕小一号在下（`lang="ja"`）；「想起」标签是半透明深色胶囊，左边一个她颜色的小方块。气泡是 DOM，不进画布，锚点由模型给、按投影摆。

**场景内容。**

- 夜空渐变背景加星星；柱子顶面亮、两侧一明一暗、往下渐隐进夜色；底下一层缓慢转动的云。
- 闪耀色彩的东西（主体）：283 事务所的楼（窗灯、「283 PRODUCTION」的字，楼顶什么都不放：原型里的棱镜和彩虹光太夸张，已去掉）；每座岛两根她印象色的应援棒路灯；真乃的樱花树和花瓣；冬优子的补光灯；雾子的小房子和花箱。组合 logo、官方 logo 一律不用（ADR-0016）。
- AI 的梗（点缀，压暗、缩小）：天上的手机（屏幕上是一段对话）、数据库样子的记忆柱（三层圆盘、一排闪的小灯）、背景里稀疏的 embedding 星图（收进记忆时多亮一颗真乃颜色的点）、果穗拱门里低不透明度滚动的 token、转台旁一闪而过的「temperature 0.7」、远处一块刻着「ATTENTION IS ALL YOU NEED」的石碑、少量上飘的 token 粒子。
- 角色动作：整块小人没有分开的四肢。收到时一跳一压，真乃接住时身子微微后仰，传话时转向对方，平时轻微起伏，默认朝着镜头。

**体素小人（ADR-0003 补修订：体素文件和静止图也属于对访客公开、放在存储桶、清空即下线的那一类）。**

- 存储桶里 `landing-voxels/<角色标识>.json`，手动上传，缓存头 `public, max-age=86400`。后端不查存储桶，配了存储桶地址就在角色接口里给出这个地址（和来电卡图一样的规则），每位角色都给，落地页只用演员的。没有图、加载失败时，那位的位置是她印象色的小方块加名字。
- 文件格式（来自原型）：

  ```ts
  type Voxels = {
    size: [w: number, h: number, d: number]; // 网格尺寸
    front: number;                            // 脚底到头顶的格数，按它把她缩放到场景里的身高
    palette: string[];                        // "#rrggbb"
    voxels: number[];                         // x, y, z, 调色板下标 平铺；y 朝上，+z 是她的正面，+x 是她的左手边
  };
  ```

- 转换脚本（维护者在本地跑，不进构建）：输入混元 3D 导出的 GLB，输出上面的文件，默认 96 格高。原型里试出来的做法照搬：
  - 占格：按三角面大小细分取点（间距不超过半格，只取三角面内部，不取边上，免得采到贴图 UV 岛之间的填充色）；填掉六面里至少四面是实心的小坑；腰以上再填两侧两格内都是实心的细缝（发束之间的缝，不填会露出模型内部的暗色）。
  - 上色：从 6 个方向把模型正交渲染成颜色图和深度图（每格 6×6 像素），每格只取从它露在外面的那几个面看得到、深度落在这一格里的像素；正上方、正下方的像素权重很低（会看进发束缝）；越靠近外表面的像素越重；按 4 位一档分桶，取权重最大那一桶的平均色，不归到全身统一的小调色板上（眼睛的颜色会被并进肤色）。
  - 保五官：头部（高度 66% 以上）的皮肤格子里，比肤色暗的像素（睫毛、瞳孔、嘴）票数大幅加重；其他地方略偏向亮色（不要贴图里的描线）。皮肤的判断：R > 200、R − B ≥ 15、G/R ≥ 0.82、G ≥ B − 5（灰紫、浅棕的头发不能算皮肤）。
  - 去杂点：表面上一格的颜色在周围表面格子里没有相近的、而周围至少 5 格彼此相近，就换成那种颜色；头部皮肤不碰。
  - 一格都看不到的格子从周围有颜色的格子借。
- 渲染：每格的顶面、底面颜色各压一点（0.86、0.78），保留方块感。原型试过按周围空格子估「平滑表面」的法线来打光，横纹没了，但脸发灰发脏，不用。
- 素材的做法（写进部署文档）：用生图模型参照官方半身立绘和 Q 版图画出 Q 版三视图（白底、平光、约三头身、站直、双臂略离身体、不带文字），切出正面，放到 1024×1024 白底上居中；在混元 3D 网页版用「单图生成」、带纹理，导出 GLB；跑转换脚本；上传存储桶。多视图生成没有用到（三视图本身对不齐）。CREDITS 写明来源和做法。

**静止图和静止版式。**

- 维护者脚本在无头浏览器里用和页面同一套场景代码，渲染第 5 幕终局全景（四人、四块真乃颜色的方块、连线）的一张图，放存储桶 `landing-memory/still.webp`。
- 定格档、静态档、3D 画布出问题时，第 5 幕是这张图，下面是标题、正文，按顺序列出制作人和四个人的话（原文加字幕），和最后一句。图加载不到时只有文字。静态档不加载任何脚本。

**删掉的。**

- 旧的第 5 幕：两屏宽的光路布景、光点（着色器里画光点的那段）、DOM 上的 SVG 连线、静态档的 SVG 光、指针痕迹（只有第 5 幕用），连同它们的测试和样式。

**无障碍和查找。**

- 这一幕没有可聚焦的控件。

## Testing Decisions

好的测试只看外部行为：给定滚动位置、视口、档位，落地页模型说镜头在哪、谁收到了、方块在哪、哪些气泡看得见、在屏幕的哪里；给定角色配置，接口给出什么。不测 three.js 怎么画、体素长什么样。

- **落地页模型**（沿用现有第 5 幕的场景测试，替换掉旧光路的那些）：
  - 方块依次落到真乃、收进她的柱子，传到果穗，再传到冬优子和雾子；每个人收进柱子的时刻按顺序，收进以后柱顶一直有块，往回滚就没了。
  - 副本沿路线连续地走，不跳；转台在副本上桥之前已经接上；台阶在副本下台阶之前已经升好。
  - 每个气泡只在它的节拍里出现；在出现的那段里，锚点投影到屏幕上都在画面里、离边缘有余量（电脑、竖屏各一组）。
  - 镜头随进度连续变化；全景节拍里四座岛都在画面里。
  - 演员缺一位时，她的气泡和收到不出现，其他照常。
  - 时间线：第 5 幕的长度，第 4 幕到第 5 幕、第 5 幕到第 6 幕的衔接连续；静止版式里没有这一幕的场景状态。
- **后端**（沿用来电卡图的测试）：配了存储桶地址时，角色接口给出体素文件的地址；没配时没有。
- **字体子集**：现有的字形覆盖测试守住新文案。
- **体素化脚本不写单元测试**：它是维护者在本地跑的工具，效果靠截图和人眼看。
- **人工验收**（落地页验收脚本，不进 vitest；体素文件和静止图要在存储桶里）：首屏 JS 预算不变，第 5 幕的场景代码和体素文件不算首屏，另外报大小；完整档电脑、竖屏手机在九个节拍各截一张，往回滚截一张；简化档截一张、量一段帧耗时；定格档、静态档截静止版式；画布丢上下文后换成静止图、落地页不降档；体素文件缺失时是印象色方块加名字；读屏器顺序和页内查找能找到一句气泡。
