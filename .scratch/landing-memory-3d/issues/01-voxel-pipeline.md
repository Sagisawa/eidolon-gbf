# 01: 体素小人的素材管线

**What to build:** 维护者能把混元 3D 导出的 GLB 转成落地页用的体素文件，照部署文档一步步从官方立绘做到存储桶；落地页通过角色接口拿到每位角色体素文件的地址。做完以后，四位演员（真乃、果穗、冬优子、雾子）的体素文件已经转好、在存储桶里。

包括：
- 转换脚本（维护者本地跑，不进构建）：输入 GLB，输出体素文件，默认 96 格高、可按参数出别的格数。文件格式和算法照 spec「体素小人」：按三角面细分取点占格、填小坑和发束细缝；6 个方向正交渲染取看得见的颜色、按 4 位分桶取最重的一桶；头部皮肤上暗像素加权保住五官；去杂点（头部皮肤不碰）；看不到的格子从周围借色。原型分支 `prototype/landing-memory-3d` 的转换脚本可以照着改写。
- 角色接口给出体素文件地址：存储桶的 `landing-voxels/<角色标识>.json`，配了存储桶地址才有，不查存储桶，规则和来电卡图一样。
- 部署文档：存储桶结构表加这一行；新增一节写素材做法（生图模型画 Q 版三视图的提示词要点、切出正面放到 1024×1024 白底、混元 3D 网页版「单图生成」带纹理导出 GLB、跑脚本、上传、缓存头 `public, max-age=86400`）。
- CREDITS 写明体素小人的来源和做法（落地页的 CREDITS 那一份）。
- ADR-0003 补一条修订：体素文件和第 5 幕的静止图也属于对访客公开、放在存储桶、清空即下线的那一类。
- 四个 GLB 在仓库外的 `E:/Download/others/agent-test/eidolon-sc-assets/landing-memory/hunyuan/`。转出 96 格和 64 格两套放在仓库外同一目录下；96 格的那套交给部署者上传到存储桶（或经部署者同意后用 `.env` 里的存储桶密钥上传）。

详见 `.scratch/landing-memory-3d/spec.md`「Implementation Decisions」的「体素小人」。
