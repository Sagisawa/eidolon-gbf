# 05: 场景加料和画质分档

**What to build:** 第 5 幕的场景不再简陋：远处是 283 事务所的楼，每座岛上有她自己的东西和两根她印象色的应援棒路灯，角落里藏着几个压得很淡的 AI 梗，空中有花瓣、粒子，底下有云；完整档有阴影和泛光，掉帧降档时这些效果关掉、场景照常。

包括：
- 闪耀色彩的东西（主体）：283 事务所的楼（窗灯、「283 PRODUCTION」的字，楼顶什么都不放）；每座岛两根印象色应援棒路灯；真乃的樱花树和飘落的花瓣；果穗身后的拱门；冬优子的尖塔和自拍补光灯；雾子的小房子和花箱。不用任何官方 logo、组合 logo。
- AI 的梗（点缀，压暗、缩小，不抢主体）：数据库样子的记忆柱已在 03；背景稀疏的 embedding 星图（收进记忆时多亮一颗真乃颜色的点）；果穗拱门里低不透明度滚动的 token；转台旁一闪而过的「temperature 0.7」；远处刻着「ATTENTION IS ALL YOU NEED」的石碑；少量上飘的 token 粒子。
- 夜色里缓慢转动的云、漂浮的小方块。
- 画质表加一项「阴影和泛光」：完整档开；简化档、basic 档关，粒子减半；DPR 按档位封顶。

详见 spec「场景内容」「结构和加载」。

## Comments

- 2026-10-16 完成。画质表（`model/tier.ts`）加了两项：`shadowsAndBloom`（完整档开）和 `particles`（完整档 1，其余 0.5）；票里说「加一项」，粒子减半单独成一项，3D 层按它改花瓣、token 粒子的绘制数量，降档时不用重建。
- 布景在 `memoryDressing.ts`，位置和配色照原型；和 3D 层共用的小工具（贴图、柱子、渐隐进夜色、胶囊字）抽到 `memoryKit.ts`。随机数都换成固定种子，会动的东西只看 `time`（原型的 token 粒子按帧累加，帧率不同快慢不同）。原型拱门上方的「CONTEXT WINDOW」牌子 spec 的清单里没有，没做。
- 模型（`memoryStory.ts`）加了 `temperature`（转台转的那段一闪而过）和 `embedding`（真乃收进记忆时星图上那颗点亮起来）。那颗点的位置 `EMBEDDING_STAR` 由模型定：原型的挑法挑到的点在每个节拍都在画面外。电脑和竖屏最后全景是同一个镜头、竖屏取景高得多，同一个点落不进两边上方的天空，所以定在电脑右上、竖屏右边；它在真乃收进的那一刻（镜头推得很近）看不到，镜头拉远去看桥时才看到。
- 泛光下天上那台手机的白屏被吹成一块白，屏幕压暗到泛光门槛下面（`PHONE_SCREEN`），只在亮起时叠上光晕才泛光。星图的连线比原型调淡（0.09 → 0.05）。
- 第 5 幕晚加载的场景代码 10.8 KB → 16.6 KB（加了 EffectComposer 和 UnrealBloomPass），首屏 JS 49.2 KB 没变。
- 验收脚本（`landing-check.mjs`）加了一项：另起一个用显卡的 Chromium（Windows 上走 D3D11），截完整档、简化档的开场全景（`full-act5-dressing.png`、`lite-act5-dressing.png`），简化档停在开场全景量 3 秒帧耗时，不超过降档门槛 36 ms；拿不到显卡（SwiftShader）时跳过。这台电脑上完整档、简化档都是 16.7 ms，档位不变。现有的第 2 到 7 幕截图用的是软件渲染，一帧几百毫秒，完整档一开场就降到了 basic，那些「full」截图其实不是完整档（和这张票无关，留给 07 判断）。这次整份跑下来只有页首入口那两项失败（入口先找到了 GitHub 链接），和这张票无关。
- 完整档在 Windows 的显卡上，控制台有一条 ANGLE 编译阴影深度解包时的 `warning X4122`（精度提示，不是错误）；验收脚本里「第 2 到 7 幕的控制台没有报错和警告」用的是软件渲染，碰不到它。
