# 05: 制作人档案

**What to build:** 用户在设置页编辑自己的制作人档案，包括称呼、性别和时区。没有设置的项沿用默认值：称呼按角色的人设，性别沿用原作中男性制作人的设定，时区取浏览器检测到的值，检测不到时用 Asia/Shanghai。档案会进入提示词，角色能知道按用户时区计算的现实当前日期和时间。档案只影响角色当下怎么对待用户，不改写剧情。

**Blocked by:** 02

**Status:** resolved

- [x] 提供读取和更新制作人档案的接口，档案属于用户而不属于某一把访问密钥
- [x] 设置了称呼后，提示词中包含该称呼，并说明它只是叫法、用户仍然是制作人
- [x] 没有设置称呼时，提示词不覆盖人设中的默认称呼
- [x] 设置的性别会进入提示词；没有设置时沿用原作设定
- [x] 提示词中的当前日期和时间按用户的时区计算（测试中固定当前时间）

- [x] 设置页可以编辑并保存称呼、性别、时区

## Comments

实现摘要：

- 档案存在 `producer_profiles` 表，以用户标识为主键（同一用户的所有访问密钥共用一份）。`GET /api/profile` 读取，`PUT /api/profile` 整份保存；某项留空或为 null 即恢复默认。称呼最多 20 字，性别为 `male`/`female`，时区须是有效的 IANA 时区名，否则返回 422。
- 提示词拼装在 `eidolon.producer`：人设之后加一段「# 制作人」，说明对方是 283 事务所的制作人；设置了称呼时说明这只是叫法、对方仍是制作人，没设置时不提称呼，由人设决定；设置了性别时说明这只影响当下的对待方式、原作剧情保持原样，没设置时不提；最后给出按用户时区计算的当前日期、星期和时间。
- 时区：档案里的时区是手动设置；浏览器每个请求都带 `X-Timezone`（检测到的时区，检测不到时为 Asia/Shanghai），语音通话在信令请求时带上。后端取档案时区 → 设备时区（须有效）→ Asia/Shanghai。前端的 `/api/*` 代理会转发这个请求头。
- 对话引擎可注入时钟，测试中固定当前时间；文字对话和语音通话走同一条路径。
- 后端新增 `tzdata` 依赖，保证精简镜像里也有时区数据。
- 设置页新增称呼、性别（默认「沿用原作设定（男性）」）、时区（默认「自动（检测到的时区）」）和保存按钮。
- 验证：后端测试覆盖接口、归属、校验和提示词；另用真实前后端加假 LLM 冒烟测试了设置页保存、自动时区（浏览器设为 Asia/Tokyo）和手动时区覆盖。
