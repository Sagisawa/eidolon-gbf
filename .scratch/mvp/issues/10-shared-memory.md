# 10: 记忆的抽取与共享检索

**What to build:** 新增「后台模型」配置。后台模型在对话中抽取关于用户的中文记忆，每条记忆都带上所属用户和来源角色。之后的对话中，对话引擎会检索当前用户的记忆放进提示词；如果一条记忆的来源不是当前角色，就要求角色用转述的口吻提起（ADR-0002）。这样用户对真乃说过的事，恋鐘也会以「听真乃说……」的口吻知道；不同用户之间的记忆则完全隔离。新对话只靠检索到的记忆接上以前聊过的事，不另外带上次对话的摘要。

**Blocked by:** 02, 03, 07

**Status:** resolved

- [x] 支持单独配置「后台模型」，与对话模型分开
- [x] 对话中透露的信息会被抽取成中文记忆，并记录所属用户和来源角色
- [x] 新对话中，与当前话题相关的记忆会进入提示词
- [x] 提示词中标注每条记忆的来源角色；来源不是当前角色时，附带「用转述的口吻提起」的要求
- [x] 用户 A 的记忆永远不会出现在用户 B 的对话中
- [x] 测试：用户对真乃说了一件事之后，在和恋鐘的对话中，假 LLM 收到的提示词包含这条记忆，且来源角色为真乃

## Comments

实现摘要：

- 后台模型：`BACKGROUND_LLM_BASE_URL` / `BACKGROUND_LLM_API_KEY` / `BACKGROUND_LLM_MODEL`，目前是 OpenAI 兼容接口（其他协议见 13）。每一项不填时沿用对话模型的设置（`Settings.background_llm()`），所以只填模型名就能在同一个服务上换一个便宜的模型。
- 抽取（`memory.MemoryWriter`）：每个回合记录下来之后，在后台任务里把这一轮（前 4 条消息、制作人最新的一句话、角色的回复，以及用户最近 50 条已有记忆）交给后台模型，要求输出 `{"memories": [...]}`：以「制作人」开头的中文陈述，只记制作人自己透露的事，相对时间按用户时区换算成日期，已经记住的不重复。每回合最多 5 条、每条最多 200 字；同一用户完全相同的文字只存一条（`UNIQUE (user_id, text)`）。输出不是这个 JSON 或后台模型出错时只记日志，不影响对话。记忆存进 `memories` 表（用户、来源角色、对话、文字、按引擎时钟记下的时间），写入后立即向量化（`memory_vectors` 表；向量化失败时在下次检索时补上）。
- 不耽误回复：抽取在回复完成后后台进行；同一用户的下一个回合在检索前最多等 5 秒，让刚说的事来得及被记住。服务关闭时同样最多等 5 秒，然后取消。
- 检索：Jev 多了一个问题 `about_producer`（制作人是否在说自己的生活、近况、计划、家人宠物等）。判断结果多了一种 `memories`：只检索记忆，不检索剧情和角色资料。判断为 `references` 时，记忆和剧情、角色资料一起检索，放进同一次重排，但分开取：记忆最多 3 条，门槛 0.01（剧情和资料仍是最多 5 条、门槛 0.3）。`nothing` 和 `recall` 不检索记忆。
- 提示词：单独一节「# 关于制作人的记忆」，每条注明日期和来源角色。来源是当前角色时写「制作人对你说的」；来源是其他角色时写「制作人对{名字}说的，你是听{名字}说的」，并要求用转述的口吻提起。来源角色已从配置中删除时写「事务所的另一位偶像」。
- 隔离：记忆的查询都按用户过滤，向量也按用户保存。
- 新对话只带检索到的记忆，不带以前对话的内容（原本就只带本次对话的历史）。
- 记忆和检索一起开启：没有配置 Jev 和硅基流动时既不检索也不抽取（`test_memory_needs_retrieval`），因为抽取出来的记忆没有办法被找到。
- 测试（切入点 A，`test_shared_memory.py`）：
  - 对真乃说的事进入和恋鐘对话的提示词，来源为真乃，并要求转述；
  - 对自己说的事不要求转述；
  - 用户之间隔离，重排的候选里也看不到别人的记忆；
  - 后台模型读到这一轮对话、日期和已有记忆；
  - 相同的记忆只保留一条，日期取引擎时钟；
  - 只检索记忆的路径；
  - 无关的记忆不进入提示词；
  - 闲聊不检索，但新记忆在写入时已经向量化；
  - 抽取失败（服务出错、不是 JSON、格式不对）不影响对话；
  - 后台模型的配置和回退。
  
  另外 `test_retrieval_services.py` 覆盖了 Jev 第三个问题的判断组合。

真实服务验证（2026-09-25）。对话模型和后台模型都是 `.env` 里配置的对话模型；Jev 和硅基流动都是真实服务；数据库是临时的空库，没有导入剧情。

- 抽取：
  - 「我家最近养了一只叫小白的猫，特别黏人」记成「制作人家里最近养了一只叫小白的猫，特别黏人」；
  - 「下周六我要去北海道出差」记成「制作人将于2026年10月3日去北海道出差」。当时在用户时区是 9 月 26 日（周六），日期换算正确；
  - 「今天好累啊」和各种提问都没有记下；
  - 每次抽取 3–5 秒，在后台进行。
- 转述：
  - 爱丽丝问恋鐘「你知道我家的猫叫什么名字吗？」，恋鐘答「我知道哦～！听櫻木真乃说的。叫『小白』对吧？」；
  - 问「我最近要出远门，你听说了吗？」，她答出了 10 月 3 日去北海道出差，也说是听真乃说的；
  - 再和真乃开新对话，她同时提到自己记得的小白和「听恋鐘酱说，小白最近半夜里总是叫」（这条是对恋鐘说的）。
- 隔离：另一位用户 bob 问恋鐘同一个问题，提示词里没有任何记忆，恋鐘表示没听说过。bob 那一轮被记成「制作人家里养了猫」。
- 调整过程：
  - 第一版只在 Jev 判断「需要检索」时带记忆。结果「我最近要出远门」和「我家的猫最近总是半夜叫」都被 Jev 判为不需要检索；
  - Qwen3-Reranker 给这类「相关但措辞不同」的记忆打分也很低：出差记忆对「我最近要出远门」只有 0.03，而无关记忆都不超过 0.005；
  - 于是加了 Jev 的 `about_producer` 问题，并给记忆单独设 0.01 的门槛。实测 Jev 对说自己的事给出 0.91–0.96，对寒暄、剧情和设定问题不超过 0.18；
  - 改后上面两句都带上了正确的记忆。
- 首个字幕在 10–16 秒，和以前一样主要取决于对话模型本身。

留给后续的注意点：

- 0.01 的门槛是用 8 条记忆、12 句话试出来的，余量不大；记忆多了以后可能要重新调。
- 判断为 `recall` 的回合不带记忆。「上次我跟你说的那次旅行」这类说法如果被判成回顾剧情，就会漏掉记忆；判为 `nothing` 的寒暄（如「我回来啦」）也不带记忆。
- 去重只针对完全相同的文字。换一种说法的同一件事会再记一条，只能靠后台模型看到已有记忆后自己避免。记忆相互矛盾时（例如搬家）也只是新增一条，不会更新旧的。
- 下一个回合等待抽取的逻辑只在单个进程内有效。
- 回复格式的容错问题（字幕里出现 `</ja><ja>`）这次验证中又出现了，与本 ticket 无关。
