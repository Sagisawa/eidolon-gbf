# 14: 按用户限流

**What to build:** 按用户统计用量并限流，避免某位用户用得太多，把大家共用的 API 额度耗光。超过限额时，前端显示友好的提示，并告诉用户什么时候可以再用。

**Blocked by:** 02

**Status:** resolved

- [x] 文字对话回合和语音连接都按用户计入用量（同一位用户的多把访问密钥合并计算）
- [x] 限额可以配置（参考项目的默认值是每小时 5 次连接）
- [x] 超过限额时拒绝请求，并返回可以恢复使用的时间
- [x] 前端对超额情况显示友好的提示
- [x] 以上行为都有通过后端对外接口驱动的测试（使用可控的时钟）

## Comments

实现摘要：

- 计数（`eidolon/usage.py`，数据在 `store.py` 的 `usage` 表）：按用户统计最近一小时（滚动窗口）的用量，同一位用户的所有访问密钥合并计算，存在 SQLite 里，重启不清零。文字对话每个回合计一次；语音通话在新建连接（`/api/offer` 不带 `pc_id`）时计一次，重新协商、通话中说的话和打的字都不另外计数。Pipecat 客户端断线重连时带着原来的 `pc_id`，也不计数。
- 限额：文字对话和语音通话分开计算，由 `EIDOLON_TURNS_PER_HOUR`（默认 60）和 `EIDOLON_CALLS_PER_HOUR`（默认 5，即参考项目的「每小时 5 次连接」）配置，填 0 表示不限制，不是非负整数时启动报错。文字对话的 60 次没有出处，是按「和朋友正常聊一小时够用」估的。
- 拒绝：超额时返回 429，响应体为 `{"detail": "这一小时的文字对话次数已经用完了（每小时 N 次）", "retry_at": ISO 时间}`，并带 `Retry-After`（秒）。被拒绝的请求不计数。回复失败的回合（流中报 `error`）和没能建立连接的通话会退回这次计数。
- 前端（`lib/api.ts`）：429 的提示后面接上本地时间「HH:MM 之后可以再用。」，时间向上取整到分钟；不是今天时加上日期。文字回合被拒时，和其他失败一样，把输入放回输入框。
- 测试（`test_rate_limit.py`，可控时钟，全部通过后端对外接口驱动）：文字对话超额被拒，最早一次滑出窗口后恢复；多把密钥共用限额，其他用户不受影响；语音通话单独限额，重新协商不计数；不限制；从环境变量读取限额；失败的回合和没能建立连接的通话退回计数。

真实服务验证（2026-09-25）：真实对话模型、Soniox 和 Fish Audio，`EIDOLON_TURNS_PER_HOUR=2`、`EIDOLON_CALLS_PER_HOUR=1`。前两个文字回合正常回复，第三个返回 429（`Retry-After: 3586`）。浏览器（Playwright 驱动 Chromium，使用假麦克风）里文字超额时显示「这一小时的文字对话次数已经用完了（每小时 2 次），20:11 之后可以再用。」，输入放回了输入框。第一次语音通话正常接通，挂断后再打，显示「这一小时的语音通话次数已经用完了（每小时 1 次），20:12 之后可以再用。」。dev 模式下 Next 的 Issue 标记来自 Pipecat 自己在 offer 被拒时打的 `console.error`，401、503 时同样会出现。

留给后续的注意点：

- 通话在接通之后才失败（例如 Soniox、Fish Audio 连不上）时，额度不会退回：管线在后台任务里启动，连接请求那一刻看不到失败。
- 前端的时间格式没有自动化测试（前端还没有测试框架），只做了真实浏览器验证。

后续补充（2026-09-25，按评审后的讨论）：单次通话的上限

- 评审指出通话接通后，里面的回合不受限额约束，挂着一个通话可以一直消耗模型和 TTS 额度。于是给单次通话加了时长和回合数上限：`EIDOLON_CALL_MINUTES`（默认 10）和 `EIDOLON_TURNS_PER_CALL`（默认 40，约等于 10 分钟正常对话的轮数，主要挡住通话中快速连续打字），填 0 表示不限制。
- 实现在 `CallTurns`（`CallLimits`）：到了上限，给浏览器发 `{"type": "ended", "message": 原因}`，正在进行的回复照常完成，然后推 `EndWorkerFrame`，让 TTS 把已经排队的话说完再挂断；之后说的话不再处理。前端在通话断开时显示这个原因，而不是「通话已断开」。
- 测试（`test_call_turns.py`）：回合数到了上限时，最后一个回复仍然被读出来，之后的话不处理；时间到时，正在进行的回复完成后挂断。
- 真实服务验证（`EIDOLON_TURNS_PER_CALL=1`、`EIDOLON_CALL_MINUTES=1`，真实 Soniox、Fish Audio 和真乃的音色）：通话中打一句话，真乃的回复约 40 秒的语音完整播完（日志里 "Bot stopped speaking" 之后才收到 `EndWorkerFrame`），然后挂断，前端显示「这次通话已经说了 1 轮了，先挂断啦。想接着聊可以重新拨打。」；什么都不说时，接通约 63 秒后挂断，显示「这次通话已经满 1 分钟了，……」。
- 上下文长度和单次通话无关，是整个对话的历史没有上限，另记为 ticket 17。
