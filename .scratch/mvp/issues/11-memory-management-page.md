# 11: 记忆管理页

**What to build:** 用户在记忆管理页查看角色关于自己的所有记忆，每条都注明来源角色；可以逐条删除，也可以一键清空。不支持手动新增或修改记忆。

**Blocked by:** 10

**Status:** resolved

- [x] 接口：列出当前用户的全部记忆（带来源角色）、删除单条、一键清空
- [x] 用户只能看到和操作自己的记忆
- [x] 已删除的记忆不会再出现在任何对话的提示词中
- [x] 前端记忆管理页：记忆列表、单条删除、需要二次确认的一键清空
- [x] 以上行为都有通过后端对外接口驱动的测试

## Comments

实现摘要：

- 接口（都要访问密钥，都按当前用户过滤）：
  - `GET /api/memories`：最新的在前，每条带 `id`、`text`、`source_character_id`、`source_character_name`（来源角色已从配置删除时为 `null`）和 `created_at`。列出前最多等 5 秒，让刚说的事来得及出现在列表里。
  - `DELETE /api/memories/{id}`：删除单条，返回 204；不是自己的或已不存在的返回 404「记忆不存在」。
  - `DELETE /api/memories`：一键清空，返回 204。
- 删除（`MemoryWriter.delete` / `clear`）同时删掉 `memories` 表里的行和 `memory_vectors` 里的向量。检索本来就以 `memories` 表为准，所以删除后既不会进入对话提示词，也不会出现在后台模型的「已经记住的事」里。
- 清空和后台抽取的竞争：清空会先等正在进行的抽取（最多 5 秒）。另外每位用户有一个清空计数，回合开始时记下（`MemoryWriter.mark`），抽取写入前如果发现期间清空过，就丢弃这一轮的结果。这样抽取慢于 5 秒，或者清空时回复还在生成，都不会让记忆在清空后冒出来。计数只在单个进程内有效，和 10 里「等待抽取」的限制一样。
- 前端 `/memories`：从设置页进入。记忆列表显示来源角色和日期，可以逐条删除；「清空全部记忆」要在页内再确认一次。没有记忆和记忆功能未开启时都显示空状态。
- 测试（切入点 A，`test_memory_management.py`）：列表和来源角色；删除后的记忆不进入对话提示词和后台模型的提示词；删除不存在的记忆返回 404；清空；清空等待抽取完成；抽取慢于等待时间时清空后也不会冒出来；用户隔离；需要访问密钥；记忆功能未开启时列表为空。

留给后续的注意点：

- 单条删除不会丢弃进行中的抽取。在同一段对话里继续聊时，后台模型读到的前几条消息里还有这件事的原话，而它已不在「已经记住的事」里，所以理论上可能被重新记下。指令要求只从「最新的一句话」里抽取，这种情况应该很少；如果实际遇到，可以只给后台模型看删除之后的消息。
- 同一段对话的历史本身仍然带着原话，所以在这段对话里角色还「记得」。删除针对的是记忆，不是聊天记录。
