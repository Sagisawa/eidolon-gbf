# 06: 剧情库导入（CSV）

**What to build:** 管理员用一条导入命令，把 SCTranslationData 格式的剧情 CSV（`id,name,text,trans`，末尾有一行 `info` 指向原始剧本）导入剧情库。每段剧情带有分类、出处（卡或活动）、标题、出场角色，以及按说话人分好的台词，并通过硅基流动的 Qwen3-Embedding 写入向量索引。只收录正式经历，排除失败结局；重复导入是幂等的。这一步同时建立切入点 B 的测试。

## Comments

实现摘要：

- 命令：`eidolon story import-csv <目录>`（`--characters` 可指定角色配置）。读取目录下所有 `*.csv`，每个文件一段剧情；需要 `SILICONFLOW_API_KEY`，默认模型 `Qwen/Qwen3-Embedding-0.6B`（`EMBEDDING_MODEL` 可换）。数据写入 `EIDOLON_DATABASE_PATH` 同一个 SQLite 文件（`episodes`、`episode_cast`、`episode_lines`、`episode_passages`），不进仓库；原始数据建议克隆到 `corpus/`（已忽略，docker compose 只读挂载到 `/corpus`）。
- 主键：CSV 末尾 `info` 行指向的原始剧本（如 `produce_events/100100101`），重复导入整段覆盖。没有 info 行的文件以 `csv/<相对路径>` 为主键并给出警告。多个文件指向同一剧本时（实际数据有 11 组），保留台词最多的那份。
- 失败结局：SCTranslationData 的文件名很多只是编号，所以按剧本编号识别，规则来自对全部约 5600 个文件的调查：W.I.N.G. 季度未达成 / 敗退 / 决赛落败，G.R.A.D. 各轮落败、败者复活线（以预赛落败为前提，与成功线矛盾）和淘汰线，试镜落败，约定未遵守。实际数据中排除 272 段。文件名像失败结局但规则没有覆盖的，会给出警告（实际数据只剩 3 个正常标题）。Landing Point 的「成功」和感谢祭「通常」不算失败结局，照常收录。
- 选项：`select` 行（制作人的选项）不收录，之后的角色反应保留。
- 出场角色：`characters.toml` 新增 `speakers`（如 `["真乃"]`），按台词说话人识别，`真乃＆めぐる` 这类合说台词拆开识别；两位角色不能共用一个说话人名字。制作人和非角色人物不在 `speakers` 里，所以不算出场角色。没有用「id 全零」来判断，因为实际数据里偶像没有语音的台词 id 也是全零。修改 `speakers` 或新增角色后要重新导入。
- 分类按剧本编号（P卡剧情、S卡剧情、培育剧情、活动剧情、特别剧情、主页剧情、营业剧情）；出处取文件所在目录名，标题取文件名。
- 向量索引：剧情按连续台词切成约 1200 字的文本块（带出处和标题，台词附中文），用 numpy 按余弦相似度检索，并按出场角色过滤（`StoryCorpus.search`）。文本没变的块沿用原向量，所以重复导入不花向量化费用。出场角色为空的剧情只入库、不向量化。
- 验证：切入点 B 的测试用样例 CSV 加假向量化，覆盖分类、出处、标题、台词、选项、出场角色、失败结局、幂等、重复来源和按角色过滤的检索。另用真实 SCTranslationData 全量试跑（假向量化）：导入 5341 段，其中真乃 445 段、恋鐘 341 段，约 1940 个文本块需要向量化，第二次导入 0 个。

留给后续 ticket 的注意点：

- 很多文件名只是编号（如 `produce_events_602000101`），标题不理想；09 导入 JSON 时可以按剧本编号补全标题。09 导入同一剧本时，不要覆盖已有的、带中文翻译的 CSV 版本。
- 培育剧情的出处都是「W.I.N.G.編」这类名字，不带偶像名。08 生成目录时要在角色层下面分组。
- 上游删除的文件不会从剧情库移除，只有被识别为失败结局的会被移除。
- 换了向量化模型但还没重新导入时，检索会返回空。
