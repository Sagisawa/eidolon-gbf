# 12: 人设初稿生成命令

**What to build:** 管理员用一条命令，让后台模型根据某位角色出场过的剧情，生成这位角色的人设草稿（身份、自称、对他人的称呼、口癖、组合成员、硬性规则），写入人设文件，供人工校对后使用。

**Blocked by:** 06, 10

**Status:** resolved

- [x] 命令接收一个角色标识，只用该角色出场过的剧情作为素材
- [x] 生成的草稿包含人设要求的各个部分，并明确标记为草稿
- [x] 默认不覆盖已存在且经过人工校对的人设文件，只有显式指定时才覆盖
- [x] 剧情素材超出模型的上下文长度时，先采样或分批总结，而不是直接失败
- [x] 测试：使用假的后台模型，验证素材只来自该角色出场过的剧情，以及已有文件不会被覆盖

## Comments

实现摘要：

- 命令：`eidolon character draft-sheet <角色标识>`，可选 `--characters`、`--output`、`--force`、`--budget`。后台模型用 `BACKGROUND_LLM_*` 配置，没填的项沿用 `CHAT_LLM_*`（`config.background_llm_from_env`）。这个命令只需要这些配置，不需要服务的其他设置。角色配置用 `load_characters(..., require_sheets=False)` 读取，所以人设文件还不存在时也能用。
- 素材：`corpus.list_episodes(角色)`，只包括她出场的剧情。剧情库本来就只收正式经历。每段剧情写成「分类｜出处「标题」」加逐行台词（有中文翻译时附上）。
- 草稿（`sheet_draft.py`）：
  - 依次是 `## 身份 / 自称 / 对他人的称呼 / 口癖 / 组合成员 / 硬性规则`。模型漏掉的小节补成「（待补充）」。模型把标题写成「## 身份：」「### 口癖」时仍然算有这一节，不会重复补。
  - 第一行是 `DRAFT_MARKER`（HTML 注释）。有这一行时人设照常可用：`load_characters` 会去掉标记，标记不会进入提示词，启动时会警告这是未校对的草稿。
  - CONTEXT.md 的「人设」补上了组合成员。
- 不覆盖：目标文件已存在且没有草稿标记时，视为已校对，抛 `SheetReviewed`；命令行提示加 `--force`。还没校对的草稿会被新草稿直接替换。这个检查在请求模型之前做。目标写不进去时（例如 docker 里只读挂载的 `characters/`）同样提前报错，并建议用 `--output`。
- 超出上下文：
  - 每次请求最多带 `--budget` 字素材，默认 40000。
  - 素材放得下时一次写完；放不下时按批让后台模型做笔记（每份笔记最多 budget/3 字），笔记还放不下就再对笔记做笔记，最后根据笔记写草稿。
  - 单段剧情超出上限时拆成几段（标题加「（续）」），不截断。
  - 第一轮超过 `MAX_BATCHES`（20）批时，先从全部剧情里均匀抽取。
  - 命令在 stderr 输出进度（第几批，共几批）。
- docker：README 写了 `--output /data/drafts/<id>.md` 加 `docker compose cp` 的做法。
- 测试（`test_sheet_draft.py`，用假后台模型，素材从样例 CSV 导入）：
  - 素材只来自出场剧情（真乃和恋鐘各一例）；
  - 各小节齐全、带草稿标记，加载后标记不进提示词；
  - 已校对的人设不覆盖、不花钱，`overwrite` 时才覆盖；
  - 未校对的草稿会被替换；
  - `--output` 不动原人设；
  - 分批做笔记，每次请求不超过上限；
  - 长剧情拆分而不截断；
  - 剧情过多时均匀抽样，第一轮批数不超过上限；
  - 标题写法略有出入的小节不重复；
  - 没有出场剧情时报错；
  - 命令行覆盖了拒绝覆盖、未知角色、缺后台模型配置、目标不可写。

真实服务验证（2026-09-25）：

- 条件：后台模型为 `.env` 里的对话模型 deepseek-v4.1-flash（OpenAI 兼容接口）。剧情库是 SCTranslationData 里真乃和恋鐘两个目录的 373 个 CSV，导入 366 段、排除 7 段失败结局，用本地假向量化导入，生成初稿不需要向量。
- 真乃：218 段剧情，约 33 万字。第一轮 11 批笔记，加笔记的笔记，共请求 14 次，用时 15 分 40 秒。这次用的是审查修复前的代码。
  - 草稿六节齐全，内容扎实：
    - 自称：「私」「わ、私」，模仿ピーちゃん时用「ボク」；
    - 称呼：「プロデューサーさん」「灯織ちゃん」「めぐるちゃん」，以及对动物加「さん」的习惯；
    - 口癖：「ほわっ」系列、「むんっ」「ふふっ」；
    - 组合口号「輝きを、みんなに届けよう！」。
  - 需要人工校对的错误：
    - 组合成员写成「杜野めぐる」，应为八宮めぐる。
    - 身份一节把导演和制作人对她的评价混在一起。
- 恋鐘：用修复后的代码，加 `--output` 运行。145 段剧情，9 批笔记，然后 2 批笔记的笔记，共请求 12 次，约 16 分钟。
  - 进度日志正常。
  - 草稿六节齐全，包括长崎佐世保出身、方言（「〜ばい」「〜けん」）、アンティーカ成员等。
  - 草稿指出素材里年龄有 18/19 两种说法，交给人工判断。
- 后端加载真乃的草稿：启动时警告「unreviewed draft」，标记不在人设正文里。

留给后续的注意点：

- 草稿偏长：真乃约 4000 字，恋鐘约 7000 字。人设每回合都完整带上，校对时最好删减，特别是「对他人的称呼」里那些很少用到的称呼。
- 生成一份要 15 分钟左右。模型的笔记会把同一件事在各批里重复记录。如果嫌慢，可以换一个更快的后台模型，或者调大 `--budget`（上限取决于后台模型的上下文长度）。
- 命令读取角色配置时，会对其他角色的未校对草稿也打印警告，有点吵，但无害。
