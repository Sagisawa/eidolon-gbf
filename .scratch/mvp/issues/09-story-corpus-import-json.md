# 09: 原始剧本 JSON 导入补全

**What to build:** SCTranslationData 里缺少的剧情，由管理员用插件导出游戏原始剧本 JSON（字段包括 speaker、text、select、voice 等），再导入剧情库补全。JSON 导入和 CSV 导入遵循同样的正式经历规则：选项分支只保留角色的反应，不认定制作人当时选了哪一项。同一段剧情如果已经通过 CSV 导入过，不会重复入库。

**Blocked by:** 06

**Status:** resolved

- [x] 导入命令支持游戏原始剧本 JSON
- [x] 选项分支：保留角色对每个选项的反应，但剧情内容不认定制作人选了哪一项
- [x] 同样排除失败结局
- [x] 同一段剧情分别通过 CSV 和 JSON 导入时，只保留一份（按来源标识去重）
- [x] 只通过 JSON 导入的剧情没有中文翻译，但检索和剧情目录都能正常使用
- [x] 切入点 B 的测试：包含选项分支的样例 JSON，以及 CSV 和 JSON 重叠的情况

## Comments

实现摘要：

- 命令：`eidolon story import-json <目录>`（`--characters` 同 CSV）。读取目录下所有 `*.json`，每个文件是一段游戏剧本的帧数组（游戏在 `assets/json/<剧本>.json` 提供的格式）。有 `text` 的帧是一句台词（`speaker` 为空时是旁白），只有 `select` 的帧是制作人的选项，不收录；没有文字的帧（背景、音乐等演出）跳过。这和汉化插件从同一份 JSON 生成 CSV 的规则一致，所以两种来源的内容相同。
- 选项分支：各选项对应的角色反应在帧数组里依次排列，全部保留；选项本身不收录，所以剧情内容不认定制作人选了哪一项（与 CSV 相同）。
- 来源标识：JSON 里没有剧本编号，所以从文件路径取：游戏的路径 `produce_events/100100101.json`，或汉化插件的命名 `produce_events_100100101.json`（编号至少 8 位，避免误认）。路径里没有剧本编号的文件跳过并警告，因为无法和 CSV 去重。
- 出处和标题：像 SCTranslationData 那样放在「出处/」目录下时，取目录名和文件名；按游戏路径存放时，出处是去掉最后两位话数的剧本编号（如 `produce_events/2011005`），标题是 `produce_events_201100501`。
- 失败结局、出场角色、分类、分块向量化、同一次导入内的重复来源，都和 CSV 共用同一套处理（`story_import._import`）。
- CSV 与 JSON 去重：`episodes` 表新增 `imported_from`（`csv` / `json`；旧库启动时自动补列，已有剧情都记为 `csv`）。JSON 导入遇到剧情库里已有的 CSV 版本时跳过（报告 `csv_versions_kept`，命令会打印），不覆盖带中文翻译的版本；之后导入的 CSV 会替换 JSON 版本。主键相同，所以任何顺序下都只有一份。
- 只从 JSON 导入的剧情没有中文翻译（`zh` 为空），检索、回顾剧情和剧情目录照常可用。
- 测试：`test_story_import_json.py`（切入点 B）用含选项分支、旁白、演出帧、合说台词、非角色说话人的样例 JSON 和样例 CSV，覆盖台词与分类、选项分支、失败结局、没有译文的剧情可检索并进入目录、两种存放方式的出处和标题、CSV 与 JSON 重叠（两种导入顺序）、重复导入幂等、同一剧本两个文件、无法读取或没有剧本编号的文件；两个命令行测试改为同时覆盖 `import-csv` 和 `import-json`。
- 验证：用真实 SCTranslationData 全量导入 CSV（假向量化）后，再导入由真乃的 200 个 CSV 还原成的剧本 JSON 加 3 个新剧本：194 段保留 CSV 版本、6 段失败结局被排除、3 段新剧本入库，第二次导入 0 次向量化；旧版数据库打开后自动补列，已有剧情记为 CSV。手头没有游戏真实导出的 JSON，格式依据汉化插件（biuuu/ShinyColors）读取剧本的代码。

留给后续的注意点：

- 按游戏路径存放的剧本没有标题和出处名，目录里显示为编号。06 提到的「按剧本编号补全标题」需要一份编号 → 标题的对照表，目前没有数据来源；拿到后可以在导入时补全（也可以顺便补全 CSV 里只有编号的文件名）。
- 「去掉最后两位话数」作为卡或活动的分组，是按 `produce_events` 的编号规则推断的；其他剧本类型只是近似（用真实 CSV 的剧本编号核对过：1212 组编号对应 1135 个目录，大体一致）。
- 还没有用游戏真实导出的 JSON 验证过；如果实际导出的文件带有包装结构（不是帧数组），会被报告为无法读取并跳过。
