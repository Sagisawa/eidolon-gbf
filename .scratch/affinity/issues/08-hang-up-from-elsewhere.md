# 08: 在别处进了冷却，挂断这边的通话

**What to build:** 用户在另一段对话或另一台设备上让她进了冷却时，这边正在进行的通话立刻被她挂断，不等用户开口：她正在说的那句说完就挂，不再生成告别；空闲着就直接挂；挂断前用户说的话不再被回答。结束原因和因冷却挂断的一样，这边的对话里同样留一条「挂断了电话」。见规格「她挂断电话」里「冷却从通话外开始」。

**Blocked by:** 07（她在通话里挂断）

**Status:** resolved

- [x] 回合记下时发现这回合让她进了冷却，就通知这位用户和这位角色之间其他进行中的通话
- [x] 收到通知的通话：已经送去合成的话播完就挂，空闲就直接挂；不再生成告别，挂断前用户说的话不再回答
- [x] `ended.reason` 是 `cooldown`、带 `cooldown_until`；这边的对话里写入「挂断了电话」；运行记录的结束原因是「角色挂断」；照常计入限额
- [x] 只通知同一位用户和同一位角色的通话，别的角色、别的用户的通话不受影响
- [x] 通话测试（浏览器测试替身）：在另一段对话里让她进了冷却，这边空闲着的通话不等用户开口就被挂断，结束原因同冷却，这边的对话里有「挂断了电话」；和另一位角色的通话不受影响

## Answer

- **谁通知**：冷却开始的地方只有一处，`Affinities.change`。它记下让她进冷却的回合时，当场告诉登记过的听者（`Affinities.on_cooldown`，传用户、角色、解除时刻）；组装时把 `Calls.cooled` 登记上去。文字回合、别的通话里的回合都走这条路。
- **不挂发起的那一通**：引擎在通话回合里时，`CallTurns` 用 ContextVar（`_taking_turn`）标明是哪一通在跑回合；`Calls.cooled` 跳过这一通，它照票 07 的路子说完这句再挂。同一用户、同一角色的其他通话都挂；别的角色、别的用户不碰。
- **收到通知的通话**：`CallTurns.cooled` 先告诉 `CallOutcome.cooled`（按冷却挂断，解除时刻就是通知里的；一通里先定下的挂断理由为准），再问 `TurnTaking.hung_up_on`：空闲就什么都不做；她已开口、有完整一段的回复按打断处理（`StopReply`，只记完整的段，后面不再送去合成，已经送去的照常播完）；还不能打断的（没开口或没有完整的段、等补充中）整回合丢掉（新命令 `DropTurn`，不留记录）。之后叫醒回合循环，它问 `she_hangs_up`，走票 07 的 `_end`：`ended`（`cooldown`，带 `cooldown_until`）、写「挂断了电话」、运行记录「角色挂断」、照常计入限额。挂断前用户说的话不再接（`TurnTaking` 已在结束）。
- **测试**：浏览器测试替身的接口测试一条（空闲的通话不等开口就挂、结束卡数据、对话里有挂断事件、看板「角色挂断」，同时开着的和另一位角色的通话照常说话）；通话回合层两条（已开口的回复停下、记下完整的段、之后说的话不接；没开口的回复整回合丢掉）；`TurnTaking` 的四种状态。
