# 07: 她在通话里挂断

**What to build:** 通话里有一个回合让她跌进冷却，或者这一通里第 2 次说了不该说的话，她说完这一句就挂断：挂断音照常，结束卡写「{角色名}挂断了电话。」，对话里留下一条「挂断了电话」的对话事件，她之后也知道自己挂过电话。因为冷却挂断的结束卡多一行解除时刻、只有「回到对话」；因为不该说的话挂断的结束卡主按钮仍是「重拨」。见规格「她挂断电话」。

**Blocked by:** 05（冷却）、06（对话事件）

**Status:** resolved

- [x] 定下要挂断的回合带通话版收尾指示（「说完这句你就挂断电话」的说法）

## Answer

- **在哪儿定下要挂断**：引擎在回合开始、判断出结果时定（`affinity.hangs_up`：会跌进冷却，或者 `in_call.out_of_line` 加上这一回合到了 `OUT_OF_LINE_PER_CALL = 2`），定下的回合拿通话版收尾指示（`affinity_prompt` 的 `parting` 换成 `"parts"` / `"hangs_up"`）。通话回合调用 `engine.turn(..., in_call=InCall(次数))`，文字回合不带，提示词和原来一样。
- **记下以后怎么告诉通话**：引擎在 `done` 之前多产出一个只留在服务器上的 `CallTurnRecorded`（这一回合有没有不该说的话、挂不挂、冷却的解除时刻），只在通话里产出，和 `SpeechDelta`、`SegmentComplete` 一样不发给浏览器；判断结果不随 `done` 漏给用户。没记入对话的回合（失败、被丢弃）没有这条，所以不挂断、不计数；补充后按合并的整段话重新判断，被打断的回复照样记下、照样挂断。
- **次数和先后**：一通里的次数在 `CallOutcome`；`CallTurns` 在回合之间先问 `she_hangs_up()`，再问 `limit_reached()`（`LimitReached` 改名 `Ending`，多一个 `by_her`）。`ended` 的 `reason` 是 `out_of_line` 或 `cooldown`，后者带 `cooldown_until`（另一回合同时记下、冷却没真的开始时为 null，结束卡就不写时刻那一行）；运行记录的结束原因 `character_hung_up`（看板「角色挂断」），结果成功、照常计入限额。
- **挂断了电话**：`CallTurns._end` 在她挂断时把事件写进这通电话的对话（`Calls` 的 `store` 改成必填，传给 `CallTurns`），`ended` 带上这条事件（`ConversationEvent.shown()`，和读记录接口同一形状）；前端收到就把它接进记录、通知对话列表。
- **结束卡**：内容收成纯函数 `callEnd.endCard`（标题、说明、是否计入、主按钮），冷却版的时刻用 `untilText`，按制作人的时区。
- **验收**：本地后端接不通，`ended` 又走数据通道，光拦 `/api/offer` 造不出这两种卡。做法是页面里另起一个 `RTCPeerConnection` 冒充后端：拦下 `/api/offer` 交给它应答，接通（回 `bot-ready`）后由它发 `ended` 和 `peerLeft`。两种屏宽、两种结束卡的标题、说明、按钮、计入限额和回到对话后的分隔线 20 项通过。写法记进了 `docs/agents/local-acceptance.md`。

## Comments

- 票 05 留下的：`engine.py` 的收尾指示（`affinity_prompt(..., cools)`）不分文字和通话，现在通话里跌进冷却的回合拿到的是文字版那句。这张票要在通话回合里换成「说完这句你就挂断电话」的说法。
