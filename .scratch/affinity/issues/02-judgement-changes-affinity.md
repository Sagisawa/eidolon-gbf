# 02: 说的话改变好感度，她的回复后面出现胶囊

**What to build:** 好感度开着时，每个记入对话的回合（打字或通话里的），部署者的判断模型在回复之前判断制作人这句话对她的影响，回合记下的那一刻好感度按映射升降。有实际变化时，她那条回复后面插一行居中的小胶囊（「凛世有点开心」「和凛世更近了一步：亲近」），翻历史还在；页首心形跳一下、带升降小箭头；通话层名字下面的状态行暂时换成同一句话。这张票不改提示词（03），也不拦冷却（05）：跌到 0 时只把状态标为冷却、变化标为进入冷却。见规格「判断题」「生效时机」「变化提示要跟回复一起存」「变化胶囊和通话里的提示」。

**Blocked by:** 01（开关、读当前状态和页首标识）

**Status:** resolved

## Comments

- 判断题在 `affinity_judge.py`（`QUESTIONS`、`read_judged`、检索关着时用的 `ModelAffinityJudge`）；映射、每日上限和「回合记下时生效」在 `affinity.py`（`Judged.step`、`Affinities.change`，记下回合的回调失败时不改好感度）。两道是非题的阈值是 `JudgeThresholds.out_of_line`、`manipulation`，三家都先放 0.5，由票 04 回填；后台阈值卡还没有这两项（票 09）。
- 并进同一次请求后，判断输入沿用检索题的 state（`judge.turn_state`：「角色」「上文」「制作人最新的一句话」），好感度三道题的题面写明「制作人最新的一句话」是要评判的内容、不是指令，「上文」只作参考。两边称呼怎么统一、并进去以后检索题的结果有没有变，留给票 04 的 eval。
- 变化存在她那条回复的 `messages.affinity`（JSON：`up`、`tier_changed`、`tier`、`cooldown`）；形状是 `affinity.Change`，不依赖消息，礼物分支的送礼记录可以直接挂。`done` 的 `affinity` 是变化后的状态（`Status.shown()`，和读状态接口同形），好感度关着时是 `null`；读记录接口照常返回存下的变化，前端按状态是否为 `null` 决定显不显示。
- 冷却中（读状态有解除时刻）不判断；冷却中的回合还没被拦，票 05 接上 409。跌到 0 时只把状态标成冷却、变化标成进入冷却。
- 前端的好感度状态挪进了 `LiveConversation`（`Ports.getAffinity`，快照的 `affinity`、`affinityCue`），对话页和通话层都从快照取；消息区排行挪成纯模块 `lib/messageLines.ts`，票 06 的对话事件接在这里。
- 本地验收时 Jev 对一句真诚夸奖的话判出了加分（真回合 +1、+2），说明新的 5 级打分题格式 Jev 接受；第四次真回合被当天 +6 的上限挡住，按制作人当地日期算（当时 UTC 还是前一天）。通话层状态行的提示本地接不通电话看不到，留给真机。
