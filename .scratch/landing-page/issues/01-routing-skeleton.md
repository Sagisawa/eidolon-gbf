# 01: 分流骨架：访客在 `/` 看到落地页，用户直接进对话列表

**What to build:** 打通落地页最薄的一条完整链路。访客打开 `/` 或 `/about`，看到落地页的骨架：服务端渲染的标题「Eidolon-SC」和「和 283 事务所的偶像说说话」、首屏一行非官方声明、CSS 画的静态白光、右上角的「登录」入口和页脚。点登录会在落地页里弹出登录面板。已登录的用户打开 `/` 直接进入对话列表，对话列表从 `/` 搬到 `/conversations`。背景见 `../spec.md` 的「路由与分流」，术语见 `GLOSSARY.md` 的「落地页」「访客」。

落地页用路由组拆出自己的根 layout（ADR-0016 修订）：不加载应用根 layout 里的 next/font 字体，只引入全局样式表给登录面板用，永远深色。这一张先用系统字体，正式字体由 03 接上。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 把现在登录页里的「登录方式列表 + 同意说明 + 没有登录方式时的提示」抽成共用的登录组件。`/login` 用它，外观和行为都不变，继续负责登录被拒原因和开发登录。落地页的登录面板也用它。
- [ ] `/` 和 `/about` 渲染同一个落地页，`/about` 的 canonical 指向 `/`。
- [ ] `/` 的分流：没有会话 cookie 时直接渲染，不请求后端；有 cookie 且会话有效时，重定向到 `/conversations`；会话无效或已过期时，照常渲染落地页。
- [ ] `/about` 不重定向，已登录时行动按钮和右上角入口显示「继续」，链到 `/conversations`。
- [ ] 对话列表搬到 `/conversations`，双栏和两级页面布局不变，应用内所有指向对话列表的链接跟着改。
- [ ] 401 时客户端跳到 `/`，不再跳到 `/login`。退出登录、删除账号后回到 `/`；同意页完成后去 `/conversations`。428 仍然跳 `/consent`。
- [ ] 后端 OAuth 回调成功后跳到 `/conversations`；登录被拒、取消、state 不对时仍跳 `/login?error=…`。
- [ ] 设置页底部加「关于 Eidolon-SC」，链到 `/about`。
- [ ] 标题从一开始就可见，没有透明度动画；页脚有非官方声明、隐私政策和使用条款的链接。
- [ ] 现有测试按新的跳转目标更新断言并通过：前端的 `redirectFor`，后端登录回调的跳转。
- [ ] 验收脚本的初版沿用原型的测量脚本：能测 `/` 的分流（不带会话、带有效会话、带过期会话）、`/about` 的「继续」、手机 4G 节流下的 LCP，以及 LCP 元素是不是标题文字。
- [ ] PRODUCT.md 的「现有页面」和「Operating Context」按新路由更新。
