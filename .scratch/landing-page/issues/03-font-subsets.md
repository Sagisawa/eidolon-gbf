# 03: 字体子集：落地页用自托管的子集字体，缺字时测试会失败

**What to build:** 落地页换上拍板的字体：日文和拉丁字母用 Shippori Mincho B1，中文大标题用 Noto Serif SC，中文正文用 Noto Sans SC。这些字体按落地页实际用到的字做成静态子集，自托管，首屏不再被几百 KB 的字体 CSS 拖慢。背景见 `../spec.md` 的「字体」，以及 ADR-0016 修订。

**Blocked by:** 01

**Status:** done

- [ ] 一个由维护者在本地运行的脚本，收集要覆盖的文字：落地页文案、登录组件的文案、所有角色名、组合名，以及招呼的原文和字幕（配置里有就收）。脚本生成三种字体的 woff2 子集，外加一份「子集里有哪些字」的清单，一起提交进仓库。前端的 Docker 构建拿不到角色配置，所以子集不能在构建时生成。
- [ ] 子集保留竖排字形（`vert`、`vpal`）和竖排标点（、。「」ー… 等）。
- [ ] 落地页的根 layout 用这些子集，不用 next/font/google 加载 CJK 字体；首屏只预载第 0 幕用到的字体。
- [ ] 覆盖契约测试（vitest）：读取角色配置、落地页文案和登录组件的文案，断言其中每个字都在清单里。新增角色或改了文案却没重新生成子集时，测试失败，失败信息列出缺的字和该怎么重新生成。
- [ ] 验收脚本测得 LCP 没有因为换字体而变差。
- [ ] 脚本的用法写在它的开头注释里，也写进前端的 agent 说明或部署文档中合适的位置。
