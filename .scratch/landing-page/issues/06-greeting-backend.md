# 06: 招呼的后端：配置里写好招呼，一条命令合成上传，接口给出字幕和音频地址

**What to build:** 维护者在角色配置里为一位角色写上招呼（日语原文，可以带语气提示；以及中文字幕），部署者运行一条命令，就能用她的音色把招呼合成好、上传到立绘所在的存储桶，角色列表接口随即给出这句招呼的原文、字幕和音频地址。术语见 `GLOSSARY.md` 的「招呼」，背景见 `../spec.md` 的「招呼」和 ADR-0003 修订。

**Blocked by:** 02

**Status:** done

- [x] 角色配置新增两个可选项：招呼的日语原文（语气提示的语法和回复里一致）和中文字幕。配置文件开头的字段说明一并更新。
- [x] `GET /api/characters` 的每个角色带 `greeting`：没配置时为空；配置了就是 `{ ja, subtitle, audio_url }`。`ja` 去掉了语气提示；只有配置了立绘素材地址才有 `audio_url`。
- [x] 音频路径是 `greetings/` 下的「角色标识加内容哈希」，哈希由带语气提示的日语原文和音色 ID 算出；后端不查存储桶就能算出 `audio_url`。
- [x] 新命令用部署者的语音合成 key 把招呼合成成 mp3，只合成存储桶里还没有的那几句，上传后删掉这位角色的旧版本。某一位没有音色、合成失败或上传失败时，报告这一位并继续处理其他人，最后以非零码退出。
- [x] 招呼不经过回合，不写运行记录，不计入任何人的限额。
- [x] 测试比照现有立绘上传的测试，用假的语音合成和假的存储桶，覆盖：只合成缺的；上传路径和接口算出的 `audio_url` 一致；删旧版本；单个失败不中断；不写运行记录。接口测试覆盖 `greeting` 的几种情况。
- [x] 部署文档写上这条命令、它什么时候需要跑（改了招呼或音色之后），以及下线方法：清空存储桶，立绘和招呼一起下线。
