# landing-page 拷问记录

来源：2026-10-10 的拷问会话。目标是给部署后的网站做一个对标 Awwwards / FWA / CSSDA 每日最佳水准的落地页，替代现在的「登录页加角色列表」。中途补了一轮对标调研，见 `docs/research/landing-page-references.md`（三组原始报告和截图在 `docs/research/landing-page/`）。相关文档：GLOSSARY 的「落地页」「访客」「招呼」，ADR-0016，ADR-0003 的 2026-10-10 修订。

原型已于同日拍板（见文末「原型结果」），下文已按拍板结果改过。下一步：/to-spec 写完整规格，再 /to-tickets 拆分波 ticket。

## 定位与路由（已确认）

- 名称是「落地页」，不叫官网、首页、主页。没登录的人叫「访客」。
- 访客打开 `/` 看到落地页；已登录的用户打开 `/` 直接进入对话列表。对话列表从 `/` 搬到 `/conversations`，和 `/conversation/[characterId]` 对应。
- 设置页底部有「关于 Eidolon-SC」链接回到落地页；已登录时落地页的行动按钮从「登录」变成「继续」。
- 登录面板在落地页里弹出，和 `/login` 共用同一个登录组件；`/login` 保留，负责登录被拒的 `?error=` 回跳、开发登录和直接访问。

## 视觉世界（已确认，ADR-0016）

- 落地页是独立于 DESIGN.md「制作人的手机」的视觉世界，永远深色，不跟随系统。只沿用印象色规则；shadcn 纪律只管登录面板和行动按钮。
- 主线隐喻是「棱镜分光」：一束白光散成 28 道印象色，每道是一位偶像。白光是唯一的主角，八幕里一直在，幕与幕之间靠它变形来转场，不用淡入淡出或硬切。
- 用亮度节奏代替明暗主题切换：第 1 幕分光是第一个亮点，第 6 幕最暗最静，第 7 幕白光铺满全屏是全站最亮。
- 可以向原作官方站的风格靠拢，「撞脸」不是约束，怎么好看怎么来；但不使用官方 logo、组合 logo 等商标，组合名用文字排。非官方声明在首屏放一行小字，页脚常驻。
- 语言：中文为主，日文作为视觉元素大量出现（名字、招呼、竖排），说明文字只有中文。竖排只用于日文。

## 八幕（已确认）

全站 22 到 28 屏。竖滚和横滚交替，一个滚轮连续触发；只有第 2 幕是长横滚，第 5 幕可以有一段 1 到 2 屏的短横移。

0. **开场**：一片黑，一束白光，「Eidolon-SC」和「和 283 事务所的偶像说说话」。标题是 SSR 的 DOM 文字，从一开始就可见；白光先用 CSS/SVG 画出来。
1. **分光**：白光射进棱镜，按色相出射。连续色散只在棱镜出口附近，往外吸附成 28 条官方色带，不出现印象色以外的中间色。
2. **⇄ 光谱**：光带「归队」成官方组合顺序，从左往右推进。每道光是一块竖排名牌（巨大的日文名）。按组合分段，段与段整页推入，底部常驻当前组合名，可以按组合跳转。聚焦某位偶像时，背景过渡到她印象色的极深同色相，其余降亮；她的 Spine 浮现，点一下听她的招呼并显示字幕。
3. **她说日语**：日语原文和中文字幕的排版演示，字幕被光「扫」出来，不用打字机效果。
4. **来电**：模拟一次来电，铃声在视觉上用振动和光的脉冲表现；点（或长按）「接听」才出声。
5. **记忆与回忆**：一个光点从一道光传到另一道光，颜色从来源角色渐变到接收者，体现记忆跨角色共享；剧情回忆用抽象光迹，不出现任何剧情原文。
6. **安静的诚实事项**：完全静止的居中短段落。写清非官方、免费但每小时有限额（不写具体数字）、可以自带密钥、记忆看得到也能彻底删除、管理者看不到对话。登录方式从后端的登录选项动态读取，不写死。
7. **开始**：28 道光收拢成一块手机屏幕的白光，出现行动按钮，转进应用。

导航：左侧一条竖排的日文幕名轨作为进度指示；右上角常驻登录（已登录时为继续）入口；只有第 2 幕能按组合跳转。

## 角色与光（已确认）

- 偶像整体按官方偶像编号（`characters.toml` 的 `idol_id`）排序，这样组合顺序（illumination STARS 到 CoMETIK）和组合内顺序都对上官方。`world.json` 里的成员顺序和 `characters.toml` 的排列顺序都不是官方顺序，不能用。
- 名单从后端的角色列表动态读取。新角色填了编号就自动排进正确位置；没有 Spine 或没有招呼的角色只显示名字和光。
- 每道光是白色光芯加印象色光晕，光晕按亮度反向补偿（灯织的 `#144384` 在黑底上对比度只有 2.2:1）。同屏满强度的颜色最多 3 到 5 个，其余降成余烬。不做全屏 bloom，交叠用 `max` 或 screen，不相加。
- 每位偶像离线算好一组同色相的颜色（官方色本身不改，加上极深底色、光晕色、文字色），插值在 OKLab 里做。

## 素材与声音（已确认，ADR-0003 修订）

- 角色形象只来自官方 Spine 和头像，同一时间只挂一位，用的是 `characters.toml` 里的默认衣装。Spine 用独立 canvas，只盖立绘区域，DPR 不超过 1.5，手机上离开就释放 WebGL 上下文。
- 生图不画角色。光、色散、焦散用着色器实时生成。分享卡片（OG 图）可以用生图做底图、再用代码加工和排版，但不出现角色。
- 每位偶像一句招呼：她对初次见面的制作人说的一句日语，附中文字幕，符合人设，不引用剧情原文和歌词。由 agent 根据 `characters/sheets/` 起草，用户逐句审核；用现有 TTS 流程和她的音色、带语气提示一次性合成；音频放进公开存储桶，不进仓库。
- 第一次点偶像就直接播放招呼，同时出现常驻的声音开关（状态为开）；关掉以后点偶像只显示字幕。第 4 幕永远要点「接听」才出声。不放背景音乐，不做悬停音效，同时只播一句。

## 技术（已确认）

- 新增依赖只有 `lenis` 和 `ogl`，只在落地页的路由里加载。不用 GSAP、ScrollTrigger、detect-gpu、matter.js、three.js。
- 钉住用 CSS `position: sticky`，由 Lenis 的滚动进度驱动横移，再经过自写弹簧平滑。Lenis 建议 `lerp≈0.1`，触屏不做平滑。坚持原生滚动，不接管滚轮。
- OGL 整页一张全屏 canvas，首屏内容画出来之后再动态加载。色散按档位 5、3、1 次光谱采样，加蓝噪声抖动，只在转场时出现。着色器在空闲时分批预编译。
- 字体（原型拍板）：日文明朝体用 **Shippori Mincho B1**，拉丁字母也用它，不另配拉丁展示字体；中文大标题用 **Noto Serif SC**；中文正文用 Noto Sans SC。只用开源许可的字体。
- 字体加载方式是**硬性要求**（原型拍板，ADR-0016 修订）：落地页的字体在构建时按实际用字做静态子集、自托管，保留竖排字形（`vert`、`vpal`）和竖排标点；**不能用 next/font/google 加载 CJK 字体**。原型里 next/font 的 CJK 切片 CSS 约 500 KB 阻塞渲染，LCP 4.9 秒，拦掉后 0.86 秒。
- 落地页**不挂在现在的根 layout 下**，用路由组拆出自己的根 layout（ADR-0016 修订）。这会影响「访客看到落地页、已登录的用户被带到 `/conversations`」怎么实现，规格里要一起设计。
- 预算（原型拍板，改了口径）：**落地页自身的首屏 JS 压缩后不超过 50 KB，不含框架基线**（Next 16 + React 19 每页本来就有约 161 KB，原来的「整页 ≤ 150 KB」做不到）；手机 4G 下 LCP 不超过 2.5 秒不变。原型里落地页自身约 21 KB，OGL 约 16 KB、空闲时才加载。LCP 元素必须是 SSR 的 DOM 文字；Spine、招呼音频都是聚焦或点击时才加载。
- 后端要补：`/api/characters`（前端的 `listCharacters()`）现在不返回 `idol_id`，前端没法按官方编号排序。要么给角色列表加上 `idol_id`，要么由后端直接按它排好序。

## 分档（已确认）

- 三档：完整、简化、静态。首屏前按 `(hover:none)`、`prefers-reduced-motion`、`saveData` 定初始档；运行中按帧时只降不升。每档改 DPR（完整档电脑不超过 2、手机不超过 1.5，简化档 1）、色散采样次数和焦散开关。
- 手机和电脑体验对等，手机上横滚的机制不变（竖着滑动驱动横移），效果降一级。
- 开了「减少动态效果」：着色器只渲染一帧定格的光谱后停下；横滚改成竖排；滚动驱动的变化直接显示完成态；Spine 只显示静帧。
- 浏览器不支持 WebGL 或开了省流量：不加载 canvas，用 CSS/SVG 画静态的光。
- 这两条写进验收标准。调研里 20 个站没有一个认真处理「减少动态效果」，这是要拉开差距的地方。

## 原型结果（2026-10-10 拍板）

原型在 `prototype/landing-page` 分支的提交 `3d07693`（永不合并，正式实现在 `feat/landing-page` 上从头写），路由是 `/landing-prototype`，做了第 0、1 幕和第 2 幕的 illumination STARS、L'Antica 两段。各项做法和理由写在原型代码的注释里，正式实现时直接去读：

- 光的几何、三个状态之间的插值：`frontend/src/app/landing-prototype/scene.ts`；
- 光晕的亮度补偿：`color.ts`；
- 着色器、色散采样、交叠方式，以及 OGL 的两个坑：`light.ts`；
- 分档、弹簧、立绘的层级和摆位、名牌为什么要重新测量：`Landing.tsx`；
- SSR 标题、首屏前定档的脚本：`page.tsx`；
- 复测脚本：`frontend/scripts/landing-prototype-measure.mjs`。

拍板结论：

- **光的质感**：按原方案通过。灯织的深蓝补偿后能立住，めぐる的黄不刺眼。
- **字体、横滚方向、预算口径、字体加载方式、独立根 layout**：已写进上面「技术」一节。横滚方向定为从左往右。
- **滚动手感**：Lenis、CSS sticky 加自写弹簧，以及组合之间的整页推入，都通过；用户在真机上试过，帧率没问题。
- **立绘的层级**（用户专门纠正过）：立绘要压在其他偶像的名牌上面，只有被聚焦那位的名牌在立绘之上。名字透过立绘看不清是不行的。

原型没覆盖、规格里要处理的部分：

- 第 3 到 7 幕、登录面板的弹出、声音开关的真实行为。
- 招呼的台词和音频：台词还没起草，要用户逐句审核以后才能合成。
- 两个降级档只证明了结构走得通。「减少动态效果」档现在用头像代替 Spine 静帧；静态档没有棱镜出口附近的连续色散；静态版式下，左侧幕名轨不随滚动更新。

另外开了一个单独的问题，不并进落地页：应用的根 layout 用 next/font/google 加载 CJK 字体，拖慢了所有普通页面的 LCP，见 `.scratch/root-layout-font-lcp/`。
