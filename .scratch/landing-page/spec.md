# 落地页

**Status:** ready-for-agent

术语以 `GLOSSARY.md` 为准（落地页、访客、招呼、印象色、立绘、衣装、组合、限额、自带密钥、记忆、来源角色）。依据：`.scratch/landing-page/grilling-notes.md`（全部决定，包括原型拍板的结果）、`docs/research/landing-page-references.md`、ADR-0016 及其 2026-10-10 修订、ADR-0003 的 2026-10-10 修订。原型在 `prototype/landing-page` 分支的提交 `3d07693`（永不合并）：光的几何、光晕补偿、着色器、分档、弹簧、立绘层级的做法和理由都写在原型代码的注释里，实现时先读。

## Problem Statement

部署以后，访客打开网站看到的是一个朴素的登录页加一串角色列表。它说不清这是什么、和别的 AI 聊天有什么不同、要不要付钱、数据怎么处理，也没有给人留下任何印象。这是整个项目的门面，第一眼就决定访客会不会登录，也决定会不会有人把链接转发出去。

已登录的制作人每天打开网站是为了找她说话，现在 `/` 就是对话列表，这一点不能因为加了门面而变差。

## Solution

访客打开 `/`，看到一个对标 Awwwards / FWA / CSSDA 每日最佳的落地页：一片黑里的一束白光，滚动时它射进棱镜，散成 28 道印象色，每一道是一位偶像。沿着光谱横向走过 8 个组合，聚焦到她时，她的立绘从光里浮现，点一下就能听她用自己的声音说一句招呼，配中文字幕。往下依次讲清楚：她说日语、你看字幕；可以给她打电话；她会记得你，还会说给别的偶像听；安静地交代非官方、限额、自带密钥、记忆可以删除。最后 28 道光收拢成一块手机屏幕的白光，访客在落地页里弹出的登录面板登录，转进应用。

已登录的用户打开 `/` 直接进入对话列表（搬到 `/conversations`），不经过落地页；想看落地页时，从设置页的「关于 Eidolon-SC」进入 `/about`，行动按钮显示「继续」。

落地页在手机和电脑上体验对等，按设备性能分成完整、简化、静态三档。开了「减少动态效果」的人看到定格的光谱，浏览器不支持 WebGL 的人看到 CSS 画的静态光，都能完整读到所有内容并登录。

## User Stories

### 进入与分流

1. 作为访客，我想打开网站根地址就看到落地页，以便第一眼弄明白这是什么。
2. 作为已登录的用户，我想打开网站根地址就直接进入对话列表，以便不用每次都看一遍动画。
3. 作为会话已经过期的用户，我想打开网站根地址时看到落地页而不是报错页，以便直接重新登录。
4. 作为已登录的用户，我想从设置页的「关于 Eidolon-SC」看到落地页，以便把它转发给朋友前自己先看看。
5. 作为在 `/about` 看落地页的已登录用户，我想行动按钮显示「继续」并直接回到对话列表，以便不被要求重新登录。
6. 作为刚完成 OAuth 登录的用户，我想登录后直接进入对话列表（第一次登录先经过同意页），以便不用再看一遍落地页。
7. 作为退出登录或删除了账号的人，我想回到落地页，以便知道自己已经离开了应用。
8. 作为在应用内页面遇到会话过期的用户，我想被带回落地页，在那里重新登录。
9. 作为登录被拒的访客（例如 GitHub 账号注册不满一年），我想仍然在 `/login` 看到被拒的原因，以便知道该怎么办。
10. 作为部署者，我想开发模式的名字登录仍然留在 `/login`，以便本地测试不受落地页影响。
11. 作为收藏了旧的 `/` 的已登录用户，我想打开收藏时仍然到达对话列表。

### 第 0 幕：开场

12. 作为访客，我想打开页面的瞬间就看到标题「Eidolon-SC」和「和 283 事务所的偶像说说话」，而不是加载动画或「点击进入」，以便不用等就知道这是什么。
13. 作为访客，我想首屏就看到一行「非官方粉丝作品，角色由 AI 扮演」的小字，以便不会把它误认为原作官方网站。
14. 作为电脑上的访客，我想移动鼠标时那束白光随之改变角度，以便感觉这个页面是活的。
15. 作为手机上的访客，我想用手指触碰时也能影响白光，以便手机上不是一张死图。
16. 作为网速慢的访客，我想标题和白光在动画库、着色器加载完之前就已经出现，以便在 4G 下 2.5 秒内看到内容。

### 第 1 幕：分光

17. 作为访客，我想往下滚动时看到白光射进棱镜，按色相散成彩虹，以便一眼认出「闪耀色彩」这个隐喻。
18. 作为访客，我想彩虹离开棱镜后收拢成 28 条边缘清晰的色带，每条都是一位偶像的官方印象色，以便知道每一道光代表一个人。
19. 作为熟悉原作的玩家，我想在这些光里认出自己推的偶像的颜色，以便产生「她在这里」的亲切感。
20. 作为访客，我想分光的色散在我滚得快时分得更开，以便感觉光对我的动作有反应。

### 第 2 幕：光谱

21. 作为访客，我想滚动时光带「归队」，重新排成官方的组合顺序，从左往右横向推进，以便按组合认识她们。
22. 作为玩家，我想偶像按官方偶像编号排列（illumination STARS 在前，CoMETIK 在后，组合内也是官方顺序），以便顺序和我熟悉的一致。
23. 作为访客，我想每道光就是一块竖排的巨大日文名牌，以便不看说明也知道她叫什么。
24. 作为访客，我想每个组合开头有组合名，底部常驻显示当前所在的组合，以便知道自己走到了哪里。
25. 作为访客，我想组合与组合之间整页推入，以便感觉到分段。
26. 作为想找某位偶像的访客，我想能直接跳到某个组合，以便不用从头滚过 28 个人。
27. 作为访客，我想聚焦到一位偶像时，背景过渡到她印象色的极深同色相，其余偶像的光降成余烬，以便全屏都感觉到「现在是她」。
28. 作为访客，我想聚焦时她的立绘从光里浮现，穿着默认衣装，以便看到她本人。
29. 作为访客，我想立绘压在其他偶像的名牌上面，只有她自己的名牌在立绘之上，以便名字和立绘都看得清。
30. 作为喜欢深色系偶像（例如灯织）的玩家，我想她的光在黑底上也清楚可见，以便她不会被埋没。
31. 作为喜欢亮色系偶像（例如めぐる）的玩家，我想她的光明亮但不刺眼。
32. 作为访客，我想点一位偶像就听到她用自己的声音说一句招呼，同时看到日语原文和中文字幕，以便亲耳确认「像她本人」。
33. 作为访客，我想第一次点击就直接出声，不需要先去找声音开关，以便点了就有回应。
34. 作为访客，我想声音播放后角落出现一个声音开关，以便随时关掉。
35. 作为关掉了声音的访客，我想再点偶像时只显示字幕，以便安静地浏览。
36. 作为访客，我想同一时间只有一句招呼在播放，点另一位时上一句停下，以便声音不会叠在一起。
37. 作为访客，我想页面从不自动发出声音，以便在公共场合打开也不会尴尬。
38. 作为在立绘素材下线后打开页面的访客，我想仍然看到名字和光，聚焦时看不到立绘也不出现空洞或报错。
39. 作为在招呼音频下线后打开页面的访客，我想点偶像时仍然看到字幕，只是没有声音。
40. 作为部署者，我想新增一位角色并填好偶像编号后，她自动出现在光谱里正确的位置，以便不用改落地页的代码。
41. 作为部署者，我想没有立绘或没有招呼的角色只显示名字和光，以便新角色可以先上线、素材后补。

### 第 3 幕：她说日语

42. 作为访客，我想看到一段日语原文和中文字幕的排版演示，字幕像被光扫过一样出现，以便明白「她说日语原声，我看中文字幕」。
43. 作为日语用户，我想日语原文竖排、清楚、保留她的口癖和语气词，以便感受到原作的味道。

### 第 4 幕：来电

44. 作为访客，我想看到一次模拟来电：全屏是她、屏幕在振动和发光，以便明白可以和她实时通话。
45. 作为访客，我想只有点（或长按）「接听」时才响起铃声和接通音，以便滚动经过时不会突然出声。
46. 作为手机上的访客，我想用长按来接听，以便操作像真的接电话。

### 第 5 幕：记忆与回忆

47. 作为访客，我想看到一个光点从一道光传到另一道光，颜色从来源角色渐变到另一位，以便明白「我对一位偶像说的事，别的偶像也会知道」。
48. 作为访客，我想看到抽象的光迹表现「她记得你们走过的剧情」，以便知道她能回忆原作，而页面上不出现任何剧情原文。
49. 作为访客，我想指针在这一幕留下的痕迹慢慢消散，以便呼应「她会记住」。

### 第 6 幕：诚实事项

50. 作为访客，我想读到「这是非官方粉丝作品，与版权方无关，角色由 AI 扮演」，以便知道自己在用什么。
51. 作为访客，我想知道可以免费使用但每小时有限额，以便对用量有正确的预期。
52. 作为访客，我想知道可以自带密钥，自带的部分费用自理，以便知道怎么突破限额。
53. 作为在意隐私的访客，我想知道她记住的事我都看得到、都能彻底删除，管理者看不到我的对话，以便放心登录。
54. 作为访客，我想看到现在支持哪些登录方式，以便判断自己能不能登录。
55. 作为部署者，我想登录方式的说明从后端的登录选项读取，以便以后接入新的 OAuth 时不用改落地页。
56. 作为访客，我想这一段安静、没有特效，以便认真读完。

### 第 7 幕：开始

57. 作为访客，我想看到 28 道光收拢成一块手机屏幕的白光，以便感觉到「从这里进入她们的世界」。
58. 作为访客，我想点行动按钮后在落地页里弹出登录面板，以便不离开这个页面就能登录。
59. 作为访客，我想登录面板列出可用的登录方式，并说明登录即表示同意隐私政策和使用条款，以便知情同意。
60. 作为后端没有配置任何登录方式时打开页面的访客，我想登录面板说明暂时无法登录，而不是一个空面板。

### 全局导航

61. 作为访客，我想左侧有一条竖排的日文幕名轨，当前幕亮起，以便知道自己在整个故事的哪里。
62. 作为想直接登录的访客，我想右上角始终有「登录」入口，以便不用滚到底。
63. 作为已登录用户，我想右上角的入口显示「继续」。
64. 作为访客，我想页脚常驻非官方声明和隐私政策、使用条款的链接。
65. 作为访客，我想页面是原生滚动，键盘翻页、页内查找、浏览器后退都正常，以便不被页面「劫持」。

### 分档与无障碍

66. 作为用高性能电脑的访客，我想看到完整的色散、焦散和高分辨率的光。
67. 作为用普通手机的访客，我想画面依然流畅，即使效果降了一级，以便不卡、不烫。
68. 作为设备在运行中变卡的访客，我想页面自动降低效果并且不再来回切换，以便体验稳定。
69. 作为开了「减少动态效果」的访客，我想看到一帧定格的光谱，横滚改成竖排，所有内容直接呈现完成状态，立绘只显示静帧，以便不晕也不错过内容。
70. 作为浏览器不支持 WebGL 或开了省流量的访客，我想看到用 CSS 画的静态光和全部内容，以便照样能读完并登录。
71. 作为用读屏器的访客，我想偶像名字、招呼和所有说明都是真文本，每道光都能用键盘聚焦，以便不依赖视觉也能使用。
72. 作为用键盘的访客，我想用 Tab 聚焦一位偶像、用 Enter 听她的招呼。
73. 作为横屏或窄屏手机上的访客，我想竖滑时光谱照样横向推进，名字仍然竖排。

### 转发与识别

74. 作为把链接贴到 QQ、微信、X、Discord 的人，我想看到一张有设计感的预览图和标题、描述，以便朋友愿意点开。
75. 作为版权方或其他人，我想在预览图和页面上都看不到官方 logo 和组合 logo，以便清楚这不是官方产品。

### 招呼的制作（部署者与维护者）

76. 作为维护者，我想每位角色的招呼台词写在角色配置里（日语原文和中文字幕），以便和人设一起维护、一起审核。
77. 作为维护者，我想由 agent 根据人设起草 28 句招呼，我逐句审核后才合成，以便每一句都符合她的人设、不引用剧情原文和歌词。
78. 作为部署者，我想用一条命令把所有招呼用她们的音色合成并上传到立绘所在的存储桶，以便不用逐个手动处理。
79. 作为部署者，我想重新运行这条命令时只合成文字或音色变了的招呼，以便不重复花钱。
80. 作为部署者，我想某位角色合成失败（没有音色、密钥出错）时命令报告清楚，并继续处理其他角色。
81. 作为部署者，我想收到权利方的要求时清空存储桶，立绘和招呼就一起下线，落地页自动退回只有字幕和光，不需要改代码或发版。
82. 作为部署者，我想访客播放招呼时不实时调用语音合成，以便不产生费用、也不会被刷。

### 字体与性能（维护者）

83. 作为维护者，我想落地页的字体按实际用到的字做成子集，自托管，以便首屏不被几百 KB 的字体 CSS 拖慢。
84. 作为维护者，我想在新增角色、修改招呼或文案却忘了重新生成字体子集时，测试会失败，以便不会出现缺字、换字体的情况。
85. 作为维护者，我想落地页的依赖（Lenis、OGL）和字体只在落地页加载，不进应用的包，以便应用不因落地页变慢。
86. 作为维护者，我想有一个验收脚本测出落地页自身首屏 JS、手机 4G 下的 LCP、两个降级档的截图和 `/` 的分流，以便每次改动后都能复测。

## Implementation Decisions

### 路由与分流

- 落地页用路由组拆出**自己的根 layout**（ADR-0016 修订），不加载应用根 layout 里的 next/font 字体。它引入应用的全局样式表，只为了登录面板和行动按钮（shadcn）；永远深色，不跟随系统。
- 落地页挂在两个地址：`/` 和 `/about`，两者渲染同一个页面，`/about` 的 canonical 指向 `/`。
- `/` 在服务端判断访客还是用户：请求里没有会话 cookie 时直接渲染落地页（不额外请求后端，保住访客的 LCP）；有会话 cookie 时向后端确认会话有效，有效就重定向到 `/conversations`，无效（已过期）就照常渲染落地页。`/about` 不重定向，只用同样的判断决定行动按钮是「登录」还是「继续」。
- 对话列表从 `/` 搬到 `/conversations`，原有的双栏和两级页面布局不变；应用内所有指向对话列表的链接跟着改。
- 未登录（401）时客户端跳转的目标从 `/login` 改为 `/`；退出登录、删除账号后也回到 `/`。同意页完成后跳到 `/conversations`。需要同意（428）时仍跳 `/consent`。
- 后端 OAuth 回调成功后的跳转目标改为 `/conversations`（第一次登录时由 428 带去同意页）。登录被拒、取消、state 不对时，仍然跳到 `/login?error=…`。
- `/login` 保留：显示登录被拒的原因、开发模式的名字登录，也可以直接访问。它和落地页的登录面板共用同一个**登录组件**（列出登录方式、同意说明、没有登录方式时的提示），这个组件从现在的登录页里抽出来。
- 设置页底部加「关于 Eidolon-SC」，链到 `/about`。

### 后端：角色列表

- `GET /api/characters` 仍然对访客公开，改为按偶像编号升序返回；没有编号的角色排在有编号的后面，保持配置里的顺序。
- 每个角色新增字段：
  - `idol_id`：偶像编号，可以为空；
  - `unit`：组合名，取自世界设定里这位偶像所属的组合，查不到时为空；
  - `greeting`：招呼，没有配置时为空。有的时候是 `{ ja, subtitle, audio_url }`。`ja` 是去掉语气提示后的日语原文，`subtitle` 是中文字幕。`audio_url` 在配置了立绘素材地址时给出，否则为空。
- 另外给出组合的官方顺序（世界设定里组合的排列顺序），让前端不用自己硬编码组合顺序。形式由实现决定：可以是列表里每个角色带一个组合序号，也可以单独提供一个字段。

### 招呼

- 招呼的台词写在角色配置里，是两个可选项：日语原文（可以带语气提示，语法和回复里的语气提示一致，只给语音合成用）和中文字幕。招呼的文字进仓库，音频不进（ADR-0003 修订）。
- 新增一条命令，用每位角色的音色和部署者的语音合成 key，把招呼合成为 mp3，上传到立绘所在的存储桶，路径是 `greetings/` 下的「角色标识加内容哈希」。哈希由带语气提示的日语原文和音色 ID 算出。所以：
  - 后端不用查询存储桶，就能算出 `audio_url`；
  - 文字或音色变了，地址就变，浏览器缓存不会播旧的；
  - 命令只合成存储桶里还没有的那几句；旧版本的文件由命令顺手删掉。
- 某位角色没有音色、合成失败或上传失败时，命令报告这一位并继续处理其他角色，最后以非零退出码结束。
- 招呼不经过回合，不写运行记录，也不计入任何人的限额。
- 台词的产出流程：agent 根据人设起草 28 句，交用户逐句审核；审核通过后才写进配置并合成。

### 前端：落地页模型（深模块）

一个不依赖 DOM、WebGL、Lenis 的纯函数模块，是落地页所有编排的唯一出处。着色器层、DOM 层、立绘层都只负责把它的输出画出来。

- **名单准备**：输入后端的角色列表，输出排好序、按组合分段的光谱。每位偶像带一组离线推出的颜色：官方色本身（不改），极深的同色相底色，按感知亮度反向补偿的光晕色和光晕宽度，以及能在官方色上读清的文字色。插值在 OKLab 里做。原型里光晕补偿的做法已经拍板，照搬它的算法。
- **画面描述**：输入滚动进度、视口尺寸和档位，输出这一刻的画面。包括：
  - 当前在哪一幕，以及幕内的进度；
  - 白光和 28 道光各自的位置、宽度、颜色和强度：第 1 幕是色相顺序，第 2 幕是组合顺序，「归队」时在两者之间插值；同屏满强度的最多 3 到 5 道，其余是余烬；
  - 横移量，组合之间的整页推入；
  - 聚焦的是谁、她的背景色、立绘该不该出现；
  - 幕名轨亮到哪一格、底部的组合名；
  - 色散强度：只在转场时出现，随滚动速度变大。
- **交互状态**：一个 reducer，管这些事：
  - 聚焦和点击偶像；
  - 招呼要不要出声：第一次点击就出声并出现声音开关，开关关掉后只显示字幕，同时只播一句；
  - 声音开关；
  - 第 4 幕的接听：只有接听才出声；
  - 档位：首屏前根据 `(hover:none)`、`prefers-reduced-motion`、`saveData` 和 WebGL 是否可用定初始档；运行中按帧时只降不升。每档决定 DPR 上限、色散采样次数（5、3、1）和焦散开关。
- 「减少动态效果」档：模型对任何进度都给出各幕的完成态，光谱定格成一帧，横滚改成竖排。「不支持 WebGL」档：模型照样给出画面描述，由 CSS/SVG 层画出静态的光。

### 前端：渲染层

- 不用 GSAP、ScrollTrigger、detect-gpu、three.js、物理引擎。新增依赖只有 `lenis` 和 `ogl`，只在落地页里加载。
- 原生滚动加 Lenis（`lerp≈0.1`，触屏不做平滑），不接管滚轮。钉住用 CSS `position: sticky`，横移由 Lenis 的进度经自写弹簧平滑后写入。
- 整页一张 OGL 全屏 canvas，在首屏内容画出来之后、浏览器空闲时动态加载。着色器分批预编译，滚到某幕时不能卡一下。不做全屏 bloom，光带交叠用 `max` 或 screen，不相加。
- 首屏的白光先用 CSS/SVG 画出来，标题是服务端渲染的 DOM 文字，从一开始就可见，不用透明度动画压住。LCP 元素必须是这段文字。
- 立绘复用应用现有的立绘组件（spine-ts 3.6），用独立的 canvas，只盖立绘区域，DPR 不超过 1.5，同一时间只挂一位；手机上离开她就释放 WebGL 上下文。层级是：立绘在其他人的名牌之上、在她自己的名牌之下。
- 招呼的音频在点击时才加载；加载失败就只显示字幕，不报错。
- 每道光都对应一个可聚焦、可点击的 DOM 元素，名字和招呼都是真文本；着色器只负责发光。
- 不放第三方统计和 cookie 横幅。

### 字体

- 日文（名字、招呼、幕名、拉丁字母）用 Shippori Mincho B1，中文大标题用 Noto Serif SC，中文正文用 Noto Sans SC。都是开源许可。
- 字体按落地页实际用到的字做静态子集，自托管 woff2，保留竖排字形（`vert`、`vpal`）和竖排标点。不用 next/font/google 加载 CJK 字体。
- 前端的 Docker 构建拿不到角色配置，所以子集由维护者用一个脚本在本地生成，和一份「子集包含哪些字」的清单一起提交进仓库。要覆盖的文字包括：落地页文案、登录组件的文案、所有角色名、组合名、招呼的原文和字幕。

### 文案与分享卡片

- 落地页的全部文案（各幕的标题和说明、幕名轨的日文幕名、诚实事项、行动按钮）放在现有的文案目录里，成为单独的一节；由 agent 起草，交用户审。限额不写具体数字，登录方式从后端的登录选项读取。
- 分享卡片：一张静态图，底图可以用生图，再用代码加工（裁切、调色、颗粒、排版），不出现角色形象和官方 logo。页面带上 Open Graph 和 Twitter 卡片的标题、描述、图片。

### 文档

- PRODUCT.md 的「现有页面」和「Operating Context」按新的路由更新（`/about`、`/conversations`、未登录时跳 `/`）。
- `docs/deploy.md` 加上招呼的合成命令和下线方法。

## Testing Decisions

好的测试只验证外部行为：接口返回了什么，模块在某个输入下给出了什么画面或状态。不验证内部怎么算出来的。着色器、DOM 结构、Lenis 的手感已经在原型里拍板，不写单元测试，交给验收脚本和人工验收。

1. **后端 `GET /api/characters`**（沿用已有接缝，先例是 `test_characters.py`）：
   - 按偶像编号排序，没有编号的排在后面；
   - 带 `idol_id`、`unit` 和组合顺序；
   - 招呼的 `ja` 去掉了语气提示；
   - 没有招呼或没配立绘素材地址时，对应字段为空；
   - `audio_url` 随文字或音色变化。
2. **后端招呼合成命令**（新接缝，照 `test_stand_upload.py` 的做法，用 `fakes.py` 风格的假语音合成和假存储桶）：
   - 只合成存储桶里还没有的；
   - 上传路径和后端算出的 `audio_url` 一致；
   - 旧版本被删掉；
   - 某一位失败时报告它、继续处理其他人，并以非零码退出；
   - 不写运行记录。
3. **前端落地页模型**（新接缝，vitest，先例是 `imageColor.test`、`standDirection.test`、`callTones.test`）：
   - 名单的排序和分段；新角色自动排进正确位置；
   - 颜色契约：官方色不变；光晕在黑底上的可见度有下限，深蓝也达标；文字色在官方色上的对比度达标，比照 `imageColor` 的对比度契约；
   - 各幕边界上的画面描述：第 1 幕是色相顺序，第 2 幕是组合顺序，归队过程连续；同屏满强度的数量有上限；
   - 聚焦与立绘出现的条件；
   - 「减少动态效果」档在任何进度下都给出完成态；
   - 交互 reducer：第一次点击出声并出现开关；关掉开关只显示字幕；同时只播一句；第 4 幕没接听就不出声；档位只降不升。
4. **字体子集覆盖契约**（新接缝，vitest）：读取角色配置、落地页文案和登录组件的文案，断言其中每个字都在提交进仓库的子集清单里。
5. **验收脚本**（沿用原型的测量脚本，Playwright，人工运行，不进 vitest），检查这几项：
   - 落地页自身的首屏 JS 压缩后不超过 50 KB，不含框架基线；
   - 手机 4G 节流下 LCP 不超过 2.5 秒，并且 LCP 元素是标题文字；
   - 「减少动态效果」档和「不支持 WebGL」档的截图；
   - `/` 的分流：不带会话时是落地页；带有效会话时重定向到 `/conversations`；带过期会话时是落地页；`/about` 带有效会话时显示「继续」。
6. 路由搬迁和 401 跳转目标的改动，跑现有的前端测试（`api.test.ts` 的 `redirectFor`）和后端登录测试（`test_sign_in.py` 的回调跳转），按新的目标更新断言。

## Out of Scope

- 应用根 layout 的 CJK 字体拖慢普通页面 LCP 的问题，另开在 `.scratch/root-layout-font-lcp/`。
- 落地页的日语版和英语版；日文只作为视觉元素出现。
- 为落地页另配衣装：用的是配置里的默认衣装。
- 在落地页上实时调用语音合成。
- 背景音乐、悬停音效。
- 第三方统计、埋点、cookie 横幅。
- 国内登录方式（QQ、bilibili 等）：落地页只是从后端读取现有的登录方式。
- 应用内页面（对话、设置、后台）的视觉改动，除了设置页的「关于 Eidolon-SC」链接和路由跟着改。

## Further Notes

- 原型分支 `prototype/landing-page` 永不合并。正式实现在 `feat/landing-page` 上从头写，但原型代码注释里的做法和理由是一手资料：光的几何和三个状态的插值、光晕亮度补偿、着色器的色散采样和交叠方式、OGL 的两个坑、分档、弹簧、立绘的层级和摆位、名牌为什么要重新测量、SSR 标题和首屏前定档的脚本。
- 招呼的台词和落地页的文案都要用户审核，审核是实现路径上的人工环节；没有审核完之前，落地页可以先用没有招呼的状态上线，因为没有招呼的角色只显示名字和光。
- 立绘和招呼都依赖立绘素材地址。本地开发没有存储桶时，`.env.example` 里写了用本地静态服务器代替的办法。
- 起服务看效果时，前端用 `next build` 加 `next start`，不用 dev。
- 调研里 20 个获奖站没有一个认真处理「减少动态效果」，也没有一个守住我们的预算。这两点是验收的硬标准，也是这个落地页要拉开差距的地方。
