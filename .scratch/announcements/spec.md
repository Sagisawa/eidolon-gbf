# 公告

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，特别是「公告」「未读公告」「后台」「管理者」「对话列表」「隐藏 / 置顶」。设计在 2026-10-12 的 grilling 中定下。已读状态只存在设备上，延续了隐藏、置顶的做法；其他决定改起来也不难，所以不另写 ADR。

## Problem Statement

部署者想告诉用户一些事：网站改了什么、什么时候维护停机、上了新角色。现在没有任何渠道。用户登录后直接进对话列表，不会再去看落地页、README 或 GitHub，部署者的话传不到他们那里。

## Solution

管理者在后台写**公告**并发布，用户在对话列表页首的铃铛里看。

- **后台**：侧栏多一项「公告」。
  - 列表页列出所有公告（草稿和已发布的）。
  - 编辑页只有一个正文，用 Markdown 写，可以切到「预览」看用户会看到的样子。
  - 写好先是草稿，可以发布。已发布的可以修改，修改不改变发布时间。可以撤回成草稿，再发布时发布时间改成那一刻。草稿和已发布的都能删除。
- **用户端**：对话列表页首的 GitHub 键和「…」之间多一个铃铛键。有未读公告时，铃铛右上角有一个小圆点。点开是一个弹窗：
  - 列出最近 20 条公告，最新的在上面。每条是发布日期、未读标记「新」和正文。
  - 底部两个键。「关闭」只收起弹窗，点还在。「已读」把当前所有公告标为读过，然后收起弹窗，点消失，直到下一条公告发布。
- **已读状态**只存在这台设备上，和隐藏、置顶一样：换设备不跟过去，同一台设备上的不同用户分开。一台设备上从没点过「已读」的，所有公告都算未读。

## User Stories

1. 作为管理者，我希望在后台写一条公告，这样我可以把网站的改动告诉所有用户。
2. 作为管理者，我希望公告只写正文、不用起标题，这样写一条短消息很快。
3. 作为管理者，我希望正文能用 Markdown 写加粗、斜体、链接、列表和行内代码，这样一条说明可以分条列出、附上链接。
4. 作为管理者，我希望写的时候能切到「预览」，看到和用户看到的完全一样的效果，这样发布前就能发现格式错误。
5. 作为管理者，我希望写好的公告先保存成草稿，这样我可以改好了再发。
6. 作为管理者，我希望能把草稿发布出去，发布后用户就能看到。
7. 作为管理者，我希望修改已发布公告里的错字时，用户不会因此再看到一次未读，这样小改动不打扰人。
8. 作为管理者，我希望能把发布了的公告撤回成草稿，这样发错的东西可以马上收回。
9. 作为管理者，我希望撤回、改过再发布的公告重新算作新公告，这样有实质改动时用户会再看一眼。
10. 作为管理者，我希望能删除公告，删除前要我确认，这样不会误删。
11. 作为管理者，我希望在后台列表里看到每条公告的正文开头、状态、发布时间和最后修改时间，这样没有标题也能认出是哪一条。
12. 作为管理者，我希望列表里最新的在上面。
13. 作为管理者，我希望后台的公告页面和其他后台页面一样，有侧栏一项和面包屑。
14. 作为管理者，我希望正文和其他输入一样有长度上限，超了会告诉我，这样不会写出一条没人读完的长文。
15. 作为管理者，我希望其他管理者也能写、改、发布、撤回和删除公告，大家权限一样。
16. 作为不是管理者的人，我希望访问公告的后台接口时得到的结果和访问其他后台接口一样，看不出有后台存在。
17. 作为用户，我希望在对话列表页首看到一个铃铛，这样我知道去哪里看公告。
18. 作为用户，我希望有我没读过的公告时铃铛上有一个点，这样我不用每次点开看。
19. 作为用户，我希望点开铃铛后看到最近的公告，最新的在上面，每条都写着哪天发布。
20. 作为用户，我希望没读过的公告带一个「新」的标记，这样我知道从哪里开始看。
21. 作为用户，我希望公告正文直接展开显示，不用一条条点开。
22. 作为用户，我希望公告里的链接在新标签页打开，这样不会打断我正在进行的通话。
23. 作为用户，我希望点「关闭」只是收起弹窗、点还在，这样我可以晚点再看。
24. 作为用户，我希望按 Esc 或点弹窗外面和点「关闭」一样。
25. 作为用户，我希望点「已读」后点消失，直到下一条公告发布前都不再出现。
26. 作为用户，我希望没有未读时「已读」键不可点，这样我不会以为它还有作用。
27. 作为用户，我希望页面开着时有新公告发布，切回这个标签页就能看到点，不用刷新。
28. 作为用户，我希望一条公告都没有时，点开铃铛看到「还没有公告」，而不是一个空白弹窗。
29. 作为用户，我希望在手机和电脑上都看到同样的弹窗。
30. 作为用户，我希望读屏软件能告诉我这个键是「公告」，有未读时告诉我「有未读」。
31. 作为用户，我希望在一台新设备上第一次登录时能看到所有公告都是未读的，这样我知道网站最近改了什么。
32. 作为和别人共用一台设备的用户，我希望我的已读状态和别人的分开。
33. 作为用户，我希望浏览器存不了数据（比如隐私模式）时，铃铛照样能用，只是已读状态在关掉页面后不保留。
34. 作为用户，我希望公告上不写是哪位管理者发的，这样公告就是这个网站在说话。
35. 作为访客，我看不到公告，也拿不到公告接口的内容；登录并同意条款之后才能看到。
36. 作为用户，我希望公告不会显示原始 HTML 或图片，这样公告里不会冒出奇怪的东西。
37. 作为用户，我希望铃铛的点和页首其他键的风格一致，不出现网站其他地方没有的颜色。

## Implementation Decisions

- **存储**：后端加一个新模块，管理一张公告表，字段有：
  - id、正文
  - 状态（草稿或已发布）
  - 发布时间：草稿为空；撤回时清空，再发布时写入当时
  - 创建时间、最后修改时间

  建表的写法和其他模块一样，用 `CREATE TABLE IF NOT EXISTS`。这张表不属于任何用户，要登记进数据库模块的 `NOT_USER_DATA`，并改写那段文档字符串。

- **后台接口**：放在 `/api/admin/announcements` 下，每个接口都用现有的 `Admin` 依赖，所以非管理者一律得到 404。具体是：
  - 列出全部公告：草稿和已发布的都要，排序是先按发布时间、再按创建时间，从新到旧。
  - 读一条。
  - 新建：新建出来的是草稿。
  - 改正文。
  - 发布：只对草稿有效。
  - 撤回：只对已发布的有效。
  - 删除。

  对已经处在目标状态的公告再做一次同样的操作，不报错，也不改动任何字段。具体用哪种 HTTP 动词，跟随现有后台接口的风格。

- **长度上限**：正文去掉首尾空白后不能为空，最多 5000 字。超出时回 422，信息要可读。

- **用户接口**：新增一个只读接口，返回最近 20 条已发布的公告，每条只有 id、正文和发布时间，从新到旧排。
  - 用现有的已登录、已同意条款的依赖：没登录 401，没同意条款 428，被封禁 403，和其他用户接口一致。
  - 不返回作者，也不返回草稿。

- **时间**：发布时间用后端的 `clock()` 取，前后端之间按现有接口的时间格式传递。

- **前端后台页面**：
  - `/admin/announcements` 是列表页，`/admin/announcements/[id]` 是编辑页（新写的也走这里）。
  - 侧栏在「用户」后面加一项「公告」，后台页面清单同步加上。
  - 面包屑的第三级由编辑页报上来，显示正文开头。
  - 列表用表格，列有：正文开头、状态（草稿用 outline Badge，已发布用 secondary Badge）、发布时间、最后修改时间。右上角一个「写公告」按钮。
  - 编辑页：
    - 正文用 `Textarea`，上面用 `Tabs` 切换「编辑」和「预览」。
    - 草稿的按钮是「保存草稿」和「发布」，已发布的是「保存」和「撤回」。
    - 「删除」走 `AlertDialog` 确认，确认框里真正执行的那一下用 `destructive`。
    - 按钮样式遵守 DESIGN.md 的后台规则：表单提交用 `default`，其他用 `outline` 或 `ghost`。

- **Markdown 渲染**：引入 `react-markdown`，做一个共用的正文组件，后台预览和用户弹窗都用它。规则如下：
  - 只允许这些元素：段落、换行、加粗、斜体、链接、有序和无序列表、行内代码。
  - 其他元素（标题、表格、图片、代码块、引用、分隔线）都不渲染成对应元素，退化成纯文本或直接去掉，以不丢字为准。
  - 不解析原始 HTML。
  - 链接一律 `target="_blank"` 加 `rel="noopener noreferrer"`。
  - 样式用 Tailwind 写在组件里，不引入 typography 插件。

- **前端纯模块**：在 `lib/` 里加一个公告模块，不依赖 React，负责以下几件事：
  - **已读时间点的存取**：localStorage 键名是 `eidolon.announcementsRead.<userId>`。读坏了就当作没有，存不进去就只留在内存里，写法照 `listPreferences`。
  - **判断未读**：给定公告列表和已读时间点，算出哪些未读、有没有未读。没有已读时间点时全部算未读。
  - **点「已读」后要存的值**：等于当前列表里最新那条的发布时间。用户打开弹窗之后才发布的公告不包含在内。
  - **后台列表的正文开头**：去掉 Markdown 记号，把空白合并成一个，截到大约 40 个字，超出的加省略号。

- **用户端组件**：
  - **铃铛键**：在对话列表页首，排在 GitHub 键和更多菜单之间。
    - 样式是 ghost `icon-lg`，图标用 Lucide `Bell`，从 theme 的图标出口导出。
    - 有未读时，右上角一个 6px 的 `bg-foreground` 圆点。
    - 读屏名字是「公告」，有未读时是「公告，有未读」。
  - **公告弹窗**：用 shadcn `Dialog`，两种屏宽都一样。
    - 标题是「公告」，不显示右上角的 ✕。
    - 列表可以滚动，最高大约占视口的 70%。
    - 每条先是一行发布日期，用 muted 小字，只写日期，按设备时区；未读的日期后面跟一个 secondary Badge「新」。下面是正文，条与条之间用 `Separator` 隔开。
    - 没有公告时用 `Empty`，写「还没有公告」。
    - 底部右对齐两个键：「关闭」用 ghost，「已读」用 default。没有未读时「已读」禁用。
    - 按 Esc 或点弹窗外面，等同于「关闭」。
  - **拉取时机**：对话列表加载时拉一次；页面从隐藏变回可见（`visibilitychange`）时再拉一次。拉取失败不报错，铃铛保持上一次的状态。

- **文案**：全部进 `i18n/zh.ts`，用户端的放在 `app` 或对话列表那一节，后台的放在 admin 那一节。

- **DESIGN.md**：
  - 「Conversation list」的页首写法加上铃铛和未读点。
  - 组件一节加上公告弹窗。
  - 后台一节加上公告列表页和编辑页。
  - 写明 Lucide `Bell` 走现有的图标规则。

## Testing Decisions

- 好的测试只看外部行为：发了什么请求，回来什么状态和内容；存进 localStorage 的值在下次读时是什么样。不测函数怎么拆、内部调用了谁。
- **后端只走 HTTP 这一个接缝**，用现有的 `make_client`，不直接测存储模块。覆盖：
  - 管理者能新建（出来是草稿）、改、发布、撤回、删除。列表里草稿和已发布的都有，按约定的顺序排。
  - 非管理者和未登录的人访问每个后台公告接口都得到 404。
  - 修改已发布的公告，发布时间不变。撤回后再发布，发布时间是再发布那一刻（用测试时钟）。
  - 空正文和超过 5000 字的正文得到 422。
  - 重复发布或重复撤回不报错，也不改字段。
  - 用户接口只返回已发布的，最多 20 条，从新到旧，不带作者。未登录 401，没同意条款 428。
  - 删除后，后台和用户接口都不再返回它。
  - 参照：`test_admin_users.py`、`test_live_config_limits.py`、`test_consent.py`。
- **前端只测 `lib/` 里的公告模块**，用 vitest，参照 `listPreferences.test.ts`、`localOwnKeys.test.ts`。覆盖：
  - 已读时间点按用户分开，存储坏了当作没有，写不进去时内存里仍然有。
  - 未读的判断：没有时间点时全部未读；有时间点时只有比它新的才算；空列表时没有未读。
  - 点「已读」后存的值是列表里最新那条的发布时间。
  - 正文开头：Markdown 记号去掉，空白合并，超过长度截断并加省略号，短的保持原样。
- 组件（铃铛、弹窗、后台页面、Markdown 渲染）不写测试，靠人工验证。仓库里本来就没有组件测试。

## Out of Scope

- 公告标题、作者署名、分类、置顶公告。
- 图片、标题、表格、代码块等 Markdown 写法，以及富文本编辑器。
- 定时发布、到期自动下架。
- 已读状态跨设备同步，或存到服务器上。
- 逐条标记已读。
- 推送、轮询，或站外的通知（邮件、浏览器通知）。
- 访客和落地页上的公告。
- 对话页首（窄屏的对话页）上的未读提示。
- 多语言公告。

## Further Notes

- 公告表登记在 `NOT_USER_DATA`，所以删除用户时不碰它；备份照常带上它。
- 别人用这个仓库部署时，没发过公告，铃铛也照样显示，点开是空状态。
- 已读时间点存的是发布时间，不是公告 id。所以删除某条公告，不会让已读状态出错。撤回再发布的那条，发布时间变新了，自然又算未读。
