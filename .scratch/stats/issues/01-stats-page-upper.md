# 01: 设置里的「统计」和上半部分

**What to build:** 用户在设置第一组的记忆后面看到「统计」，一级列表上写「已认识 N 天」。点进去是统计页的上半部分：
- 注册以来的天数；
- 当前和最长的连续来访；
- 一句话画像（常在哪个时段来）；
- 过去 52 周的热力图。

整页都没有数据时，只显示一句话和一个去对话列表的按钮。所有数都按制作人档案的时区算，删掉一段历史对话后不再算它。

这张票同时立起统计接口和前端的统计逻辑模块，后面几张票往里加。见 `../spec.md` Solution 第 1、2、4、5 条，Implementation Decisions「统计接口」「口径」「设置页」「图表」。

## Comments

- 2026-10-16 实现：后端 `eidolon/stats.py` 的 `add_stats_routes`，`GET /api/stats` 现在回 `days_known`、`visits {current, longest}`、`all_hours`（24 个数，全部时间）、`heatmap {from, counts}`（`from` 是 52 周前那周的周一，`counts` 到今天为止一天一个）。回合和送礼从 `Store.contacts(user_id)` 来（`Contact(character_id, kind: turn|gift, at)`，只联还在的对话）。注册天数含注册那天（当天注册是 1），至少 1。
- 画像并列的规则：两段并列两段都说（「常在上午和晚上来」），三段以上并列说「什么时段都会来」（`lib/stats` 的 `portrait`）。热力图深浅：没来 0，来过的按 `ceil(count / 最多那天 × 4)` 分 1–4。
- 一级摘要「已认识 N 天」由 `SettingsValues` 进设置时读一次 `/api/stats`；统计页自己每次打开再读一次。
- 审查后：上半部分的分布叫 `all_hours`，不叫 `hours`，留给 02 的跨度分布用别的名字；热力图格子直接带 `month`、`day`。
- 本地构建版 Playwright 验收（宽屏 1280、手机 390）全过：一级第一组是档案、记忆、统计，摘要「已认识 20 天」；有数据的页（Sallyn）、整页为空（新用户，按钮去 `/conversations`）、刷新 `/settings/stats` 留在原页；造两段对话后删掉历史那段，连续来访 2 → 1、24 小时分布 3 → 1、热力图 3 → 1，注册天数不变。
- 判断题，没改：进了设置以后在档案里改时区，摘要的天数要下次进设置才按新时区算（最多差一天）；来过但近两天没来时，三个数里照样显示「连续来访 0 天」。
