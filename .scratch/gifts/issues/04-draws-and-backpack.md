## Comments

- 随机来源是 `eidolon.randomness.Random`（给一个上限 n，返回 [0, n) 的整数），默认 `secrets.randbelow`，经 `build(random=…)` 传进来；测试用 `tests.fakes.FakeRandom(*numbers)`，每个数都要小于被要的上限，取空了断言失败。一次抽奖先取 `random(100)`，按 `affinity.DRAW_ODDS` 的累计区间（0 重置卡、1–69 普通、70–94 少见、95–99 稀有）定种类，是礼物再取 `random(这一档没下架的件数)`，按目录顺序选。
- 抽奖接口是 `POST /api/gifts/draws`，请求体 `{"all": bool}`，带 `X-Timezone`（抽之前先补发当天的次数）。返回 `{"drawn": [{"kind": "gift", "gift_id": …} | {"kind": "reset_card"}], "draws": 抽完剩几次}`。没开放 409 `{"detail", "gifts_closed": true}`（前端 `ApiError.giftsClosed`）；次数为 0 是 409，只有 `detail`。
- 背包表 `gift_backpacks`（`user_id`、`gift_id`、`count`，主键前两列，`USER_DATA`）。读状态的 `backpack` 按目录顺序，只列件数大于 0 的，下架的照常列。并发靠模块里那把锁加同一个事务。
- 前端：`components/gifts/DrawDialog.tsx`（抽奖弹窗）、`MyGifts.tsx`（筛选和网格），筛选是 `lib/gifts` 的 `shownGifts`。礼物盒跳用新 token `animate-hop`（`jump` 关键帧跑两遍，0.9 秒）；页面等接口和 0.9 秒都到了才揭晓，减少动态效果时不等。抽完先用接口给的次数更新抽奖台，再重读一次状态拿背包。弹窗底栏「收下」暂时是 default，票 05 加「送给谁…」时按规格改。
- 本地构建版 Playwright 验收（1280px、390px）：真抽一次（本地库抽到咖啡，次数减 1、进背包），用拦下的接口造出稀有（Badge 和闪光）、「再抽一次（还有 n 次）」接着抽到重置卡（Badge「很少见」和说明，没次数时不出再抽）、全部抽完 5 件依次淡入、没开放的 409 切成未开放页；减少动态效果时 143ms 揭晓；网格电脑 5 列、手机 3 列，×n 只在多于 1 件时出，读屏文本「蛋糕，3 件，普通」，筛饮品只剩饮品；手机不横向溢出。全部通过。
