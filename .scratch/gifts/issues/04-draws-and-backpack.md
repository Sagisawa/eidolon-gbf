# 04: 抽奖和背包

**What to build:** 点「抽一次」用掉 1 次，礼物盒跳一会儿后揭晓抽到的礼物或重置卡；「全部抽完」一次把攒下的抽光，结果排成小网格一件件出现。抽到的礼物按件数叠进背包，「我的礼物」变成按类别筛选的插画网格；重置卡另计张数。这张票里结果弹窗的「送给谁…」先不出，05 再接上。见规格「抽奖」「存储」的背包、「接口约定」的抽奖，以及「礼物页（前端）」的我的礼物和抽奖弹窗。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 加一张背包表：`user_id`、礼物 `id`、件数，主键是前两列；件数为 0 的行读的时候不显示。登记进 `USER_DATA`
- [ ] 随机来源和时钟一样，在应用组装时传进来，默认用系统的安全随机数。测试里换成按顺序给出指定值的假来源，取空了直接报错
- [ ] 每抽一次都在同一个事务里：确认次数大于 0 并减 1；从随机来源取一个 [0, 100) 的数，小于 1 是重置卡，小于 70 普通，小于 95 少见，其余稀有；是礼物时，在这一档没下架的礼物里再取一次随机数，平均选一件；礼物件数加 1，或重置卡张数加 1。不设保底，不按角色加权，背包没有上限
- [ ] 抽奖接口：分抽一次和全部抽完。「全部抽完」在同一个事务里把现有次数全部用掉，每一次都独立按上面的规则抽，结果按抽出的顺序返回；返回抽到的列表（礼物 `id` 或重置卡）和抽完后剩几次。次数为 0 时拒绝；没开放时返回 409，带一个能让前端认出「没开放」的原因（和冷却的 409 靠原因区分）。两个标签页同时抽，加起来也不会多抽
- [ ] 抽奖不调用任何模型，不写运行记录，不进看板
- [ ] 读礼物状态返回背包，只列持有的礼物；已经下架的礼物照常列出
- [ ] 抽奖弹窗：「抽一次」「全部抽完」都弹出居中的 `Dialog`。先是礼物盒图标跳约 0.9 秒（`prefers-reduced-motion` 时不跳），然后抽到的东西放大淡入
  - 单抽：大插画、名字、稀有度；稀有的用 Badge「稀有」，插画角上有一个闪光图标。下面是「再抽一次（还有 n 次）」（outline，没次数时不出）和「收下」
  - 抽到重置卡：Lucide 票券图标，名字「重置卡」，Badge「很少见」，一句「不是礼物，自己用：把所有低于信任的角色拉回信任，冷却中的马上可以说话。能攒，不过期。」
  - 全部抽完：结果排成 3 列小网格，一件件依次淡入
  - 收到「没开放」的 409 时，整页切成未开放的样子
- [ ] 我的礼物：标题右边是类别筛选（全部、吃的、饮品、花草、小物件，用 `ToggleGroup`），下面是插画网格（手机 3 列，更宽时 4、5 列）。每一格有插画方块（`bg-muted` 圆角，持有多于 1 件时右下角显示「×n」）、礼物名、稀有度。读屏能读出名字、件数和稀有度。网格里不透露哪位角色喜欢什么
- [ ] 筛选怎么算放进礼物纯模块
- [ ] `DESIGN.md` 的「礼物页」一节补上网格、筛选和抽奖弹窗；Icons 补上票券和四个类别图标的语义别名
- [ ] 走接口的测试（用假随机来源）：次数为 0 时被拒；随机值分别落在重置卡、普通、少见、稀有区间时，抽到的东西对；下架的礼物不会抽到；抽到重复的礼物时件数叠加；「全部抽完」用掉所有次数，结果条数等于原来的次数；没开放时抽奖返回 409 和「没开放」的原因，再打开后背包和次数都还在；删除用户后背包没了
- [ ] 礼物纯模块的 vitest：按类别筛选
- [ ] 本地构建版上用 Playwright 验收：单抽、抽到稀有、抽到重置卡、全部抽完的弹窗；开了减少动态效果时直接揭晓；390px 和电脑宽度下的网格、筛选和 ×n
