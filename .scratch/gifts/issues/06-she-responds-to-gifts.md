# 06: 她回应收到的礼物

**What to build:** 送了礼以后，她下一次回复时知道收到了什么、是不是她喜欢的，会先回应制作人说的话，再在合适的时候用自己的方式回应礼物，只回应一次。通话里也一样：从另一台设备送了礼，下一个通话回合她就用声音回应。送礼记录不进记忆。见规格「她下一次回复怎么知道」。

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] 拼提示词历史时，送礼事件写成一行旁白「（制作人送给你一份{礼物名}。）」；送出时是她喜欢的，就加半句「这是你喜欢的东西。」。放法沿用挂断事件：接在它后面那条用户消息的开头，后面还没有用户消息时接在这一回合用户说的话前面
- [ ] 回应一次：旁白还没被她回应过的那一回合（这条事件后面还没有她记下的回复），提示词里加一句指示，大意是「先回应制作人说的话，在合适的时候用你自己的方式回应收到的礼物，一次就够」。她回应过以后，旁白只作为历史留着，不再带指示。连送多件时这些旁白一起出现，指示只加一句。回合失败或被丢掉时不算回应过
- [ ] 滑出最近 N 个回合后她就看不到了，不另设过期，也不另加「最近收到的礼物」小节；她不提「礼物能让她消气」这类机制
- [ ] 通话每个回合都重新读历史，所以通话中送的礼下一个通话回合会被回应；通话层的状态行不提示这次变化
- [ ] 记忆提炼、找记忆、判断模型的输入里都没有送礼旁白（沿用挂断事件被去掉的那一处）
- [ ] 走接口的测试：下一回合的提示词里有礼物名；只有送的是她喜欢的才有「这是你喜欢的东西」；有回应一次的指示；她回复过以后再发一回合，旁白还在、指示没了；连送 3 件后下一回合 3 条旁白都在，指示只有一句；回合进行中送的礼，这一回合不带、下一回合才带指示；通话回合的提示词里同样有旁白和指示；记忆提炼和判断模型收到的输入里没有旁白
- [ ] 人工验收留给用户：她对礼物的回应自不自然，文字和通话各看一次
