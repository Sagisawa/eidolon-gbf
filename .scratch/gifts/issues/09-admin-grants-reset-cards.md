# 09: 后台发重置卡

**What to build:** 管理者在配置页「好感度和礼物」卡里，一键给所有现有用户各发一张重置卡，用来补偿判断模型误判的那段时间。发之前确认框写明人数、之后注册的拿不到、发出后不能收回；卡上记着上次发放的时间和实际张数。用户那边在礼物页的重置卡条上看到多了一张。这是后台第一个作用于所有用户的一次性操作。见规格「后台：发重置卡」和「接口约定」的后台。

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] 加一张重置卡发放记录表，每次发放一行：发放时刻、张数，不记谁发的、发给了谁。登记进 `NOT_USER_DATA` 并改写那段文档字符串；删除用户时不动它
- [ ] 后台读接口（用现有的管理者依赖，不是管理者一律 404）：现有用户数、上次发放的时刻和张数（从没发过时为空）、是否开放
- [ ] 后台发放接口：没开放时拒绝。在同一个事务里给每位现有用户的重置卡加 1，封禁的和管理者也算；还没有那一行的用户先建一行，次数按新用户的规矩。写一条发放记录，张数以执行那一刻的现有用户为准（可能和确认框里的 n 不同）。返回这次的张数和时刻。能再发，每次每人一张
- [ ] 不能单独给某一位用户发次数、礼物或重置卡；用户详情页里看不到背包、次数、重置卡；看板也不加礼物和抽奖
- [ ] 配置页「好感度和礼物」卡里，开关下面加一块「给所有现有用户各发一张重置卡」：一句说明，一行「上次发放：{时间}，共 {n} 张」或「还没有发过」，按钮「发放」（outline）；好感度关着时按钮不可用
- [ ] 点了弹 `AlertDialog`：标题「给所有现有用户各发一张重置卡？」，说明「现有的 {n} 位用户每人多一张，之后注册的用户拿不到。发出后不能收回。」，按钮「取消」「发出 {n} 张」
- [ ] 发完的提示写实际张数，再加一句「需要的话，去写一条公告告诉大家」，带公告页的链接；不自动配公告。用户那边不另加提醒，「礼物」入口上也不加小圆点
- [ ] `DESIGN.md` 后台一节的「配置」补上这一块
- [ ] 走接口的测试（照公告的测试写，后台和用户两头都测）：不是管理者时 404；每位现有用户都多一张，包括封禁的和管理者；之后注册的没有；读回的上次发放时刻和张数对；从没发过时为空；再发一次每人又多一张；没开放时被拒；删除用户后发放记录还在
- [ ] 本地构建版上用 Playwright 验收：配置卡上的发放块（「还没有发过」和发过以后两种）、确认框、发完的提示和公告链接、关掉开关时按钮不可用；用户那边礼物页的重置卡条多一张
