# 03: 抽奖次数和礼物页骨架

**What to build:** 导航栏和 dock 的第二项是「礼物」。礼物页最上面是抽奖台，显示「抽奖 还有 n 次」、7 个小点和一句说明。次数按制作人当地 0 点每天发 1 次，最多攒 7 次，读取时补发，关着的日子不补。抽奖按钮在这张票里还不能用（04 才接上）。背包是空的，「我的礼物」显示「还没有礼物」。好感度和礼物没开放时，整页显示「礼物暂时没有开放」。见规格「礼物模块」「存储」「抽奖次数的发放」「接口约定」的读礼物状态，以及「礼物页（前端）」的位置、抽奖台、我的礼物空状态、没开放时、纯函数。

## Comments

- 后端模块是 `eidolon.gifts.Gifts`（`Backend.gifts`）；票 01 的礼物目录改名为 `Backend.gift_catalog`。读状态接口是 `GET /api/gifts`，背包每项写成 `{gift_id, count}`（这张票里总是空的），角色每项是 `{id, tier, cooling, cooldown_until}`；没开放时 `characters` 是空的（好感度关着时什么都不显示），次数、背包、重置卡照样给。
- 表：`gift_balances`（`user_id`、`draws`、`given_on`、`reset_cards`，`USER_DATA`）和 `gifts_opened`（一行：上次看到时开没开、最近一次开放的时刻，`NOT_USER_DATA`）。
- 「开放时刻」的写入合成一条规则：`Gifts.notice()` 看现在开没开，上次看到是关、现在是开，就记下现在。它在后端组装时跑一次（所以启动时从没配判断模型变成配好、`.env` 里把开关从关改成开都算），并挂在 `LiveConfig.on_change` 上，后台每次保存或恢复一项配置后跑；每次读状态前也先跑一次，免得开关刚打开、还没通知到时读到的那一下把关着的日子补上。第一次部署、库里还没有这一行时，开着就当刚开放。
- 没开放时没有行的用户不建行，次数读成 0；开放后第一次读照新用户建一行、给 1 次。
- 「抽一次」「全部抽完」这张票里只占位，没有 onClick；「我的礼物」的空状态直接用 `Empty`，节标题用 `SectionHeading`（Header 字号）。
- 本地构建版 Playwright 验收（390px、1280px）：导航栏、dock 三项和当前项，抽奖台、读屏的次数，「还没有礼物」，后台关掉开关后的未开放页（导航里仍有礼物），通话中（呼叫中代替）切到礼物页时通话条在、没有结束卡，全部通过；验完开关恢复成 .env 的值。
