# 自带密钥只存在用户的浏览器里

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，相关决策见 ADR-0017（自带密钥只存在用户的浏览器里，服务器不保存），并修订了 ADR-0012。设计在 2026-10-10 的 grilling 中定下。

## Problem Statement

用户填的自带密钥目前加密后存进服务器的数据库，跟着账号走，也会进每天的备份。有些用户不愿意让服务器保存自己的 API key，哪怕是加密过的、界面上只显示末 4 位。他们不愿意填，也就用不上自带密钥带来的限额豁免。

## Solution

自带密钥只保存在用户自己的浏览器里，服务器不保存。每次文字回合和通话时，浏览器把这次要用的 key 随请求交给服务器，服务器只在内存里持有，用到这次回合或通话结束（包括之后的后台写记忆），不写入数据库、日志或备份。

- 填 key 时，服务器照旧先试调一次，但只校验、不保存；通过后由浏览器存起来。
- 换设备、换浏览器或清除浏览器数据，都要重新填。
- 主动登出或删除账号时，清掉这个浏览器里这个账号的 key。
- 限额豁免按这次请求实际带了哪些 key 来判断，规则本身不变。
- 管理者不再看得到用户填没填自带密钥，只看得到用量里有多少是自带密钥的。
- 服务器不再记下自带 LLM 的服务地址和模型名。
- 上线时删掉服务器上已存的 key，用户需要重填一次。
- 顺带做两项加固：一是服务器日志和报错不能带出 key；二是全站加一个务实版的 CSP，降低前端 XSS 读走 key 的风险。

## User Stories

1. 作为介意隐私的用户，我希望自带密钥只存在我自己的浏览器里，这样服务器被攻破或备份泄露时，我的 key 不会在里面。
2. 作为用户，我希望设置页明确告诉我 key 只存在这台设备的这个浏览器里、不会存到服务器，这样我知道换设备要重填。
3. 作为用户，我希望填 key 时系统先替我试调一次，不通就不存，并告诉我服务商说了什么，这样我不会存下一个用不了的 key。
4. 作为用户，我希望试调 LLM 时照旧检查它能流式输出、能调工具，这样我不会到聊天中途才发现模型不支持工具。
5. 作为公开部署上的用户，我希望服务器照旧只连公网上的 LLM 地址，每次连接都检查，这样别人没法借我的设置去探测服务器的内网。
6. 作为填阿里云百炼语音识别 key 的用户，我希望系统照旧自动判断我的 key 属于北京还是新加坡，判断一次就记在我的浏览器里，这样每次通话不用重新判断。
7. 作为用户，我希望设置页照旧显示我填的 LLM 的「模型 · 服务地址」和末 4 位、语音识别的服务商和末 4 位、语音合成的末 4 位，这样我认得出填的是哪一个。
8. 作为用户，我希望能在设置页删掉某一项自带密钥，删掉后这一项改回用部署者的服务。
9. 作为用户，我希望改了 key 以后，同一个浏览器里别的标签页下一次发请求就用上新的，不用刷新。
10. 作为用户，我希望文字对话时浏览器自动带上我的 LLM key，这样我照旧用自己的 LLM 聊天、提炼记忆。
11. 作为用户，我希望通话时浏览器自动带上我的三项 key，这样通话照旧用我自己的 LLM、语音识别和语音合成，没带的那几项用部署者的。
12. 作为用户，我希望文字对话用了自己的 LLM 就不计入每小时限额，通话三项都用自己的才不计入，跟以前一样。
13. 作为用户，我希望设置页和通话结束页照旧告诉我这次计不计入限额，而且这个判断依据的是我这个浏览器里存的 key。
14. 作为被管理者设成「只能用自带密钥」的用户，我希望只要带了对应的 key 就照常能用，没带时被拒并告诉我去设置页填。
15. 作为用户，我希望自带的 key 调用失败时，这一轮照旧失败并告诉我是哪一项出了问题，不悄悄改用部署者的 key。
16. 作为用户，我希望服务商的报错原文里即使出现了我的 key，显示给我的、记进服务器日志的也是被遮住的。
17. 作为在共用电脑上用的用户，我希望主动登出时浏览器里我的 key 被清掉，这样下一个人打开开发者工具也看不到。
18. 作为用户，我希望删除账号时浏览器里我的 key 也被清掉。
19. 作为在同一个浏览器里登过几个账号的用户，我希望每个账号的 key 分开存，一个账号看不到、也用不到另一个账号的 key。
20. 作为在所有设备上登出的用户，我希望确认时被告知其他设备上的 key 不会被清除，这样我知道要去那几台设备上自己清。
21. 作为用隐私模式或禁用了本地存储的浏览器的用户，我希望设置页直接告诉我这个浏览器无法保存自带密钥，而不是看起来存上了、刷新就没了。
22. 作为以前在服务器上存过 key 的用户，我希望上线后设置页提示我「以前填过的需要重新填一次」，这样我知道为什么 key 没了。
23. 作为用户，我希望隐私说明准确写明自带密钥只存在浏览器里、只在处理请求期间留在服务器内存里、不写入数据库、日志或备份。
24. 作为用户，我希望服务器的运行记录里不再有我自带 LLM 的服务地址和模型名，这样服务器也不会知道我用的是哪一家、哪个中转。
25. 作为用户，我希望以前运行记录里留下的我自带 LLM 的服务地址和模型名，在上线时一并清掉。
26. 作为落地页的访客，我希望看到「自带密钥只存在你的浏览器里」这样的说明，这样还没注册就知道这一点。
27. 作为管理者，我希望后台用户页照旧把用量拆成部署者的和自带的两部分，这样我知道一个用户是不是主要在用自己的 key。
28. 作为管理者，我希望后台不再显示每位用户填没填自带密钥，因为服务器已经不知道这件事，显示出来就是错的。
29. 作为管理者，我希望照旧能把某位用户的限额设成零、让他只能用自带密钥。
30. 作为管理者，我希望看板照旧按「服务 + 是不是自带」统计健康状况和用量。
31. 作为部署者，我希望不设 `EIDOLON_SECRET_KEY` 时用户也能自带密钥，因为它不再用来加密用户的 key。
32. 作为部署者，我希望部署文档、`.env.example`、`scripts/setup-oauth.sh` 和 README 不再说「自带密钥加密保存、需要 `EIDOLON_SECRET_KEY`」，同时说明 `EIDOLON_SECRET_KEY` 仍然用于后台保存的 key 和封禁名单。
33. 作为部署者，我希望升级时数据库迁移自动删掉旧的自带密钥表、清掉运行记录里自带 LLM 的服务地址和模型名，不用手动操作。
34. 作为部署者，我希望服务器日志里不会出现用户的 key，包括第三方语音库的调试日志，这样我看日志、转发日志时不会碰到用户的 key。
35. 作为部署者，我希望全站有 CSP，只允许加载本站的脚本、只允许向本站发请求，这样即使前端出现 XSS，脚本也很难把 key 发到别处。
36. 作为部署者，我希望 CSP 不影响落地页的静态渲染和首屏速度。
37. 作为部署者，我希望 CSP 不挡住通话（WebRTC、TURN）和其他正常请求。
38. 作为恢复备份的部署者，我希望知道上线前的备份里还留着加密的旧 key、最多 30 天后随备份过期消失，也知道恢复时不再需要用 `EIDOLON_SECRET_KEY` 解开用户的 key。
39. 作为还开着旧页面的用户，在上线那一刻发的回合可能因为没带 key 而被计入限额；刷新页面后一切照常。不为这种情况做兼容。

## Implementation Decisions

### 服务器不再保存自带密钥

- 去掉自带密钥的表，以及对它的读、写、删除，也不再把它算作「用户数据」的一部分。数据库迁移删掉这张表。
- 自带密钥模块不再加密、解密，也不再依赖 `EIDOLON_SECRET_KEY`。自带密钥始终可用：去掉「没设密钥就关掉」的开关、对应的 404 和 `available` 字段。`EIDOLON_SECRET_KEY` 仍然用于后台保存的部署者 key 和封禁名单的 HMAC，这两处不动。
- 「解不开已存的 key」这类失败整类消失：回合的 409 和通话预检的 409，以及这时记下的那条「没能接通」，都不再需要。
- 自带密钥模块的职责收窄为三件事：
  1. 校验一份 key：只试调，不保存。
  2. 根据这次请求带来的 key，给出回合或通话要用的服务和是否免计入限额。
  3. 对报错原文遮掉 key。
- 「用谁的 key」的规则不变：带了就用用户的，没带就用部署者的；用户的失败了就失败，不回退到部署者的。

### 这次请求带来的 key 的形状

服务器端用一个值对象表示「这次请求带来的自带密钥」，每项都可以没有：

- **llm**：`api_key`、`base_url`、`model`、`protocol`（`chat-completions` / `responses` / `anthropic`）。
- **tts**（Fish Audio）：`api_key`。
- **stt**：`api_key`、`provider`（`soniox` / `bailian`）、`region`（只有百炼有，`beijing` / `singapore`）。

接口层用 Pydantic 接收，字段约束跟现在保存接口的一样：key 是 8–500 个可打印 ASCII 字符，`base_url` 不超过 500 字符，`model` 不超过 200 字符。`api_key` 用 `SecretStr`，在 repr、traceback 和校验错误日志里都不露出来。

### 接口

- **校验（只试调，不保存）**：
  - `POST /api/account/keys/llm/check`，请求体为 llm 的字段。
  - `POST /api/account/keys/{tts|stt}/check`，请求体为 `api_key`，stt 还要带 `provider`。
  - 都要登录才能调。试调规则跟现在保存时的一样：公开部署要求 https 加公网地址；LLM 要能流式输出、能调工具，失败时不带工具再试一次，用来区分原因；Soniox 和 Fish 请求各自的只读接口；百炼两个地域都试一遍。
  - 通过时返回 200。百炼返回它判断出来的 `region`，浏览器连同 key 一起存下；LLM 返回规范化后的 `base_url` 和 `model`（去掉首尾空白）。
  - 不通过时返回 422，带上服务商原因，原因里的 key 已经遮掉。
- **原有的「列出 / 保存 / 删除自带密钥」接口去掉**。前端需要的 LLM 协议列表，留一个不带用户信息的只读接口提供，或者直接写进前端常量，实现时二选一。
- **文字回合**：`POST /api/conversations/{id}/turns` 的请求体在 `text` 之外多一个可选字段 `own_llm`。文字回合只用 LLM，不接收其他两项。
- **通话预检**：`GET /api/ice-servers` 多一个查询参数 `own`，列出这次要自带的服务名（如 `own=llm,tts,stt`），不带 key 本身。服务器据此做限额预检、算出 `callExempt`，不碰任何 key。
- **发起通话**：`POST /api/offer` 的 `requestData` 在 `conversation_id`、`muted`、`quality` 之外，多一个可选的 `own_keys`，里面可以有 llm、tts、stt 三项。准入和豁免以这里实际收到的 key 为准，预检时声明的服务名不算数。重新协商（带 `pc_id` 的 POST）和 ICE trickle（PATCH）不带 key，也不看 key。
- key 一律放在请求体里，不新增自定义请求头（Next 的代理只转发白名单里的请求头）。

### 内存里的生命周期

跟现在一样：

- 文字回合的 key 留在这一回合的 LLM 对象里，直到这一回合的后台写记忆结束。下一回合开始前最多等 5 秒，等上一回合的写记忆完成。
- 通话的 key 留到挂断，再加上最后一轮的写记忆。

不新建任何存放 key 的缓存，也不跨请求复用。

### 限额豁免

- 规则不变：文字回合带了 llm 就免计入；通话 llm、tts、stt 三项都带了才免计入。限额为零（只能用自带密钥）的用户，没带够对应的 key 时被拒，提示去设置页填。
- 设置页和通话结束页的「计入 / 不计入」改由前端根据本地存的 key 算出来，沿用现有的豁免判断函数，只是输入换成本地存了哪几项。通话结束页照旧以服务器在 `ice-servers` 预检时返回的 `callExempt` 为准。

### 运行记录与后台

- 运行记录里，自带 LLM 的服务调用不再记服务地址的主机名和模型名，改记一个固定的通用值。数据库迁移把已有的、属于自带 LLM 的调用记录的这两列也改成这个通用值。
- 价格匹配、看板健康统计和用量拆分本来就不依赖这两列，行为不变；要确认改完以后价格那边不会把这个通用值当成「未设单价的模型」列出来。
- 后台用户页的接口不再返回每项服务「填没填」的布尔值。用户列表的徽章和详情页的相应展示都去掉。「部署者 / 自带」的用量拆分和「只能用自带密钥」的限额选项保留。

### 日志和报错不带出 key

- 启动时把 Pipecat 用的 loguru 降到 INFO 级以上，不再输出 DEBUG。这样也不再把用户的话打进日志。
- 自带密钥失败的报错（回合中、通话中、校验时）在生成给用户看的原因时，把原文里出现的这把 key 替换成 `***`，再截断到原来的长度上限。写记忆失败时打的 warning 用的是同一条已遮掉的消息。
- 请求体里的 key 用 `SecretStr`，所以 FastAPI 的校验失败日志和 traceback 里不会出现明文。422 的响应体会回显用户提交的值，但只回到用户自己的浏览器，可以接受。

### 前端：本地存的自带密钥

- 新建一个前端模块，管理浏览器里存的自带密钥。照现有 localStorage 模块的写法：用 try/catch 包住，不可用时不抛错。它负责：
  - 按用户 ID 读、写、删某一项，清空某个用户的全部 key；
  - 报告这个浏览器能不能存；
  - 组装文字回合要带的 `own_llm`、通话预检要带的服务名列表、发起通话要带的 `own_keys`；
  - 给出本地存了哪几项，供豁免判断用。
- 存储位置是 `localStorage`，键为 `eidolon.ownKeys.<userId>`，值是明文 JSON，每项含完整 key 和展示需要的字段（末 4 位由前端从 key 算出）。每次发请求都现读，所以别的标签页的修改下一次请求就生效。
- 设置页的自带密钥一节：
  - 填写时先调校验接口，通过后写进本地。删除只删本地。
  - 显示的内容跟以前一样：LLM 显示「模型 · 服务地址」和末 4 位，语音识别显示服务商和末 4 位，语音合成显示末 4 位。
  - 开头的说明加上：只保存在这台设备的这个浏览器里、不存服务器；换设备、换浏览器或清除浏览器数据要重填；每次聊天或通话时随请求发给服务器、只在处理期间使用；以前填过的需要重新填一次。
  - 浏览器存不了时，显示「这个浏览器无法保存自带密钥」，表单禁用。不退而存在内存里。
- 发文字回合时带上 `own_llm`；打通话时，在 `ice-servers` 带上服务名，在 `offer` 的 `requestData` 带上 `own_keys`。
- 主动登出（单设备登出，以及同意页上拒绝后的登出）和删除账号成功后，清掉当前用户在本地的 key。「在所有设备上登出」也清当前浏览器的，并在确认里说明其他设备上的自带密钥不会被清除。

### CSP

在 Next 的全局响应头里给全站加 CSP，并保持页面静态渲染：

```
script-src 'self' 'unsafe-inline'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

视需要补上 `default-src`、`img-src`、`media-src`、`font-src`、`worker-src`，具体以实际用到的来源为准（立绘可能来自对象存储，Spine 和音频可能用到 blob 或 data URL）。要逐项确认没有挡住正常功能。严格的 nonce 版不做，原因见 ADR-0017。

### 文案和文档

- **隐私说明**：
  - 「我们保存哪些数据」里的自带密钥那条，改成「只保存在你的浏览器里，我们不保存；每次回合或通话时随请求发给服务器，只在处理期间留在内存里，不写入数据库、日志或备份」。
  - 运行记录那条保留「是否用了自带密钥」，加上「不记密钥，也不记自带 LLM 的服务地址和模型名」。
  - 管理者能看到的内容，从「每项服务有没有填自带密钥」改成「你的用量里有多少用的是自带密钥」。
  - 删除数据那条去掉自带密钥，改成「浏览器里的自带密钥会在登出或删除账号时一并清除」。
  - 「内容会发到你自己选择的服务商」那条 note 不动。
- **落地页**第 6 幕的自带密钥那句，补上「只存在你的浏览器里」。
- **设置页**的说明、删除数据的说明、后台删除用户的说明里，凡是暗示服务器保存了自带密钥的说法都改掉。
- **README**（中、英、日三版）、`docs/deploy.md`、`.env.example`、`scripts/setup-oauth.sh`：去掉「加密保存」「自带密钥需要 `EIDOLON_SECRET_KEY`」的说法，说明这个变量仍用于后台保存的 key 和封禁名单。`docs/deploy.md` 里关于恢复备份的说明，按 ADR-0012 的修订来改。
- GLOSSARY 和 ADR 已在本分支更新，不在票里。

## Testing Decisions

好的测试只看对外的行为：用户发一个回合或打一通电话，它用的是谁的服务、计不计入限额、失败时说了什么、日志和数据库里留下了什么。不断言内部函数怎么调用、对象怎么组装。下面四层都沿用现有的接缝，不新开测试层：

1. **后端 HTTP 接口**，沿用 `test_own_llm`、`test_own_speech_keys`、`test_delete_account` 的写法，测试客户端加 fakes。
   - 回合请求体带 `own_llm` 时用的是用户的 LLM，写记忆也是；不带时用部署者的。

## Out of Scope

- 「跟账号同步」或任何服务器端保存自带密钥的选项。
- 在浏览器里加密存储 key（IndexedDB 加 WebCrypto）。
- 严格的 nonce 版 CSP，以及因此要做的全站动态渲染。
- 上线时把旧 key 一次性发回浏览器的迁移接口。
- 兼容上线时还开着的旧前端页面。
- 改动或提前清理上线前的旧备份。
- 校验接口的专门限流（保存接口现在也没有）。
- 记住哪些用户以前填过 key、只对他们显示「请重填」。
- 部署级别的「关闭自带密钥」开关。

## Further Notes

- 「请求一定会经过服务器」是这项设计的前提（ADR-0003、ADR-0017）：服务器从此不保存 key，但处理请求期间仍然碰得到 key。所有文案都不能写成「服务器碰不到你的 key」。
- 百炼地域判断的结果原来跟 key 一起存在服务器上，现在由校验接口返回、浏览器存下，通话时随 key 带上。如果地域不对（比如 key 被换了地域），通话会以自带密钥失败告终，用户重新校验一次就会更新。
- 前后端一起部署（`git push vps`）。部署后要重启服务，并按人工验证清单实际打一通电话。
