# 06: 收尾：服务器不再保存自带密钥

**What to build:** 02、03 已经让回合和通话只用浏览器带来的 key，这张票删掉服务器上存储自带密钥的那一整套。上线时数据库迁移删掉已存的自带密钥，用户在设置页看到「以前填过的需要重新填一次」。不设 `EIDOLON_SECRET_KEY` 的部署也能用自带密钥。后台不再显示用户填没填自带密钥，因为服务器已经不知道这件事了。

**Blocked by:** 02, 03

**Status:** ready-for-agent

- [ ] 数据库迁移删掉自带密钥的表，它也不再算作用户数据的一部分；删除账号的流程和测试不再涉及它。
- [ ] 去掉列出、保存、删除自带密钥的接口，以及 01 里留下的「从数据库读 key、解密」那一步。「解不开已存的 key」相关的回合 409、通话预检 409 和那条「没能接通」记录都去掉。
- [ ] 自带密钥不再依赖 `EIDOLON_SECRET_KEY`：去掉「没设就关掉」的开关、对应的 404 和 `available` 字段。后台保存的部署者 key 和封禁名单照旧使用这个变量，行为不变。
- [ ] 设置页需要的 LLM 协议列表，改由一个不带用户信息的接口提供，或者直接写进前端常量，二选一即可。
- [ ] 后台用户页的接口不再返回每项服务「填没填」自带密钥。用户列表的徽章和详情页的相应展示都去掉。用量里「部署者 / 自带」的拆分，以及「只能用自带密钥」的限额选项保留。
- [ ] 设置页的自带密钥一节开头写明：只保存在这台设备的这个浏览器里、不存服务器；换设备、换浏览器或清除浏览器数据要重填；每次聊天或通话时随请求发给服务器、只在处理期间使用；以前填过的需要重新填一次。删除数据的说明、后台删除用户的说明里，暗示服务器保存了自带密钥的说法都改掉。
- [ ] 测试：迁移以后表不存在；不设 `EIDOLON_SECRET_KEY` 时也能带 key 发回合；后台用户页接口里没有「填没填」字段。原来测试加密、解不开、没设密钥就关掉的用例删掉。
