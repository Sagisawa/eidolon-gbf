# 06: 收尾：服务器不再保存自带密钥

**What to build:** 02、03 已经让回合和通话只用浏览器带来的 key，这张票删掉服务器上存储自带密钥的那一整套。上线时数据库迁移删掉已存的自带密钥，用户在设置页看到「以前填过的需要重新填一次」。不设 `EIDOLON_SECRET_KEY` 的部署也能用自带密钥。后台不再显示用户填没填自带密钥，因为服务器已经不知道这件事了。

**Blocked by:** 02, 03

**Status:** done

- [x] 数据库迁移删掉自带密钥的表，它也不再算作用户数据的一部分；删除账号的流程和测试不再涉及它。
- [x] 去掉列出、保存、删除自带密钥的接口，以及 01 里留下的「从数据库读 key、解密」那一步。「解不开已存的 key」相关的回合 409、通话预检 409 和那条「没能接通」记录都去掉。
- [x] 自带密钥不再依赖 `EIDOLON_SECRET_KEY`：去掉「没设就关掉」的开关、对应的 404 和 `available` 字段。后台保存的部署者 key 和封禁名单照旧使用这个变量，行为不变。
- [x] 设置页需要的 LLM 协议列表，改由一个不带用户信息的接口提供，或者直接写进前端常量，二选一即可。
- [x] 后台用户页的接口不再返回每项服务「填没填」自带密钥。用户列表的徽章和详情页的相应展示都去掉。用量里「部署者 / 自带」的拆分，以及「只能用自带密钥」的限额选项保留。
- [x] 设置页的自带密钥一节开头写明：只保存在这台设备的这个浏览器里、不存服务器；换设备、换浏览器或清除浏览器数据要重填；每次聊天或通话时随请求发给服务器、只在处理期间使用；以前填过的需要重新填一次。删除数据的说明、后台删除用户的说明里，暗示服务器保存了自带密钥的说法都改掉。
- [x] 测试：迁移以后表不存在；不设 `EIDOLON_SECRET_KEY` 时也能带 key 发回合；后台用户页接口里没有「填没填」字段。原来测试加密、解不开、没设密钥就关掉的用例删掉。

## Comments

### 实现（2026-10-10）

- 后端：`Store` 启动时 `DROP TABLE IF EXISTS own_keys`（库开着 `secure_delete`，删掉的页会被覆写），建表语句、`OwnKeyRecord` 和读、写、删除方法都删了；`database.USER_DATA` 不再有这张表。`OwnKeys` 不再接 `store` 和 `secret_key`，去掉 `available`、`describe`、`save_llm`、`save_speech`、`exemptions`、`delete`、`OwnKeysUnavailable` 和加密；只剩三件事：校验、按这次带来的 key 决定用谁的服务和免不免计入、遮 key（07）。
- 接口：`GET /api/account/keys`、`PUT /api/account/keys/{llm,tts,stt}`、`DELETE /api/account/keys/{service}` 删了。三个校验接口原来各自把 `OwnKeyRejected` 转成 422，现在合成一个异常处理（03 评审时留着的那条）。
- `EIDOLON_SECRET_KEY` 只剩后台保存的 key 和封禁名单在用；`Settings.secret_key` 的说明、后台配置页里这项的只读理由都改了。
- 后台用户接口不再返回 `own_keys`；列表的「自带密钥：…」徽章、详情页的「自带密钥」一项和对应的文案、`broughtKeys` 都删了。用量的部署者 / 自带拆分、「只能用自带密钥」的限额照旧。
- 设置页：协议列表改成前端常量 `LLM_PROTOCOLS`（`api.ts`，类型 `LLMProtocol` 由它推出），不再向服务器要；整节不再等服务器说「开放了没有」。开头说明加上只存在这个浏览器、不存服务器、换设备或清数据要重填、以前填过的要重填一次、随请求发送只在处理期间使用。删除数据的说明改成「这个浏览器里的自带密钥也一并清除」，后台删除用户的说明去掉自带密钥。隐私说明、落地页、README 和部署文档归 09。
- 测试：`test_own_llm.py` 加迁移删表、不设 `EIDOLON_SECRET_KEY` 也能校验和带 key 发回合；删掉加密保存、库里存的不再用于回合和通话、没设密钥就关掉的用例；`test_own_keys.py` 删掉存库和「没设密钥不豁免」的用例；`test_admin_users.py` 断言接口里没有 `own_keys`；`test_delete_account.py` 不再存 key。

### 人工验证

用构建版前端（`next build` + `next start`）和本地后端，先用旧版本的库（`own_keys` 表里有行的）启动：

1. 启动以后用 `sqlite3` 看库：`own_keys` 表不存在了。
2. 设置页「自带密钥」一节照常显示，开头说明里有「只保存在这台设备的这个浏览器里……以前填过的也需要重新填一次……只在处理期间使用」；「接口类型」下拉框有三项，填一个 LLM 能试调通过、存进本地。
3. `.env` 里去掉 `EIDOLON_SECRET_KEY` 重启：设置页「自带密钥」一节照样在，填 LLM 能通过，发一个回合用的是你的 LLM（后台看板「用自带密钥的回合」加一）。恢复这个变量再继续。
4. 后台用户列表：状态一格只有「正常 / 已封禁」和单独限额，没有「自带密钥：…」徽章；点进用户详情：没有「自带密钥」一项，「近期用量」里照旧拆成部署者和自带密钥；「单独限额」照旧能选「只能用自带密钥」。
5. 设置页「删除我的全部数据」和后台「删除这位用户」的说明里不再把自带密钥列在服务器要删的数据里。

### 人工验证通过（2026-10-10）

用户用构建版前端加本地后端按清单验证，没有问题。
