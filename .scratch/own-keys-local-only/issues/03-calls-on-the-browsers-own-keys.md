# 03: 通话用浏览器里存的三项 key

**What to build:** 语音合成和语音识别的自带密钥也改成先校验、再存进浏览器本地。用户打电话时，浏览器在通话预检里声明这次要自带哪几项（只带服务名、不带 key），在发起通话时带上实际的 key，通话就用用户自己的 LLM、语音识别和语音合成，没带的几项用部署者的。三项都带时不计入限额。设计见 spec 的「接口」「限额豁免」两节和「Further Notes」里关于百炼地域的说明。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 语音合成和语音识别各有一个只校验、不保存的接口，要登录才能调。试调规则跟原来的一样：Soniox 和 Fish 请求各自的只读接口，百炼两个地域都试一遍。百炼通过时返回判断出来的 `region`。不通过时返回 422 并带上原因。调用后数据库里不留任何记录。
- [ ] 通话预检接受 `own` 查询参数，列出这次要自带的服务名。服务器据此做限额预检、返回 `callExempt`，不碰任何 key，也不再读数据库里的 key。
- [ ] 发起通话的 `requestData` 接受可选的 `own_keys`，里面可以有 llm、tts、stt 三项（stt 带服务商和地域），`api_key` 用 `SecretStr`。准入、豁免和用谁的服务都以这里实际收到的为准，跟预检声明的不一致时以这里为准。重新协商和 ICE trickle 不带 key。
- [ ] key 一直持有到挂断、最后一轮写记忆结束。通话中自带的 key 失败时，通话照旧结束，并说明是哪一项出了问题。
- [ ] 本地存储模块支持三项，能组装预检用的服务名列表和发起通话用的 `own_keys`。
- [ ] 设置页的语音合成和语音识别两节：先校验、通过后写进本地（百炼连同 `region` 一起存），照旧显示服务商和末 4 位；删除只删本地。
- [ ] 设置页的豁免提示和通话结束页的「计入 / 不计入」全部改由前端根据本地存的 key 算，沿用现有的豁免判断函数和它的测试。
- [ ] 测试：HTTP 层测「三项全带不计入、只带一部分照常计入、部署者没有的那项用户带了也能打、预检声明和实际带的不一致时以实际为准、百炼校验返回地域并在通话时用上」；前端测请求的组装。
