# 07: 服务器的日志和报错不带出 key

**What to build:** 现在 key 会出现在请求体和服务器内存里，部署者看日志、转发日志时，不应该看到用户的 key；用户看到的报错里，即使服务商回显了 key，也要被遮住。设计见 spec 的「日志和报错不带出 key」一节。

**Blocked by:** 02, 03

**Status:** ready-for-agent

- [ ] 服务启动时把 Pipecat 用的 loguru 降到 INFO 级以上，不再输出 DEBUG（这样也不再把用户的话打进日志）。
- [ ] 回合中、通话中、校验时这三种自带密钥失败，在生成给用户看的原因时，把原文里出现的这把 key 替换成 `***`，再按原来的上限截断。写记忆失败时打的 warning 用的是同一条已遮掉的消息。
- [ ] 请求体里的 key 一律用 `SecretStr`，repr、traceback 和校验失败日志里都不出现明文。
- [ ] 泄露测试：用一把特征明显的假 key，分别跑一个成功的回合、一个服务商报错里回显了这把 key 的失败回合、一次写记忆失败、一次 key 格式不合法的请求，再加一次服务商报错回显 key 的校验。抓取 Python logging 和 loguru 的输出，断言都找不到这把 key；同时断言返回给用户的原因里，key 被替换成了 `***`。
