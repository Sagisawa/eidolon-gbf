# 02: 文字回合用浏览器里存的 LLM key

**What to build:** 用户在设置页填自己的 LLM 时，服务器先试调一次，但只校验、不保存；通过以后由浏览器按当前用户存进本地。之后每发一个文字回合，浏览器都在请求体里带上这把 key，这一回合（包括之后的后台写记忆）就用用户自己的 LLM，而且不计入限额。这是贯穿前后端的第一条路径，设计见 spec 的「接口」「前端：本地存的自带密钥」「限额豁免」几节。

过渡期说明：这一票合进来后、03 合进来前，通话里的 LLM 仍用服务器上存的那份，或者部署者的。分支要等全部做完才部署，这个中间状态可以接受。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 有一个只校验、不保存的 LLM 接口，要登录才能调。试调规则跟原来保存时的一样：公开部署要求 https 加公网地址，要能流式输出、能调工具，失败时不带工具再试一次以区分原因。通过时返回规范化后的 `base_url` 和 `model`，不通过时返回 422 并带上服务商的原因。调用后数据库里不留任何记录。
- [ ] 文字回合的请求体接受可选的 `own_llm`（`api_key`、`base_url`、`model`、`protocol`），字段约束跟原来的保存接口一样，`api_key` 用 `SecretStr`。带了就用它扮演角色、写这一回合的记忆；没带就用部署者的。不再从数据库读用户的 LLM。
- [ ] 文字回合带了 `own_llm` 就不计入限额。限额为零的用户没带时被拒，提示去设置页填。自带的 LLM 失败时，回合照旧失败，不回退到部署者的。
- [ ] 公开部署每次连接都检查公网地址，相关的现有测试照旧通过。
- [ ] 前端有一个本地存储模块，按用户 ID 分开存，键为 `eidolon.ownKeys.<userId>`，值是明文 JSON。它能读、写、删某一项，清空某个用户，组装文字回合要带的 `own_llm`，并且每次发请求都现读。这一票只需要用到 LLM 这一项，但存储格式要能放下三项。
- [ ] 设置页的 LLM 一节：填写时先校验、通过后写进本地；照旧显示「模型 · 服务地址」和末 4 位（末 4 位由前端算）；删除只删本地。
- [ ] `sendTurn` 在请求体里带上本地存的 `own_llm`。
- [ ] 设置页的豁免提示里，「文字对话计不计入」按本地有没有 LLM 来判断。
- [ ] 测试：HTTP 层测「带了用用户的、没带用部署者的、校验只试不存、限额为零没带被拒」；前端测本地存储模块（stub `localStorage`）和 `sendTurn` 的请求体。
