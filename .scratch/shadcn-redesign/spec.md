# 前端换成 shadcn/ui，改成 LINE 风格

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，尤其是「印象色」「对话」「通话」「通话层」「立绘」「只看文字」。换库的取舍见 ADR-0015。**视觉规范以根目录 `DESIGN.md`（「制作人的手机」）为准**，本规格只引用、不重复；`DESIGN.md` 与本规格冲突时以 `DESIGN.md` 为准，并回头修正本规格。组件写法的规则以 `frontend/AGENTS.md` 的「shadcn 纪律（新代码）」一节为准（底座波写入，内容见下文「组件纪律」）。

决定的出处是地图 `map.md` 和 `issues/01`–`10`，每条决定后面的括号注明来源 ticket。

## Problem Statement

前端现在用 Astryx 加一套自定义的「手帐」主题。制作人（用户）打开对话列表、和她聊天、打电话时，看到的是复印纸、横线、墨水这些很重的隐喻，组件本身的质感也不好；Astryx 的组件形态改不动，只重写主题解决不了问题。后台也是同一套手帐样式，数字、表格、表单挤在一起，不像一个管理工具。

对开发者来说，Astryx 要求不写裸 `<div>`、一律走它的布局原语和 token，300 多处 `Text`/`VStack`/`HStack` 让改样式很费劲；主题要先 `theme:build` 生成产物，CI 还要检查产物有没有过期。

## Solution

把前端的组件库从 Astryx 整体换成 shadcn/ui（底层 Base UI，样式 `base-nova`）加 Tailwind v4，视觉改成克制的 LINE 风格：中性灰白的外框，属于她的地方（对话壁纸、发送键、未读数、通话层、通话条）用她的印象色，制作人的话用事务所深蓝墨水。用户侧、后台、法务所有页面都换，最后彻底移除 `@astryxdesign/*`。

信息架构和交互流程不变：仍然是对话列表 + 对话的 IM、全屏的通话层、可以收起；领域逻辑（`lib/` 下的模块和测试）不动。浅色、深色模式都保留，跟随系统。

全部工作在 `feat/shadcn-redesign` 上分五波完成，分支内两套库短期并存；换完、Astryx 删干净后，用一个 PR 合进 main。在此之前线上一直是旧样式。

## User Stories

### 对话列表与对话

1. 作为制作人，我想打开应用先看到一张中性灰白、密而干净的「对话」列表，这样我能一眼扫到每位偶像最近说了什么。
2. 作为制作人，我想在列表的每一行看到她的 56px 头像、名字、时间和最后一句，这样不用点进去就知道对话到了哪里。
3. 作为制作人，我想看到用她颜色做底的未读数，这样我知道谁有新消息，而且黄色、浅粉这类印象色上的数字也读得清。
4. 作为制作人，我想在列表顶部用搜索框找到某位偶像，这样角色多了也不用一直往下翻。
5. 作为制作人，我想让当前选中的那一行铺一层中性的灰底，这样选中状态清楚，又不会把列表染成她的颜色。
6. 作为制作人，我想在通话中的那一行看到「通话中 mm:ss」或「正在呼叫…」，这样回到列表也知道电话还没挂。
7. 作为电脑上的制作人，我想拖动列表右边的线把列表调宽或调窄（240–480px），而且刷新后还是我调好的宽度，这样能按屏幕大小安排两栏。
8. 作为电脑上的制作人，我想在没选任何偶像时看到右栏居中的一句提示，而不是一片空白。
9. 作为手机上的制作人，我想一次只看列表或对话，对话页首有返回键，这样小屏上不挤。
10. 作为制作人，我想在她的对话里看到她色相的一层极淡的壁纸，这样一进来就知道这是她的地方。
11. 作为制作人，我想看到她的气泡在左、白底，日语原文在上、中文字幕小一号在下，这样既能听她的原话又看得懂。
12. 作为制作人，我想让自己的话用事务所深蓝墨水的气泡排在右边，这样一眼分清谁说的。
13. 作为制作人，我想让她连着发的几条成一组，头像和名字只在第一条出现、时间只在最后一条出现，这样对话不显得啰嗦。
14. 作为制作人，我想看到 22px 圆角、没有尾巴的气泡，这样界面圆润而不幼稚。
15. 作为制作人，我想在跨天的地方看到居中的日期条，这样知道这段话是哪天说的。
16. 作为制作人，我想要一个实底的输入栏，输入框圆润、最多长到几行，发送键是她颜色的圆形按钮，这样打字舒服、发送键好找。
17. 作为制作人，我想在对话页首点用她颜色画的电话键直接打电话。
18. 作为制作人，我想在页首的更多菜单里开始新对话、换衣装等，菜单弹出来也带着她的颜色和清楚的边线（深色模式下也一样）。
19. 作为制作人，我想在通话中离开这段对话之前看到确认框「会挂断和她的通话」，这样不会误挂。
20. 作为在深色环境里用手机的制作人，我想让整套界面跟随系统切成深色，并且壁纸、气泡、时间戳在深色下都清楚。

### 通话层与通话条

21. 作为制作人，我想打电话时整屏变成她：放大模糊的头像做底，压一层她颜色的渐变，这样通话有沉浸感。
22. 作为制作人，我想在呼叫中看到「正在呼叫」和依次闪的三个点，没有立绘时头像外有波纹，这样知道还没接通。
23. 作为制作人，我想在呼叫中只能按挂断、静音和切换麦克风是灰的，这样不会对还没接通的电话做无效操作。
24. 作为制作人，我想在通话中看到她的名字和计时，以及底部毛玻璃卡片里她当前这句的日语原文和字幕。
25. 作为制作人，我想要一条毛玻璃底栏：静音、切换麦克风是圆形图标键，挂断是写着「挂断」的红色胶囊，这样手指一下能按到。
26. 作为制作人，我想按下静音后按钮变成白底黑图标，这样知道麦克风关了。
27. 作为制作人，我想在通话中点「切换麦克风」，从底部面板（或抽屉）里选另一个麦克风，当前的一项写着「正在使用」。
28. 作为制作人，我想打开「只看文字」后胶囊变成白底，上一句台词淡淡地留在当前这句上面，这样不听声音也跟得上。
29. 作为制作人，我想在呼叫中也能切换「只看文字」，和现在的行为一样。
30. 作为制作人，当她有立绘时，我想看到立绘铺在底上、台词卡和底栏压在衣服上也看得清；手机上立绘从下方升起、取景到膝，电脑上原地淡入、取景到腰。
31. 作为制作人，当立绘加载失败或浏览器不支持 WebGL 时，我想让通话照常进行、布局不跳，也不弹提示打扰我。
32. 作为制作人，我想在通话结束后看到同样毛玻璃的结束卡：原因、说明、是否计入限额，以及「回到对话」和重拨（或「去设置自带密钥」）两个按钮。
33. 作为制作人，我想把通话层收起回到对话的文字记录，对话页首下面出现一条她颜色的通话条，写着「通话中 mm:ss」和「回到通话 ›」，点一下就展开。
34. 作为制作人，我想让通话层从对话栏底部整张滑上来、收起时滑下去，按 Esc 也能收起；系统开了「减少动态效果」时没有过渡。
35. 作为用键盘或读屏的制作人，我想让焦点在展开时进入通话层，收起后落在通话条上（通话已结束则落在电话键上），底下的内容不可交互。
36. 作为制作人，我想在通话中从更多菜单换她的衣装：电脑上是对话框、手机上是底部面板，正在预览的卡铺中性灰底，大预览的底是她的壁纸。

### 外围页面

37. 作为第一次来的访客，我想看到一张干净的登录页，能选 Google 或 GitHub 登录，被拒绝时看到清楚的提示。
38. 作为新用户，我想在同意页读完说明后同意并继续，这样知道自己同意了什么。
39. 作为任何人，我想在条款页和隐私页读到排版清楚的正文和联系方式，页脚有法务链接。
40. 作为制作人，我想在设置页改称呼、性别和时区，绑定或解绑登录方式，选默认麦克风和通话偏好，填自带密钥，删除账号，每一节是一块清楚的区域。
41. 作为管理者，我想在设置页看到进入后台的入口，普通用户则完全看不到这一节。
42. 作为制作人，我想在记忆页看到她记住的事、删掉其中一条或清空，删除前有确认；没有记忆时看到空状态，加载失败时看到失败提示。

### 后台

43. 作为管理者，我想要一个带侧栏的后台（看板 / 配置 / 用户，底部「返回设置」），手机上侧栏收进抽屉，这样在哪都能管。
44. 作为管理者，我想在每页顶上看到面包屑和页首，内容列限宽居中，这样宽屏上不至于一行拉得很长。
45. 作为管理者，我想在看板上切换 24 小时 / 7 天 / 30 天 / 90 天的范围，看到「此刻」和「{范围}内」两组数字卡。
46. 作为管理者，我想看到黑白（深色模式白黑）的趋势图和比例条，悬停时那一槽高亮、其他降到半透明，这样图表清楚又不花。
47. 作为管理者，我想在服务健康里只有出问题的服务带琥珀色或红色的点，正常的只写灰字，这样一眼看到问题。
48. 作为管理者，我想看到按角色、通话时长、花费的统计，每一块是一张卡。
49. 作为管理者，我想在用户列表里按后端支持的三种方式排序，看到「已封禁」「管理者」「自带密钥」「单独限额」等标记；窄屏时表格换成一行一行的列表。
50. 作为管理者，我想在用户详情里看到资料、近期用量，能封禁或解封、设单独限额、删除用户，危险操作前都有确认框，真正执行的那一下是红色按钮。
51. 作为管理者，我想在配置页每一项一张卡，标出「已被后台覆盖」「覆盖没有生效」，点「修改」在卡里展开表单，同一时间只开一张，还能「恢复成 .env 的值」。
52. 作为管理者，我想在单价表里点「修改」在那一行下面展开编辑。

### 开发与维护

53. 作为前端开发者，我想直接写 `<div>` 加 Tailwind 类做布局，不用再套一层布局原语。
54. 作为前端开发者，我想让她的颜色、挂断红和 `DESIGN.md` 里有名字的尺寸都注册成具名 token（`bg-her-wall`、`bg-hangup`、`text-meta`、`rounded-bubble`），这样不会散落 hex 和魔法数。
55. 作为前端开发者，我想直接改 `components/ui/` 里的 shadcn 源码并留 `// eidolon:` 标记，这样默认值不合适时有统一的改法，以后更新组件时看得出改过哪里。
56. 作为前端开发者，我想让 CI 用一个 grep 脚本拦下 `from "cn"`、任意值里的颜色和 `!` important 类，这样纪律不靠记性。
57. 作为前端开发者，我想让主题覆盖值和她的成对颜色都有对比度测试，这样改色不会悄悄掉到 4.5 以下。
58. 作为维护者，我想在每波结束时应用都能 `next build`、能逐页人工验收，这样分支不会长期处于半坏状态。
59. 作为维护者，我想在底座波和共用件波用像素比对证明旧页面没被污染，这样能放心地在旁边搭新底座。
60. 作为维护者，我想有一个截图脚本把每页浅色、深色各拍一张存档，附在 PR 里给人翻看。
61. 作为维护者，我想合进 main 时 `grep @astryxdesign` 为零、`theme:build`/`theme:check` 和生成产物都删掉，这样不留两套体系。
62. 作为部署者，我想在出问题时 `git revert` 合并提交、CI 重发 `:main` 镜像、VPS `docker compose pull` 就能回滚，因为这次不动数据库和后端接口。

## Implementation Decisions

### 技术栈与主题（02、05）

- shadcn/ui 底层用 **Base UI**，`shadcn init -b base -p nova` 生成 `components.json`（`base-nova`，生成后不能改）、`lib/utils.ts`、全局 CSS 的 `@theme inline` 与 `:root`/`.dark` 令牌。社区写法里的 `asChild` 要改成 `render`。
- Tailwind v4 用 `@tailwindcss/postcss` + `postcss.config.mjs`，全局 CSS 里 `@import "tailwindcss"`。
- 主题以 **shadcn neutral** 为底，不进 tweakcn。只覆盖有理由的变量（`--destructive` = 挂断红、深色浮层边线等），每个覆盖值都写进主题对比度测试。
- `shadcn init` 会把根布局字体换成 Geist、并生成自引用的 `--font-sans`，要撤掉。字体：中文 Noto Sans SC，日语台词 LINE Seed JP（`next/font` 的 `LINE_Seed_JP`，400/700；构建时「没有 fallback 度量」的提示无害）。
- 本机 npm 全局 `allow-scripts` 会让 shadcn CLI 报 `EALLOWSCRIPTS`，用 `NPM_CONFIG_USERCONFIG` 指向一份不带它的临时 npmrc 绕开。

### 印象色注入（02、05、07）

- `imageColor.ts` 的成对推色和对比度契约保留，只改注入方式。注入点（现在的 `herVars`）在对话子树上覆盖 shadcn 的 `--primary`/`--primary-foreground`（她的 accent/onAccent）和 `--ring`（她的 mark），以及 `--her-*` 变量；**不是** shadcn 的 `--accent`（那是悬停底色）。`color-scheme` 要和明暗同步。
- 留下的颜色对：`wall`（新增，对话壁纸；`--foreground`、`--muted-foreground` 在上面 ≥ 4.5）、`accent`/`onAccent`、`mark`、`button.bg`/`button.fg`（发送键和未读数）、`call.deep`（通话层渐变终点和通话条底，白字 ≥ 7）。
- 删掉的颜色对：`paper`、`paperMuted`、`note`、`noteRule`、`call.top`、`call.glow`、`call.rule`，连同它们的契约。`note`/`noteRule`（`--her-note`/`--her-note-rule`）在第三波 ③ 随通话条替换 `CallNote` 时删；其余在用到它们的最后一屏换完的那一波删。
- 浮层（Dialog、Drawer、Sheet、DropdownMenu、Popover）渲染到 body 拿不到子树变量：需要她的颜色时，传 Portal `container` 或在浮层内容上再注入一次（Scoped Colour Rule）。
- 选中状态一律中性 `bg-muted`，不用她的颜色。

### 两套库并存（02、03、04）

- CSS 层顺序：`reset, theme, base, astryx-base, astryx-theme, components, utilities`。
- Astryx 在 `@layer reset` 里给 `h1`–`h6`、`p`、`small` 设了颜色和字号，会渗进 shadcn 区域：在 Tailwind 的 `base` 层把它们改回 `color: inherit; font: inherit`。
- 两者在清理波一起删掉。不用双根布局、不加 `tw` 前缀。

### 迁移节奏（04）

- 所有实现提交都在 `feat/shadcn-redesign` 上，全部换完后一个 PR 合进 main。main 不冻结：**每波开工前先把 main 合进分支**，冲突在分支里解决；main 上必须做的 UI 改动在分支上用新组件重做一遍。
- **以屏为单位替换**：每波结束时，任何一屏都不能同时出现新旧两种组件；共用同一个布局的屏一起换（`(conversations)` 下的对话列表和对话页；`admin/` 下的全部后台页）。
- 每波结束时应用都能 `next build`。
- 合进 main 的条件：清理波把整张验收清单走完（`next build` + `next start`，浅色深色，用户侧、后台、法务），CI 全绿，`grep @astryxdesign` 为零。
- 回滚：revert 合并提交 → CI 重发 `:main` → VPS `docker compose pull`。不搭预发环境。

### 组件对应（01、06）

- 直接用 shadcn 组件：Button、Alert、Empty、Dialog、AlertDialog、Drawer、Sheet、Field/FieldGroup、Toggle Group、Tabs、Sidebar、Card、Badge、Table、Resizable、DropdownMenu、Popover，以及官方聊天组件（Message、Bubble、Message Scroller），按需取用。
- 薄封装：Selector、MoreMenu、BottomSheet、Avatar、Token、Table（排序、行展开）、Pagination、Resizable。
- 自写：StatusDot、Timestamp、MetadataList、NumberInput、ChatComposer、`useMediaQuery`、通话层强制深色。Astryx 的 `Text`/`Heading`/Stack/Layout 系列不再有对应物，直接写元素加 Tailwind 类（见组件纪律）。
- 原样保留：`imageColor.ts`（按上面增删颜色对）、`panelSizes.ts`、`icons.ts`（Lucide 语义别名）、`Ja.tsx`、手写 SVG 的 `TrendChart`。删除：`astryxIcons.ts`、`notebookTheme.ts`（其中深色修补和对比度决定搬进新主题）、`lineState.ts`（Line-State Rule 已删）、`theme/built/`、`@stylexjs/stylex`。
- **不引入 TanStack Table**：排序三档全在后端，行展开只有单价表一处，shadcn `Table` 加普通 state 就够。
- **对话列表调宽用 shadcn `Resizable`，按像素**：默认 320、240–480px、`groupResizeBehavior="preserve-pixel-size"`，`onResize` 的 `inPixels` 记进 localStorage，挂载后在 layout effect 里恢复，沿用 `useSavedSize` 的行为。不自己写拖拽。

### 组件纪律（10）

底座波把以下内容写进 `frontend/AGENTS.md` 的「shadcn 纪律（新代码）」一节，根目录 `AGENTS.md` 的 Astryx 说明保留并加一句「只适用于还没迁移的屏」；清理波删掉两份文件里的 Astryx 部分。

- **布局**：直接写 `<div>` 加 Tailwind 类，不自写 `Stack`/`Row` 原语。同样的结构在两屏以上出现、并且能用 `GLOSSARY.md` 或 `DESIGN.md` 里的词叫出名字，才抽成项目组件。
- **颜色**：只用具名主题变量。`--her-*`、挂断红等固定色在 `@theme inline` 里注册成 Tailwind 颜色（`bg-her-wall`、`bg-hangup`）。任意值里不准出现颜色（`[var(--…)]`、hex、oklch、rgb、hsl 都不行）。新增固定色写进对比度测试。
- **尺寸**：`DESIGN.md` frontmatter 里有名字的值（字号层级、气泡圆角、头像等）注册成 `@theme` token（如 `text-header`、`text-meta`、`rounded-bubble`），必须用 token。间距只用 Tailwind 刻度。任意值只用于一次性的布局约束（`max-w-[min(30rem,72vw)]`、`grid-cols-[…]`、`h-[80%]`）。
- **`components/ui/` 直接改**（Own-the-Source），改处加 `// eidolon: <原因>`。`shadcn add` 不带 `--overwrite`，更新组件先看 diff。
- **调用处不改外观**：调用处的 className 只管定位和排布。外观要变就到 `ui/` 组件加 variant/prop 或改那条带条件的类；禁止 `!` important；`group-data-[…]` 盖不住的情况同样这样处理。
- **目录和命名**：项目共用件放 `components/app/`，后台的放 `components/app/admin/`，文件名与旧版相同（PascalCase），新旧靠目录区分；清理波只删旧文件，不搬家不改名。各屏自己的组件（`conversations/`、`admin/` 下）在所属那一波就地重写。`ui/` 用 shadcn 的 kebab-case。
- **`cn`** 一律从 `@/lib/utils` 导入，`shadcn add` 生成的 `from "cn"` 当场改掉。
- **机器检查**：不装 ESLint。底座波在 CI 前端 job 加一个 grep 脚本，禁止 `from "cn"`（`lib/utils.ts` 除外）、任意值里的颜色（`-\[(#|oklch|rgb|hsl|var\(--)`，以及 v4 的变量简写 `bg-(--x)`、`text-(--x)` 这类颜色工具类）、`!` 前缀的 important 类；清理波把 `@astryxdesign` 加进同一个脚本。字号、圆角任意值的界线交给代码审查。

## Testing Decisions

- **好的测试只测外部行为**：对比度测试断言「某一对颜色在某个模式下的对比度 ≥ 阈值」，注入测试断言「给定印象色，子树上的 `--primary`/`--ring`/`--her-*` 是什么值」，不测组件内部结构或类名。这次没有组件测试，也不新增；界面行为靠人工验收清单。
- **测试接缝只有三处，都沿用现有的**：
  1. **颜色契约**：`imageColor.test.ts` 的 `pairs()`（5 位官方色 + 216 色网格）。新增 `wall` 一对，删掉 `paper`/`paperMuted`/`note`/`noteRule`/`call.top`/`call.glow`/`call.rule` 的契约。
  2. **注入**：`herVars.test.ts`。底座波加 `--primary`/`--ring` 断言；旧断言（`--color-accent`、`--her-note` 等）先留着当「旧页面没被污染」的证据，哪个旧变量在某一波之后没人用了就在那一波删它的断言；清理波删掉剩下的。`adminUsers.test.ts` 若引用了 Astryx 的类型或值，随用户列表那张 ticket 改。
  3. **主题对比度**（新增，替代 `notebookTheme.test.ts`）：`--muted-foreground` 在 `--background` 和 `--muted` 上 ≥ 4.5；`--destructive` 上白字 ≥ 4.5；深色浮层边线和浮层底、页面底都 ≥ 3；新增的固定色（挂断红等）也写进来。底座波加，`notebookTheme.test.ts` 留到清理波删。
- **`lib/` 下的逻辑测试**（`liveConversation`、`conversationLog`、`callFocus`、`panelSizes`、`dashboard` 等约 30 个）原样保留、必须一直通过；这次不改领域逻辑，它们是回归保护。
- **CI 前端 job**：`typecheck` → `npm test` → `theme:check`（保留到清理波）→ grep 脚本（底座波加）。清理波删 `theme:check`，不换同类检查。
- **截图脚本**：参照 `scripts/stand-thumbnails.mts` 调用 Playwright Chromium 的写法，连本地真实后端和开发库（不造 mock），每页浅色、深色各一张，输出到 gitignore 的目录。**只做存档，不做自动比对**；通话层等依赖实时状态的页面不进脚本。
- **像素比对只用在底座波和共用件波**：基准图拍在「只换字体」的那个提交上；后续提交和它比，要求零差异。范围限于不依赖实时数据的页面：登录、法务、后台各页的静态部分。
