# 通话属于导航外壳，不属于对话页

通话原来跟着对话页的生命周期：对话页自己建一份对话的实时状态（`LiveConversation`，管着记录、文字回合、通话和通话层），离开她的对话页就丢掉它，通话随之挂断，哪怕只是去设置看一眼通话音质、或者在手机上回列表看看别人的最后一句。接下来的礼物还要求「通话中从别处送礼，下一个通话回合她回应」，在同一个标签页里做不到。

所以通话改由导航外壳持有（对话、设置共用的那个 layout，以后还有礼物页）。有通话在进行时，这份实时状态、她的声音（`CharacterVoice` 和放声音的元素）、电话本身的声音（铃声、接通音、挂断音）和切换麦克风的面板都在外壳里，换页时不卸下；回到她的对话页时用外壳里那一份，记录、通话层收没收起都和离开时一样。在不是她对话页的外壳页面上，最顶上一条带她名字的通话条，点了在当前页打开通话层。

同一时间只和一位角色说话：通话中打开另一位角色的对话、离开外壳（后台、记忆、`/about`、隐私政策、使用条款）先问，确认了才挂断；退出登录、删除全部数据只有各自的确认，确认了就挂断；关掉页面就挂断。这些挂断都算用户自己挂断（GLOSSARY「通话」）。去哪里要不要问，由一个不依赖 React 的纯模块（`frontend/src/lib/navShell.ts`，「外壳的去处规则」）回答，外壳和确认框只照它的回答做。

`LiveConversation` 本身的状态机（拨号、接通、结束、收起、展开）不变，变的是谁持有它、它活多久。

## Considered Options

- **照旧离开对话页就挂断，只是去设置前不问**：改动最小，但「换页不断线」和礼物的「通话中送礼」都做不到。
- **跨浏览器标签页保持通话**（例如放进 SharedWorker 或单独的通话窗口）：WebRTC 连接和麦克风要搬出页面，复杂得多，也不是用户要的；同一个标签页里换页不断线已经够用。
- **允许同时和几位角色通话**：麦克风只有一个，用户也只能同时和一个人说话，没有意义。

## Consequences

- 通话中换页不挂断是用户能感觉到的边界，以后不好改回去；礼物的「通话中送礼」建在它上面。
- 通话层有两处画：她的对话页上盖住对话栏（由那一页画），别的外壳页面上盖住当前页（由外壳画）；画的是外壳里同一份实时状态，收没收起、画哪一通都在它的快照里。
- 外壳里的页面不再占满整个视口，而是占满外壳给它的那一块（顶上可能有一条通话条）。
- 不经确认的离开（按浏览器的返回离开外壳、在地址栏里打开另一位角色）拦不住：外壳卸下或者打开另一位角色时照样挂断，只是没有先问。
