# 统计里的通话另记在对话下面，不读运行记录

统计要给用户看通话次数和通话时长，但对话数据里原本没有通话本身，只有通话里说的回合；通话的开始和接通时长只在运行记录里。我们没有让统计去读运行记录，而是从统计上线起，每次接通的通话在它所在的对话下面另记一条，只有开始时间和接通时长，不含内容，跟着对话一起删。上线前的通话不补，所以通话时长只从上线那天起才有。

## Considered Options

- **统计直接读运行记录**：不用多存一份，还能立刻看到最近 90 天。但运行记录按定义只有管理者能看；它只留 90 天，做不了全部时间的累计；它也关联不到对话，用户删了一段历史对话，那段里的通话照样留在统计里，违背了「删了就彻底没了」。
- **用运行记录补回上线前 90 天**：运行记录里没有对话 id，只能按用户、角色和时间去猜是哪段对话，猜错了统计就错，换来的只是 90 天的旧数据。
- **不做通话时长**：通话是这个产品的招牌，统计里少了它就少了一大块。

## Consequences

- 通话时长在运行记录和对话下面各有一份，口径都是接通后的时长，但用途不同：前者给看板，后者给统计。别为了去重把统计改成读运行记录。
- 隐私政策里列我们存了什么的那一节要补上这份通话记录。
