# 用户可以导出、导入自己的数据包，好感度和礼物不随行

部署者哪天不做了，用户原本没办法带走自己的数据，也没办法在另一个部署上接着用。现在用户可以在设置里把自己的对话（连同照片）、记忆和制作人档案导出成一个数据包，再导入到这个或别的部署；导入时并进那位用户已有的数据，不覆盖。数据包是用户自己下载、自己保管的，这和 ADR-0012 里「不做导出」并不冲突：那里拒绝的是管理者从服务器导出整库，留下不受保留期约束、碰得到所有用户内容的明文副本；数据包只有本人能导出，只有他自己的东西，管理者既不能代为导出，也看不到。

数据包是用户手里的文件，他想怎么改都行；而它要能导入到别的部署，就验不了旧部署的签名。所以只带改了也只影响他自己的东西：对话和记忆就算是伪造的，也只改变她怎么对待这一位用户，照原样导入，不校验真假。好感度、抽奖次数、重置卡和礼物背包不在数据包里，导入后所有角色从信任重新开始，抽奖次数和背包从零开始：它们只能在这个部署里挣来，和管理者不能单独给某位用户发礼物、好感度只有重置卡能改是同一个道理。

## Considered Options

- **好感度和礼物照原样导入**：搬家最完整，但改一下文件就能把好感度拉满、背包塞满。
- **导入，但好感度压到正常值以下**：用户只要把低的几条删掉，就等于只导入了坏的，没有意义。
- **只导出、不导入（留作记录）**：用户会以为带走了，到了新部署却没有；数据包里只放能导入的东西。

## Consequences

- 对话里的附带记录照原样导入，包括消息上的好感度变化标签和文字回合上她快要不耐烦了的记录：导入的最后一段要是成了当前对话，她在旧部署上的不耐烦会跟过来。好感度本身从信任开始，旧标签只是一段历史。
- 新部署上没有的角色，和她的对话不导入，免得留下看不见、删不掉的记录；她当来源角色的记忆照样导入，显示成已不在的角色。
- 数据包导出以后不归我们管：用户删除数据时，他下载过的数据包不会跟着消失，ADR-0006 的「真删」只管服务器和备份。
- 数据包带格式版本号：新版本能导入所有老格式，老版本遇到更新的格式就拒绝，不悄悄丢掉认不得的部分。
