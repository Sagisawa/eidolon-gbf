# 语音识别服务在部署时二选一（Soniox 或阿里云百炼），自带密钥的用户自己选

部署时用 `STT_PROVIDER=soniox|bailian` 选一家语音识别服务（不填为 `soniox`），整个部署只用这一家，出故障也不换另一家。自带语音识别密钥的用户在填 key 时自己选 Soniox 还是阿里云百炼，和部署者的选择无关：两家的实现本来就都要写，让用户选几乎不增加成本，而大陆用户拿百炼的 key 远比拿 Soniox 的容易，这正是自带密钥的意义。所以同一个部署里，不同用户的通话可能由不同的服务识别；补充和打断依赖的时序（多久出终稿、没听到词时出不出稿）由各家服务自己给出，不再是一个全局常量。

百炼的 key 分地域（北京、新加坡互不通用），由系统自动判断：先试北京，被拒再试新加坡，判断结果随 key 存下；部署者的 key 在启动时判断，两个地域都不通或模型没开通就拒绝启动。

公开部署选百炼时，允许使用北京地域，即陌生用户的声音会送到中国内地处理、按中国法律保存。这是有意接受的取舍：按量付费调用的数据阿里云承诺不用于训练，和 ADR-0005 修订里 Gemini 免费层的情况不同；剩下的是「会保存、期限不公开、受所在地法律管辖」，由隐私说明写清楚（固定文案，两家都列，写明不训练、会保存、存放在中国内地或新加坡），读的人自己判断。

## Considered Options

- **用户的语音识别密钥跟随部署者的选择**：界面更简单，但部署选 Soniox 时大陆用户就几乎没法自带语音识别密钥，也就几乎拿不到通话的限额豁免。
- **公开部署只允许新加坡地域**：隐私上更保守，但会把大陆部署者挡在外面；而且大陆以外的用户拿北京的 key 本来就难，真正受影响的主要是大陆用户自己。
- **隐私说明按部署实际的服务商和地域动态显示**：更精确，但要后端多暴露一项配置；自带密钥的用户又可能用另一家，动态文案也说不全。
- **由用户或部署者手选地域**：普通用户分不清自己的 key 属于哪个地域，只会多出一类「选错地域」的报错。

## Consequences

- 已经存下的语音识别 key 没有记服务商，一律视为 Soniox 的。
- 百炼的 STT 模型跟部署者的配置走（`BAILIAN_STT_MODEL`），用户不选模型；部署选 Soniox 时用代码里的默认百炼模型。
- 百炼新加坡地域的老域名 `dashscope-intl.aliyuncs.com` 官方标为「即将下线」，下线时要改用带 WorkspaceId 的域名，届时用户可能要多填一项。
