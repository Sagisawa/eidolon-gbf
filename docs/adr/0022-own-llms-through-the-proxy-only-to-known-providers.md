# 用户自带的 LLM 和生图只在连已知服务商时才走网络代理

自带密钥的请求都是服务器发出的（ADR-0017），用户自己开的代理或 VPN 管不到。服务器在国内时，自带 Gemini、OpenAI、Fish Audio、Soniox 的 key 直连都不通，所以网络代理给用户自带的密钥加了三项选择（LLM、语音合成、语音识别），和部署者的服务分开勾，因为两边用的服务商可以不同。语音合成和语音识别连的是固定的服务商地址，勾上就走代理。自带的 LLM 不一样：地址是用户自己填的，直连时服务器在建立连接前检查解析出来的地址是不是公网（防止有人借服务器去访问它所在的内网，SSRF），而交给代理以后，解析和连接都在代理那边做，服务器查不到实际连到了哪里。mihomo 这类按规则分流的代理还会把内网地址和国内域名放行直连。所以自带的 LLM 只有在服务地址是 HTTPS、主机名属于已知服务商时才走代理；名单取价格目录里 models.dev 写了服务地址的服务商，加上代码里认得的几家和 OpenRouter；目录里不是 HTTPS 的地址、IP 地址、`localhost` 和模板地址都不算。其他地址照旧直连并做公网检查。后来加的自带生图同理：地址也是用户自己填的（官方接入点或各家中转），只有 HTTPS 的 NovelAI 官方生图地址算已知服务商，勾上才走代理，中转一律直连并做公网检查。

## Considered Options

- **自带的 LLM 一律走代理**：国内用户填任何海外中转都能用，但 SSRF 的防线就没了。
- **先在本机解析、确认是公网再交给代理**：挡不住 DNS rebinding（代理那边再解析时可以换成内网地址），而且国内的 DNS 对谷歌这类域名的解析可能被污染，会误伤最需要代理的那几家。名单里是公开服务商的域名，攻击者控制不了它们的解析，所以走代理时不在本机解析。
- **部署者在后台手动加信任的主机名**：多一个容易填错的口子；真需要时，部署者可以把那个中转配成自己的服务。
- **自带密钥沿用部署者同一项服务的勾选**：部署者的语音识别用百炼直连、用户自带的是 Soniox 时就会出错。

## Consequences

- 价格目录拉不到时（新部署、models.dev 访问不了），名单只剩代码里的那几家；这时名单外的地址照旧直连，不放宽。
- 名单随 models.dev 每天更新。models.dev 新收录一个服务商、写了它的地址，那个主机名就能走代理；这相当于信任 models.dev 收录的地址都是公开的服务商。
- 用户自带密钥走的是部署者的代理流量，所以这几项默认都不勾，由部署者决定。
